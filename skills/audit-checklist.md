# 監査チェックリスト v1

**監査は合否の門ではなく、補助の目です（ADR-0027）。** 見るのは diff と受け入れ基準
（acceptance criteria）の対応であって、コードベース全体の健全性一般ではありません。
検証コマンド（verify）を回すのはあなたの仕事ではありません——それはマージ前ゲートが
検証環境の中で機械的に行います。ここで一式を回して待つと、判定を出せないまま
ターンが終わり、工程が止まります。

まず diff だけで下の項目を判断してください。判断できない項目だけ、関係するファイルへ
遡って確認してください（遡ったら `audit_report` の `consultedBeyondDiff` に理由を書く）。

すべての項目がパスした場合のみ `verdict: "pass"` を報告する。
一つでも問題があれば `verdict: "fail"` とし、具体的な指摘を findings に記述する。

## 必須チェック項目

### 1. タスク定義の acceptance criteria の充足
- [ ] diff の変更内容が、各 acceptance criteria の text を満たしているか
- [ ] （検証コマンドの実行結果はここでは見ない——マージ前ゲートの担当）

### 2. スコープ遵守（P1）
- [ ] diff に含まれるファイルが、タスクの `scope.paths` の範囲に収まっているか
- [ ] スコープ外の変更が「ついで」で行われていないか
- [ ] スコープ外で発見した問題は incident として記録されているか（直接修正されていないか）

### 3. エラー取り扱い（I2）
- [ ] diff 上でエラーが握りつぶされていないか（空の catch ブロック、サイレントな失敗など）
- [ ] 回復不能なエラーは failed 状態として記録されているか

### 4. 型安全性（I4）
- [ ] diff が TypeScript strict モードに違反していないか
- [ ] `any` を使う場合は、その行に理由コメントが付いているか

### 5. 依存追加の理由記録（D6）
- [ ] diff が新しい外部依存を追加している場合、追加理由が 1 行コメントで記録されているか

### 6. エスカレーション未判断事項（D1）
- [ ] diff が不可逆な選択（公開 IF 変更、データモデル変更、外部依存追加）を自己判断していないか
- [ ] 判断が必要な場合は escalate されているか

## 合格基準

上記すべての項目が diff から（必要なら遡って確認した範囲を含め）パスした場合のみ
`verdict: "pass"` を報告する。疑わしい点がある場合は `verdict: "fail"` として findings に
具体的な問題を記述する。

## 基準の変更について

この checklist の変更は git diff として見える（D2: 基準はテキスト、機構はコード）。
基準を変更する場合はこのファイルを編集し、変更理由を commit message に記録する。
