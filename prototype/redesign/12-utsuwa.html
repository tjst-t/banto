器の語彙案11「膳」の土台 案11 膳 →

Tool の戻り値を、番頭が
中核の器に載せて膳に組む

モジュールは GUI 部品を作らない。この語彙に載る形でデータを返すだけ。
番頭が決めるのは「どのデータを・どの器で・どれだけ」であって、レイアウトを作ることではない。

提案 · 2026-08-09 · 案11「膳」に付随 · 器 13 種

この語彙が守る4つの規則

  1. 番頭は選ぶが、作らない。器は有限。無から組ませると、同じ話が毎回違う見た目になる。生成UIではなく選択UI。
  2. 器は中核が持ち、モジュールは形を合わせる。spec-canvas-ui §10「モジュールごとの CSS を足さない。足りない語彙は §5 に追加して全モジュールで共有する」の延長。
  3. 膳は小さい。大きいものは面へ。Tool の戻り値は 4000 文字で切り詰められる（TOOL_PAYLOAD_MAX_CHARS）ので、この線は規約ではなく機構が引く。切ったことは隠さない（I1）。
  4. どの器も「畳んだ姿」を持つ。広い姿と、狭いときの1行（「4件」「+42 −18」）。 判定はコンテナクエリ——ビューポートではなく「会話の帯の幅」で決まるので、 細い帯でもモバイルでも同じものが効く（spec-canvas-ui §3 と同じ規約）。 器を1つ足すコストが2倍になるので、語彙を増やしにくくする歯止めにもなる。
  5. 器は凍る。どの器も「いつの」を出す。器はそのときそう見えた記録で、会話の一部だから後から変わってはいけない（幹は追記のみ・D3）。 いまの状態が要るなら open で面へ行く。枝の札だけは参照なので生きる——記録と参照を混ぜない。
  6. 分からないものは分からないと出す。件数・時刻・大きさを 0 と偽らない（I1）。器は null を「—」として描き、勝手に埋めない。
層誰が持つかデータの出どころ大きさ
面（canvas-view）モジュール（React・決定12 のまま）自分で endpoint から取る（決定25）画面いっぱい
膳の器（この頁）中核番頭が canvas.show で指した Tool の戻り値会話の1ブロック

決定25 が部分的に裏返る。面は自分でデータを取るが、器は番頭の文脈を通ったデータを描く。 これは制約であると同時に安全弁でもある——文脈を通る以上、膳に載るものは必ず小さい。

行の一覧

list

いちばん使う器。同じ形のものが複数あり、1つずつに状態が付くとき。職人・環境・記憶・ファイル・枝——ほぼ何でも載る。 10 行を超えたら面へ送る（膳は舐めるためのもので、探すためのものではない）。

Tool の戻り値

{ "utsuwa": "list",
  "title": "止まっていない検証環境",
  "total": 3,
  "items": [
    { "label": "env-31 · task-0086 の検証",
      "state": "warn",
      "meta":  "6日 · 1,400円/月" },
    …
  ] }

state は 5役だけ（run / turn / stop / warn / done）。 モジュールが独自の状態名を持ち込まない——持ち込ませると色の意味が崩れる。

上限に対してどこまで来たか。quota・文脈の使用量・進み具合。 上限が分からないときは使わない——分母の無い割合は嘘になる（I1）。

推移

spark

数字1つでは「良くなっているのか」が言えないとき。 P6 が要求する計測（何回中何回落ちるか）は、いまの率だけでなく下がっているかどうかで意味が変わる。 1本だけ・8〜30点まで。軸も凡例も出さない——比べるものが1つなら、要るのは形と現在値だけ。

Tool の戻り値

{ "utsuwa": "spark",
  "label": "タブに中身が出ない率",
  "points": [37,33,35,30,12,8,2,0],
  "unit": "%",
  "span": "直近8日",
  "good": "down" }

good は「どちらへ動けば良いか」。器はこれを見て色を決める—— モジュールに「緑にして」と言わせない（D5）。値の目盛は出さない。読みたいのは向きと現在値で、 細かい数字が要るなら表か面へ。

文書

doc

散文の抜粋。ADR・spec・記憶の本文・引き継ぎ資料。 見出しと最初の数段落まで。それ以上は「全部読む →」で単体のファイルを読む面へ送る ——長い散文は器の大きさを超える。

Tool の戻り値

{ "utsuwa": "doc",
  "title": "ADR-0017（草案）",
  "path":  "docs/adr/adr-0017-…md",
  "excerpt": "## 会話の面：幹1本と枝、器と面\n\n会話が…",
  "truncated": true,
  "open": { "view": "file.viewer", "args": { "path": "…" } } }

描くのは見出し・段落・箇条書き・強調だけ。表も画像もコードも器の外へ出す ——マークダウンを全部描けるようにすると、器が小さなブラウザになる。

面への口

open

膳に載らないとき。10行を超える一覧・全部の差分・触れる環境。 この器があるから、他の器が小さいままでいられる——載らないものを無理に載せない逃げ道。

Tool の戻り値

{ "utsuwa": "open",
  "view": "git.viewer",   // または file.viewer（単体を読む）
  "label": "差分をぜんぶ見る",
  "meta": "12 ファイル · +420 −180",
  "args": { "place": "banto", "ref": "HEAD" } }

描けない面は出さない（決定12・17）。濾すのは offer する側＝UI。実体の無い面を並べると、押した先が「この面を描けません」になる。

探す面と読む面は分ける。file.browser（探す・移動する）と file.viewer（1つを読む）は目的が違うので別種にする——決定17 が 「シェルと職人ビューアは目的が違うので別コンポーネント」としたのと同じ理屈。

開いた面は「膳と同じ頁」に出る（案11）。幹の隣に寄り添い、狭い画面ではめくりの1枚になる ——枝と面で置き場を分けない。閉じても会話には抜粋が残るので、あとから遡れる。

見本

作らない器

足さない理由を書いておく。書いておかないと同じ議論が戻る
作らないものなぜ代わりに
棒グラフ膳に載る程度の本数（2〜5本）なら、表のほうが速く正確に読める。棒は本数が多いときに効く器で、多いなら膳ではない表／面
円グラフ角度は人が読み違える。割合が1つなら目盛、複数なら表で足りる目盛／表
散布図・箱ひげ点を見比べる作業は膳の大きさを超える。ここで要るのは分析ではなく判断面
ツリー・グラフ図依存や階層は、番頭が言葉で言えるなら言うべき（「Aが終わらないとBは動けません」）。図にすると読む手間が増える本文／面
カンバン・ボード面の仕事（kobo.board）。膳に置くと、眺めるためのものが会話に居座る面
マークダウンの全部描画表・画像・コード・脚注まで描けるようにすると、器が小さなブラウザになる。文書の器は見出しと段落と箇条書きだけ文書＋面
自由な図・画像の生成番頭に絵を描かせると、選択UIが生成UIに戻る。この語彙の前提が崩れる——

共通する判定は1つ：「見比べる作業」は面、「判断に要る事実」は膳。 グラフのうち spark だけを残したのは、これが見比べる器ではなく1つの事実（向き）を言う器だから。

足すときの歯止め

器を1つ足すたびに、番頭の選択肢が増え、画面のばらつきが増える。 だから足すのは ADR を通す。判定はこの2つ：

① いまの器の組み合わせで描けないか。ほとんどは「行の一覧＋鍵と値」で足りる。
② 載せたいものが、そもそも膳の大きさか。4000文字に収まらないなら、それは器ではなく面の仕事。

逆に、使われていない器は畳む。案11 は番頭の選択に賭ける案なので、選択肢が多いほど賭けが重くなる。

決まったこと

2026-08-09 · PO裁定
  1. どの器で描くかは番頭が都度指定する。モジュールは素のデータを返すだけで、器のことを知らない。 同じ戻り値でも文脈によって出したい器は変わり、モジュールは文脈を知らないから（D5）。
    データは再送させない——番頭は「どのツール結果を・どの器で・どこを」だけを言い、実体はホストが 退避済みの結果（決定47(a) の artifacts/）から引く。
    副作用：新しい Tool が1つ要る（canvas.show）。ADR に書く。
  2. 膳＝器1つ。並べたいときは器を続けて出し、縦に並べる。まとまりを表現する＝レイアウトを組ませることなので、 「番頭は選ぶが作らない」が崩れる。入れ子は許さない。足りないと分かったら、上限3・入れ子なしの配列を後から足せる。
  3. 器は凍らせ、「いつの」を必ず出す。面と器は二重管理ではない—— 器＝そのときそう見えた記録（会話の一部・書き換わらない）、面＝いまの状態（自分で取る）。 枝の札だけは参照なので生きる。
  4. 描けない戻り値は会話に出し、番頭にも返す。どのモジュールのどの Tool か・頼んだ器・何が足りないかまで書く （直せるのは登録した人なので、出所が分かる形で）。番頭にも同じものが返るので言い直せる。会話は止めない—— 回復可能だから I2 の「failed にして止まる」には当たらない。素の値は畳んで置き、黙って素の JSON を出さない （壊れた見た目が既定になる）。
