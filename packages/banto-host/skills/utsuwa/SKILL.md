# 器（utsuwa）— ツールの戻り値を会話に載せる

## いつ使うか

調べた結果を PO に見せるとき。**判断に要る事実は器、見比べる作業は面**。

## 器は選ぶもので、作るものではない

語彙は中核が持つ**13種で固定**。あなたが決めるのは「**どの観測を・どの器で・どこを**」だけで、
レイアウトは作らないし、データも書き直さない。

```
canvas.show({ utsuwa: "list", artifact: "a-0007", path: "envs", title: "止まっていない検証環境" })
```

- `artifact` は**観測のID**。ツール結果の末尾に `［観測 a-0007｜canvas.show で器に載せられる］`
  として必ず出ている。**データを打ち直さない**——ホストが退避先から引く
- `path` は観測の中のどこを載せるか（`envs.items` のようなドット記法）。省くと全体
- **膳＝器1つ。** 並べたいときは続けて呼ぶ

## どの器を選ぶか

| 器 | いつ | 上限 |
|---|---|---|
| `list` | 同じ形のものが複数、1つずつに状態が付く。**いちばん使う** | 10 行 |
| `facts` | 1件についていくつかの事実。三部構成もこれ | 12 件 |
| `table` | **列どうしを見比べる**ときだけ。比べないなら `list` のほうが軽い | 4列8行 |
| `diff` | 何がどう変わるか。抜粋であることを隠さない | 24 行 |
| `stats` | 数そのものが答え | 3つ |
| `meter` | 上限に対してどこまで来たか。**上限が分からないなら使わない** | — |
| `spark` | 数字1つでは「良くなっているか」が言えないとき。1本だけ | 30 点 |
| `timeline` | **並びを変えてはいけない**とき | 10 件 |
| `image` | 見せたほうが速いとき。`alt` は必須 | 1枚 |
| `doc` | 散文の**抜粋**。全部は `file.viewer` の面へ | 1200 字 |
| `quote` | 出どころのある文字をそのまま。出どころを必ず添える | 600 字 |
| `open` | 膳に載らないとき。面への口 | — |

`choice`（判断待ち）は**器から出せない**。判断を求めるものは `inbox.post`（取次1本）。

迷ったときの判定：

- 同じ形が並ぶ → `list`。**10行を超えるなら面へ**（膳は舐めるもので、探すものではない）
- 1件の内訳 → `facts`
- 数字を縦に比べたい → `table`。比べないなら `list`
- 「良くなっているか」を言いたい → `spark`（1点では言えない。2点以上要る）
- 触る・探す・全部見る → **面**（`canvas.open` か `open` の器）

## 面との使い分け

> **見比べる作業は面、判断に要る事実は膳。**

- **面**（`canvas.open`）は幅が要る作業のためのもの——探す・移動する・比べる・触る。
  開くと会話に1行残るので、PO はあとから戻れる
- 器に載せようとして大きすぎるなら、`open` の器で面への口を出す。
  **この口があるから、他の器は小さいままでいられる**

## 描けなかったとき

`canvas.show` は「**どのモジュールの・どの Tool の・どの器で・何が足りないか**」を返す。
同じものが会話にも出るので、PO からも見えている。**会話は止まらない。**

やること:

1. **別の器にする。** `table` が `cols` 不足なら `list` で出し直す、が典型
2. **面へ送る。** 大きすぎたなら `open` の器にする
3. **モジュールの側の問題なら、そう言う。** 直せるのは登録した人なので、
   出どころ（モジュール名・Tool名）をそのまま伝える

**同じ器で繰り返し試さない。** 足りないものは器を変えても増えない。

## やらないこと

- **データを打ち直して渡さない。** 観測のIDで指す（打ち直すと文脈を二重に食う）
- **素の JSON を会話に貼らない。** 描けないなら `broken` がその旨を出す
- **器を組み合わせて画面を作らない。** 入れ子は無い。並べたいときは続けて出す
- **「いつの」を自分で書かない。** 観測を取った時刻が自動で載る（器は凍る記録）
