# Deliverables（リポジトリに紐づかない成果物の残し方）

## いつ使うか

PO に頼まれた調査・比較・整理の結果を、**会話の外に残す**とき。

特定のリポジトリについての文書なら、その場所の中（`docs/` 等）に置く——ここで扱うのは
**どのリポジトリにも属さない**もの。会話に流したままだと、章を畳んだ時点で PO からは
追えなくなる。

## どこに置くか

**場所 `desk` に置く。** 実体のパスは環境ごとに違い、PO が設定で決める。

**この手順書にも成果物の本文にも、実体の絶対パスを書かないこと。** 書いた瞬間に、人や
デプロイ先が変わると通用しなくなる。指すのは常に場所の id（`desk`）と、そこからの相対パス。

## 手順

1. **場所を確かめる。** `place.list` に `desk` があるか見る。無ければ PO に
   「成果物の置き場所（`desk`）を設定してほしい」と頼む——設定画面の「場所」で足せる

2. **書く。**

   ```
   file.write({ place: "desk", path: "reports/2026-08-05-<件名>.md", content: "..." })
   ```

   **断られたら**（書き込み範囲の外・読み取り専用）、範囲を頼む：

   ```
   place.request_write({ place: "desk", patterns: ["reports/**"], reason: "調査結果を残すため" })
   canvas.open({ kind: "place.permissions" })
   ```

   頼んだだけでは書けない。**PO が許可するまで `file.write` は失敗し続ける**ので、
   承認を待ってから書き直す。範囲は必要な分だけ狭く頼むこと。

3. **見せる。** 書いたら開いて示す。書きっぱなしにしない：

   ```
   canvas.open({ kind: "file.browser", params: { place: "desk", path: "reports/2026-08-05-<件名>.md" } })
   ```

## 書き方

- ファイル名は `YYYY-MM-DD-件名.md`。**名前順がほぼ時系列になる**（一覧は名前順で出る）
- 冒頭に日付・題・何のための調べ物かを1行ずつ。後から見た PO が、文脈なしで読み始められること
- 長い調査でも1ファイルにまとめてよい。画面は途中で打ち切らず「続きを読む」で最後まで読める
- **番頭はコミットできない**（決定37）。書いたものは未コミットのまま残り、PO の目を通る
