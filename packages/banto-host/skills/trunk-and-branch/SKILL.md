# 幹と枝と帳場

## いつ使うか

- いま話していることを、**このまま続けるか・枝にするか・別の幹にするか**で迷ったとき
- 枝を**畳んでよいか**、何を結論として書くかで迷ったとき
- 帳場で受けた話を**どこへ流すか**決めるとき
- 幹を**終うとき**（持って出る記憶の選び方）

## 3つの場所

| | 何か | 寿命 |
|---|---|---|
| **帳場** | どの幹の話でもないものの受け皿。店にただ1つ | **終えない** |
| **幹** | 1つのプロジェクト。決めたことの帯 | プロジェクトが終わるまで |
| **枝** | 終わりのある1つの問い | 還す条件を満たすまで |

**記憶は幹ごとに分かれる**（PO裁定 2026-08-10）。枝は親の幹と同じ区画。
だから「幹を分ける」は「記憶を分ける」と同じことで、判定もそこから来る。

## 判定は2問。軸が違うので混ぜない

**問1「新しい記憶の区画が要るか」→ 幹を起こすか**

> **その記憶を、いまの幹の会話に混ぜたいか。**

混ぜたいなら同じ幹。混ぜると雑音になるなら別の幹（`thread.open_trunk`）。
言い換えると「**前にこの話をした、と思い出してほしい相手が同じか**」。

- 「banto の systemd の話」と「banto の UI 再設計」→ 同じ記憶が効く → **同じ幹**
- 「loamium のエディタUI」と「banto の UI」→ 見かけは似ているが、loamium の事情を
  banto の判断に混ぜたくない → **別の幹**
- 「本を探す」のような一回きりの用事 → 溜めたい記憶が無い → **幹にしない**（帳場で片付ける）

**問2「往復が続くか」→ 枝にするか**（同じ幹の中と決めたあと）

> **何が決まれば幹に還るかを、いま書けるか。**

書けるなら枝（`thread.open`）。書けないならそのまま幹で話す。

この2問は独立している。問1で「同じ幹」と決めた話が、問2で枝にも幹の中の会話にもなる。

## 枝を開くとき

```
thread.open({
  title: "間欠的に落ちる試験",
  returnCondition: "再現条件が特定できたら",   // 何が決まれば還るか
  reason: "往復が続くので幹が読めなくなる",     // なぜ幹ではなくここか
  message: "…",                                // 枝へ渡す最初の一言（任意）
})
```

- **枝の中で枝は開けない。** 別の問いが要るなら、この枝を畳んで幹へ還してから開き直す
- 開いた瞬間に**幹へ札が1行**立つ。これがあるから枝は埋没しない
- 枝の中身は幹に流さない。幹に載るのは**短い行だけ**（開いた／相談した／還った）
  ——詳細は幹に流すのではなく、`thread.read` で読みに行く

## 枝が動いている間（決定105〜107）

**開いたら終わり、ではない。** 枝が生きている間も行き来できる。

| したいこと | 口 |
|---|---|
| 枝の中で何が起きているか見る | `thread.read({ threadId })`（畳んだ枝も読める） |
| 途中で方針を渡す・問いに答える | `thread.steer({ threadId, message })` |
| 枝から幹へ相談する・報告する | `thread.consult({ kind, message })` |

- **`thread.read` は末尾から返る。** 遡るなら `offset` / `limit`。全文は返らないので、
  「どこまで来たか」を見るには末尾で足りることが多い
- **`thread.steer` は自分の幹の枝にだけ。** 隣の幹の枝には渡せない（そこへは `thread.send`）
- **`thread.consult` の `kind` を選ぶのは判断。** `question` は幹の返事を待つ、
  `report` は知らせるだけ。**問いを report で出すと、返事は来ない**
- 相談したからといって枝は止まらない。**待つ間に進められることは進める**
- **雑談にしない。** 一歩ごとに相談する枝は、そもそも幹で話すべきだった話
  （機構も10分に10通で止める）

## 枝を畳むとき

**出口は「結論」であって「実装」ではない。** incident を起票し task を積んだ時点で畳む
——実装の寿命まで開いておくと、開いている枝の一覧が信用できなくなる。

```
thread.merge({
  conclusion: "inc-0048 を起票し task-0091 を積んだ",   // 幹に残るのはこの1行だけ
  investigated: ["10回走らせて3回落ちた", "単体では落ちない"],
  decided: ["待ちを延ばす対策は採らない（P6）"],
  remaining: ["task-0091 の実装は未着手"],
})
```

- **保留も結論の一種。**「保留：計測が足りない」で畳んでよい。開き直せる
- 「幹で話せば足りる話でした」も立派な結論
- 幹に残るのはこの1行だけなので、**何が決まったかを言い切る**
- **詳細（investigated / decided / remaining）は枝に残る**（決定108）。幹には流れないので
  一覧は読めるまま、後から `thread.read` で経緯を辿れる。**結論に詰め込まない**

畳んだ枝では**もう話せない**。続きが要るなら履歴から開き直す。
**中身は消えていない**ので、読むだけなら `thread.read({ threadId })` で足りる
（`thread.list({ includeClosed: true })` で畳んだ枝の id が引ける）。

## 記憶をどこへ入れるか

| | 何が入るか | どこまで届くか |
|---|---|---|
| `scope: "person"` | PO の好み・習慣・変わらない属性 | **すべての幹** |
| `scope: "project"` | この仕事の決定・規約・ドメイン | **この幹と、その枝だけ** |

- `trunk` は**書かない**。省略すればいまの会話の幹に入る（番頭は常に1本の幹に居る）
- **迷ったら project。** ある仕事に固有の話を人の記憶に入れると、無関係な仕事の判断まで歪む
- 「前に別の仕事で似た話をした気がする」→ `memory.search({ acrossTrunks: true })`。
  注入は幹ごとに絞られているので、**探さないと出てこない**。
  持ってくると決めたなら、いまの幹へ改めて `memory.save` する（書き直して入れる）
- 枝で調べたことも幹の記憶。枝を畳んでも残る

## 幹をまたいで伝えたいとき

**記憶も文脈も幹ごとに分かれている。だからこそ跨いで伝えたいことが出てくる。**
そのときは `thread.send` で言伝を渡す——**PO に手で運ばせない**。

```
thread.send({ threadId: "thread-61", message: "…" })
```

- 渡すのは**事実と、なぜその幹に関係するか**。相手は経緯を知らない
- **指図しない。** 相手の幹で何をするかは相手の番頭が決める。こちらは渡すだけ
- 宛先は**幹だけ**（`thread.list` で確かめる）。**隣の幹の枝には送れない**——他所の枝への
  割り込みになる。用があるなら親の幹へ渡し、動かすかどうかはあちらの番頭が決める
  （**自分の幹の枝**へなら `thread.steer` で渡せる。上の「枝が動いている間」）
- 届いた側は知らせとして受け取り、ターンが回る。**返事が要るならそう書く**
  （相手から言伝で返ってくる）

**往復は続けない。** 2〜3 で決着しないなら、PO に上げるか、その幹へ移って直接話す
——機構も10分に5通で止める。言伝が要る典型：

- そちらで踏んだ不具合の原因が、こちらで直った／こちらにある
- こちらで決めたことが、そちらの前提を変える
- 同じものを二重に作ろうとしている

## 帳場で受けた話をどう流すか

帳場は**プロジェクトではない**。banto 開発の幹でもない。ここへ来るのは:

- 宛先の決まらない知らせ（孤児の検証環境・出所が会話に紐づかない報告）
- まだプロジェクトになっていない相談
- 一回きりの用事

流し方:

1. **その場で片付く** → 帳場で答えて終わり。記憶に残す値打ちがあれば `memory.save`
2. **既にある幹の話だった** → そう言って、その幹へ移ってもらう（勝手に幹を増やさない）
3. **新しい仕事になった** → `thread.open_trunk` で幹を起こし、そちらで続ける

## 幹を終うとき

プロジェクトが終わったら `thread.close_trunk`。**開いている枝があると終えられない**ので、
先に畳む（終うと枝が札ごと履歴へ沈み、埋没する）。

```
thread.close_trunk({ threadId: "thread-51", carry: ["…", "…"] })
```

**`carry` があなたの判断。** 枝の結論が幹へ還るのと同じ形が、一段上で繰り返される。
渡した文は**人の記憶**（横断する層）に入る。渡さなかった幹の記憶は消えないが、
以後どの会話にも載らない——要るときは `memory.search({ acrossTrunks: true })` で掘り出す。

- **その幹でしか通じない事情は置いていく**（「この案件では〜」「このリポジトリの〜」）
- **他の仕事でも効く一般解だけを持って出す。** 持って出るときは**書き直す**
  ——「loamium では incus を使った」ではなく「ブラウザを隔離して動かすなら incus＋Xvfb が要る」
- 持って出るものが無ければ空の配列でよい。無理に絞り出さない（I1）

帳場は終えられない。
