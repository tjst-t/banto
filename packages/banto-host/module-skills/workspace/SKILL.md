# ワークスペース（場所・ファイル・Git）

## いつ使うか

**どこで作業できるか・何がそこにあるかを見るとき。** 場所の一覧、ファイルの中身、git の状態・履歴を確かめるときに使う。書きたくなったときの手順もここに含む。

## 手順

1. **まず `place.list` で場所を確認する**
   - リポジトリ・ワークツリー・設定された作業領域が、id / label / path 付きで返る
   - **書ける範囲（writable）も返る**。既定はどこも読み取り専用
2. **場所を選んで見る**
   - `file.*` も `git.*` も**どの場所か `place` 引数で選ぶ**（呼び出しごとに選ぶ。場所が1つしかなければ省略できる）
   - ファイル閲覧: `file.list` / `file.read` / `file.stat` / `file.find` / `file.grep`
   - git 閲覧: `git.status`（変更の有無）/ `git.diff`（差分）/ `git.log`（履歴）/ `git.show`（特定のコミット）/ `git.blame`（行の出所）/ `git.branches`（ブランチ一覧）
3. **書きたいときは、まず書けるか確かめる。** `place.list` の writable に範囲が無ければ `file.write` は失敗する——それが既定
4. **書こうとして断られた・範囲が無いときは `place.request_write` で範囲を頼む**
   - `place` に場所、`patterns` に**必要な分だけ狭い**範囲（例: `docs/**`）、`reason` に一言
   - **これは頼むだけ。** 許可されるまで `file.write` は失敗し続ける
   - **頼むと取次に判断待ちが積まれ、PO は会話の横のボタンでその場で許せる**（決定73）。
     面を開かせる必要はない——`canvas.open` は要らない
   - 答えが出ると**知らせが入って自分のターンが回る**。それまでこの件は進めない
5. 範囲が手に入ったら `file.write` で書く——自分の成果物（決定の記録・起票・メモ）を残すための道具

## 書いた後

- **書いたものは未コミットのまま残り、PO のレビューを通る**。番頭はコミットできない（決定37）——コミットが必要な仕事は職人へ委譲する
- 成果物を残す用途以外（コードを直す等の実装作業）に file.write を使わない——`worker.delegate` で職人へ委譲する（D10）

## やってはいけないこと

- **許可が無い場所に書こうとしない**。書けないのが既定。断られたら頼む、の順で動く
- **広い範囲を頼まない**。必要な分だけ狭く。広く頼むと PO の判断が重くなる
- **git の変更操作を探さない**。git.* は閲覧専用（決定37）。履歴を変える必要があるときは職人へ委譲
- **頼んだら待つ**。承認は PO の判断。自分の要求が処理待ちであることを根拠に催促しない
