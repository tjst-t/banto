# リポジトリとワークツリー

## いつ使うか

**作業できる場所の把握と用意のとき。** どのリポジトリで作業するか、同じリポジトリの別ブランチで同時に進めたい、というときに使う。repo-manager は**手元にあるリポジトリと、その git ワークツリー**をそのまま提供する——独自の登録簿は持たない（決定36b）。

## 番頭が自分で持つのは「見る」側だけ

リポジトリを増やす・ワークツリーを切る／畳む道具は**番頭には提示していない**。番頭の手にあるのは場所の一覧（`place.list`）と git の閲覧（`git.status` / `git.diff` / `git.log` / `git.show`）まで。**場所の実体を作り変えるのは職人の仕事**——`worker.delegate` で委譲する（D10・決定37）。

## 手順

1. **まず `place.list` で何があるか把握する**
   - 手元のリポジトリ（id は `github.com/<owner>/<repo>` の形）と、その git ワークツリーが id / label / path 付きで返る。ワークツリーは親リポジトリを指す
   - 設定で足した作業領域も同じ一覧に出る
   - **書ける範囲（writable）も返る**。既定はどこも読み取り専用
2. **同じリポジトリの別ブランチを別ディレクトリに置きたい** → `worker.delegate` で職人に切らせる
   - 依頼に**リポジトリとブランチ**を書く。無いブランチなら作るところから頼む
   - 置き場所は指定しない——並びで決まる（この環境では `/home/ubuntu/worktrees/<host>/<owner>/<repo>/<ブランチ>`。`/` は `-` に畳む）
   - **リモートの有無に依らない**。まだ push していないリポジトリでも切れる（PO裁定 2026-08-11）
   - できた場所は**次の `place.list` に出る**。場所は `ghq` / `gwq` から導出しているので、誰が作ったかを問わない（決定36b・D3）。そのまま `file.*` の `place` や `worker.delegate` の `worktreePath` に渡せる
3. **リポジトリが手元に無い** → 職人へ委譲する。**外に出ていく操作**（ネットワーク越しの取得）なので、頼まれたときだけ
4. **空のリポジトリを新しく作りたい** → 職人へ委譲する。手元に空のリポジトリができるだけで、リモートは作らない——公開はしない

## 畳む・消す

- 用が済んだワークツリーの片付けも職人へ委譲する。消えるのは**作業ディレクトリだけ**で、コミット・ブランチは残る
- **未コミットの変更は消える**。頼む前に `git.status` / `git.diff` で自分で中身を確かめる（I1）
- 消してもブランチ・履歴はリポジトリ本体に残る。取り返したくなったらまた切らせればよい

## やってはいけないこと

- **commit・push・branch の操作を探さない**。番頭は git の変更操作を持たない（決定37）。履歴を変える必要があるときは `worker.delegate` で職人へ委譲する
- **頼まれてもいない clone をさせない**。リポジトリが増えるのは作業できる場所が増えることで、外とのやりとりを伴う。必要になったときだけ
- **知らない場所を渡して作らせない・消させない**。手元に無い場所は `place.list` に出ない。出ていないものを職人に触らせない——黙って別の場所を触られる
