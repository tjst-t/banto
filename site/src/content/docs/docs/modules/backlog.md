---
title: Backlog
description: ストーリー・タスク・バグの管理。
---

Backlog は、プロジェクトのストーリー・タスク・バグを管理するモジュールです。AI はツールで項目を作成・更新し、人は Backlog の画面で一覧を確認・編集します。

## 項目の種類

| 種類 | 用途 |
|---|---|
| ストーリー | 大きな機能。実装するときにタスクに分割する |
| タスク | 実装の単位。ストーリーの下に置ける |
| バグ | 不具合。ストーリーとは独立して置ける |

各項目には、状態・優先度（高・中・低）・ラベル・マイルストーン・完了条件・本文などを設定できます。項目どうしに依存関係（この項目が終わるまで始められない）を設定することもできます。項目には通し番号（例：`#42`）が付きます。

## 状態

| 状態 | 意味 |
|---|---|
| 積んだだけ | まだ着手の準備ができていない |
| 準備できた | 着手できる |
| 進めている | 作業中 |
| 終わった | 完了 |
| やめた | 中止（理由を記録） |

## 一覧の表示

Backlog の画面では、「次にやる」「すべて」「バグ」「閉じたもの」を切り替えて表示できます。項目を選ぶと、右側に詳細が表示されます。並び順がそのまま優先順で、ドラッグで並べ替えられます。

## データの保存場所

項目はリポジトリの専用のブランチ（既定は `backlog`）に保存されます。コードのブランチとは独立しているため、どのブランチで作業していても同じ一覧を参照でき、マージでコンフリクトすることもありません。

リポジトリに `origin` が設定されている場合、変更のたびに自動で push されます。プロジェクトのルートが Git リポジトリでない場合は利用できません。

## Factory との連携

着手できる状態のタスクは、[Factory](/docs/modules/factory/) に渡して自動で実装させることができます。
