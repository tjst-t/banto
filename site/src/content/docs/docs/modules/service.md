## Service

Service は、開発サーバーやファイルの監視など、動き続けるプロセスを管理するモジュールです。Shell のコマンドは1回で終わるため、常駐させたいものは Service で起動します。

### 起動と管理

AI は名前・起動コマンド・作業ディレクトリ・待ち受けるポートを指定して、サービスを登録・起動します。

| 操作 | 内容 |
|---|---|
| 起動 | 初回は登録と起動を同時に行う。2回目以降は名前だけで起動できる |
| 停止 | 停止する。登録は残る |
| 再起動 | 停止して起動し直す |
| 削除 | 停止して登録を削除する |
| 一覧 | 状態（動作中・停止・異常終了など）と、ポートの待ち受け状況 |
| ログ | 標準出力と標準エラーの末尾 |

- サービスが異常終了した場合は、自動で再起動します
- コンテナを再起動したときも、登録済みのサービスは自動で起動します
- 同じ名前で別の内容を登録しようとすると拒否されます。変更する場合は、いったん削除してから登録し直します
- シークレットは、Shell と同じく Vault の参照名で環境変数に渡せます

## Publish

Publish は、Service で起動したサーバーに、ブラウザからアクセスできる URL を割り当てるモジュールです。

公開すると、`<サービス名>-<プロジェクト ID の先頭8文字>.<banto のドメイン名>` のような URL が割り当てられます。公開するたびに承認を求めます（プロジェクトで承認の自動許可を有効にしている場合を除く）。

### アクセス制限

公開したサービスにアクセスするには、banto へのログインが必要です。banto にログインしているブラウザであれば、そのまま開けます。

### 公開の条件

- Cloudflare の API トークンを指定してインストールしている必要があります（ワイルドカード証明書と DNS レコードを使うため。[HTTPS の設定](/docs/install/https/)を参照）
- サーバーは `0.0.0.0` で待ち受ける必要があります（`127.0.0.1` だけで待ち受けていると届きません。Vite の場合は `--host` を指定します）
- 開発サーバーが知らないホスト名からのアクセスを拒否する場合は、割り当てられた URL のホスト名を許可してください（Vite の `server.allowedHosts` など）

サービスを削除すると、公開も自動で停止します。
