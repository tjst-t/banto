banto を使ううえで知っておきたい概念は、次の6つです。

```text
banto
├── プロジェクト A           ← 作業の単位。作業ディレクトリとコンテナを1つずつ持つ
│   ├── Memory               ← プロジェクトで決まった事項。すべての会話に渡される
│   ├── Base（メインの会話）
│   ├── Fork「案A」          ← Base から分岐した会話
│   └── Fork「案B」
├── プロジェクト B
└── 受信箱                   ← すべてのプロジェクトの、あなたの対応が必要なもの
```

## プロジェクト

作業の単位です。作業ディレクトリ（ルート）を1つ持ち、Git リポジトリを置くのが一般的です。プロジェクトごとにコンテナが作成され、AI によるコマンドの実行やファイル操作はそのコンテナ内で行われます。

ハードウェア仮想化が必要な作業などのために、SSH で接続した[別のサーバー](/docs/admin/remote/)をプロジェクトの実行環境にすることもできます。

## 会話（Thread）

AI とのやり取りの単位です。各プロジェクトには、メインの会話（Base）が1つと、そこから分岐した会話（Fork）が任意の数だけあります。

会話はサーバー側で動いているため、ブラウザを閉じても AI の作業は続きます。別の端末で開けば、同じ会話の続きを確認できます。

## Fork

会話の分岐です。単なる続きではなく、**同じ前提から始める別のアプローチ**として使います。

- 同じ依頼に対して、複数の実装を試して比較する
- 本題を止めずに、別の調査を並行して進める
- 長くなった会話から、前提を引き継いで新しい話題を始める

Fork を作成するときは、それまでの会話を引き継ぐか、新しい会話として始めるかを選べます。AI が作業を分担するために、自分で Fork を作成することもあります。

## Memory

プロジェクトで決定した事項の記録です。設計上の判断などが決まると、AI が Memory に追記します。Memory の内容は、会話が長くなって要約されたあとも、Fork した先でも、毎回 AI に渡されます。

内容は、プロジェクトの設定の「Memory」で確認・編集できます。すべてのプロジェクトに共通の事項は、banto 全体の Memory に書きます。

## 受信箱

あなたの対応が必要なものが集まる場所です。

- AI からの承認依頼や、判断の依頼
- AI が応答したあと、まだ確認していない会話
- リソースの上限に達した、などの通知

## モジュール

banto に機能を追加するコンポーネントです。コマンドの実行（Shell）、ファイル操作（FileSystem）、シークレットの管理（Vault）など、よく使う機能は標準で組み込まれています。

モジュールは **AI と人の両方から利用できます**。AI はツールとして呼び出し、人は画面（Canvas）で操作します。AI が開いた画面を人がそのまま操作することも、人が見ている画面について AI に相談することもできます。

モジュールには、banto 全体で1つ動くもの（Vault、Repositories など）と、プロジェクトごとにコンテナ内で動くもの（Shell、Backlog など）があります。詳しくは[モジュール](/docs/modules/)を参照してください。
