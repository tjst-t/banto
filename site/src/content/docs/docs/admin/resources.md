## リソースの上限

各プロジェクトのコンテナには、メモリ・CPU・プロセス数の上限が設定されます。1つのプロジェクトの処理がサーバー全体を使い切らないようにするためです。

既定値は、コンテナを起動するときにサーバーのリソースから計算されます。

| 項目 | 既定値 |
|---|---|
| メモリ | サーバーの全メモリから、サーバー用に一定量を残した残り |
| CPU | サーバーのコア数から1を引いた分（最低1コア） |
| プロセス数 | 8192 |

上限は次の場所で変更できます。変更は、動作中のコンテナにも再起動なしで反映されます。

- banto 全体の設定の「コンテナ」：すべてのプロジェクトに共通の上限（サーバーに残すメモリや CPU など）
- プロジェクトの設定の「コンテナ」：そのプロジェクトだけ、全体の上限より低く設定する

サブエージェントや時間のかかるコマンド、Factory のテストなどの処理は、コンテナの上限よりさらに低い範囲で実行されます。重い処理がメモリを使い切っても、モジュールなど banto の動作に必要な部分が止まりにくくなっています。

## 使用状況を確認する

banto 全体の設定の「資源」で、サーバー全体とプロジェクトごとのリソース使用状況を確認できます。プロジェクトごとに、モジュール・AI の処理・コマンド・Service など、何がどれだけ使っているかの内訳が表示されます。

リソースが逼迫しているプロジェクトには、サイドバーに印が表示されます。サーバー全体が逼迫している場合は、サイドバーにお知らせが表示されます。

## 上限に達したとき

コンテナがメモリやプロセス数の上限に達し、プロセスが強制終了された場合は、受信箱に通知が届きます。通知には、現在の上限と変更方法が表示されます。

## サーバーを守る設定

インストーラーは、メモリ不足でサーバー全体が応答しなくなることを防ぐため、earlyoom をインストールします。メモリが逼迫すると、AI の処理など優先度の低いプロセスから停止されます。
