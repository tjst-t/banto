- [#41429] 案A の P1 の実測（2026-10-17、banto-dev-vm）：人が VM の root で一度 `incus project set user-<uid> restricted.devices.proxy=allow` を打てば、SSH ユーザーの制限された区画のまま proxy device が使え、3つの道が全部通った——(1) 公開：bind=host・listen=tcp:0.0.0.0:<VM のポート>・connect=tcp:127.0.0.1:<コンテナのポート>（コンテナの中は 127.0.0.1 で待ち受けてよい）、LAN から 200、(2) 中から banto へ：bind=instance・listen=tcp:127.0.0.1:<ポート>・connect=tcp:127.0.0.1:<VM の逆向きのトンネル>、Claude の中継が 401（届いた）、(3) unix ソケット：bind=instance・listen=unix:/run/agent.sock・connect=unix:<VM の ssh-agent のソケット>、繋がった。
- [#41873] Shell の道具が会話中に消えた件の原因（2026-10-17）：00:05〜00:07 UTC に host から別のサーバ2台へ同時に約2分届かなくなった（host 側の経路の途切れ、Tailscale 等）。全 Module が ping に答えず止まり、SSH が ServerAlive（15秒×3）で閉じ、繋がり直した。host の banto-host のログは journal ではなく /home/ubuntu/banto-host.log（時刻は UTC）。見つけた不具合：#362・#370・#363（どれも直した）。

- [#58854] containers で仮想化の実験の実測（2026-10-20、ベアメタル banto@10.10.254.50：Ubuntu 26.04・72コア・256GB・Intel・カーネル 7.0・Incus 7.5.1、区画 user-1001）：区画の既定は nesting・disk（/home/banto）・gpu・proxy・idmap が allow、unix-char・特権・lowlevel は禁止。特権無しで区画に restricted.devices.unix-char=allow だけを足し、コンテナに /dev/kvm と /dev/vhost-net を unix-char（mode=0666）で見せると、中の qemu が KVM で動き（init まで KVM 0.92秒・TCG 2.54秒）、ブリッジ・tap・VXLAN・macvlan・veth が作れ、Docker と containerlab 0.81.1 が動き2ノードで ping が通り、Docker --privileged の中の qemu も KVM で動いた。足りないもの：カーネルモジュール→区画の restricted.containers.lowlevel=allow と linux.kernel_modules で効いた。hugepages→ホストで nr_hugepages を確保し hugetlbfs を /home/banto の下にマウントして disk device で /dev/hugepages に見せると qemu -mem-path で使えた。特権にしても hugepages の数・modprobe は中から変えられず、今回の範囲では特権が要るものは見つからなかった。試したものは全部元に戻した。
