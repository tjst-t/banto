# Vault の管理画面の直し：グループを作る入口・値を変える・vault-local の設定 Canvas（2026-10-07）

ユーザーから3つ頼まれた。仕様は `docs/specs/v4-modules.md` §2.1（「紐付けの選択肢は2つ」・C節の表・
「各 backend の設定 Canvas」・管理 Canvas の行）に書いた。ここには決め方と、実装で自分が判断したことを残す。

## 1. グループを作る入口

- 仕様は前から「紐付けの選択肢は2つ：既存グループから選ぶ／新しいグループを作る」と言っていたのに、管理 Canvas には
  作る入口が無く、作れるのは banto 全体の設定（Global の置き場）だけだった
- **置き場の変更・移す・参照を作るの3つの小窓**で、グループ欄の最後に「＋ 新しいグループを作る…」。選ぶと名前の欄と
  「作る」が出て、窓口の `createGroup`（名前の検査は backend）を呼び、作ったグループを選んだ状態にする
  （設定画面の Global の「作る」と同じ考え）。版の欄はグループ欄と独立（作るのは既定の版のグループの名前）
- 作れなかったら、その小窓のエラー欄に窓口の文言をそのまま出す。作ったのに選択肢に出てこなければそう言う（規則2）
- **Infisical の「フォルダができます」をどう知るか**（自分で判断）：実装の名前（接続名）は人が好きに付けられるので、
  名前の頭で見分けると2本目（`vault-infisical-cloud` 等）や改名で外れる。**backend が名乗る**形にした——
  kit の `VaultModuleOptions.groupCreateNote`、kit の tool `describeGroups`（値を返さない `admin`）、窓口の
  `getPlacements` が Vault ごとに `groupCreateNote` を添える。`describeGroups` を持たない古い実装は「添え書き無し」
  （置き場の一覧からは落とさない）
- **登録の小窓（保存先）には置かなかった**（自分で判断）：頼まれたのは3つの小窓で、保存先は既定でよい人のための欄。
  既定の外に作りたい人は、移す等の小窓で作れる
- 名前の欄で Enter を押すと「作る」（小窓の送信——先頭の「やめる」——に流れない）

## 2. 既存の秘密の値を書き換える（`replaceSecretValue`）

ユーザーが決めた（以前の「差し替えは消して作る」をやめる）。消すと用途・参照の指す先が切れ、作り直すまで名前が無くなる。

- kit：人専用（`admin`、`assertHuman`——updateAlias・deleteAlias と同じ）。値は返さない。窓口は中継
- `secret`・`file` は `value`。`ssh-identity` は `value`（貼る）か `regenerate: true`（`generateKeypair` で同じ置き場に
  作り直す）で、新しい公開鍵だけ返す。`oauth-token`・参照は断る
- **貼った鍵の検査**（自分で判断）：`createAlias` の `ssh-identity` は値が空でないことしか見ていない（形は見ない）ので、
  「同じ検査」はそれだけ。ただし置き換えでは公開鍵を返す必要があり、読めない鍵を貼ると**動いている鍵を壊して**から
  公開鍵の導出で落ちる。そこで「置く → backend に公開鍵を導かせる → 導けなければ元の鍵に書き戻して断る」にした。
  失敗の文言に ssh-keygen の出力を載せない（貼った鍵の断片が混ざりうる）。書き戻しにも失敗したら、そう言う
- **ssh-agent を落とす**（自分で判断、頼まれていない穴）：両 backend は鍵を抱えた ssh-agent を置き場ごとに使い回すので、
  鍵を置き換えても次の `startSshAgent` が**古い鍵**を配り続ける。`putSecret` の中で、その置き場の鍵で立てた agent を
  落とすようにした（vault-local・vault-infisical）。次に呼ばれたら新しい鍵で立て直す
- **参照を断る文言の「実装の名前」**（自分で判断）：kit が知っている名前は自分の宣言上の名前（vault-local は
  固定の `vault-local`）で、2本目（`vault-local-2`）でも `vault-local` と言ってしまう。実装の名前を知っているのは窓口
  なので、**窓口が先にその実装の一覧（`listAliases`、置き場を `alsoGroups` で）を読み、参照なら値を渡す前に断る**。
  kit も断る（窓口を通らない呼び出しのため）。1往復増えるが、人の操作1回に1回
- **値を変えた日時**（`valueUpdatedAt`）：台帳の行に持つ。組み込みは `aliases.json`、Infisical は秘密の注記
  （`lastUsedAt` と同じ置き方）なので、**両方で残せる**。Infisical は注記を「読んだ行」から組み直して書くので、
  読むとき（`toMeta`）に拾わないと次の使用記録で消える——拾うようにして試験で押さえた。作ったときは付けない
  （作った日時ではない）。値の中身の履歴は持たない
- **限界**：Infisical で banto の注記が無い秘密（人が置いたもの）の値を変えると、日時を書くために注記が banto の JSON に
  なる（元の注記は用途として中に残る）。「banto は注記を書き足さない」に反するが、使用記録（`lastUsedAt`）と用途の書き直しが
  既に同じことをしている。分けるなら注記の外（Infisical の秘密の `updatedAt` 等）を使うことになるが、注記を書くたびに
  変わるので「値を変えた日時」にならない
- **限界**：貼った鍵の置き換えは「置く（新）→ 公開鍵を導く → だめなら置く（旧）」なので、その間に Vault のプロセスが落ちると
  読めない鍵が残り、日時も付かない（一覧からは置き換えたことが分からない）。backend に「書いて確かめてから入れ替える」口が無いため
- **限界**：窓口の `replaceSecretValue` は `group` を省くと、その実装の一覧で**同じ名前の最初の行**を見て参照かを決める。
  kit の解決（共通の既定 ＞ 1つだけ）とは別の行を見ることがある。画面は必ず `group` を渡す
- AI の目録（`vault://aliases`）にも `valueUpdatedAt` は載る（`lastUsedAt` と同じ扱いのメタデータで、値ではない）
- 空の秘密：一覧の `empty` は読んだときの印で保存しないので、置き換えれば外れる（Infisical の店の試験で確認）
- 画面：行のメニューの「用途を編集」の次に「値を変える」。参照・OAuth の行でも出し、押すと入力欄を出さずに理由と元の場所を
  出す（「押せない形」より、どこへ行けば変えられるかが言える）。SSH 鍵は「貼り付ける／Vault の中で作り直す」と、
  「相手（GitHub など）に登録した公開鍵と合わなくなります」。終わったら新しい公開鍵の小窓（コピーできる）。
  入力した値は小窓が閉じたら（やめても、変えても）DOM から消す。日時は名前の下に「値を変更 2026/10/07 14:03」
  （列を足すと名前の列が潰れる——2026-09-20 の列幅の決定）

## 3. vault-local の設定 Canvas を消す

- `ui://banto-vault-local/config` は alias の名前を並べるだけで、設定することが無かった。同じ一覧は管理 Canvas にある。
  設定画面に「Vault（ローカル）」が出ても、開いて決められることが無かった（規則13）
- 仕様には「各 backend 自身の `ui://<id>/config` は残す（vault-directory が無い環境でも backend 単体で同じ操作が
  できなければならない）」とあった。組み込みの画面は一覧だけで、その約束も果たしていなかったので、
  「設定することがある backend だけが持つ」に改めた（仕様に書いた）。単体の MCP ホストからは C節の `admin` tool を
  そのまま呼べる
- kit の `configApp` は残す（vault-infisical が繋ぎ方の画面に使う）
- 落ちた試験：`module-settings-canvas.spec.ts` の2本が vault-local の設定画面を開いていた。窓口の「Vault の置き場」に
  置き換え、「Vault（ローカル）」が出ないことを足した

## 直していない間欠的な失敗（規則6、記録）

- `vault-directory.spec.ts` の「選択欄：グループは Vault での本当の名前…」は、**4回中2回**、試験の前提
  「この Project の置き場の上に選択肢がある」で落ちる。**この変更の前（HEAD の画面と試験）でも 4回中2回**で同じ
  （2026-10-07 に両方を計測）。グループの選択肢の順は vault-local の `listGroups`（ディレクトリを読んだ順）に
  紐付けを足したもので、この Project のグループ（UUID）が先頭に来ると、キーボードで「1つ上を選ぶ」段が成り立たない。
  機構（並び順が決まっていない）の問題で、この作業の範囲の外なので直していない。人に上げる

## レビューの指摘で直したこと（2026-10-07、Fable）

- **貼った SSH 鍵の改行**：`ssh-keygen -y` は末尾に改行の無い鍵・CRLF の鍵を読めない（手元で実測、`error in libcrypto`）。
  `createAlias`・`replaceSecretValue` の ssh-identity は `\r` を除き末尾に `\n` を補ってから置く。secret・file は変えない
- **グループ名の `@`**：Infisical は `g@prod` を「環境 prod のフォルダ g」と読むので、人の入口（管理画面の作る欄・窓口の
  `createGroup`）で断る。banto 全体の設定画面の「作る」も窓口を通るので効く（E2E で確かめた）。kit の `backend.createGroup` は
  版付きの名前を受けたまま（紐付け・移す・参照で版付きの置き場を作るのに要る）
- **kit の `createGroup` の口に `assertHuman`**：台帳・置き場を変える他の口と揃えた。置くついでに作る（`groupForNewAlias`）は
  口を通らないので変わらない。窓口の中継（人の画面＝admin の刻印）からは作れる（単体・E2E で確かめた）
- **書き戻し失敗の文言**：backend のエラー文を載せない（他の分岐と同じく伏せる）
- **古い実装の判定は `/unknown tool/i` の文言のまま**（直していない）：実装が `describeGroups`・`describeVariants` を持つかを
  tools/list で見たいが、Module が中継で使える口は `relayListTargets`・`relayCallTool`・`relayReadResource` 等で、
  **相手の tool の一覧を引く口が無い**（core の `host-relay-endpoint.ts`）。足すと中継の許可・監査の作り替えになるので今はしない。
  文言は kit が投げる `unknown tool: <名前>`（kit の既定の分岐）で、kit を変えるときはこの判定（窓口の `variantsOf`・
  `groupCreateNoteOf`）も見ること

## 「選択欄」の試験の間欠を直した（2026-10-08、ユーザー「並び順が製品の不具合なら製品を直して」）

- **再現**：直す前の main で `-g 選択欄 --repeat-each 4` を流し、4回中1回、前提「この Project の置き場の上に選択肢がある」で
  落ちた（前日の計測は4回中2回）
- **原因**：グループの選択肢の並びが決まっていなかった——窓口の `getPlacements` は実装の `listGroups` の順をそのまま使い、
  vault-local はフォルダを読んだ順（`readdirSync`、決まった順が無い）。この Project のグループ（UUID）が先頭に来た回に落ちる。
  人から見ても、開くたびに並びが変わりうる製品の不具合
- **直し**：窓口で名前の順に並べる（大文字小文字を区別せず、数字は桁の大きさで。Infisical も同じ口を通るので揃う）。
  試験は、名前の順で並んでいることを確かめ、キーボードの段は「1つ上」を前提にせず隣（先頭なら下）を選ぶ形にした——
  名前の順でも、この Project の UUID がその回の名前次第で先頭に来うるため
