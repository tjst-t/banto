# 画面と Module の間の流れ——口と共通の部品を作ったときの記録（2026-10-08）

Backlog #237（stream-relay）。仕様はアーキ §5.8。ここには測ったこと・仕様から動かしたこと・選ばなかった案を残す。

## 測ったこと：コンテナの中で作ったソケットに host から繋げるか

**繋げる。** 使い捨てのコンテナ（`banto-base-…` の像、`raw.idmap=both 1000 1000`、btrfs のプール `banto`、カーネル 6.8）に
host のフォルダを同じパスで見せ、中で uid 1000 の node が `s/stream.sock` に待ち受けを立てた。host の node から
`net.connect` で繋ぐと、こだま（`echo:hello`）が返った。§5.8 の (a) incus exec の中継・(b) 決まったポートには替えない。

E2E（`stream-relay.spec.ts`）でも、Project のコンテナの中で動く試験用の Module に host が繋いで往復している。

## 仕様から動かしたこと：107 バイトの上限をやめた

§5.8 は「パスは 107 バイトまで。超えたら名乗りを無効として扱う」としていた。実際に組むと、

- 自前の host の置き場（`~/.cache/banto-e2e/<回>/own-xxxxxx/data`）では `modules/<名前>-<Project の id>/s/stream.sock` が
  115 バイトを越え、どんな名前の Module でも流れが開けない
- 本番（`~/.local/share/banto`）でも、Project ごとの Module の名前が 16 字を越えると届かない

ので、両側（host の connect と `@banto/stream-server` の listen）とも**置き場のフォルダを開いた番号を通して**
`/proc/self/fd/<番号>/stream.sock` で繋ぐ・立てることにした。Linux で sun_path の長さを避ける決まった逃げ道
（規則12）。155 バイトのパスで立てて繋げることを測った。banto は Incus の上でしか動かないので Linux だけでよい。

- 立てた側は、閉じてもファイルが残る（libuv が消そうとするのは `/proc/self/fd/…` の名前）——`close()` で自分で消す。
  立てる前に古いファイルを消すのは前からの決まり
- 選ばなかった案：置き場の名前を短くする（Project の id を縮める）——置き場の名前は Module の起動・マウント・Vault の
  鍵の窓口と共有していて、流れのために動かすと影響が広い。`chdir` して相対パスで立てる——host は1つのプロセスで
  多くの流れを同時に繋ぐので、作業フォルダを替えられない

## 決めた細部（仕様に書いたもの）

- **待ち受けの住所は API の基点から作る**：§5.8 は「画面のオリジン（`uiOrigin`）の `/api/streams`」としていたが、開発・E2E
  では画面（Next）と API（host）のポートが違い、画面のオリジンには `/api/streams` が無い。画面が API を叩いている基点
  （`publicUrl`、本番は画面と同じオリジン）から作る。本番では同じ値
- **刻印は JSON を base64url にしてヘッダに載せる**：`params` に日本語が入ると HTTP のヘッダにそのまま載らない
- **閉じる番号**：札が無効・最初の1通が来ない＝1008、Origin が違う＝Upgrade で 403、Module に繋がらない・Module が落ちた
  （1006）・止まる（1001）・banto が止まる＝1012、Module が送れる番号で閉じたらそれを渡す（4404 で画面は止まる）、
  1通が 1 MiB を越えた＝1009（どちら向きでも）
- **iframe ごとの印**（`frame`）は親が描いた枠ごとに作る乱数。上限の数え先は「ログインのセッション＋印」
- 上限に数えるのは開いている流れと、まだ使われていない札（札を出すたびに、切れた札は捨てる）
- 開閉の記録は host のログの `[stream-audit]` の1行（`stream.open`・`stream.close`・`stream.refused`）。中身は書かない

## 踏んだもの

- **読むのを止めたまま閉じると 30 秒残る**：札を受けたあと、Module に繋がるまで画面の側から読むのを止めている
  （`pause`）。その間に断って閉じると、画面からの閉じる返事を読めず、`ws` の閉じる待ち（30 秒）まで接続が残っていた。
  単体試験で 30 秒・60 秒かかったことで気づいた。断る前に読むのを再開する

## 依存

- **`ws` を足した**（core・`@banto/stream-server`）：Node の標準には WebSocket の待ち受けが無く、標準の WebSocket（undici）は
  UNIX ソケットの先へ繋げない（規則10）
