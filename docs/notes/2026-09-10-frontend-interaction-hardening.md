# フロントエンドの「要確認」4件を、実ブラウザで確かめて直した（2026-09-10）

`docs/notes/2026-09-09-repo-review.md` §3.2 に「要確認」のまま残っていた4件。
**まず再現を取ってから直した**（規則1——測る前に犯人を決めない）。
結果は4件とも性質が違った。

## 1. Escape が前面のダイアログと背面のパネルを同時に閉じる → **再現。指摘より悪い**

Fork を開いた上で Command Palette を開いて Escape を押すと、実際には
**前面（Palette）は開いたまま、背面の Fork が閉じた**。

Palette と panel-stack が同じ Escape で**それぞれ router を書き換える**ので、
後に走ったほう（Fork を閉じる）が勝ち、Palette を閉じる書き換えは消えていた。

直し方：panel-stack 側も「上に何か開いていたら手を出さない」を見る。
`/settings` 側（`use-escape-navigate-back.ts`）は**既に同じ検査をしていた**
——非対称だったのが原因なので、判断は `lib/overlay-open.ts` に1つだけ持つ（規則3）。

## 2. Reload・Edit・BranchPicker が実 Thread で半接続 → **再現。実害あり**

実測（Edit で文面を変えて送った後）：

| | |
|---|---|
| 画面 | 新しいやり取りだけが残り、`1/2` の枝送りが出る＝やり直したように見える |
| host の記録 | **直列に4件**（`印123` のやり取りも消えていない） |
| リロード後 | 分岐は消え、4件が並ぶ |

人は「前の失敗した指示は無かったことになった」と思うが、**それは次のターンの
文脈に残る**。規則13（繋がっていないものは出さない）。

**隠した**（`CONNECTED_FEATURES.threadBranching = false`）。本物の分岐は host 側
——会話の切り詰めと resume-point の巻き戻し——が要るので、`docs/tasks.json` に
`thread-branching-host` として起票した。モックの台本はローカルで完結しているので
そちらには出したまま。

## 3. SandboxFrame が親の再描画のたびに橋を張り直す → **再現。ただし予想した実害は出ていない**

数えたら **9回**（Canvas を1つ出して Fork を2回開閉するだけで）。
ただし指摘が心配していた「以後カード内が無反応になる」は**起きなかった**
——内側の文書は生き延び、画面からの tool 呼び出しも通った。

**数えて初めて分かった本当の原因**：依存に毎レンダー新しくなるもの
（`onRequestFullscreen`）が入っていたのは確かだが、それを ref に逃がしても
**9→3 にしか減らなかった**。残りは別物で、依存のうち `ownerKey(owner)`＝
Thread の id が**実際に変わっていた**：

> 画面の覚え書き（`inlineViewByToolCallId`）が **toolCallId だけを鍵**にしていた。
> **Fork は親の履歴をそのまま持つ**ので、Fork を開いた瞬間に同じ toolCallId で
> 上書きされ、**Base の会話に出ている画面が「自分は Fork のものだ」と言い出す**。
> そこからの tool 呼び出しも Fork の側に記録されていた。

鍵を「Thread と toolCallId の組」にし、会話の奥のカードには
「いまどの Thread を描いているか」を context で渡した（`thread-id-context.tsx`）。
**当てずっぽうで直していたら、ここには辿り着かなかった**——`data-bridge-generation`
という形で「何回張り直したか」を見えるところに出したのが効いた（規則4）。

## 4. 同一文面の再送で1本の SSE を2つの run が食い合う → **再現できず。ただし穴は実在する**

composer 側が判断待ち中の送信を止めているので、**画面からは辿れなかった**。
しかし見分け方そのものが弱かった：`run()` が「再開」か「新しい発言」かを
**最後の発言の文面**で見ていたので、**同じ文面をもう一度送ると区別できない**。

文面ではなく **①人の発言の数 ②いま誰かが読んでいるか** で見分けるようにし、
判断だけを `lib/backend/live-turn-guard.ts` に切り出して単体試験を付けた
（画面から再現できないものを、E2E で証明したことにしない）。

## ついでに見つけたもの（直した）

- `home-content.tsx` が効果の中で同期に state を触っていた（lint が拾った）。
  前日に自分が入れたもの。読み込みが返ってから触るように直した。

## 直していないもの（記録）

- **host に並行ターンの錠が無い**（レビュー §3.1）。いまの抑止はブラウザ側だけ
  ——別のタブ・別の端末からは同時に走らせられる。`turnEvents.isRunning()` が
  できたので実装は軽いが、これは別件なので `docs/tasks.json` に置いた
  （`host-turn-concurrency-lock`）。
- **`review-use-tooluseid`（承認の toolCallId に SDK の `toolUseID` を使う）**の
  検証は、Agent SDK の `query()` を差し替えないと書けない。いまは無い。
