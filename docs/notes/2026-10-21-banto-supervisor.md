# 番頭——人の代わりに細かい判断をして進める（2026-10-21）

仕様はアーキ §4.5・フロント §6.54。ここは経緯。

## 要望
全 Project の開発を監督し、人の代行で自動に進める。release に入れて push のような細かい判断を Thread ごとに人がやるのがつらい。
仕様・アーキの判断は人に。

## 人に確かめたこと（2026-10-21）
- 任せる：決まった手順＋今の仕様に収まる小さな設計判断（画面の文言・tool の引数の形）。人：仕様の向き・公開・お金・消す操作
- 線引き：banto 全体の方針1つ＋Project ごとの足し外し（banto開発は release まで、本番インフラは試験まで）
- 起きる：決めることが出た・Factory/試験が止まった出来事＋数時間おきの見回り（止まった会話を進める）
- Backlog の ready を優先順に Factory に流してよい。流したら知らせる
- #58965 は番頭が動き始めたら改める

## 案
- A：判断役（§4.3）に全体の方針・問いの種類・Factory に流すを足すだけ。小さいが、選択肢しか選べず止まった会話を進められない
- B：banto 全体に番頭の会話を1つ。手間はいちばん減るが、Backlog・Factory・Shell は Project ごとの Module で Project をまたいで動かす口が要る
  （今は Project をまたぐ送信は人の承認）。1つの会話に全部の文脈が溜まる。外の文に操られたとき全部の Project に及ぶ
- **C（採用）**：方針と帳面は全体で1つ、番頭は Project ごと。今の境目（Module・承認・Memory は Project ごと）をそのまま使い、
  被害がその Project に留まる。全体を見渡すのは AI ではなく画面に持たせる

## 判断役との違い
判断役はまとめの選択肢を選ぶだけ・Project ごと・中身を読まない。番頭はそれに、指示の文（`instruct_thread`、書き手 `supervisor`）・
止まった会話の一覧（まとめと状態だけ）・Factory に流す、を足す。tool の承認には答えない点は判断役と同じ。

## 実装で決めたこと（2026-10-21、Backlog #507）
仕様は `docs/specs/v4-architecture.md` §4.5「実装で決めたこと」。ここは経緯だけ。
- **自動化は4件**：仕様の下書きは「3件」だったが、1件の自動化は1つの出来事しか待てない（`source.event` は1つ）。Factory の出来事を2件に分けた
  （器を広げて1件に複数の出来事を持たせる案は、`AutomationSource` と照合・まとめ・回数の歯止めを全部触るので採らない）
- **一覧に「出さない」**（「印を付けて分ける」は採らない）：印を付けて並べると、自動化の画面の一時停止・削除・今すぐ動かすが1件ずつ効いてしまい、
  「4件一緒」が崩れる。AI の `list_automations` に出すと、AI が id を知って触ろうとする。番頭は番頭の口（と §6.54 の画面）だけで扱う
- **方針を書く口を足した**：番頭の回に届く文は host が組むので、E2E の偽のモデルへの指示を置ける場所が方針の文しかなかった。方針を書く口は
  画面（§6.54）でも要るので、人のセッションだけの口として先に作った（AI の tool には出さない）
- **readExternal が読めないときは「読んだ」側**：番頭にだけ効く断りなので、属性の無い古い出来事で選ばせないほうに倒した（判断役は見ない）
- **時刻の間隔は再開で引き直す**：時刻の自動化の `source` は台帳に残るので、方針を変えるたびに追いかけると「方針の写し」になる。作る・再開する
  ときに方針から作り直すだけにした（変えたら一時停止→再開で効く）。回のたびに方針から間隔を引く時計は、時計の数え（`clockFrom`）と噛み合わない
- **Factory の2件と見回りはまだ何もしない回**：#508（`instruct_thread`・`list_stalled_threads`）・#509（Factory の tool）まで、届く文は
  「何もせずに終える」と書く。回は記録に残る（量の歯止めは作る順の 5.「守り」）

## 実装で決めたこと（2026-10-21、Backlog #508）
仕様は §4.5「実装で決めたこと（Backlog #508）」。ここは経緯だけ。
- **答えていない決めることの判定に「最後のターンのまとめ」を足した**：仕様の下書きは「受信箱のカードの有無」だけ。カードは人が「見た」にすると
  消えるが、問いは答えていない——そこで番頭が continue を頼むと、元の AI が自分の問いを番頭の頼みで片づけうる（H1 と同じ穴）。止まった一覧の
  `decision-missed` の会話にも頼めないことになり、一覧の `hint`（何もしない）と揃う
- **走っている間に積んだ指示を、始まる直前に見直す**：宛先が走っている間に頼むと、そのターンが決めることを出して終わっても、積んだ指示が
  残っているのでカードも出来事も出ずに、すぐ指示のターンが始まる——答えていない会話に指示が届く。頼むときに「走っていたら断る」案は、仕様の
  「そのターンの後に始まる」と合わないので採らず、始める直前に捨てる形にした。全部捨てたらターンを始めず、鍵を返したときのターンの終わりの
  扱いでカードと出来事を出す（新しい仕組みを作らない）
- **連鎖の上限を超える指示は届けずに断る**：届けて留める（今の届ける口の決まり）と、人が次に送ったターンで「人を優先」で捨てるだけになる
- **`reason` を宛先に送らない**：送ると自由な文の口が2つになる。記録とカードには残す
- **`decision-missed` は何もしない**：番頭が答えられるのは届いた出来事だけ（#507）。出来事を出し直す口は新しい仕組みなので作らず、まだ決めて
  いないことに置いた
- **今すぐ見回るの口を足した**：番頭の自動化は自動化の口に出さない（#507）ので、E2E で見回りの回を起こす道が無かった。画面（§6.54）でも要る
- **任務の回数**：もとから任務の届けもので起こした回だけ数える。ただし「最後のターンがどの任務の回か」が、番頭の指示のターンを前の任務の回に
  数えていた（回の結果をそのターンで書く）ので、番頭の指示で区切った。自動化の回も同じ

## 実装で決めたこと（2026-10-21、Backlog #509）
仕様は §4.5「実装で決めたこと（Backlog #509）」。ここは経緯だけ。
- **番頭の Fork が Factory の札を持つと、番頭の回が止まる**：`runFactory` は返信用の札を出すので、番頭の Fork は「裏の仕事の返事待ち」になり、
  自動化の「前の回が終わっていない」で見回り・Factory の出来事の回が全部飛ぶ（出来事は溜まる）——止まった件に答える回が起きない。
  さらに札の知らせが届くと、前の回の会話を続けたまま番頭の決まりの届かないターンが起きる。案：(a) 番頭の `runFactory` には札を渡さない
  （出来事だけで知る）——Factory が「知らせる先がありません」を実行の記録に積み、仕様の「返信用の札で届く」とも合わない／(b) 番頭の Fork
  では札の知らせで起こさず、返事待ちを「終わっていない」に数えず、知らせは次の番頭の回に一緒に積む。(b) にした（出来事が回を起こし、札の
  知らせが中身を運ぶ。仕様の両方と合う）。#507 の単体試験「返事待ちなら時刻の回を飛ばす」は、意図（前の回が終わっていなければ飛ばす）を
  番頭の自動化の届けものが積まれていない場合で保ち、返事待ちは飛ばさない試験を足した
- **数えは番頭が流した件だけ**：仕様の「全部の番頭の合計」をそのまま。全部の件を数える案は、人が Factory を回している Project で番頭が
  何もできなくなり、人の判断で使っている分を番頭の歯止めに混ぜる
- **件の今の様子は Factory に聞く**：記録だけで数える案（出来事で外す）は、複数件の実行の途中で取り込まれた件・人が1件だけ取りやめた件・
  人が画面から答えて動き出した件を拾えない。Factory の様子は Factory にしか無い（写しを持たない、規則3）
- **超えたら全部断る**：流せる分だけに切る案は、Factory が中で断った項目の分の枠が空いたまま残り、どれが流れなかったかを番頭が読み違える
- **流すのは merge を任されているとき**：仕様の Factory の項は行いの表と結んでいなかったが、Factory は main へ取り込むまで運ぶ。`remove: ["merge"]`
  の Project で番頭が流せると、方針の外し方をくぐれる
- **answerFactory の instruction を断る**：止まった件の回は必ず外の文（テストの出力・レビューの文）を読んでいる。指示の文に運べると H4（自由な
  文が外の文の抜け道）と同じ穴になる
- **許す tool の一覧を役割で持つ**：#507 では `<Module の識別子>/<tool>` の空の一覧だった。識別子は banto が採番し、人が別名で入れられるので、
  名前で持つと同梱の Factory を別名で入れた Project で番頭が使えない／同じ名前の別の Module に当たる
- **きっかけの文を今の文から引く**：#508・#509 で手順を足したが、台帳の `instruction` は作ったときの写しなので、前に置いた番頭には「何もせずに
  終えて」が届き続けていた

## 実装で決めたこと（2026-10-21、Backlog #510）
仕様は §4.5「実装で決めたこと（Backlog #510）」。ここは経緯だけ。自動許可の絞りは人の決定待ちなので作っていない。
- **量で飛ばした回の決めることは「人に任せました」と同じ扱い**：案は (a) 何も付けない（カードは今のまま）／(b) `incomplete`（揃わなかった）／
  (c) `deferred`。(a) は見回りが `decision-missed` として拾い直し、人にも番頭が見なかったことが見えない。(b) は番頭が答えかけたように読める。
  番頭は何もしていないので (c) にし、理由に「この回を飛ばしました」を書いた。受けたものは溜めずに片づける（溜めると空いたときに番頭へ届き、
  人が答えている問いに番頭が答えうる）
- **上限は「ちょうどで飛ばす」**：N 回走ったら N+1 回目を飛ばす。数えは fold の回の記録（届けた回だけ）と記録の `instructed` から——別の数えを
  持つ案は、起こし直しで食い違う（規則3）
- **止めた理由は一時停止の印（`pausedScope`）で分けた**：理由の文で見分ける案は、文を直すと壊れる。全体の「全部止めた」旗を別に持つ案は、
  番頭ごとの一時停止と二重になる（写し）。全部止めている間に Project ごとに止め直したら印を外す——全部再開で勝手に動かないように
- **(c) を (a) より先に**：ターンを止めてから預かりを人に回すと、止まるまでの間に残りの問いが揃って届きうる。先に `endTurn` で預かりを畳む
- **選んだ答えの取り消しはターンごと**：記録は問いごとだが届けたのは1回。1問ずつ取り消せると、同じ届けものへ人の発言が何通も届く
- **人の発言は host が画面と同じターンを開いて送る**：届けもの（`deliver`）で送る案は、人の発言にならず（印が付く）、宛先の番頭の指示を
  「人を優先」で捨てる決まりも効かない
- **記録の id は fold が seq から付ける**：書くときに乱数を持たせる案は、前に書いた記録に id が無い。seq は出来事ごとに一意で、読み直しても同じ

## 実装で決めたこと（2026-10-21、Backlog #511——画面）
仕様は v4-frontend.md §6.54「実装で決めたこと」とアーキ §4.5「実装で決めたこと（Backlog #511）」。ここは経緯だけ。
- **置き方は受信箱と同じ前面の1枚**：案は (a) 自動化と同じ Canvas（Project の隣）／(b) `/supervisor` のページ／(c) 受信箱と同じ `overlay`。
  (a) は Project に結びつくが、番頭の方針と見渡しは banto 全体のもの。(b) は開くと下の会話が作り直される（外枠は残るが、開いていた
  Fork・Canvas の URL の印が消える）。受信箱から「全部止める」へ行き来する形にも (c) が合う
- **カードの「取り消す」は記録を押してから引く**：カード（`ReviewJudge`）に記録の id を足す案は、id が fold の seq から付く（#510）ので、
  決めを付ける時点では id が無い。読むときに組んで添える案は受信箱の組み立てに番頭の記録を混ぜる。押したときにその会話の記録を引いて
  照らす（頼みは指示の id で一意、選んだ答えは問い・選択肢・時刻）
- **「1日のまとめの時刻」の欄は出さない**：時刻を保存しても、その時刻に何かをする仕組みが無い——繋がっていない欄になる（規則13）
- **「番頭を置く」は3つのスイッチの外**：§6.51 の3行は Project の設定の「一般」と同じ並び・言葉（規則3）で、試験もその3行を見ている。
  番頭は設定ではない（置く・外すは番頭の画面）ので、すぐ下の別の1行にした
- **受信箱の取り直しを全体で比べる**：画面を開いたまま番頭が決めると、カードは先に読み込まれ、決め（`judge`）はあとから付く。中身を `turn`
  だけで比べていたので描き直さず、「番頭が決めました」が出なかった（E2E で見つけた。判断役でも同じことが起きうる）
- **番頭の会話の帯は見回りの帯と同じ場所**：仕様は「上の帯」。今ある読むだけの会話の帯が入力欄の上にあり、並べて同じ場所に置いた
- **自動許可オンの注記**：仕様の文（公開・Project をまたぐ送信・秘密を返す中継は聞く）は、自動許可の絞り（人の決定待ち）ができてからの
  動き。今は「公開や消す操作も人に聞かれません」と今の動きを書いた。絞りを作ったら仕様の文に替える
