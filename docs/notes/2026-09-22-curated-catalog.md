# MCP Registry を主の面から降ろし、banto が選んだ目録を置いた（2026-09-22）

前日に作った MCP Registry のタブ（`docs/notes/2026-09-21-mcp-registry.md`）を、
**人に見せる主の面から外した**。きっかけはユーザーの一言：

> なんかあまりに玉石混合すぎて、MCP Registry、そのままユーザに提示はつらい気がしてきた

印象で動かず、**全件数えた**。

## 「提供元だけに絞る」は成立しなかった

自動判定で絞る案を測った。よく使う20サービスで検索して、`vendor` と判定される
ものが1件以上出るか：

```
★ 出る (9/20)  stripe notion linear figma cloudflare atlassian paypal …
  0件  (11/20)  github slack sentry postgres jira asana hubspot
                shopify datadog twilio mongodb
```

**公式を出していない会社が多い**ので、絞ると画面が壊れて見える。

さらに自動判定は**ブランド名が同じだけの別物を拾う**（同じ測定で発覚）：

- `app.vercel.*` が「vercel」の検索で**16件も提供元になった**
  ——`*.vercel.app` は**誰でも取れるサブドメイン**。`io.github.*` と同じ
  「共有ホスティング」なのに、そこだけ特別扱いしていた
- `al.square/fiskalizimi`（`square.al`）は決済の Square ではない
- `app.elasticflow` は Elastic ではない／`io.astrotune`（占星術）は Astro ではない
- `com.microsoft.esrp/esrp-oss-mcp-test` は Microsoft のものだが**社内の試験用**

**ドメイン名が同じ語というだけのものは、原理的に見分けられない。**
つまり「提供元」という札は、自動判定だけに任せると言いすぎになる。

## 決めたこと（ユーザー決定）

**banto が選んだ目録を主にし、registry は「カスタム」の中へ降ろす。**

- **おすすめ** ＝ banto 同梱のコード ＋ **目録**（`curated.ts`、第三者だが
  **人が実物を確かめた**もの。載せた時点で 12 件）
- **カスタム** ＝ JSON を貼る／手で書く／**MCP Registry を探す**

registry の機能（検索・並び順・取得・接続）は**そのまま残っている**
——降ろしたのは**入口の高さ**だけ。自分で探す人は今までどおり使える。

### 目録が持つのは「registry のどれか」だけ

起動の指定は**書かない**（規則3）。持つのは `registryName` と、
**なぜ載っているか**の1行。実際の繋ぎ方は host が `server.json` を
**引き直して**組み立てる——写しを持つと、相手が版を上げたときに食い違う。

おかげで「目録から入れる」と「自分で探して入れる」が**同じ道**を通る
（解決・入力欄・秘密の扱い・承知・取得が1本）。

### 言えることだけ言う

目録が保証しているのは**出所**だけ——「Stripe のサーバは Stripe が出している」
まで。**コードは監査していない**ので、画面にそう書く（規則2）。

## 実機で見つけて直した3つ

UI を本番に出して触って見つかった：

1. **Stripe の Module 名が `mcp` になっていた**。見出し（`displayLabel`）は
   前日に直したのに、**名前のほうが `/` の後ろをそのまま使っていた**。
   `suggestedName` を足して host 側で1回だけ決める（規則3）。
   **名前に `title` は使わない**——`E2E Greeter` のような文は識別子にならない
2. **「MCP Registry を探す」を選んでも、手動入力の欄が一緒に出ていた**
   （同じ「名前」の欄が2つ）。`mode === "custom"` で受けていて `customMode` を
   見ていなかった。**E2E が捕まえた**
3. Azure の説明に `**…**` がそのまま出ていた（文字列に markdown を書いていた）

**2つ目は、私の frontend ビルド確認の grep が甘くて見逃していた**
（`^ *error` では `… error TS2367` に当たらない）。E2E の webServer 起動失敗で
初めて表に出た——**ビルドの成否を自分の grep で判定しない**。

## 残した課題

- **共有ホスティングのドメイン**（`vercel.app`・`herokuapp.com` 等）を
  `io.github.*` と同じ扱いにする手当ては**まだ入れていない**。目録を主にしたので
  緊急度は下がったが、registry を探す面では「提供元」の札が誤って点く
- **`planFor` は remote を優先する**ので、両方持つもの（Context7 など）を
  **ローカルで動かしたくても選べない**。人に選ばせる材料が無いと判断して
  1つに決めた設計だが、必要なら選べるようにする
