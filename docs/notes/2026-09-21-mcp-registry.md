# MCP Registry から Module を入れる（2026-09-21）

仕様は `docs/specs/v4-architecture.md` §5.1・`v4-security.md`。ここには
**なぜそうしたか・測って変えたこと・却下した案**を残す。

## きっかけ

ユーザー：「Module の追加に、MCP Registry の一覧からのインストールのタブを
追加して欲しい。server.json を参照して、リモートならつなぐ。ローカルなら
インストールして、つなぐまで、一貫してできる手段が欲しい」

決めたこと（ユーザー回答）：
1. **対応は npm のみ**。ただし**今後 全形式に対応するときに大きな
   アーキテクチャ変更にならないように**作る
2. **追加の承知は取らない**（閉じ込めに頼る＝いまの「JSON を貼り付け」と同じ扱い）。
   ただし**一覧で各サービスの公式を優先して出す**
3. **まず UI だけ本番 banto に入れて確認**してから中身を配線する

## 測って分かったこと（設計を決めた事実）

### `npx -y` は閉じ込めの下では動かない

宣言に `npx -y <pkg>` と書けば起動時に取ってきてくれそうに見えるが、**動かない**。
banto は Module を Landlock で包んで起動し、instance の Module が書けるのは
`moduleDataDir` と `/dev` だけ。実機で確かめた：

```
$ banto-landlock-exec --ruleset-file … -- /bin/sh -c 'touch "$HOME/.npm/probe"'
touch: cannot touch '/home/ubuntu/.npm/probe': Permission denied
```

npm はキャッシュもログも書けない。**だから取得は閉じ込めの外＝host がやる**。
これが「インストールして、つなぐ」が1本の筋になる理由そのもの。

置き場は `<dataDir>/module-packages/<Module 名>/` で、起動時は
**読み取り専用**で渡す（`moduleInstallDirs`）。`moduleDataDir`（読み書き）とは
分ける——同じにすると、動いている Module が自分のプログラムを書き換えられる。

**この穴は試験をすり抜けていた**：外から足す E2E が使っていたのは
`/bin/sh -c true`（すぐ終わる）で、**npx 由来の Module を一度も立てていなかった**。

### registry は「公式」を持っていない

`_meta.io.modelcontextprotocol.registry/official` にあるのは `status`・`isLatest`・
日付だけ。verified も publisher も無い（API リファレンスと実データの両方で確認）。

**唯一の手がかりは名前空間**で、そこは registry が公開時に検証している
（`io.github.*` は GitHub アカウント、独自ドメインは DNS/HTTP チャレンジ）。
なので「Stripe が出している Stripe のサーバ」は
**名前空間のドメインが検索語と一致するもの**として導ける——**ブランド名の一覧は
持たない**（規則3——持つと書き足す当番ができ、書き忘れが静かな誤りになる）。

実データでの効き（2026-09-21）：

| 検索 | 先頭 |
|---|---|
| stripe | ★`com.stripe/mcp` → `app.vercel.stripecheckup/…` → `io.github.*` |
| notion | ★`com.notion/mcp` → `ai.smithery/…` → `io.github.*` |
| google | ★`com.googleapis.*/mcp` が並ぶ（前方一致を認めている） |
| gmail | **★は付かない**——Google は `com.google/gmail` を出していない |

**近似であることは画面にも出す**（出所を札で出す）——並び順だけに判断を預けない。

## 途中で測って**やめた**もの

**検索していないときも「提供元」を出そうとして、やめた。**
「自分のブランドで出しているか」で代用したら、**実データの先頭12件が全部
「提供元」**になった（`ac.snag/snag`・`ai.aard/aard`…公開者はたいてい自分の
ブランドで出す）。常に点く札は何も教えないうえ、**並びは実際には名前順なのに
優先が効いているように見える**（規則13）。

→ **検索するまで一覧を出さない**形にした。「答えられない問いに、それらしい
答えを返さない」（規則2）。数千件を名前順に並べた頭は、目録としても役に立たない。

## 実機で見つけた2つ（UI 先行で出した甲斐があった）

1. **見出しが「mcp」になっていた。** `title` は任意で、**公式ほど書いていない**
   ——`com.stripe/mcp` には無く、`/` の後ろをそのまま出していた。
   `title` → 無ければ（名前が `mcp`・`server` 等なら）ドメイン名、に直した
2. **対応していない形式でも「追加」が押せた。** 押せば host が断るので壊れは
   しないが、**押せて見えること自体が誤り**（規則13）。理由を出して押させない形にした

どちらも E2E に回帰を足した。

## 形式を増やすときに触るところ

**2箇所だけ**で済むようにしてある：

1. `modules/registry/support.ts` の `FORMAT_SUPPORT` に1行
2. `modules/registry/install/<形式>.ts` を1本足す

呼ぶ側（HTTP の口・画面）は `registryType` を**1つも知らない**。
`supported: false` の行も**消さずに並べる**——画面が「まだ対応していない」と
理由つきで言えるようにするため。消すと人には「そんな形式は無い」に見える。

## 境界（変えていないこと）

- **宣言を組み立てるのは host。** 画面が送るのは「目録のどれか・付ける名前・
  人が入れた値」だけ。`server.json` は **host が引き直す**——貼り付けた JSON が
  金庫の窓口を名乗る経路を、ここから復活させない（`v4-security.md`）
- **役割は名乗らせない**（`satisfies: []`）
- **閉じ込めは外せない**（`confinement: {kind:"landlock", root:"none"}`）
- **秘密は名前だけが宣言に残る**（`${secret:…}`）。直書きも通すが、
  **記録に残り続けることを画面が言う**
- **聞かれていない欄は差せない**（画面から任意のヘッダ・環境変数を足せない）

## 試験

**本物の registry も npm も叩かない**（規則6——外の都合で落ちる試験にしない）。
偽の MCP Registry（中身は本物から写し）と**偽の npm registry**を立て、
後者が配るのは**依存を持たない MCP サーバ1本**（依存があると npm が本物を見に行く）。

E2E は「入れたら**実際に取ってきて立ち、AI が見る経路から呼べて、人が入れた値が
起動まで届いている**」ところまで見る——`[host] greeter connected` を実測。

フル E2E **105 passed / 0 failed**（従来 100 ＋ 今回 5）、単体 381 passed。
