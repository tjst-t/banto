# Agent SDK を 0.3.237 → 0.3.281 に上げた（2026-09-24）

## なぜ

「Opus 5.5 が見えない」（ユーザー）。banto のモデル一覧は **SDK に同梱の Claude Code の版**で
決まる。0.3.237 は Claude Code 2.1.237 を同梱していて、既定＝Opus 5・Fable 5 までしか知らない。
システムの `claude`（2.1.280）に同じ SDK から聞くと Opus 5.5・Fable 5.1 が出た——版の差が原因。
0.3.281 は Claude Code 2.1.281 を同梱する。上げると既定が Opus 5.5 になる。

却下：SDK はそのままでシステムの `claude` を使わせる（`pathToClaudeCodeExecutable`）——SDK と CLI の
版が噛み合わない組み合わせになり、システムの `claude` は勝手に上がるので、banto が何で動くかが
知らないうちに変わる。

## 44版の変更で banto に効くもの（CHANGELOG を読んだ）

| 版 | 変更 | banto |
|---|---|---|
| **0.3.267** | **独自の system prompt を既定で記録し、resume では記録を使い回す**（`snapshot: false` で従来どおり） | **効く**。下で測った。`snapshot: false` を渡した |
| 0.3.242／0.3.257 | `getContextUsage({ detail })` を足した | 既定は `'full'` のまま——変わらない |
| 0.3.277 | タスク管理の tool が新しいモデルの既定から外れた | banto は `tools` を明示している——影響なし |
| 0.3.261 | `Symbol.dispose` の無い実行環境で `query()` が投げる | Node 24 で動く——影響なし |
| 0.3.281 | CLI が初期化の返事を先に返す・同梱物が小さくなった | 影響なし（良くなる方） |

ほかは足し算（新しい欄・新しいオプション）。

## 測ったこと

- **system prompt の記録**（同じアカウント・Haiku）：1ターン目に合言葉 PELICAN、resume した2ターン目に
  WALRUS を渡して「合言葉は？」と聞く。**既定では PELICAN と答えた**（2ターン目の prompt が無視された）。
  `snapshot: false` では WALRUS。——上げるだけだったら、モデルの名前（§2.3）と Fork の Memory の差し替えが
  黙って効かなくなっていた
- **本物の Runner で banto を通す1ターン**（別データ・別ポートの host、Haiku）：Module の tool
  （`listDirectory`）が中継を通り、承認待ちに載り、承認すると実行され、答えに実在のファイル名とモデル ID
  （system prompt で渡したもの）が出た。文脈使用量も返った。**Haiku は auto モードを持たない**
  （一覧の `supportsAutoMode` が無い）ので、auto でも tool ごとに承認を求める——SDK の変化ではない
- **古い版で作ったセッションを新しい版で resume できる**：2.1.237 で作ったセッションを 2.1.281 で
  resume し、前のターンの内容を覚えていた——稼働中の会話はそのまま続けられる

## 直したもの

- `npm run check:agent-sdk`（仕様 §6.5 が「SDK との疎通確認はこの1本」と決めている口）が壊れていた
  （`dist` に無いファイルを指し、中身も古い形）。本物の SDK で、モデル一覧・1ターン・選んだモデルで走る・
  **resume したターンで、そのターンの system prompt が効く**を見る形に書き直した。**SDK を上げたら回す**

## 残したもの

- アーキ仕様 §2.4 の「Claude Code CLI 2.1.237 は Tasks（非同期の Elicitation）を advertise しない」は
  2.1.237 での実測。2.1.281 で変わったかは測っていない（変わっていれば「後で答える」の作り方に効く）
