# Phase の建て付けを組み替えた（2026-09-11、ユーザー決定）

> 「次は基本Moduleを作りこんでいきたいと考えています。その前にやるべきことは
> ありますか？ ちょっと事前のPhaseの考え方は見直したいなと思います。」
> → 「Moduleを先でお願いします。あとそもそも、FactoryもModuleの一部にする
> つもりなので。」「1（Project ごとの Module 管理 UI）でお願いします。
> Kitはもう少しModuleを作りこんでから、共通化します。」

決まったことは `docs/requirements.md`「Phase と完了条件」。ここには
**何を測ってそう判断したか**と、**却下した案**を残す。

## 着手前に測ったこと

| 見たもの | 状態 |
|---|---|
| Module の契約 | 確定・実証済み。**Python の Module を宣言だけで繋げた**（コード変更なし、2026-09-06）。Canvas 4形態も本実装 |
| Phase 1 の完了条件 | ほぼ満たしている（3本書けた／TS でない Module が動く／tool 120個でキャッシュが落ちない） |
| Module 作業を直接塞ぐ残タスク | **1件だけ**（`phase1-project-modules-ui`）。他の8件は独立 |
| Module を足す口 | **コード内の `DEFAULT_MODULE_DECLARATIONS` と設定ファイルだけ**。画面から Project ごとに選べない |
| Module を書く足場 | **無い**。3本とも `Server`＋`setRequestHandler`＋`_meta` を手書き、設定 Canvas の HTML も 100行ずつ手書き |
| Module 側の契約試験 | **無い**（host 側の試験はある） |

**つまり「契約が決まっていないから増やせない」という状態ではない。**
増やす前に効くのは、契約ではなく**運用の口**（どの Project にどれを繋ぐか）だった。

## 決めたこと

1. **Module を Factory より先に**（Phase 2 ＝ 標準 Module を揃える）。
   元の順の根拠は「モジュールを増やす前に、Factory の一本の体験を磨き切る」
   （要件 C5）だったが、**前提が変わった**——banto は既に日常的に使われていて、
   いま足りないのは Factory ではなく毎日使う道具のほう。
2. **Factory も Module の1本**（Phase 3 ＝ Factory Module の作り込み）。
   core 側の特別な機構にしない（要件 C8 と同じ理由——core を2つにしない）。
3. **入口は「Project ごとに Module を選べること」**。宣言は instance 既定なので、
   1本足すと全 Project に繋がる。増やすほど、使わない Project にも tool が載る。

## 却下した案（記録）

- **Module kit（共通の骨）を先に作る**——「もう少し Module を作り込んでから
  共通化する」（ユーザー判断）。3本では共通部分の形が決めきれず、
  **足場を作りすぎるほうが高い**。4〜5本目で同じものが3度目に現れた時点でまとめる。
- **Factory を薄く1本だけ通してから Module へ**——Factory を Module にすると
  決めた以上、「先に通す」意味が薄い（他の Module と同じ扱いになる）。

## モックで決めたこと（2026-09-11）

`mock/` で「この Project の Module」を作り、1往復して形が決まった
（決定そのものは `docs/specs/v4-frontend.md` §6.15）。

**1往復の中身**：最初は「繋ぐ・外すのたびに確認ダイアログ」を出していた
——依存を一緒に繋ぐことや、外すと何が止まるかを、その場で言えるので。
ユーザーの反応は「**いちいちダイアログが出るのが面倒**」。続けて何本か繋ぎ変える
操作と合っていなかった。

**直した形**：下書きを編集して、**保存で1回だけ**確認する。言いたかったこと
（依存・止まるもの・増える減る tool）は**保存の差分**に移した——出す情報は減らさず、
出すタイミングだけを変えた。繋ぎ変えは Module のプロセスを立てたり落としたりするので、
「まとめて効かせる」ほうが実態にも近い。

**モックで決める価値が出た例**：この判断は設計書の上では出てこなかった。
「確認は丁寧なほどよい」と書けてしまうが、**触ると煩わしい**。
§10 の D 群（画面を見ないと決まらない）に置いた意味がそのまま出た。
