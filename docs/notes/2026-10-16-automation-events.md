## 器の実装（#345・2026-10-16）

仕様はアーキ §4.3「段2の器で実装で決めたこと」。ここは理由と却下した案。

- **名乗りの置き場は宣言の `dev.banto/module` の `events`**（仕様の初稿は `_meta["dev.banto/events"]` と別の鍵）。別の鍵にすると、宣言の差分
  （overlay）を重ねる `applyModuleOverlay` と、目録の宣言を読むたびに取り直す `refreshFromCatalog` が `meta` しか運ばないので、名乗りが
  落ちる。`meta` の中なら今の道にそのまま乗る。`parseModuleMeta` は知らない鍵を読まないので `BantoModuleMeta` には入れず、宣言の読み込みで
  生のまま持って使うときに読む（下）。仕様をこちらに直した（規則8——黙って寄せずに記録して直す）
- **名乗りは読み込みで照らさず、使うときに読む**：名前の頭は宣言の名前と照らす。目録の1本を別の名前で入れると合わなくなるが、読み込みで
  投げると全部の Module の読み込みが落ちる。その Module の出来事だけ受けない（作る口は「名乗っている Module がありません」で断る）
- **溜める上限に達した自動化には積まず、出来事は受け取ったと返す**：仕様の初稿は「溜める上限を超えた異常な量は断る」。断ると出口の箱が
  その出来事を捨て、同じ出来事を待つほかの自動化にも届かない。詰まっているのはその自動化だけなので、その自動化に積まずにログに残す
- **出せない呼び元にも `{ refused }` を値で返す**（投げない）：投げると箱は一時の失敗として7日間出し直し続ける。断りは何度出しても通らない
- **回数の歯止めはメモリ**：数えるのに要る「主体ごとの起こした時刻」は台帳に無い（回は 50 件で切れ、受けたものは届けると消える）。消えない
  置き場に持つと一番増える出来事がもう1つ増える。起こし直しで数え直しになるのは、起こし直しの回数が輪の速さより十分遅いので許す。
  却下：`automation.fired` から数え直す（主体を持たない・50 件で切れる）
- **呼び出しの写しを書くのは代理の、Module を呼ぶ直前**：Module が出来事を出すのは呼び出しの最中のこともあるので、終わってから書くと間に
  合わない。Project が違う写しは引かない——`causedBy` は申告なので、別の Project の呼び出しの印を書けばホップや「自分の回」を操れてしまう
- **まとめた1本の 64KB**：最初は「合計が超えたら全部の本文を省く」にしていたが、レビューで直した——1件 16KB までなので5件まとめると4件分は
  収まるのに全部捨てていた。先頭から積み、収まらなくなったものから省く。一度省き始めたら後ろの小さいものも省く（途中から本文が戻ると、
  AI がどこまで省いたか読み違える）
- **試験用の Module は目録の隠れた1本**（`tools-probe` と同じ形）：出来事を名乗れるのは同梱だけで、`/api/modules` で足した Module は外から
  繋いだ扱いになる。同梱の判定は「起動するプログラムと引数が既定・目録のどれかと一致」なので、目録に置けば同梱の扱いで入れられる
- **E2E で「繋がっていない間」を作る形**：Module に「箱に書くだけで出さない」を頼み、host を SIGKILL して起こし直す。起きた Module は
  繋がったら箱を古い順に出す。前に受けた `eventId` を箱に混ぜ、起こし直しても二度動かないことも同じ回で見る
- **base の載せ替え**：最初の実装はローカルの main（6a54559b）から出ていて、origin/main（仕様コミット 0cc6326d を含む）と履歴が分かれていた
  （同じ題で SHA の違うコミットが並ぶ）。自分のコミット1本だけを origin/main に載せ替え（`git rebase --onto origin/main main`）、衝突は
  `relay/host-relay-endpoint.ts` とその試験（`raiseNotice` に `threadId` が足されていた）の2つだけで、両方を残して解いた

## 待たれている出どころを起こしておく（#346・2026-10-16）

- **「止める」まではしない**：一時停止・消したとき、Module を畳むことも考えたが、やめた。Project ごとの Module はもともと使われたら
  次に畳むまで起きている（使われないときに止める仕組みは無い——それがスリープで、別の Fork で検討中）。ここで畳むと、人が同じ Project で
  使っている Module を自動化の一時停止で落とすことになる。仕様の言葉どおり「起こしておくのをやめる」だけにした
- **見直しは「きっかけ＋1分ごと」**：きっかけ（待ち受け・台帳の変更・Project の一覧の変更・畳んだあと）だけだと、最初に起こせなかった
  もの（コンテナの用意の失敗など——落ちたものと違い `scheduleRestart` に乗らない）と、知らせの無い変化（別の実行場所へ移し終えた）を
  拾えない。1分ごとの見直しで拾う。待たれている Module が無い Project では宣言を読むだけ、繋がっているものは `connectDeclaredModule` が
  すぐ返し、試し直しの間は `connectBackoff` が断るので、1分ごとでも重くない
- **畳んだあとに起こし直すのは、画面の操作の口だけ**：`releaseProjectModules` そのものに入れると、起動の途中で Project が畳まれたときの
  片づけ（`connectDeclaredModule` の中から呼ぶ）や、移すときの片づけ（`ProjectMover`）が起こし直しを呼んでしまう。HTTP に渡す口で包んだ
- **E2E で「起きていない」を確かめる形**：起きているかは `GET /api/projects/:id/modules` の `connected`（起こさずに読める）。tool を呼ぶと
  呼んだことで起きる。「起こし直したあと起きていない」は待つ時間で決めず、同じ起こし直しで、いつも待たれている見比べ役の Project の
  Module が起きたのを見てから確かめる（同じ見直しで同時に起こすので、見比べ役が起きたなら、起こすべきだった側も起きているはず）。
  見直しを止めると「作っても起きない」で落ちることを確かめた

## 最初の出来事の実装（#347・2026-10-16）

仕様はアーキ §4.3「最初の出来事で実装で決めたこと」。ここは理由と却下した案。

- **出す口を module-contract に1つ**（`EventPublisher`）：3つの Module の中継の口はどれも `(name, args) → { text, isError }` の形なので、
  箱に書く・出す・見回るを共通にした。却下：各 Module に `EventOutbox` を直に持たせる（見回りと初回の遅らせ方が3か所に写る）
- **Service の箱はコンテナの中のローカル**：起動役は systemd のユーザーの unit として動き、Module の置き場（host のディスクのマウント）の
  場所を知らない。サービスの置き場（`~/.banto-service`）は起動役も Module も同じ所を見ているので、その下に置いた。箱の場所は起動役の引数で
  渡す（起動役が自分の置き場から推すと、試験の置き場が `/tmp` の直下の箱を共有してしまう）。引数が無ければ書かない（前の形の unit）
- **Service の見回りは 3 秒**：起動役は別のプロセスなので、Module は箱を見回るしかない。`fs.watch` は張るフォルダがまだ無い・コンテナの
  中の inotify の上限、の2つで当てにできないので、小さいフォルダの readdir を 3 秒ごとにする
- **始めた呼び出しの印を「動いているものを起こすだけ」で変えない**：その呼び出しは起動を始めていない。変えると、別の会話が様子見で
  startService を呼んだだけで、落ちた出来事がその会話のターンのものになる
- **人の画面から起こしたら印を消す**：前の AI のターンの印が残ると、人が起こしたものが落ちたのに「その AI の回が起こした」扱いになり、
  その自動化が自分で起こさない（`allowSelfTriggered`）で黙る
- **`factory.run-finished` は主体を名乗らない**：仕様の初稿は「`factory.*` は `item`」だったが、終わりは件を持たない。名乗らなければ出来事名
  だけで数える（同じ自動化で1時間に6回まで）。却下：`runId` を主体にする（実行ごとに1回しか出ないので歯止めにならない）
- **Factory・Backlog の属性を仕様の初稿より足した**（`title`・`runId`・`item`・`number`）：条件で絞るのにも、届いた見出しで何のことかを
  読むのにも要る。`backlog.item-changed` の主体（項目の id）は属性に無いと名乗れない
- **Backlog は前後の文書を比べて決める**：tool ごとに「何が変わったか」を書くと、splitStory（できたタスクが複数）や Factory の updateItem の
  ように形の違う書き込みのたびに写しが増える。書き込みの土台は compare-and-swap で読み直した文書なので、それを返す
- **E2E で「Module が止まっていた間」を作る形**：Service を「合図のファイル（Project の根）が置かれたら1回だけ落ちる」形で起こし、host を
  SIGKILL してから合図を置く。落ちる直前に根に印のファイルを残させ、それを見てから host を起こす（決まった時間を待たない）。起き直した
  host で Service は使われるまで起きない（起こしておくのは #346）ので、listServices で起こしてから届くのを待つ

## 判断役の実装（#348・2026-10-16）

仕様はアーキ §4.3「判断役で実装で決めたこと」。ここは理由と却下した案。

- **答える先は届けものから覚える**（`beginTurn`）：「いま走っているターンを起こした届けもの」は turn-runner しか持っていない（会話の記録に
  積んだ発言からも読めるが、前の回を引き継ぐ Fork では過去の回の発言と混ざる）。届けものの `kind: "automation"` と、その自動化が判断役で
  あることの両方を見る——`banto.*` は core しか出せないが、外から来たもの（`kind` 無し）の囲みに同じ形を書かれても答える先にしない
- **選択肢は記録から引く**：出来事の `text` にも選択肢は入っているが、真実は元の会話のまとめ（規則3）。数が合わなければ断る
- **判断役の理由は元の会話に届けない**：`decision` は「従ってよい」書き手なので、判断役の AI が書いた文を混ぜると、判断役が読んだ外の文
  （`readExternal` の元）がそこを通って元の会話の指示になりうる。選んだ選択肢は元の AI が自分で書いた `reply` なので混ぜてよい
- **「判断役が見ています」は記録に残さない**：走っているターンの間だけの状態で、host を起こし直したら消えるのが正しい（残すと、落ちたあとも
  見ていることになる）。`GET /api/inbox` が走っている判断役のターンから引く
- **判断役の会話の permissionMode を `default` に固定**：仕様の「承認は必ず聞く」は自動許可を外すだけでは足りない——専用の Fork は
  Project の既定（ふつう `auto`）で走り、そもそも何も聞かない。会話の設定ではなく、ターンを始める口（`resolvePermissionMode` の手前）で
  固定する（会話の設定に書くと、人が画面で変えられてしまう）
- **`answer_decision` は承認を通さない**：承認を通すと判断役が答えるたびに人に聞くことになり、判断役が要らなくなる
- **一時停止した判断役の会話も自動許可を効かせない**：一時停止は「出来事を待たない」で、会話は残る。人がその会話で何かを頼んだとき、
  一時停止しただけで自動許可に変わると「必ず聞く」が外れる
- **出来事はレビュー待ちを出したあとに出す**：最初は `ThreadTurns` の `ended` を別に聞いて出していたが、レビュー待ちを出すのも同じ
  `ended` からの非同期で、判断役（まとめる待ち 0 秒）が先に答えるとカードが無く、「判断役が決めました」が付かずに消える。レビュー待ちを
  出す処理の後ろにつないだ（条件も同じ `reviewDueAfterTurn` なので、そこに置くのが素直）
- **却下：途中の答えを台帳に残す**——仕様どおりメモリ。揃わないまま host が落ちたら、カードには何も付かず人を待つ（人の答えを待つ側に倒れる）
- **E2E の偽の Runner**：`answer_decision` の `turnId` は試験が指示を書く時点では分からない。本物のモデルが囲みの属性を読んで書き写すのと
  同じく、tool の引数の `"$eventField:<名前>"` を prompt の最後の `<banto-external … fields="…">` から引いて置き換える（引けなければ投げる）。
  元の会話の続きは、届いた `reply` に「「…」と返して」を入れて既定の返事で見る（`reply` に指示の印を入れると、判断役の prompt の出来事の
  本文にも入り、判断役の指示を上書きしてしまう）
- **「人が先に答えた」を時間に頼らずに作る**：判断役の指示で、承認の要る tool を先に呼ばせる。判断役が承認で止まっている間に人が元の会話で
  送り、そのあと承認に答える——同じ回で「自動許可でも判断役の会話は聞かれる」も見られる
