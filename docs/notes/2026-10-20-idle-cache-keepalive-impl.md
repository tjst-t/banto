# 空いた会話の温め直し（#472 idle-cache-keepalive）の実装で決めたこと・人に確かめたいこと

正本は `docs/specs/v4-architecture.md` §3.1「温め直し（中継）」「切り替え」。ここは実装の経緯と、仕様に書かれていない細部の解釈。

## 形

- `claude-login/keep-alive.ts`（`CacheKeepAlive`）：時計・止める条件・上限・#473 が読む様子（`cacheOf(threadId)`：最後の本物の要求か
  温め直しの時刻と当たったか・最後に当たった時刻・止まった理由 `abandoned`）。中継（`relay.ts`）が持つ（`relay.keepAlive`）
- 中継：本体の要求（本体用の合言葉・`x-banto-thread-id` あり・`/v1/messages`。count_tokens は除く）の応答を流しながら、stream なら
  最初の `message_start` の usage、stream でなければ全体の usage を読む（`UsageTap`、見る量は 4MB まで）
- host（`cli.ts`）：`threadTurns` の started で `turnStarted`（止めて候補を集め直す）、ended で `turnEnded(ticket)`。ticket は
  閉じた会話・読むだけの会話・閉じた／眠っている（眠らせている途中の）Project・`thread.idleCompaction` オフなら渡さない。
  ticket の印は resume-point・rewindTo・モデル・effort・Module の宣言の名前の集合。送る前に `keepAliveWarmable` で「ターンが走って
  いない・印が同じ」を確かめる——閉じた・Clear・やり直し・眠らせた・モデル等を変えた・スイッチを切ったは、どれもここで止まる
  （出来事ごとに口を足さず、送る時点で1か所で見る）
- E2E：`BANTO_TEST_KEEP_ALIVE_MINUTE_MS`（1分の長さ）で縮める。`idle-cache-keepalive.spec.ts`。止める処理を外すと落ちることを確かめた

## 解釈（人に確かめたい）

1. **使用率が分からない窓は「余白がある」扱い**にした（読んだことがない・リセットを過ぎた）。`select.ts` の「分からない＝使える」と
   揃えた。本物の上流は毎回見出しを返すので、固定のアカウントは直前の本物の要求で読めているはず。「分からなければ温めない」に
   するなら `relay.ts` の `warmMargin` を変える
2. **5時間の窓の 2,000万トークン**は、会話を足すときに「窓で使った分＋温めている会話のこれから送る分（残りの回数×入力の量）」で
   見積もり、超えたら最後の要求が古い会話から押し出す。送る直前にも「使った分＋今回」で確かめ、超えればその会話をやめる
3. **固定の寿命を延ばすのは温め直しが 2xx のときだけ**。失敗したらその会話の温め直しはやめるので、延ばす意味が無い
4. **Fork の最初のターン**：Fork の会話のターンが始まった時点で、その会話（Thread）の温め直しを止める。親の会話の温め直しは続ける
   （親のセッションは替わらない）。「鍵が替わる」を親も止める意味に読むなら直す
5. 温め直しが 401 でも、取り直して同じアカウントへ送り直すこともしない（中継の本物の道は 401 で1回だけ送り直す）。仕様の「401 でも
   送り直さない」をそのまま読んだ
