# サイドバーとモバイルのナビを作り直した経緯（2026-09-09）

> 決まったことは `docs/specs/v4-frontend.md` §6.7。ここには**なぜそうしたか**と
> **採らなかった案**、**途中で踏んだ罠**を残す（消さない）。

## 発端

ユーザー指摘（この順で来た）：

1. 「サイドバーの幅が狭くてアイコンしか出ないので不便。Project 名が読めたほうがよい。
   合わせてフォークスレッドの表示も見直したい」
2. 「モバイルも同じように使いにくい」
3. 「サイドバーをドラッグでサイズ変更できるようにして」

**モックで形を決めてから本実装へ入れた**——1と2は「見ないと決まらない」種類だったため
（CLAUDE.md の3段：モック→本実装）。3は形が自明だったので本実装に直接入れ、
そのあとモックへ写した（両者が食い違うと、次にモックで検討するときの土台がずれる）。

## 何が悪かったか（測った結果）

| | 症状 |
|---|---|
| デスクトップ | 58px のレール。Project は頭文字1文字（`b` `自` `記`）＋ツールチップでしか読めない。開いている Fork Thread は**アイコンの角の3pxのバッジ**＋ポップオーバーに隠れていた |
| モバイル（390×844） | 上部バー50px＋パネルのヘッダ44px＝**常時94px が2段**。**履歴・設定は両方の段にあり**、それでいて **Fork Thread へ行く口が無かった**（Command Palette で探すしかない）。アイコンは28〜36pxで画面最上部に9個 |

**Fork へ行けないのは規則13 の不備**——機能はあるのに画面から到達できない。

## 採らなかった案

- **モバイルを下部タブバー（会話／受信箱／Project／設定）にする**——banto のモバイルは
  下端を composer が占める。加えて切り替える対象が「固定の4タブ」ではなく
  **Project × Thread の2階層**なので、タブでは表現できない。目次を1枚持つほうが素直
- **上部バーを残したまま Project 名だけ出す**——2段のままでは面積が戻らないうえ、
  履歴・設定が両方の段にある重複も残る
- **狭い画面でサイドバーを自動で畳む**——挙動が予測しにくくなる。⌘B と
  ドラッグがあるので、人が決められる状態のままにした
- **サイドバーの目次に「畳む」を別実装で足す**——ヘッダの畳む操作は
  「閉じる前に host の最新の中身を写す」手順を含む。同じ操作を2箇所に書くと
  片方だけ古くなる（規則3）ので、`foldForkThread()` に一本化して両方から呼ぶ形にした
- **モバイルのヘッダから「Fork を開く」を「…」メニューへ畳む**——ヘッダが7要素で
  やや密なのは事実だが、実操作の位置が変わり E2E も3本触る。**保留**（未決）

## 途中で踏んだ罠

- **Caddy 経由のホスト名が `allowedDevOrigins` に無く、モックが「画面は出るがボタンが
  効かない」状態だった**——Next の dev クロスオリジン保護で `/_next/*` が
  **Origin ヘッダ付きのときだけ** 403 になる。`curl` では（Origin を送らないので）
  200 が返り再現しない。切り分けには `-H "Origin: http://<ホスト名>"` を付ける
- **サーバを動かしたまま `npm run build` すると、古いマニフェストが参照するチャンクが
  消えて画面が真っ白になる**（`/_next/static/chunks/*` が 500）。
  **ビルド→サーバ再起動→確認**の順を守る
- **`pkill -f "...4175"` は自分自身のシェルも殺す**（コマンド文字列に一致するため）。
  PID を特定して `kill` する
- **E2E のほぼ全部（17本）がモバイル幅で走っていた**——「新しい Project」ボタンの場所と
  `Base Thread — 名前` という題に依存しており、モバイルの作り直しで一斉に落ちた。
  共有手順（`openNav`/`expectProjectOpen`/`createProject`）を `e2e/helpers.ts` に
  集約して解消。**幅で変わるものは、各スペックに書き写さない**
- **新しい回帰試験が既存の不具合を掘り当てた**——Project が25件あると、畳んだレールの
  一覧が下の段（履歴・設定・明暗）の上に溢れ、**設定が押せなくなっていた**。
  原因は Fork バッジを切らないための `overflow-visible`。縦だけスクロールさせ、
  バッジのぶんの余白を上に取る形に直した
- **作業ツリーは他の作業者と共有している**——途中で自分の未コミットの変更が、
  別件（携帯キーボードの修正）のコミットに巻き込まれた。一時スクリプトも一緒に
  入ってしまったので、作業用のファイルは作業ツリーに置かない
