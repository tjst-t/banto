# 端数の倍率で「画面に合わせる」が効かない・開き直すと「映しています…」のまま（Backlog #359）

2026-10-16。仕様は `docs/specs/v4-modules.md` §4.1「人の画面」の「画面に合わせる」と、「動画で流す」の③。

## 報告

倍率 1.5 の端末（動画・H.264）で、

1. 「画面に合わせる」をオンにしても、ページ（「ページ 843×641」「ページ 1009×641」）が絵を出す場所（およそ 1150×830・
   1150×950）に合わず、絵は横に引き伸ばされ上下に余白。高さが 641 のまま追いつかない
2. Canvas を閉じて開き直すと「映しています…」のまま絵が来ない。そのとき VM で動画の子（python3 の GStreamer）が動いていなかった

## 測ったこと（この機械・Google Chrome・Xvfb、Module の部品を直に動かす小さなスクリプト）

**窓の大きさでページの大きさを決めきれない**。`setViewport`（窓の3手）のあとのページの `innerWidth×innerHeight`：

| 倍率 | 指定 → ページ |
|---|---|
| 1.5 | 843×641 → 844×642、1009×950 → 1010×950、1150×830 → そのまま、842×642 → そのまま（偶数はそのまま・奇数は +1） |
| 1.25 | 841→842・842→843・843→844・844→844（4の倍数だけそのまま） |
| 1.75 | 840×640 → 841×640、1000×800 → 1001×801、**1280×800 → 1280×801**（画素の整数になる大きさでも +1。`Page.getLayoutMetrics` の visual viewport は 841.14 = 1472/1.75——画素で +2） |

Chrome は窓の大きさ（CSS ピクセル）を画素に丸めるので、ページは指定より 1〜2 大きくなる。規則は倍率ごとに違い、
1.75 では予測で合わせられない。

**指定どおりにならないと、そのたび 2 秒止まる**：`settle`（ページの大きさが指定に落ち着くまで待つ）が上限の 2 秒まで待つ。
その間は `resizing` が立っていて、人の画面は動画を流さない（`runVideo` は子プロセスを起こす前に戻る）。倍率 1.5 で size を
843×641 にしたとき：size から最初の絵まで **約 4 秒**（`applyFit` が1回の size で `setViewport` を2回積む——1回目が
`this.size` を置く前に、始めた知らせの `refresh` から2回目が入る——ので 2 秒×2）。届いた絵の頭は 843×641、取り込む範囲は
843×1.5 から 1264×962、描かれたページは 844×642（1266×963 画素）で食い違う。閉じて開き直したとき（ブラウザを止めて起こし直した
場合も）も、合わせ直す `setViewport` が同じく 2 秒×2 待ち、開いてから絵まで約 4〜5 秒。

## 原因

倍率が端数のとき、窓の大きさで決めたページの大きさが指定と食い違う。そのせいで

- 窓を変え終えるのを毎回 2 秒待ち、その間は動画を流さず子も起こさない（報告2の「子が動いていなかった」と合う）。人の画面の
  大きさの知らせ（ResizeObserver から 120ms 置き）が来るたびに積まれ、表示の「ページ W×H」も古い知らせから順に替わる
  （報告1の、高さが追いつかない「ページ 1009×641」はこの遅れと見ている——**実機の画面で、知らせが何回積まれたかまでは測っていない**）
- 届いた絵は取り込む範囲（指定×倍率）とページが 1〜2 画素食い違う

報告1の「横に引き伸ばされ、上下に大きな余白」は、絵の頭（指定の大きさ）と、届いている最後の絵（前の大きさのキーフレームの続き）
の比が違う間の見え方と考えている——直した後は E2E で絵の画素がページ×倍率・角の印が画素単位で合うことを見ている。

## 直し方（決定）

1. **端数の倍率では、幅 500 未満と同じページの大きさの上書き（`Emulation.setDeviceMetricsOverride`、deviceScaleFactor 0）を
   併せる**（`session.ts` の `applyOverride`）。窓は指定以上の大きさになる（測った範囲ではいつも）ので、上書きしたページは
   窓の左上から指定どおりの大きさで描かれ、`innerWidth` も指定どおり。待ちは 2 秒→約 0.2 秒
2. **「画面に合わせる」は倍率を掛けて偶数の画素になる大きさに切り下げる**（`view-stream.ts` の `fitPageSize`）。上書きしても
   ページ×倍率が端数なら画素の境目に乗らず、奇数なら x264 が受けないので右端・下端の1画素を落とす

1.25・1.5 は 2 だけで窓の大きさが合う（4・8 の倍数）が、1.75 は合わない（1280×800 → 1280×801）ので 1 も要る——片方ずつ外して
単体試験で確かめた（1 を外すと 1.75 だけ落ちる）。

## 却下した案

- **窓の大きさを測って補正し直す**（ずれた分だけ窓を小さく指定し直す）：ずれ方が倍率ごとに違い（1.75 は画素の整数でもずれる）、
  収まる保証が無い。上書きは幅 500 未満で画素単位で合うことを確かめ済みの道
- **常に上書きする**（整数の倍率も）：整数の倍率では窓だけで合っていて、今の形を変える理由が無い
- **`settle` の待ちを短くする**：待ちを削って緑にするだけで、ページと取り込む範囲の食い違いは残る（規則6）
- **AI の resize も偶数の画素に丸める**：今回の報告の外（規則7）。端数の倍率では上書きが効くので AI の指定どおりの
  `innerWidth` にはなる。ページ×倍率が端数になる指定（1.5 で 843 等）では右端の1画素がにじむことは残る

## 確かめ

- 単体（`view.test.ts`）：倍率 1.25・1.5・1.75 で、絵を出す場所 1151×831 に合わせると、ページの `innerWidth×innerHeight`・様子・
  絵の頭が合わせた大きさ（偶数の画素）になり、復号した絵の角の印が画素単位で合う。閉じて開き直しても、窓が落ち着かない知らせを
  出さずに絵が来る。**直す前は落ちる**（1151×831 は倍率を掛けて整数にならない／1.75 は上書きを外すと `innerWidth` が合わない）。
  `fitPageSize` の純粋な試験
- E2E（`browser-video.spec.ts` の2本目）：倍率 1.5・1.25・1.75 の端末（窓 1501×1001）で起こし直し、「画面に合わせる」で
  「ページ W×H」・絵の頭・絵の画素（W×倍率）・ページの中の `innerWidth`・角の印が合い、Canvas を閉じて開き直しても同じ
