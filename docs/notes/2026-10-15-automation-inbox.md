# 自動化の回の受信箱で決めた細部（2026-10-15、Backlog #317 `automation-inbox`）

アーキ仕様 §4.3「受信箱」を実装したときに、仕様に書かれていない細部を決めた。仕様 §4.3 はこのブランチには無く `main` にある
（abafa075）——仕様書への反映は取り込むときに人が判断する（規則8）。

## 決めたこと

- **置き場**：出すか・どう出すかの判定は `banto/packages/core/src/inbox/automation-review.ts`（純粋な関数）、置き換えるかは
  `InboxStore.raiseAutomationReview`。呼ぶのは今までどおり `cli.ts` のターンの終わり。`raiseReview` は変えていない
- **どの回のターンか**は Thread の記録から読む：最後の人の発言（`origin` の無い user）と自動化の届けもの（`origin.automation`）の
  うち新しいほう。裏の仕事の結果が届いて起きた続きのターンも、その回に数える。自動化の層（`AutomationRunner.settleRuns`）も
  同じ `ended` を聞いて結末を書くので、そちらの書く順番に頼らないため
- **人が見ないといけない回**（`attention`）：結末が completed でない（止めた・失敗・切れた）→ `failed`、生きた判断待ちがある →
  `waiting`、そのターンのまとめに `decisions` がある → `decisions`。どれかなら「受信箱に出さない」でも出す
- **置き換え**：同じ Thread に `attention` つきの未確認があれば、後の回が何も無く終わっても出さない（`undefined`）。後の回も
  `attention` つきなら、**前のものを残して並べて出す**（仕様は「何も無く終わっても置き換えない」までしか言っていない。見ないと
  いけない回を後の見ないといけない回で消すと、人が見る前に前の回の決めることが消えるので、残す側に倒した）。`attention` の
  無い未確認は今までどおり置き換える
- **ターンの始まりの「見た」**：自動化の届けものもホップ 0 で起きるので、`cli.ts` の「人が送ったターン（hop 0）が始まったら
  見たにする」に当たって前の回のカードを消していた。始まった時点でその Thread に自動化の届けもの（`deliveries` の
  `automation`）が残っていれば「見た」にしない（`acknowledgesReviewsOnStart`）。人が並んでいて自動化の届けものも一緒に
  積むターンでは始まりで消さないが、終わりにふつうのレビュー待ち（`raiseReview`）が出て前のものは消える
- **残したカードの中身**：毎回まっさらでも Clear は印を付けるだけで発言は記録に残る。レビュー待ちの記録に、そのターンの
  始まりの seq と結末を持たせ、`GET /api/inbox` は最後のターンでなければ「始まりの seq より後・レビュー待ちを出した出来事の
  seq より前」の発言から組む（`reviewTurnOf` の `earlier`）。tool の数は最後のターンの分しか数えられないので添えない
- **まだ見ていない回の数**（`unseenRuns`）：カードに数え始め（`since`＝最初の未確認の回が動いた時刻）を持たせ、`GET /api/inbox`
  が台帳の回から数える（その Thread で、`since` 以降に終わった done／failed／waiting）。置き換えたカードの `since` を引き継ぐ。
  台帳に残る直近 50 回の中で数える。画面は 2 回以上のときだけ「この会話には、まだ見ていない回が n 回あります」を出す
  （1回なら、そのカードの回だけ）

## 残したこと

- 乗り換え（`AUTOMATION_FORK_RUNS`）で専用の Fork が変わると、前の Fork のカードは前の Fork の回だけを数える
- 受信箱の行で自動化らしい出し方（送り手・自動化の名前）は `automation-canvas` で扱う
