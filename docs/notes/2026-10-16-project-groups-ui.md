# サイドバーのグループの画面（Backlog #353 project-groups-ui）——実装で決めた細部と食い違い

2026-10-16。仕様は v4-frontend.md §6.43、見本はモック `fork/project-org`。

## 仕様と実態の食い違い（規則8——人に上げる）

- タスクの説明は「§6.43 は 20bf0ec2 で main に入れた」だが、**このブランチ（main から切った `factory/project-groups-ui`、
  ff3006aa）の `docs/specs/v4-frontend.md` には §6.43 が無い**。20bf0ec2 は `fork/project-org` にだけあり、main の祖先ではない
  （`git merge-base --is-ancestor 20bf0ec2 HEAD` が偽）。実装は `fork/project-org` の §6.43 を読んで書いた。仕様書は
  このブランチでは書き換えていない——`fork/project-org` の仕様の変更を main に入れる手順で揃える必要がある

## 実装で決めた細部（§6.43 に書いていないところ）

- **「グループへ移す」・「グループに入れない」で入れた先の位置は、その塊（グループ／グループの外）の最後**。
  ドラッグで見出しに落としたときと同じ。グループの外へ出すのに先がまだ誰もいなければ先頭
- **行の「上へ／下へ」は同じ塊の中だけ**。端なら押せない。グループをまたいで動かすのは「グループへ移す」かドラッグ
- **畳んだレールの並べ替えは同じ塊の中だけ**。入れ先を変える口は名前が読める幅だけに置いた（58px に見出しの落とし先を
  作れない）
- **「すべて畳む／すべて開く」の判定は見えている Thread の目次だけを数える**。畳んだグループの中にいま開いている
  Project があると、リロードしたとき目次は既定で開くので、それを数えると全部畳んでいるのに「すべて畳む」のままになった
  （E2E で踏んだ）
- **ドラッグは並べ替え（sortable）ではなく落とす先で決める**（`sortable-list.tsx` の `DropList`・`DraggableRow`・
  `useDropZone`）。行は動かさず、落とす先の行の上に線・見出しを塗る。dnd-kit の掴み方・落とした1回だけ書く、は §6.11 のまま
- **見出しの「…」の「中の Project を全部スリープに」は出していない**。スリープはまだ繋がっていない（project-sleep-core／ui）
  ——規則13。スリープの画面のときに足す
- 「＋」がメニューになったので、E2E の「新しい Project」は `helpers.ts` の `clickNewProject`（「＋」→「新しい Project…」）を通す。
  畳んだレールの「新しい Project」ボタンはそのまま
- 畳んだ状態の localStorage `banto.sidebarGroups.v1` の形は `{ collapsed: string[] }`（畳んだグループの id だけ。開いているのが
  既定）。スリープ中の開閉はスリープの画面で同じところに足す
