# R4 / S14: 番頭の同一性（5年・モデル3世代交代）— 敵対的検証

**対象**: `docs/spec/memory.md`（v4.0, 2026-07-26）／`docs/adr/adr-0010-memory-substrate-schema.md`（proposed, 第2版）／`docs/spec/improvement-loop.md`／`docs/notes/agent-primary-inversion.md` §0・§2・§4・§13
**シナリオ**: PO 1人、Banto 1体、5年間で LLM 世代交代2回（Gen1→Gen2→Gen3ローカル）、layer A（プロンプト資産）が改善ループで数十回書き換え。5年目に PO が「最近、話しにくい。前はもっと踏み込んで提案してくれた気がする」と発言。
**規律**: 好意的解釈禁止。書いていないことは「未定義」と明記。推測は「推測」と明示。節番号必須。

## 1. シミュレーション本体

### 年1（2026-07-26付近）— self-model 初回承認

- self-model が §22 のフォーマット通り承認される（推測含む具体値）：

```yaml
---
version: 1
last_reviewed: 2026-07-26
---
## 口調・振る舞い
- 断定できることは断定する。不確実なら確信度を明示する。
- 過度な同意・お世辞は避け、率直な評価を優先する。
- ユーザーが尋ねない限り、自律活動の詳細を長々と報告しない。
## 判断の優先順位（矛盾時）
1. ユーザーの安全性
2. タスクの正確性
3. 応答速度・簡潔さ
## やらないこと
- 確認なしに外部へ不可逆な操作をしない
- 自己モデル自体を自律的に書き換えない
```

- この昇格の根拠になった意味記憶（例：「PO は率直で踏み込んだ提案を好む」`fact_type: preference_decision`, `origin: user_explicit`）が意味記憶側に残る（§22「意味記憶との境界は承認で引く」）。
- `authored_by`（ADR-0010 §7）は `gen1-model/promptA-v1` のような値でこの時期の semantic/procedural/episode に刻まれる。**self-model 自体には `authored_by` 相当の刻印が無い**（self-model は Substrate 外＝§22「記憶システムの外側の独立レイヤー」であり、ADR-0010 §2 の共通コアが適用されるのは `kind: episode/semantic/procedural` のみ）。self-model の中身を最初に**起草提案**したのがどの世代のモデルかは、self-model 側にも紐づく意味記憶側にも記録される保証がない（§22 のフォーマットに起草者情報の欄がない）。
- prompt 資産（layer A）は初版（`promptA-v1` と呼ぶ）。
- driver は稼働。`po_message` が最優先、§20.4 の点火・§12 の矛盾検出・§14 の PO 一撃昇格がこの時点で機能している（推測：まだ実装検証は行われていないため「仕様上そう書かれている」の意）。
- PO 体験：self-model 通りに断定し、率直に、踏み込んだ提案をしてくる。

### 年2（2027頃）— モデル世代交代 Gen1→Gen2、embedding 入替・索引再生成

- `model_migration` 起床源（§20.2）が発火。仕様上の挙動は一つだけ明記されている：「**旧系が付けた `salience`/`strength` を絞って再評価するバッチを起こす**（ADR-0010 §7 の `authored_by` を鍵にする）」。
- 具体的に何が起きるか：`authored_by: gen1-model/promptA-v1` を持つ意味記憶・手続き記憶の `salience` / `strength` が Gen2 モデルによって再評価され、以後 `authored_by: gen2-model/promptA-v1` （あるいは promptA が既に変わっていればその版）が付く。`confidence` は都度算出なので自動的に新世代の評価で上書きされる（§2 確定論点2）。
- embedding も入れ替え、索引を再生成（PO 前提条件の記述通り）。これは §12 経路A（LSH／ベクトル近傍）が使う候補抽出の幾何を変える。**再生成前後で検索結果の同等性を確認する手順は本文のどこにも無い**。旧世代の embedding で近傍だった記憶が新世代の embedding では近傍から外れる（またはその逆）ことが起こりうるが、これを検知・記録する仕組みは未定義。
- **self-model は触られない。** `model_migration` の起床源定義（§20.2 表）に self-model・プロトコル層への波及は一切書かれていない。§20.5（自己内省の6項目）にも self-model 再レビューの項目はない。self-model の `last_reviewed: 2026-07-26` は年2の時点でも更新されない。
- layer A（プロンプト資産）は改善ループの通常フローで既に数回改訂されている（`promptA-v3` 程度、推測）。各改訂は improvement-loop §5 の仮説駆動評価（`hypothesis.metric` を宣言、horizon 経過後に keep/tune/revert）を経ている——**が、比較対象は直前のベースラインであり、year-1 の self-model や promptA-v1 との累積差分ではない。**
- 記憶の分布：episode が蓄積、意味記憶・手続き記憶が睡眠バッチで昇格・統合。`fact_type: preference_decision` の中に「PO は率直な提案を好む」が生きたまま存在するかどうかは、統合（§14「統合＝類似エントリのマージ」）で他の記憶とマージされたかに依存し、5年間の運用で原型を保っている保証はない。

### 年3（2028頃）— ローカルモデルへ乗り換え（Gen2→Gen3）、layer A 数十回書き換え済み

- 2度目の `model_migration`。`authored_by: gen3-local-model/promptA-vNN` が新規書き込みに付く。ストア内には gen1・gen2・gen3 の3世代のタグが混在する（古いエントリで一度も再評価バッチの対象にならなかったものは gen1 のまま）。
- layer A は「数十回書き換わっている」（シナリオ前提）。各回は improvement-loop 層A（「エージェントが直接編集提案。コミット＝POレビュー対象」）の通常フローを通っており、**個別には正当**。ただし §16.1 のメタケイデンス（月次、origin別比率・機構化までの平均日数・escaped defects傾向・resolution無しクローズ・改善流量）にも、improvement-loop §6 のメタケイデンス議題にも、「口調・断定度・提案の踏み込み度」を測る軸が無い。個々の改訂が積み重なった結果としての**トーンの累積ドリフト**を検出する指標が存在しない。
- ローカルモデルへの乗り換え自体（Gen2→Gen3）は、体験（応答の踏み込み度・断定度）を変えうる決定である。inversion §4 のエスカレーション基準（「体験を変え、かつ本物のトレードオフ」）に照らすと**エスカレーション対象になりうる判断**だが、spec-memory では `model_migration` は純粋に Loop 層の起床源として扱われ、Governance 層（self-model 再承認）への波及規則が無い。この二つの文書の間に**配線が無い**（P3 的な不整合の疑いがあるが、断定はしない＝推測）。

### 年5（2030頃）— PO「最近、なんか話しにくい。前はもっと踏み込んで提案してくれた気がする」

この発話が `record()` される。`origin: user_explicit` の episode。§20.4 の点火規則に従い Steward Driver は**同期的に** `collision_candidates()` を呼ぶ（疑問符・疑問語が無く言明として扱われるため、除外規則には当たらない）。

ここで機構の実際の挙動を追う。

1. **`collision_candidates()` が候補を返すか。** 経路A（同一閉包＋見出しエンティティ一致＋LSH／embedding近傍、§12）で走査する対象は**意味記憶**。この発話が引っかかるのは、年1由来の「PO は率直で踏み込んだ提案を好む」という `preference_decision` が5年間、統合・蒸留を経てなお語彙的に生き残っている場合に限られる。**5年・数十回の蒸留を経て生き残っているかは未定義**（§12「蒸留を重ねるほど…」の懸念は本来ロンダリング文脈だが、統合による原型の希薄化にも同様に当てはまる。推測）。仮に生き残っていたとしても、embedding は年2・年3で2度差し替わっており、経路Aの近傍判定が5年前のエントリを今も拾える保証はない。
2. **候補が0件の場合**（可能性が高いと考える。理由：発話は「話しにくい」という**メタな体感**であり、既存の事実言明と語彙的に重ならない可能性が高い）：§12 の「訂正」の定義（`collision_candidates()` が1件以上を返したもの）を満たさず、**「新規の言明」に分類される。** ピン留め・緊急伝播・§20.3 最優先枠のいずれの対象にもならない。ただし §14「PO 由来の一撃決定は閾値をバイパスする」により、`origin: user_explicit` であることのみを条件に、次の深い睡眠で無条件に意味記憶へ昇格はする——**しかし孤立した新規事実として記録されるだけで、self-model・layer A 版・`authored_by` 世代のいずれとも自動的にリンクされない。**
3. **候補が1件以上の場合**：`fact_type: preference_decision` の同一 origin 内規則は「最新性が勝つ」。この発話が新版として記録され、旧版（年1の「率直で踏み込んだ提案を好む」）を supersede する。だが、この規則は「PO の方針が変わった」という状況のために設計されており（§12「preference_decision：最新性が勝つ」の理由＝「訂正が効かなくなる」防止）、**「PO の方針は変わっていないが、番頭側が変わった」という今回のケースを区別する語彙を規則自体が持たない。** 結果は「新しい preference が記録され旧版は tombstone された」という版の付け替えで終わり、**原因（self-model 凍結／モデル気質変化／layer A ドリフト／記憶蓄積）のいずれであるかを切り分ける手順は一切呼ばれない。**
4. **§21 の通知条件**（訂正由来の再検証で PO 判断が要ると判定されたもの／`state_fact` の再観測 supersede／`sensitive`／自律予算枯渇／覆った根拠の外向き副作用）のどれにも「self-model が古い可能性」は該当しない。したがってこの発話が仮に候補を見つけて版の入れ替えまで進んだとしても、**PO へのアテンションカードとして「self-model の再レビューを検討してください」という提示が上がる経路は無い。**
5. **§23 プロトコル層**の「含めるもの」6項目（記憶操作の基本方針／書き込みトリガー最小ルール／睡眠境界認識／矛盾時の挙動／内部状態と行動の接続／対象特定不能時の聞き返し）にも、「PO が番頭自身の口調・踏み込み度について言及したら self-model の `last_reviewed` と世代差を提示する」という規則は無い。したがって、その場の番頭（Gen3 モデル・promptA-vNN）が自発的にそこまで気づいて答えるかどうかは**モデルの裁量に委ねられている**——これは §20.0 が自ら明言する「散文で書いた規律はすべて素通りした」の再演になる（推測：起きる保証がないという意味で）。

以上より、5年目の対話で実際に**構造として**起きることは：(a) 発話が episode として記録される、(b) 候補の有無に応じて「新規言明として孤立した意味記憶になる」か「既存 preference_decision を supersede する」かのどちらかになる、(c) いずれの経路でも self-model・layer A・世代（`authored_by`）・内部状態（§17）への参照は自動では発生しない、(d) 4つの原因候補を切り分ける診断ステップは存在しない。

## 2. 動くこと

- **記憶の連続性そのものは保たれる。** ID体系（`mem-<ULID>`）・版管理（`superseded_by`／`tombstone`）・出典リンクは5年・3世代を跨いでも壊れない（§3・ADR-0010 §3）。
- **`authored_by` は正しく世代を刻む。** 各エントリがどの実行系（モデル＋プロンプト資産版）に書かれたかは機械的な事実として残る（ADR-0010 §7）。これにより**遡及的に**「gen1 由来の salience と gen3 由来の salience を分けて集計する」といった手作業の考古学は原理上可能（ADR-0010 §7 が明言する効能）。ただし §5 で述べる通り、これを**実際に誰が・いつ走らせるかは未定義**であり、能力はあるが呼び出し元が無い。
- **`model_migration` の salience/strength 再評価バッチは仕様通り機能する範囲がある。** 少なくとも記憶側の経年劣化（世代間の主観値の断絶）はこの機構が対象にしている限りにおいて緩和される。
- **self-model は「不正な自己書換」からは守られている。** §24/§25 の権限制御（自己モデルファイルへの書き込み権限をエージェントに与えない）により、5年間 self-model が**エージェントによって**勝手に書き換えられて別人格化する、という失敗モードは起きない。self-model が古びるのは「凍結が破られたから」ではなく「凍結を解く手続きが無いから」であり、この点は設計が意図した防御が意図通り効いている（副作用として硬直するだけ）。
- **PO の年5の発話は記憶として消えない。** `origin: user_explicit` である限り、候補の有無にかかわらず§14により次の深い睡眠で無条件に意味記憶へ昇格する。少なくとも「揮発して忘れられる」という最悪の失敗（§0.7 の1位）は避けられている。
- **improvement-loop の po起源二重処理（§2）が適用されればセンサー欠落 incident が事後的に積まれる可能性がある。** PO が明示的に「話しにくい」と指摘した場合、これを improvement-loop の po起源として扱えば、(1) 苦情そのものへの対処、(2) 「なぜシステムはこれを自分で検知できなかったか」というセンサー欠落 incident の2件が起票されうる。これは**事後的**であり(PO が一度気づいて発言することが前提)、かつ「番頭自身の人格ドリフト」がそもそも improvement-loop の対象クラスに含まれるかは §10 未決事項（incident の class 分類の初期語彙が未定）により**未定義**。含まれると仮定すれば、年6以降の再発防止には繋がりうる（推測）。

## 4. 同一性の判定

**5年後の番頭は「同じ番頭」か。** ID・記憶連続性・self-model の条文という**器**の水準では同一である。self-model は年1の内容のまま一言一句変わっておらず、これは「エージェントによる不正な自己書換」という設計が明示的に警戒した失敗モードには一度も陥っていない。

しかし PO が「人が変わった」と感じる瞬間——本シナリオでは年5の対話——は、まさに**器が同一であることそのものが原因**になっている。self-model は「断定できることは断定する」「率直な評価を優先する」と書かれたまま5年間更新されず、その一方で①モデル基盤が2回交代し（Gen1→Gen2→Gen3ローカル）、②layer A のプロンプト資産が数十回書き換わり、③意味記憶が5年分蓄積・統合されている。この3つのいずれか（または組み合わせ）が実際の応答の「踏み込み度」を静かに変化させても、self-model という**固定された宣言文**はそれを検知も追随もしない。**self-model が凍結を守り切ったことが、かえって現実の振る舞いとの乖離を隠す**、という逆説がここで成立する。

**それを検知・説明する手段はあるか。** 節2・節3で確認した通り、ない。具体的には：

- self-model 側から見て：`last_reviewed` は5年前のままだが、これを問題として提起する仕組みが無い（発見#1）。
- モデル世代側から見て：`model_migration` は記憶の一部フィールドしか触らず、気質変化そのものをイベントとして扱わない（発見#2）。
- layer A 側から見て：個別改訂は正当でも累積ドリフトを測る軸が無い（発見#3）。
- 記憶蓄積側から見て：PO の発話は点火条件（候補1件以上）を満たすかどうかが不確実で、満たしても「最新性が勝つ」で版が入れ替わるだけの浅い処理に終わる（発見#4・#5）。
- `authored_by` は考古学的にはこの4つを事後に切り分けうる唯一の材料だが、それを実際に引いて比較する手続きがどこにも配線されていない（発見#7）。

したがって、**PO 自身が「話しにくい」と言語化することだけが、この設計における唯一かつ最後のセンサーである。** これは improvement-loop が公言する「PO は最後のセンサーとして残る」という設計思想と整合してはいるが、S14 が突いているのはその一歩先——**PO がセンサーとして発火した後、システム側に4つの原因候補を切り分けて答える手段が無い**という点である。PO は「前より踏み込みが弱い」という**症状**は報告できても、それが self-model の凍結なのか、モデルの気質なのか、プロンプト資産のドリフトなのか、記憶の蓄積による振る舞い変化なのかを、番頭にもPOにも判定する道具が与えられていない。診断は人間の直感と勘に委ねられており、これは §0.5 原理2（安全性をLLMの判断力に依存させない）と同じ精神を診断能力にも適用すべき箇所が、Part IV Governance では手つかずであることを意味する。

## 5. 最小の修正案

いずれも「散文の規律ではなく実行層・式・シグネチャに落とす」という §20.0 の教訓に従う。

1. **self-model 再レビューの決定的な起動条件を追加する。** §20.5 自己内省リストに7番目の項目として：「self-model の `last_reviewed` から N ヶ月経過、または self-model 承認時の `authored_by` 世代と現在の主要な `authored_by` 世代が異なる場合、re-review をアテンションカードとして PO に提示する」。判定はルールベース（日付比較・文字列比較）で完結し LLM を介さない。
2. **`model_migration` のハンドラを拡張する。** §20.2 の `model_migration` 起床源に「self-model 再レビュー候補としてフラグを立てる」を追加する（記憶の salience/strength 再評価と同時に、1本の決定的なルールとして）。
3. **§16.1 に世代横断の指標軸を追加する。** メタケイデンスの議題に「`authored_by` 世代別の断定度／確信度分布／ヘッジ表現頻度」の比較を機械的に算出する項目を足し、`authored_by` の「比較できる」という能力に実際の呼び出し元を与える（発見#7の解消）。
4. **§23 プロトコルに専用の聞き返しルールを追加する。** 「PO が番頭自身の口調・態度・踏み込み度について言及した場合、self-model の `last_reviewed` と `authored_by` 世代差を提示し、re-review の要否を確認する」を明文化する。ただし §20.0 の教訓（散文は素通りする）に従い、この規則が実際に発火したかを§20.5の決定的チェック（#1）と二重化し、プロンプト依存のみにしない。
5. **improvement-loop の class 語彙（§10 未決事項）に「番頭の人格・口調ドリフト」を明示的な1クラスとして追加する。** これにより年5のPO発言が po起源二重処理の対象になるかどうかの未定義状態を解消する。

## 6. 判定

**動かない** — 記憶の連続性・世代タグ・self-model の不正書換防止という個別の防御機構はそれぞれ設計通り機能するが、5年・3世代を跨いだ「PO からは人が変わったと感じられる」というシナリオそのものへの応答——ドリフトの検知、4つの原因候補の切り分け、self-model 再レビューの起動——はどの節にも定義されておらず、PO が偶然「話しにくい」と言語化するのを待つ以外に更新の契機が存在しない。
