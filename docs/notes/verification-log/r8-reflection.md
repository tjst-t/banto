### §11「顕著性」と ADR-0010 §2 の不整合（A の追加検査項目）

`spec-memory` §11 は顕著性の第4成分を次のように定義している（`docs/spec/memory.md:955`）：

> 4. **文脈一致度** — 実行文脈（**context フィールド**）の一致。3とは独立した軸

これは ADR-0010 §2 が確定させた「`context` の他キーは開いた任意の検索用特徴量であり、Substrate は値域を規定しない。可視範囲を決めるのは `scope`（閉包識別子）だけ」という区別を反映していない。「`context` フィールドの一致」という言い方は、`context` が単一の比較可能な値であるかのように読め、初版（`{tool, project, repo, mode}` の固定キー集合を単純比較する設計）当時の記述のまま残っている。**「一致」を何に対して測るのか（`scope` の祖先関係か、開いたキーの部分一致か）が §11 のどこにも定義されていない。**

`spec-memory` 冒頭の「Substrate の反映（ADR-0010 → 本文）は 2026-07-26 に完了した」という一文（`docs/spec/memory.md:46`）は §2・§3・§4・§12・§7-F1・§26 を列挙するが **§11 を含んでいない**——つまり文書自身も §11 を「直した」とは主張していない。しかし §27 の残件一覧（U1〜U24）にもこの項目は無く、**「直していない」ことが残件としても追跡されていない**。「完了した」という総括の直後に、直っていない箇所が残件表にも載らずに埋もれている。

**判定：未反映（かつ未追跡）。**

## B. 他ADR・ノートの反映漏れ

### ADR-0008（1プロジェクト＝複数リポジトリ）

`spec-memory` §26.1 の閉包識別子の例は `repo:banto-web`（ハイフン区切り、プロジェクト名を含まない）だが、ADR-0010 §2 自身の例は `repo:banto/web`（`proj:banto` の子として repo を示す表記）である。閉包の包含関係はレジストリの `parent` フィールドで持つため識別子の書式自体に矛盾はないが、**同一の概念に対して ADR と spec で異なる例示表記が使われている**。実害は無いため C ではなく参考記録として本節に留める（`slug` に埋め込む意味を持たせるなという §26.1 自身の規律に照らせば、`banto/web` のような合成表記は本来避けるべき例だった可能性がある——推測）。

ADR-0008 自体（primary repo が契約層を持つ、リポジトリ跨ぎ参照は `<project>/<repo>/id`）と §26 の閉包モデルの間に、直接の矛盾は見つからなかった。**判定：整合（軽微な例示表記の不統一を除く）。**

### ADR-0009 / agent-primary-inversion ノートの決定

- **語彙（Banto/Quirefold/Kobo/Worker Pool）**：`spec-memory` 全体で一貫して使用されている。`daemon` という語は frontmatter の `refs: [..., spec-daemon-core, ...]` という他文書ID参照にのみ残り、本文中の誤用（カタカナ「daeモン」等）は無い。**判定：反映済み**。
- **サブシステム汎用I/F（kick / query surface / command surface / surface provision）**：`kick` は `subsystem_kick`（§20.2 起床源）として反映。`query surface` は §20.4 の `state_fact` 観測手段表に1箇所のみ登場（`docs/spec/memory.md:1599`）。`command surface` および `surface provision`（GUI）は `spec-memory` 本文に一度も登場しない。**判定：部分反映**。ただし `command surface` は番頭→daemon の書き込みI/Fであり memory サブシステムの管轄外、`surface provision` は「会話／アテンションキュー／Memory 面」という具体化された提示面の語彙（§20.7.1）に置き換わっているため、実質的な欠落ではなく語彙の解像度が違うだけと見える（**推測**）。
- **決定①（Kobo と Quirefold の完全分離・ブリッジなし）**：`spec-memory` 本文・`spec-memory-contracts` 本文のいずれにも「完全分離」「ブリッジなし」という語も、「daemon（Kobo）側から Quirefold を読む手段は持たない」という制約文そのものも**一度も再掲されていない**（`grep` で0件）。この制約は agent-primary-inversion.md §11.6-① と ADR-0010 の文脈節にのみ存在する。**判定：ノートと ADR にのみ存在し、spec 本文には反映されていない。** 実務上の影響：`spec-memory` 単体を読む実装者は、「Kobo のログを episode にミラーしない」という原則（および §27 **U16** がこの原則の例外として存在すること）の**根拠**を spec 側からは辿れず、ADR-0010 の文脈節まで遡らないと分からない。
- **決定②（Banto ハーネス自作＋プラガブルLLM層）**：`spec-memory` §0.2／§0.3.2 に反映済み。`spec-memory-contracts` §0.3.2 にも反映済み。**判定：反映済み**。
- **P(番頭-1)〜P(番頭-3) などのノート限定の principle 候補**：`agent-primary-inversion.md` §9 に「候補の記録」として明記されており、ノート自身が「principles.md 変更は ADR 経由」「正式化は統合後」と述べている。spec-memory に反映されていないのは正しい状態（正式化フェーズ未着手であることが明記されている）。**判定：問題なし（意図された未反映）**。

### ADR-0009 の `status: proposed` と spec-schemas enum の不整合の追跡

`spec-schemas` §3 の adr type の `status` enum は `draft` / `accepted` / `superseded` の3値であり `proposed` を含まない。ADR-0010 冒頭の補足注記（`docs/adr/adr-0010-memory-substrate-schema.md:17`）はこの不整合を自己申告し、「ADR-0009 は依然 `proposed` のままなので、そちらは正式化フェーズで解消する」と明記している。**判定：追跡済み（ADR-0010 側のみ。ADR-0009 自身にはこの自己言及が無いが、正式化フェーズ待ちとして扱われており実害は無い）**。

## C. リファクタで壊れたもの

**すべて本セッションの `git diff HEAD` で確認した、今回の編集そのものが持ち込んだ不整合。**

### C1.【最重要】「正典の地図」表が §27 の実際の内容と食い違う

本セッションで新設された「正典の地図」表（`docs/spec/memory.md:19`）は次のように書く：

> | 未解決の残件 | 本書 **§27**（U1〜U20） |

しかし §27 は同じセッションの別の編集（付録A.2 の4項目を §27 へ移設）によって **U1〜U24** まで拡張されている。実際、`docs/spec/memory.md:2034`（同じく本セッションで書かれた付録Aのポインタ表）は正しく「**§27 の U1〜U24**」と書いており、**同一ドキュメント内の2箇所が、同じセッションの編集によって食い違ったまま残っている**。「正典の地図」表は文書冒頭にあり読者が最初に見る場所であるため、実害は小さくない。

**修正案**：`docs/spec/memory.md:19` を「本書 §27（U1〜U24）」に直す。

### C2. §2 共通コアの直後に、内容がほぼ重複する2つの blockquote が並んでいる

本セッションは `docs/spec/memory.md:222-224` に次の blockquote を新設した：

> **[ADR-0010] §1 が正典であり、本節はその反映である。** 各フィールドの決定理由は ADR を見ること（…）。
>
> **2026-07-26 に凍結済み。** フィールドを足すには ADR の supersede を要する（ADR-0010「凍結」節）。

その直後（`docs/spec/memory.md:226`、本セッションでは変更されていない既存文）に：

> **本節の一覧は ADR-0010 §1 が正典である。** 上記は反映であり、食い違う場合は ADR-0010 が優先する（P3）。**2026-07-26 に Substrate は凍結された**（ADR-0010「凍結」節）。以降フィールドを足すには ADR の supersede が必要である。

両者は「ADR-0010 §1 が正典」「2026-07-26 凍結」「フィールド追加には supersede が要る」という**同じ3点を独立に主張している**。新設した blockquote は各フィールドへの節番号対応という追加情報を持つため上位互換だが、**既存の重複する blockquote が削除されずに残った**。本書が随所で掲げる「同じことを2箇所に書かない（D3）」という規律に、本書自身の編集がこの箇所で反する。

**修正案**：`docs/spec/memory.md:226` の blockquote を削除する（新設した方が情報量で上回るため）。

### C3. §27 が「本書全体が対象」と自称しながら「Part IV — Governance」の下に位置する

§27 の見出しは「未解決の残件【本書全体が対象。ここが唯一の正典】」（`docs/spec/memory.md:1965`）であり、§20.8 から移した理由も「駆動系の残件ではなく**本書全体**の残件を扱うので、§20（driver）の下にあるのは誤配置だった」（同 1969行目）と明記している。しかし文書には「# Part V」のような区切りが無いため、§27 は見出し階層上いまも「# Part IV — Governance」（`docs/spec/memory.md:1782`）の配下にある。§26（閉包レジストリ、Part IV に置く理由が明記されている）と地続きに続いており、**「駆動系の下」という誤配置は解消したが「特定 Part の下」という同種の誤配置は解消していない**。

**判定**：軽微。参照切れや実害のある矛盾ではないが、移動の動機（「本書全体を扱うのに一部の下に置くのはおかしい」）に照らすと不徹底。

### C4. 付録Aのポインタ化で失われた記述（旧 A.1 の一部）

`docs/spec/memory.md` の付録A書き換えは「旧 A.1 は §0.9 と重複していたので削除した」（`docs/spec/memory.md:2037`）と主張する。`git diff HEAD` で旧 A.1 の全文を確認すると：

```
### A.1 実験でしか決まらないもの
1. 参照検出の信頼性（最優先）
2. 蒸留の品質、虚偽記憶の発生率、確信度算出の妥当性
3. 内部状態が意図通り行動を変えるか、他指示との優先順位の安定性
4. 全パラメータの具体値（…）
5. 関連度スコアが埋め込みだけで足りるか、LLM判定が要るか（形は §8.5.2 で決着——残るのは「A3 をいつ入れるか」の閾値）
6. 話題転換検出の閾値
```

現行 §0.9 は「蒸留の品質」「参照検出の信頼性」「内部状態が行動を変えるか」「全パラメータの具体値」の4項目に絞られている。突き合わせると：

- 項目1・4・6・7 は §0.9「全パラメータの具体値」に包含できる（実害なし）。
- 項目5 の残余（「A3 をいつ入れるか」の閾値）は §27 **U18** に対応先があり、消えていない。

**修正案**：「確信度算出の妥当性」は §16 の評価指標か §0.9 に、「他指示との優先順位の安定性」は §17 の「実際のブラックボックス性の所在」の記述に紐づけて残すか、対応が無いことを承知の上での削除であると明記する。

## D. 検証プロトコル §2.4 の7分類での通常の配線チェック

本セッションの差分は主にテキストの追加・移設であり、新しい機構・新しい規則を導入していない（内容の反映と再配置が中心）。したがって7分類のうち大半は「新設なし」に該当し、指摘は C 節で挙げた項目に収斂する。分類ごとの結果を機械的に記す。

| # | 分類 | 結果 |
|---|---|---|
| 1 | 配線レジストリ（§20.7.1）の各欄が本文に定義されているか | 本セッションでは §20.7.1 の行を変更していない。**対象外** |
| 2 | レジストリに未登録の機構が本文にあるか | 本セッションは新しい機構を追加していない（既存記述の移動・ADR反映のみ）。**対象外** |
| 3 | 宙ぶらりんの参照（「§X に規定」と書いてあるが無い） | **C1 で検出**（「正典の地図」の §27 範囲表記が実態と不一致）。他に `§20.8` への生き残り参照は無いことを確認済み（`grep -rn "§20\.8" docs/spec docs/adr docs/notes/agent-primary-inversion.md` は0件。検証ログ内の歴史的言及のみ残る） |
| 4 | 能力はあるが呼び出し元が無いもの | 該当なし（新規フィールド・新規APIの追加が無いため） |
| 5 | 検出はするが対応が無いもの | 該当なし |
| 6 | 層をまたいで配線されていないもの | 該当なし |
| 7 | 相互に矛盾する2つの記述 | **C1・C2 で検出**（U番号レンジの食い違い、および内容が重複する2つの blockquote） |

## 総括

**未反映・食い違いが複数見つかった。最も重い順に：**

1. **【C1・食い違い】** 文書冒頭の「正典の地図」表（`docs/spec/memory.md:19`）が「§27（U1〜U20）」と書くが、§27 の実体は同一セッションの別編集で **U1〜U24** に拡張済み（`docs/spec/memory.md:2034` は正しく U24 と書いている）。同じ diff の中で矛盾が生まれている。
2. **【A・未反映】** ADR-0010 帰結の「手続き記憶の実体は SKILL.md を**版付きパス**（`skills/<name>/v<N>/SKILL.md`）に置く」という規定が `spec-memory` §14 に一切反映されていない。`skills/` というパス表現は spec 全文に一度も出現しない。
3. **【A・未反映かつ未追跡】** `spec-memory` §11 の「文脈一致度」定義（`docs/spec/memory.md:955`）が ADR-0010 §2 の `scope`／`context` 分離以前の「context フィールドの一致」という初版の書き方のまま残っている。文書自身の「Substrate の反映は完了した」という総括（`docs/spec/memory.md:46`）は §11 を対象に含めておらず、かつ §27 の残件表にもこの穴は載っていない——**直っていないことが記録上どこからも辿れない**。
4. **【C2・D3違反】** §2 のスキーマ直後に、ほぼ同一内容を主張する blockquote が2つ連続している（`docs/spec/memory.md:222-226`）。本セッションが新設した方が上位互換であり、既存の方を消し忘れている。
5. **【B・ノート限定】** 「Kobo と Quirefold は完全分離・ブリッジなし、daemon 側から Quirefold を読む手段を持たない」という決定①の規範文そのものが `spec-memory` 本文に一度も再掲されていない。ADR-0010 の文脈節と agent-primary-inversion.md にのみ存在し、spec 単体からは根拠を辿れない。
6. **【C4・記述喪失】** 付録A整理で「§0.9 と重複」として削除された旧 A.1 のうち、「確信度算出の妥当性」「他指示との優先順位の安定性」の2点は実際には §0.9 にも §27 にも対応が無く、単純に消えている。
7. **【C3・軽微】** §27 が「本書全体が対象」と自称しながら見出し階層上は依然として「Part IV — Governance」の下にある。§20.8 からの移動理由（駆動系の下は誤配置）と同型の問題が Part 単位で残っている。

上記以外の ADR-0010 各決定（§1・§1.2・§1.3・§2.1・§2.2・§3・§4・§5・§7・§8・§9・§10・凍結節）、ADR-0008 との整合、ADR-0009/inversion ノートの語彙・決定②・決定①（存在の有無を除く）、および通常の配線チェック7分類のうち4〜6は、**反映済み・整合・問題なしを確認した**。
