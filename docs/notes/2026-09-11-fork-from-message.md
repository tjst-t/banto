# 発言の下から枝を分ける（2026-09-11、ユーザー要望）

> 「このメッセージの下のコピーボタンですが、テキストの左端にそろえるように
> してください。あとコピーボタンの右に、Forkボタンを入れてほしいです。その
> Forkボタンを押すと、そのメッセージの時点から分岐できるようにしてほしい。
> これは、BaseThreadでclearした後に、clearする前のセッションのForkも作ることが
> 可能にしてほしい。」

決まったことは `docs/specs/v4-architecture.md` §2.2 と
`docs/specs/v4-frontend.md` §6.12。ここには**なぜそうしたか**を残す。

## 「その時点のセッション」をどこから引くか

Thread は `resumePoint` を**1つしか**持たない（いまの続き）。過去の発言から
分けるには、その時点のセッションが要る——**いつどのセッションだったかの履歴**
（`ThreadState.resumePoints`）を残すことにした。記録（Event Store）には
`thread.resume_point_updated` が全部残っているので、**新しい事実を足したのでは
なく、射影に持ち方を足しただけ**（規則3）。

**Clear の前から分けられるのは、この履歴のおかげ。** Clear は
「次のターンで resume-point を渡さない」だけで、手放したセッションの id は
記録に残っている——だから畳んだ後でも、畳む前のやり取りの続きを別の枝として
始められる（要望の核心はここ）。

## 分けた後の親のやり取りを、枝に持って行かない

Fork は分岐時点の親の会話を引き継ぐ（2026-09-04 の決定）。過去から分けるときは
**そこまで**にした——分けた後のやり取りが枝の会話に混ざると、「その時点から
始めた」ことにならない。Clear の横線も同じ扱い（分けた位置より後のものは入らない）。

## 位置が分からない発言には、ボタンを出さない

分ける位置は host の物差し（seq）で、画面では `real-<seq>` という id として
持っている——**記録から組み直した会話だけが持つ**。いま走り終わったばかりの
発言は持たないので、そのままでは出せない（規則13）。

ただし**会話の最後の発言**は「いまの続きから分ける」と同じ意味なので出す。

## 畳んだら、記録から組み直すことにした（ついでに直った不具合）

Clear の直後に「畳む前の発言」から分けようとすると、**その発言が位置を
持っていない**ため出せなかった。組み直せば持つ——そこで Clear の後に
（走行中でなければ）記録から組み直すようにした。

実測すると、**Clear の横線も会話の中に出ていなかった**（入力欄の上の帯にだけ
出ていた）。横線は `real-<seq>` を鍵に「起きた場所」へ差し込む仕組み
（§6.4 transcriptMarkers、2026-09-04）なので、鍵が無ければ差し込めない
——同じ原因だった。組み直しで両方直った。

**走行中は組み直さない**——流れている表示を壊す（`turn-stream-reattach` の
実装で踏んだのと同じ罠、2026-09-10）。

## 残っている穴（記録）

**走行中に Clear した直後**だけは組み直さないので、そのとき画面に出ている
発言は位置を持たない。最後の発言から分けると「いまの続き＝新しい会話」に
なる（畳んだ直後なので resume-point が無い）。開き直せば記録から組み直されて
正しく分けられる。
