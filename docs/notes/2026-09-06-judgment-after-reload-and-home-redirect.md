# リロードすると承認が出せなくなる／E2Eが後ろのspecから落ちる——2つの別々の不具合

2026-09-06、ユーザー報告「実インスタンスで承認を出させようとしたが、うまく出なかった」
から始まった調査。**別々の原因が2つ**あった。

## 1. リロードすると、生きている判断待ちに誰も答えられない

実インスタンス（4737）を見ると、**host側には判断待ちが生きたまま残っていた**
（08:16 の1件と、07:48 の別Threadの1件）。つまり承認要求は正しく発生していて、
画面に出ていなかった。

### なぜ

ターンのイベント列（SSE）は `POST /api/threads/:id/messages` の**応答の中にしか
無い**。再接続の口が無いので、ページを読み直すとその走行の出力はUIから切れる。
一方hostは `canUseTool` の hold-the-line で止まったままなので、判断待ちは生き続ける。
このとき：

- 会話の画面には何も出ない（復元されるのは記録済みのテキストだけ）
- 受信箱には**答えるUIが無い**（§2.4「答えるのはThread側の1箇所」という決定）

——結果、**誰も答えられないまま止まる**。§2.4 の決定は「Thread側にカードが必ず
ある」という前提で書かれていて、その前提がリロードで崩れていた（規則8として
ユーザーに上げ、「Threadを開いたら復元する」を選んでもらった）。

### 直し方

`ThreadPanel` が、**走行中のrunが無いThread**を開いたとき、host側で生きている
判断待ちをカードとして描き直す（`restoredJudgmentMessages`）。答え先は同じ
`/api/inbox/:id/answer` なので、これだけで止まっていたターンが動き出す。

答えたあとの続きはこのブラウザには流れてこないので、hostの記録から取り直して
画面に入れる（`syncRestoredThread`——2秒ごとに `GET /api/threads/:id` を見て、
伸びなくなるまで差し替える）。`useLocalRuntime` は `initialMessages` を作成時に
しか読まないので、復元の増減と取り直しの回数を `key` に入れて作り直す。

回帰は `e2e/specs/judgment-after-reload.spec.ts`——リロード→カードが戻る→答える
→**hostが記録した返事の本文そのもの**が画面に出る、まで見る（規則14）。

## 2. E2Eが「後ろのspecほど落ちる」——ホームの自動リダイレクト

上を直した後、8 specを通すと**毎回1〜3件落ちる**ようになった。落ちるspecは毎回
違い、症状はいつも同じ：`作成する` が押せない（`element was detached from the DOM`）。

### なぜ（測って分かったこと）

- 並列を切っても落ちる → 並列は原因ではない
- dev サーバ（2日間動きっぱなしだった）を再起動しても落ちる
- 復元の機能を外すと**むしろ悪化** → 私の変更が原因ではない
- 失敗時の画面を見ると、**先頭Projectのページに移っていた**

`/` は実Projectの読み込みが終わると先頭のProjectへ自動で移る
（`home-content.tsx`）。**`/` と `/p/[id]` はそれぞれ別の `AppShell` を持つ**ので、
この移動でトップバーが作り直され、開いていた「新しい Project」ダイアログが
**入力ごと消える**。Projectが増えるほど読み込みが伸びるため、**後ろのspecほど**
この競走に負けていた。

これは製品側の不具合でもある——ホームで新規Projectを入力している最中に、
裏の読み込みが終わると入力が消える。

### 直したこと

- **テスト側**：`e2e/helpers.ts` の `openApp()` で、**行き先が決まりきるまで待って
  から**操作を始める（Projectが有れば `/p/...` へ移り終わる、0件なら空状態が出る）。
  「何秒か待つ」ではなく決着の印で待つ（規則6）
- **製品側**：`home-content.tsx` のリダイレクトを**一度だけ**にした。
  `getActiveProjects()` は毎レンダー新しい配列を返すので、それを `useEffect` の
  依存に置くと**再描画のたびに `router.replace` が走っていた**

### 測った結果

直したあと：**直列 3回 / 並列 5回、すべて 8 spec 通過**（直列 1.1分、並列 48秒。
直す前は直列 2.9〜3.8分で毎回1〜3件失敗）。

### まだ残っていること

`/` と `/p/[id]` がそれぞれ `AppShell` を持つ構造自体は変えていない。
ホームからProject画面へ移るとトップバー・レールが作り直される
——開いているダイアログ・オーバーレイはそこで消える。
`AppShell` を共有のlayoutへ引き上げるのが筋だが、`/canvas-window` は
シェルを持たない等の条件があるので、別途決めて直す（スコープ外・規則7）。
