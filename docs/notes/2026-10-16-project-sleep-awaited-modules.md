# スリープの例外：出来事を待たれている Module とコンテナは止めない（Backlog #357）

2026-10-16。仕様は v4-architecture.md §2.2「出来事を待たれている Module は止めない」（origin/main にある。このブランチの
作業ツリーの §2.2 にはスリープの節がまだ無かったので、そこは書き換えていない）と §4.3「スリープの例外——実装で決めたこと」。

## 実装で決めたこと・その理由

- **止まるもの（sleep-preview）からコンテナと一緒に消えるものを外した**。コンテナを残すと、待たないコマンド（banto-shell-*）と
  Terminal の tmux のセッションは止まらない。仕様は「Terminal の tmux のセッションはコンテナと一緒に消える」としか言っていないので、
  残ることをそのまま画面に出す（「止まります」と並べると嘘になる）。それらを止める道を足すかは決めていない——資源を返すという目的から
  見れば止めたほうがよいが、Shell・Terminal の Module に「全部止める」の管理操作が無い。要るなら人に上げる
- **片づけを1分ごとにも見る**のは、Service を止められなかったとき（別のサーバに繋がらない等）に外さずに残したものを、次のきっかけで
  また試すため。見るのは「繋がっている待たれていない Module があるか」だけで、コンテナの状態は聞かない（Incus を毎分叩かない）。
  コンテナごと止めるのは自動化の台帳が変わったときだけ
- **待たれているかが読めないとき**、起こし直しのときは止めない側、眠らせるときは止める側に倒した。起こし直しは人がいない時間に起きうる
  ので夜中の出来事を落とさない側、眠らせるのは人の操作（またはしばらく開いていない）なので今どおりの側。どちらもログに残す
- **確かめの小窓**は止まるものがあるときだけ出る（今どおり）。Service の Module が待たれていれば何も止まらないので小窓は出ず、
  「一部起きている」はサイドバーの行の印と「…」の理由で分かる

## 却下した案

- 「一部起きている」を記録（Event Store やメモリの印）に持つ——待たれている Module の集合から導出できる（規則3）
- 片づけを `keepAwaitedModulesAwake` の中でやる——起こす道と止める道を1つの関数に混ぜると、眠らせている途中の印と順序が読めなくなる。
  止める側は眠らせる手順と同じ `ProjectSleep` に置き、同じ印を使う
