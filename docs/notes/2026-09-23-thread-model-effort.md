# モデルと reasoning effort を入力欄の下で選べるようにした（2026-09-23）

## 頼まれたこと

「いまプロンプト記入欄の下でエフォートが選べるけど、モデルも選べるようにできないか」。

**入力欄の下にあったのはエフォートではなく permissionMode（`auto`）だった。** モデル・effort の
選択はモックにしか無く、本物では `CONNECTED_FEATURES.composerModelEffort: false` で隠していた
（繋がっていなかった——規則13）。

## 仕様との食い違い（規則8 → 人に上げた）

アーキ仕様 §3 は「**モデルは Project の間ずっと固定——変更＝新しい Project**」と決めていた
（プロンプトキャッシュはモデルごと）。入力欄で選べるようにするとこれを破る。人に3案を出した：

| 案 | 中身 |
|---|---|
| **A（採用）** | Thread ごとに選び、途中でも変えられる。会話が始まった後に変えるときだけ、費用を見せて確かめる |
| B | 最初の送信までだけ選べる。変えたいなら新しい Thread |
| C | 仕様どおり Project 単位（設定画面） |

**A に決まった**（ユーザー、2026-09-23）。§3 を「黙って変えない」に改めた。

## 測ったこと

- **一覧は CLI が答える**：`query()` を発言なしで開き、`supportedModels()` だけ聞く。API は呼ばず
  約0.8秒。返ったのは `default`（Opus 5・1M）・`opus[1m]`・`claude-fable-5[1m]`・`sonnet`・`haiku`
  で、effort の段はモデルごと（Haiku は effort を持たない）。**一覧を自分で持たない**のはこのため
- **effort だけ変えてもキャッシュは効かない**（同じ会話・sonnet）：

  | ターン | effort | キャッシュ読み取り | 書き込み |
  |---|---|---|---|
  | 1 | low | 0 | 8,417 |
  | 2 | low | **8,417** | 54 |
  | 3 | **high** | **0** | 8,534 |
  | 4（haiku へ） | — | **0** | 8,306 |

  だから確かめる画面は「モデル・effort を変えますか」の1つにした

## 形

- host：`thread.model_set`（`{model, effort}`、null は既定）。`POST /api/threads/:id/model`
  （一覧に無いモデル・そのモデルに無い段は 400）、`GET /api/models`（CLI に聞いて10分覚える。
  失敗は覚えない）。ターンは Thread が持つ値を `query()` に渡すだけ。Fork は親の選択を引き継ぐ
- 画面：`ComposerModelMenu`。選んだ値は host の写しを持ち、残せなかったら元に戻して言う
  （permissionMode と同じ形）
- 試験：偽 Runner が `listModels()` を持ち、`sayRuntime` で「どのモデル・effort で走ったか」を
  発言にする——**選べたことではなく、そのモデルで走ったこと**を見る

## 踏んだもの

- **E2E で、選んだ直後にもう一度メニューを押すと開かなかった。** 閉じる途中のメニューに押下が
  吸われる（人の手より速い）。待つのは時間ではなく「前のメニューが閉じ切ったこと」にした
- 自分の書き換えで、その待ちの補助関数の中の `click()` まで置き換えて無限に自分を呼んでいた。
  30秒の観測（段ごとの時刻を出す）で見つけた——フルを回していたら5分ずつ失っていた
