# SubAgent の仕組み——ACP で繋ぐ（2026-09-24〜）

## 頼まれたこと

「SubAgent の仕組みを作りたい。MCP にしてプラガブルにしたい。Claude だけでなく OpenCode や
Codex なども使えるようにしたい。まず実装方針を」。

## 出発点

- 仕様 §4.1：サブエージェントの実行は Subagent Module の持ち物。core は「頼んだ」と「結果の転記」
  だけを知る。backend の差は Module の中に閉じる。**backend の口の具体形が未決**（§10 item 1、最優先）
- 2026-08-30 の実測（`poc/03-item1-backend-interface/`、`opencode run --format json`）：
  streaming・割り込み・文脈の内訳が無かった

## 方針（ユーザーと決めた、2026-09-24）

| 論点 | 決めたこと |
|---|---|
| backend の口 | **ACP（Agent Client Protocol）**。Subagent Module は MCP サーバ＋ACP クライアント |
| サブエージェントの道具 | エージェント自身の tool を **Landlock の中で**。banto の Module は追加で渡す |
| 最初に繋ぐもの | **Claude Code と OpenCode**（Codex はこの2つが通ってから——いま手元に無い） |
| 認証 | **サブスクで使えるものはサブスク、API キーでも使える**（エージェントごとに違う） |
| 待つか | **最初は待つ形**。待たない形は core の「Thread に届ける」口と一緒に後で |

## なぜ ACP か（規則12）

「複数のコーディングエージェントを1つの口で動かす」は解かれている。ACP は Zed が始めたもので、
2026-09-24 時点で Claude（Zed のアダプタ `claude-agent-acp`、Agent SDK の上に載る）・Codex
（`codex-acp`）・OpenCode（`opencode acp`）・Gemini CLI ほか40以上が対応している。

§4.1 の7項目が ACP の口にそのまま載る（`session/update`・`session/cancel`・`session/load`・
`tool_call`・`session/request_permission`）。持っているかは `initialize` で名乗り合う——§4.1 が
決めた「無いものは無いと明示する」が仕様の形のまま手に入る。さらに `session/new` で MCP サーバを
渡せるので、banto の Module をサブエージェントにも使わせられる。

### 却下した案

- **ベンダごとに専用の橋を書く**（Agent SDK・`codex exec --json`・`opencode run`）——3本それぞれの
  癖を抱える。8月の実測で `opencode run` は streaming も割り込みも無かった
- **Claude 自身のサブエージェント（Task tool）**——Claude でしか動かない。banto の Runner は組み込み
  tool を絞っていて、そもそも使えない
- **サブエージェントの道具を banto の Module だけにする**（ACP のファイル・端末の委譲で banto に
  回させる）——どのエージェントも従うとは限らない。強制できるのは Landlock

## 測ったこと（方針を出す前）

- **MCP の非同期の仕組み（Tasks）は使えない**：Claude Code 2.1.281 がクライアントとして名乗る能力は
  `roots`・`elicitation` だけ（2026-09-24、MCP サーバで initialize を受けて確認）。長い仕事の
  「終わった」は banto が自分で届けるしかない

## PoC の結果（2026-09-24、`poc/08-subagent-acp/`）

数字と表は PoC の README。ここには**決め方に効いたこと**と、**途中で間違えたこと**を残す。

### 決め方に効いたこと

- **ACP の口で、Claude Code と OpenCode が同じクライアントのコードで通った**——仕事・途中停止
  （`cancelled`、0.1秒以内）・別プロセスでの再開（`session/load`）。8月に `opencode run` で
  「無い」とした streaming と割り込みは、ACP の口では両方ある。§4.1 の古い表は ACP の表に差し替えた
- **Landlock の中で、どちらも `/proc` が無いと起動しない**（Bun の単体実行ファイル）。9月10日に
  「`/proc` は許可しない」と決めた理由（同じドメインの子が Module の `environ` を読める）が
  サブエージェントにも当たるかを測った——**Landlock は ptrace 相当の読み取りをドメインの外に効かせる**
  ので、**入れ子のドメインで起こせば当たらない**。例外をこのドメインにだけ置いた
- **渡した資格情報は、サブエージェントのシェルから読める。** Claude Code の Bash は env から
  トークンを消しているのに、`/proc/<pid>/environ` から読めた（`/proc` を許したので）。OpenCode は
  そもそも消さない。**「渡すものを絞る」しか手が無い**——これが「Claude のサブスクで何を渡すか」を
  人に上げる理由になった
- **OpenCode は人の設定の `model` を使わなかった**（`opencode/big-pickle` になった）。
  banto が毎回明示する
- **Claude Code の MCP クライアントの上限**を CLI 本体から読んだ：全体は約28時間、無音は stdio 30分／
  http 5分で**進捗で延びる**。待つ形は Shell と同じ手当てで足りる。ついでに、**長い MCP 呼び出しを
  CLI が背景に回す仕組み**（非対話では既定で切れている）があるのを見つけた——待たない形の前に見る

### 決めたが、別の道もあったもの

- **エージェント自身の確認の出し方を main の Runner と揃える**（Claude は `auto`）。全部を
  `bypassPermissions` にする案もあった——Landlock が強制層なので安全面は同じだが、main と
  サブで挙動が違うと、人が「どこで聞かれるか」を覚え直すことになる
- **1回の呼び出し＝プロセス1つ**。常駐させる案もあった——常駐は起動の1〜2秒を省けるが、
  モデル・資格情報の差し替えのたびに作り直しが要り、§2.3 のモデルB と同じ理由で採らない

### 途中で間違えたこと

- 途中停止の測定が2回無効だった。①`sleep 45` を Claude Code が断ることがあった（長い sleep を
  ブロックする）。②待ちのループが、仕事の結果に入れた配列と**同じ配列**を比べていたので、
  新しい tool 呼び出しを永遠に見つけられなかった（30秒待ってから停止を送り、「止まらない」ように
  見えていた）。**自分の測り方を先に疑う**
- Claude を閉じ込めたとき `/proc/self` だけ足して直したつもりになった——Claude は node が CLI を
  別プロセスで起こすので、self が違う。単体の `--version` で通ったものが、ACP 越しでは通らなかった

## Claude のサブスクで渡すもの（決定・2026-09-24、ユーザー）

**`claude setup-token` の長命のトークンを Vault に置き、API キーと同じ経路で渡す。**

却下した案：**host がいまの access token だけを呼び出しごとに渡す**。漏れても被害は数時間で済むが、
host に「閉じ込めた Module にトークンを渡す口」が新しく要り、access token が切れていたら誰が
更新するか（main の CLI が最近走っていなければ切れている）まで作ることになる。setup-token は
「CLI を人の手を介さずに動かす」ために Anthropic が用意している答え（規則12）で、Vault の
alias（§2.8 の複数資格情報）とそのまま噛み合う。代償——1年もののトークンがサブエージェントの
シェルから読める——は、いつでも無効にできることと、main のログインを渡さずに済むことで受け入れた。

## 本実装（2026-09-24、`banto/packages/modules/subagent`）

### 実装で分かった食い違い（仕様を直した——規則8）

- **人への確認を Elicitation で上げる、は成り立たなかった。** Module からの `elicitInput()` は、
  Runner 側で受信箱に記録されるだけで**答えが banto に繋がっていない**（画面に「この問いはまだ banto に
  繋がっていません」と出る。`review-elicitation-not-connected` で「答えられるように見えて届かない」を
  塞いだまま、答えを届ける配線は無い）。答えの来ない問いで60秒止まって落ちるより、**断って、断った
  ことを返り値に書く**ことにした。ACP の `cancelled` は「ターンを取り消した」の意味なので使わず、
  `reject_once` を選ぶ。**実測では、main と揃えたモード（Claude は auto）で確認は1件も来なかった**
  （sonnet・OpenCode とも、ファイルを書くところまで）
- **Module 自身を閉じ込めて、その中にエージェントの入れ子を作る、は成り立たなかった。** host が
  Module に許すのはモノレポの**読み取り**だけで、launcher（`banto-landlock-exec`）もエージェント本体も
  実行できない。入れ子は親より広くなれない。**Module は Vault と同じく閉じ込めの外に置き、エージェント
  だけを閉じ込める**——Module は AI の書いたコマンドを走らせないし、閉じ込めていないプロセスの
  `environ` はエージェントのドメインから読めない（PoC で測った「ドメインの外」に当たる）。
  仕様の見出しも「入れ子のドメイン」から「自分のドメイン」に直した
- **資格情報の渡し方は、Shell の `envSecrets` と同じ口にした**（AI が alias 名を書く）。設定画面で
  Project ごとの既定を持つ案もあったが、Canvas を1枚作ることになり、Shell と違う作法が増える。
  既定の資格情報は後で足す（毎回書くのが面倒になったら）
- **tool 名は `listSubagents`・`runSubagent`**——仕様には `list_subagents` と書いていたが、既存の
  Module（`runCommand`・`showFile`）に揃えた
- **進捗は画面に出ない**——呼び出しを切らせないためだけに送っている。フロントは tool の進捗を描かず、
  カードには終わってから引数と返り値が出る
- **banto の Module はまだサブエージェントに渡していない**（`mcpServers: []`）。渡すには、サブエージェント
  向けの中継の口（URL と合言葉）を host が出す必要がある

### 確かめたこと

- 単体（偽の ACP エージェント）：返答・使用量・モデル／effort／モードの設定・候補に無いモデルを候補つきで
  断る・確認の受け渡し・取り消し（0.2秒以内に `cancelled`）・別プロセスでの再開・落ちたら終了コードと
  stderr を伝える（接続が閉じた、ではなく）
- 結合（MCP の口から、本物の Landlock）：Project の根には書けて外は `EACCES`・`envSecrets` の値が env に
  届き `BANTO_*` は届かない・確認は断って記録・再開・誤りは理由つきの isError
- E2E（偽のエージェント、本物の画面と中継）：初回の中継の承認→鍵が届く→値はカードにも画面にも出ない→
  tool カードに引数と返り値→続きから→閉じ込め→Project 設定の一覧に出る
- **本物（`npm run check:agents -w @banto/module-subagent`）**：Claude Code（sonnet・auto）と OpenCode
  （opencode-go/qwen3.6-plus）が Module のコードから Landlock の中で動き、Project の根に書き、別プロセスで
  続きを覚えていた。1回あたり Claude 約 $0.05・OpenCode 約 $0.008

## Claude は banto 本体のログインを共有する（決定・2026-09-24、ユーザー——同日の setup-token を置き換え）

ユーザー：「Host で Claude を使っているのに、subagent を使うのに別途ログインが要るのは違和感がある。
Claude については banto 本体と共有するほうがいい」。

**どう共有するかは3案あった：**

- **本体の access token を env で渡す**（午前に「host がいまの access token だけを渡す」として退けた案）
  ——却下。渡したものはサブエージェントのシェルから読める（PoC で実測）。本体のトークンは推論だけでなく
  会話の履歴・claude.ai のコネクタ（Gmail・Drive）・ファイルの送り込みまで触れ、エージェントが claude.ai の
  コネクタを読み込んでしまう心配もある
- **本体の置き場（`~/.claude`）をエージェントに見せる**——却下。refresh token まで読める。しかも2つの CLI が
  同時に更新すると回る鍵の取り合いになり、本体がログアウトしうる
- **資格情報を足す中継**——採用。エージェントには合言葉だけ。プローブ（`proxy-probe.mjs`）で1往復通り、
  中継に来たのは `/v1/messages` だけだった

**中継で分かった代償**：契約の種類の問い合わせ（`api.anthropic.com` への直接の1本、中身は TLS で見えない）が
合言葉では通らないので、エージェントは契約を知らない——既定のモデルが Sonnet、候補に `[1m]` 付きが増え、
`sonnet` の文脈は20万（本物のトークンでは100万）。明示すれば選べるので、いまは受け入れる。

**トークンの期限**：本物は毎回本体の置き場から読み直す。本体の置き場は、banto の Runner・この機械の
Claude Code・CloudCLI のどれかが動けば更新される（寿命は約8時間）。中継は更新しない——refresh token に
触れると、回る鍵の取り合いになる。**サブエージェントの仕事が期限をまたぐと落ちる**が、依頼元の AI が
続きから頼み直すと、その前に本体の CLI が更新するので通る。期限切れらしいときは、そう書いて返す。
**実際に期限をまたいだ場合の振る舞いは、まだ測っていない**（測るには期限を待つしかない）。

**ついでに見つけたこと**：Claude Code のセッションから host を立て直すと、そのセッションの環境変数
（`CLAUDECODE`・`CLAUDE_CODE_SESSION_ID`・`CLAUDE_CODE_MESSAGING_TOKEN` など）を host が継ぐ。
立て直すときはこれらを外す。

## 既定のモデルを本体と揃える・OpenCode の鍵を設定から入れる（決定・2026-09-24、ユーザー）

**既定のモデル**：「揃えます」。別に既定のモデルを選び直す案（本体の既定を調べて `opus[1m]` を渡す）も
あったが、**エージェントが本体と同じ判断をするように材料を渡す**ほうを採った——CLI には env のトークンの
ときに契約の種類を読む変数（`CLAUDE_CODE_SUBSCRIPTION_TYPE`・`CLAUDE_CODE_RATE_LIMIT_TIER`）があり、CLI
自身も背景の認証の受け渡しで同じものを使っている。本体の資格情報ファイルに並んでいる（トークンではない）。
渡すと既定が Opus 5.5（1M）、候補の並びも本体と同じになり、Max の fast モードも出た。

**OpenCode の鍵**：ユーザー「設定から入れられるといいけど、MCP App は実装はこれからかな？」
——MCP App の設定 Canvas はもう本実装にある（FileSystem・Vault・Skills）。同じ型で「サブエージェント」の
設定画面を足した。

- **置き場は Vault の決まった名前**。Module の置き場（Project ごと）に持つ案は、Project ごとに入れ直すことに
  なるので採らない。Vault は banto 全体で1つ
- **会話の中からは目録（listAliases）を引かない**。最初は目録で在るものを確かめてから引いていたが、
  **会話から引くと承認が1枚増えた**（窓口の listAliases は Module からの呼び出しでは「値を返さない口」扱いに
  ならない）。承認が3枚になると、偽 Runner の呼び出し（進捗を送らないので60秒）が先に切れた。名前で直接
  引き、「どの Vault にも無い」を「設定されていない」として読み飛ばす形にした
- **置き換え・削除はこの画面ではしない**。最初は「消してから作り直す」で置き換えていたが、Vault は削除を
  **人の管理画面からだけ**受け付ける（`vault-kit` の assertHuman）。**Project ごとの Module の画面から押した
  操作は、人の管理操作と刻まれない**——host は呼び出し元に Project があれば `{project}` を刻み、`{admin}`
  を刻むのは Project の無い呼び出しだけ（`host-relay-endpoint.ts`）。Vault の守りを越えず、Vault の設定で
  消すよう案内する。**これが意図どおりかは確かめていない**（Project ごとの Module の設定画面は、いままで
  他の Module の人向けの口を呼ぶことが無かった）——tasks.json に上げた
- **既定の鍵が「在るかどうか分からない」とき**：フル E2E でだけ落ちた（単独では通る）。前の spec が
  設定の済んでいない Infisical の Vault を足していて、窓口の返事が「見つからないが、読めていない Vault が
  ある」に変わっていた。「どこにも無い」とだけ突き合わせていたので、これを本当の失敗として仕事ごと止めて
  いた。既定の鍵は AI が明示したものではないので、**止めずに読み飛ばし、返り値の notes に書く**ことにした。
  人の banto にも vault-infisical は居るので、同じことが起こりうる

## 鍵の設定を banto 全体の設定へ移す（決定・2026-09-24、ユーザー「Project ではなく Global に」）

鍵は最初から banto 全体の Vault に置いていたのに、設定画面だけ Project 設定に出ていた——**設定画面が
どちらに出るかは Module の単位で決まる**（Project ごとの Module の画面は Project 設定、banto 全体に1本の
Module の画面は banto 全体の設定）ため。走らせる Module は作業場所と閉じ込めがあるので Project ごとから
動かせない。**設定だけを受け持つ banto 全体の Module（`subagent-settings`）を同じパッケージの別の入口として
分けた**。core に「Project ごとの Module の画面を全体に出す」口を足す案もあったが、どの Project のプロセスが
その画面を受け持つのかが決まらない。

移したら、**Vault の書き換え・削除がこの画面から通るようになった**——banto 全体の Module には Project が
無いので、画面から押した操作に host が `{admin}` を刻む（Project ごとの Module は `{project}` を刻まれ、
Vault に断られていた）。置き換え（消してから作り直す）と「消す」を戻した。E2E で、取り込みによる置き換えと
削除が通り、置き換えた値が次の仕事に届くことを確かめた。

`project-module-canvas-admin-stamp`（Project ごとの Module の画面から押した操作を人の管理操作と刻むか）は、
サブエージェントについては当面の不便が無くなった。一般の問いとしては残す。

## launcher の画面（決定・2026-09-24、ユーザー「launcher から一覧や状態を見られる UI も作るんじゃなかったっけ」）

この回の計画には入れていなかった——**抜けていた**。モックの設計（`mock/lib/mock/types.ts`「Module
（Factory/Subagent）が完了を転記したもの。中身は Module の Canvas で見る」）は前提にしていたのに、会話の中の
tool カード（返り値の JSON）だけで済ませていた。しかも進捗は画面に出ないので、**走っている間に何をしているかを
人が見る口が1つも無かった**。

- 型は既存の launcher（FileSystem のファイルブラウザと同じ）なので、モックを経ずに本物で作った
- 記録を Module に持たせた（`runs.ts`）。core に持たせる案は、§4.1 の「サブエージェントの実行は Module の
  持ち物、core は転記だけ」に反する
- 「止める」は、MCP の取り消しと同じ道（`session/cancel`）に合流させた——`AbortSignal.any` で依頼元の取り消しと
  人の「止める」を束ねる。依頼元の AI には `stopReason: "cancelled"` として返る
- 画面は走っている間2秒、それ以外は5秒ごとに取り直す（通知の口は無い）
- 鍵を使うエージェントは、最初の仕事で既定の鍵を Vault に探しに行くので、**Project ごとに初回だけ承認が出る**
  （E2E で踏んだ——誰も押さないと偽 Runner の60秒で切れる）。Shell の envSecrets と同じ扱い

## 入口と設定の画面を作り直す（2026-09-24、ユーザー「UI があまりにシンプルすぎる。ほかの UI を参考に良い UI に」）

最初の画面は、記録の中身を縦に並べただけだった（一覧も中身も同じ太さの文字、状態は語だけ）。何を芯に
するかから決め直した。

- **芯は「経過」**——サブエージェントに任せた仕事で人が知りたいのは「いま何をしていて、ここまで何をしたか」。
  呼んだツールを、種類（読む・書く・実行・探す…、ACP の `ToolKind`）の印と、頼んでからの時刻（+2:51）つきで
  縦の線に並べる。走っている間はこの線が伸び、末尾が「作業中」で脈打つ。返答も書きかけのうちから見せる
  （ACP の `agent_message_chunk` をそのまま溜める）。形は CI の実行画面（GitHub Actions の
  ステップの一覧）や Claude Code の作業ログと同じ——どれも「順に・何を・いつ」を1行ずつ見せる
- **記録に足したもの**：経過（`steps`：時刻・題・種類）、書きかけの返答、**実際に使ったモデル**（設定項目
  `model` の現在値）。モデルは頼んだときに指定したものしか記録していなかったので、既定に任せた仕事は
  一覧に何で走ったかが出なかった（E2E で気づいた）。モデルの値は `session/new` の応答が唯一の真実なので、
  そこから取る
- **形は2つ**：会話の隣（狭い）は「一覧 → 選ぶと中身」、720px 以上は左右2枚で新しい仕事を選んでおく。
  banto の既定の幅（画面の2/3）だと 1280px の画面では狭い形になる
- **見た目は banto のトークンと字の段だけ**（要件 E9）。独自の色や書体は持ち込んでいない——Canvas は
  banto の中の一枚で、ここで個性を出すと banto 全体の見た目が割れる。個性は経過の線だけに使った
- **描き直しでフォーカス・スクロール・アニメの位相を保つ**——走っている間は 1.5 秒ごとに取り直して描き直す
  ので、そのままだと押そうとしたボタンからフォーカスが外れ、回る印が毎回最初から回り直す（ガタつく）。
  前の値を覚えて戻し、アニメは時刻から位相を合わせる
- **「止める」は行の中に重ねる**——行全体がボタン（選ぶ）なので入れ子にできない。最初は行の外に出していたが、
  どの仕事を止めるのか分かりにくかった
- **設定**：エージェントごとのカード。本体のログインを使うもの（Claude Code）は「使える」と契約だけ、鍵を使う
  もの（OpenCode）は変数ごとの行に「どこの鍵か」（OpenCode Go・Zen、Anthropic…）を添えた。入力欄は常に
  開いておかず「鍵を貼る」で開く——4つの変数それぞれに空の入力欄が並ぶと、どれを埋めるべきか分からない
- **見た目の確認は速い輪で**（規則15）：`scripts/preview-ui.mjs` が、見本の記録を返す偽の親に画面を載せて、
  幅（420・1000）と明暗を変えて撮る（数秒）。E2E は最後の確認だけ
- **仕様と実態の食い違い（規則8）**：v4-frontend.md は「host が banto の色トークンを
  `hostContext.styles.variables` で渡す」と書いているが、実装は `theme` しか渡していない。そのため FileSystem
  と同じく、トークンの**写し**を Module の中に持った（標準の変数名が渡されたらそちらを使う形）。写しは規則3に
  反するので、tasks.json `canvas-host-style-variables` に上げた
- **仕事が0件のときは左右に割らない**（稼働中の banto で開いて気づいた）——広い形でも、選べる仕事が無いうちは
  右の欄が何も無いまま空いていた。0件のときは1枚で「まだ頼んだ仕事はありません」と頼み方だけを出す。E2E は
  画面を開いたまま最初の仕事を頼み、空の表示から一覧に増えるところまで見るようにした
