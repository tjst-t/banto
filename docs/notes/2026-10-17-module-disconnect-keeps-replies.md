# 2026-10-17 Module との接続が切れても、続けられる仕事の札を閉じない（Backlog #362）

仕様は `docs/specs/v4-architecture.md` §2.5「2.」の「banto は動いたまま、Module との接続だけが切れたとき」。ここは経緯と、
選ばなかった案。

## 何が起きたか

2026-10-17 00:0x UTC（Banto開発、実行場所 banto-dev-vm）。runInBackground で流したコマンド（npm ci・build・npm test・E2E）は
systemd-run で Shell から切り離されて最後まで走り、ログも残った。ところが途中で host→VM の SSH が切れ、cli.ts の
`client.onclose` が返事待ちの札を全部「Module が止まったため」で即座に閉じた。Shell の Module は 00:07:27 に起き直したが、札は
もう閉じていて、会話には「もう届きません。頼み直してください」だけが残った。

切れた原因は banto ではなく host 側の経路：00:05 ごろから約2分、host から別のサーバ2台へ同時に届かなくなった（00:05:20〜22 に
全 Module が ping 2回に答えず、00:05:44／57 に SSH が ServerAlive で閉じ、00:07:24 に繋がり直した）。繋がり直しが遅れたのは
#370（試し直しの間が何段も倍になる）。

## 決めたこと

- banto の起こし直しのために作った「続けるか」の問い（#324 の繋がるまで待つ・終わっていたら届け直すを含む）を、**banto は
  動いたまま Module だけが落ちた・切れたとき**にも使う。仕事は Module の外（systemd の単位・Subagent のエージェントの
  プロセスグループ）で続いているので、問われれば Module は続けられる——起こし直しのときと同じ前提
- **閉じ方で分ける**：落ちた・切れた→待つ／人が止めた（畳んだ・外した）→今どおりすぐ「途中で終わりました」／banto が止まる途中
  →触らない（次に起きたときの判定に任せる）
- 上限は #324 と同じ 30 分。越えたら届け直せる印を残す（題は「接続が途切れたあとに終わっていました」）

## 選ばなかった案

- **すぐ閉じたまま、繋がり直したら閉じた札を届け直す**（#324 の届け直せる印だけを使う）：会話に一度「途中で終わりました」が
  届き、AI がそれを読んで頼み直す（同じコマンドを二重に流す）おそれがある。2分の途切れで毎回それが起きる
- **待つ間、host が自分で Module を起こし直しに行く**（起き直したときの `connect` の試し直しの輪をここでも回す）：起こし直しは
  もう §5.4-0 の試し直し（`scheduleRestart`）が持っている。2つの輪が同じ Module を起こしに行くと、試し直しの間の決まり
  （#370 で直す）と食い違う。繋がったことを `moduleConnected` で受けるだけにした
- **この機械の Module は待たない**（別のサーバだけ待つ）：Shell の待たないコマンドは、この機械のコンテナでも Shell の外で
  走り続ける（E2E `module-restart.spec.ts` で確かめる）。Module が落ちただけで結果を失う理由は同じ
