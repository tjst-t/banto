# `${secret:名前}` — 宣言に秘密を書かずに済ませる（2026-09-16）

仕様は `docs/specs/v4-architecture.md`「秘密は `${secret:名前}` で書く」と
`docs/specs/v4-security.md` の脅威表（「宣言に秘密を直接書くこと」）。
ここには**なぜそうしたか・却下した案・実際に踏んだもの**を残す。

## なぜ要ったか

外から MCP サーバを繋げるようにした（2026-09-15〜16）直後に、すぐ当たった。
AccuWeather を繋ぐには API キーが要る。素直にやると：

```json
"env": { "ACCUWEATHER_API_KEY": "abcd1234…" }
```

**宣言は Event Store に残り続ける。** つまりこのキーは**後から消せない**。
しかも人が持ってくる `mcpServers` の設定には、たいてい生のキーが入っている
——「一番普通のやり方」がそこへ落ちる。

## 却下した案

### `$my-alias`（2026-09-02 に決めていた表記）

`env` の値が `$` で始まっていたら alias 名とみなす、というもの。やめた：

- **普通の値と見分けが付かない。** `"PATH_HINT": "$HOME/bin"` を書きたい人と衝突する
- **同じ `env` の中に2種類の展開規則ができる。** 既に `${projectRoot}` などの
  差し込み語があるのに、alias だけ別の記法になる

`${secret:名前}` なら既存の `${…}` の一員なので、**「知らない語は起動前に落とす」
という同じ検査にそのまま乗る**。新しい規則を1つも足していない。

なお **2026-09-02 の判断そのもの（alias は必須ではない・直書きも許す）は生きている。**
変えたのは表記だけ。

### 「秘密を渡す」専用の口を作る

host が Vault から直接読んで渡す、という形も書けた。やめた理由は
**秘密の第二の経路になる**から——刻印もグループの絞り込みも監査も、relay 側にしか
無い。もう1本道を作れば、そちらは記録が薄いまま育つ。

いま通っているのは **窓口 `vault-directory` の `lookupAlias` → その金庫の
`resolveAlias`**。relay が使っているのと同じ2段で、同じ刻印・同じ絞り込み・
同じ監査を通る。

### `command` / `args` にも書けるようにする

やめた。**展開した値が argv に載る**ので、そのプロセスが動いている間ずっと
`ps` で読める。`env` の値にしか書けない。書いたら**起動前に断る**。

## 実際に踏んだもの

### 1. 中継の2段目で刻印が消えていた（本命の不具合）

最初の E2E がこう言った：

```
秘密 "e2e-secret-…" を引けませんでした：alias … は見つかりませんでしたが、
読めていない Vault があります：vault-local（一覧を誰のために読むのかが
分かりません（host が呼び出し元を刻んでいない））…
```

host → 窓口は刻めていた。ところが**窓口は金庫へ「中継で」問い合わせる**ので、
その2段目は `HostRelayEndpoint` が刻み直す。刻印の材料は台帳
（`ModuleCallTracker`）で、そこには「Project」と「人の画面（canvas）」しか
無かった——**banto 全体のための呼び出し**という状態が表現できていなかった。

直し方：

- 台帳に `forInstance` を足し、`callerFor()` が
  `{project}` ／ `{instance:true}` ／ `undefined`（決められない）を返すようにした
- **混ざったら `undefined`。** `{instance:true}` の呼び出しが、たまたま同時に
  走っている Project の刻印を借りて広がらないようにする
- 出所に **`host`** を足した（`turn` でも `canvas` でもない——banto 自身が
  Module を起こすために呼んでいる）。`canvas` の緩め（admin 可視の宛先は
  承認を聞かない）を**人が押していない呼び出しに掛けない**ため

> **この不具合は、遅い輪を回す前に出ていた。** 最初の E2E が「書き出しが無い」
> としか言わなかったとき、**失敗時に host の言い分（`/api/modules` の `error`）を
> そのまま出す**ように試験を直した。次の1回で原因文が丸ごと出た（規則15 の 6）。

### 2. 型が3ファイルに散っていた

`CallOrigin` に `"host"` を足したら、`host-relay-endpoint.ts` の構造的な型と
`ui-apps.test.ts` の局所変数が `"turn" | "canvas"` を直書きしていて落ちた。
**同じ union を3か所に書き写していた**（規則3）。いまは足すたびに落ちるので
気付けるが、輸出した型を使うほうがよい——直していない（規則7）。

## 見たこと（規則1・規則14）

E2E `e2e/specs/module-secret-placeholder.spec.ts`：

- **値が届いたことを、Module 自身が書き出したものを読んで確かめる。**
  「起動が通った」では見たことにならない
- **取り出し口（`/api/modules/export`）に値そのものが混ざっていない**ことも見る
  ——宣言に残っていないことが目的なので、そこを見ないと意味が無い
- **引けない名前を書いたら、起動せずに理由が残り、書き出しが存在しない**
  ——空文字で立ち上げていないことを、ファイルが無いことで見る

単体では、`{instance:true}` の刻印で**共通の秘密だけ**が引けること（窓口と金庫の
両方で）。この試験は変更前のコードで**実際に落ちることを確かめた**（規則1）。

## 残しているもの

- **`vault-infisical-cloud` が未設定の環境では、引けなかったときの文言に
  「読めていない Vault があります」が混ざる。** 正しい挙動（黙って「無い」と
  言わない）だが、**人が読むと原因を取り違えやすい**。文言の整理は未着手
- **直書きも通る。** 画面は「この値は記録に残り続けます」と言うだけ。
  止めるかどうかは決めていない——使い捨てトークンまで金庫を通させたくない

## 直さずに記録したもの（規則6）

### `relay-approval` が「2回目のターン」を待たずに通り抜けた（直した）

`events.jsonl` を直に読んで `resolveAlias` の**件数**で待っていた。**core は
spec をまたいで1つ**なので、この spec より前に走った spec の記録まで数えていた
——`${secret:…}` の解決が `resolveAlias` を積むようになった瞬間、**待ち条件が
最初から満たされていた**。

**Project では絞れない**（窓口は instance に1本なので、窓口→金庫の記録に
Project が付かない）。**連番（`seq`）で切った**——試験の開始時点の最大 seq を
覚えて、それより後だけを見る。E2E は1 worker なので、これで正しく切れる。

再現条件（`module-secret-placeholder` → `relay-approval` の順）で通ることを
確かめてある。

### `module-settings-canvas` が3回に1回落ちる（直していない）

**計測：フル3回のうち1回**（`module-settings-canvas.spec.ts:25`）。
落ち方は「設定を変えたのに、最後の一覧に隠しファイルが出たまま」。
**単体では6回とも通る**（単独4回、`module-secret-placeholder` の後に2回）。

**この変更が原因ではない**と見ている——刻印の分岐（`callerFor` / `origin:"host"`）が
効くのは `${secret:…}` を解くときの `vault-directory` だけで、`filesystem` の
設定面は通らない。`callerProject` が決まるときの経路は1バイトも変えていない。

**残っている疑い**：最後の確認が **AI がもう一度 `listDirectory` を呼ぶこと**に
依存している。呼ばなければ新しい Canvas が生えず、`.last()` は前の一覧
（隠しファイルを含む）を指したまま120秒粘って落ちる。**待ち条件が「AI の気分」に
掛かっている**なら、それは試験の作りの問題（規則14 の裏側——見たい中身を待つのは
正しいが、その中身が出るかどうかが非決定なら、待ちでは埋まらない）。

**直していない**（規則7——いま触っている機能ではない）。`docs/tasks.json` に
起票していないので、次に当たった人がここを読めるように残す。
