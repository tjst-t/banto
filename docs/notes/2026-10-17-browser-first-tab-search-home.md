# Browser の起こしたときの最初のタブを検索エンジンのトップに——測ったこと・選ばなかった案（2026-10-17、Backlog #376）

仕様は `docs/specs/v4-modules.md` §4.1「新しいタブと URL 欄の検索」の「起こしたときの最初のタブも」。ここは経緯だけ。

## きっかけ

ユーザーの報告（2026-10-17）「デフォルトページを DuckDuckGo にするのが動いていなそう」。#326 で＋と url を省いた `browserOpen` は
検索エンジンのトップにしたが、起こしたときの最初のタブは `chrome.ts` の起動の引数の末尾 `about:blank` のままだった。

## 選ばなかった案：起こしてから最初のタブを goto する（読み込みは待たない）

先にこれで書いた。単体（`view.test.ts`）で、人の画面が開いてすぐ screencast を始めるときに
`Page.startScreencast: Not attached to an active page` で映せないことがあった（goto の読み込みの途中で、ページが入れ替わる）。
起動の引数に URL を書く形（Chrome がページを開いてから Playwright が繋ぐ）では出なかったので、そちらにした。

## ref の頭の `f1`——前からある穴（同じ直しで塞いだ）

`browserSnapshot` の ref は、**同じタブでページを2度移ると** `e7` ではなく `f1e7` になる。Playwright はページの移動で
最初のフレームを作り直すことがあり、作り直したフレームの番号（`frame.seq`）を頭に付ける（`refPrefix`）。小さなプローブで測った：

| 移動の順（about:blank から） | 最後の ref |
|---|---|
| `/` | `e1` |
| `/` → `/second` | `f1e2` |
| `/search?q=` → `/`（同じ origin） | `f1e1` |
| `/second` → `/` → `/search?q=` | `f2e2` |

`args.ts` の ref の形の検査（`/^[a-z]*\d+$/`）が `f1e7` を断っていた——どのタブでも2度移ると AI は要素を押せなかった。
最初のタブが検索のトップから始まると、人が1度 URL 欄で移っただけでこの形になるので、検査に `f数字` の頭を許した
（Playwright は `f数字e数字` をそのフレームで引く）。E2E の `refOf`（`ref=(e\d+)`）は今の spec ではどれも1度目の移動の
ref しか読まないので触っていない。

## 間欠的に落ちる単体（直していない）

`view.test.ts`「動画：人の画面で静かなページのタブ（別の窓）に切り替えると…」が「会話のタブに切り替えた最初の1通がキーフレームでない」で
ときどき落ちる。**最初のタブを about:blank にした（前と同じ）形でも8回中1回**、この直しの形では5回中1回。この直しのせいではない。
直していない（スコープの外）——Backlog に上げる。
