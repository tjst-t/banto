# 記録：Thread が会話になっていない

> 2026-08-20、GUI を繋いだ直後に実測で見つけた。**設計の穴であって、画面の不具合ではない。**

## 実測

同じ `threadId` に2回続けて投げた結果：

```
1回目  turnIndex 0  文脈 20,926  「スイカが好きな果物ですね。覚えておきます」
2回目  turnIndex 0  文脈 20,920  「あなたの好きな果物についての情報は、
                                  私の記憶やコンテキストには保存されていません」
```

**モデルは前のターンを何も見ていない。** 文脈も積み上がっていない（20,926 → 20,920）。

## 原因

`AgentSdkRunner.run()` は毎回 `query()` を新規に呼ぶ。`resume` を渡していないので、
呼ぶたびに**別のセッション**が立つ。Phase 0 では host が1スレッドにつき1回しか
走らせなかったので露見しなかった——`serve` で同じスレッドに2回投げられるように
なった瞬間に出た。

## 何が壊れているか

| | |
|---|---|
| **会話（要件 A2・A8）** | Thread は「base + 以降のメッセージ」のはずだが、以降のメッセージが繋がっていない。閉じても残り読み返せる、以前に、そもそも続いていない |
| **観測（決定8）** | `turnIndex` が `run()` ごとに 0 から振り直される。observer は `index` で系列を並べ替えるので、**2回目以降のターンが1回目に混ざる**。文脈サイズの系列が壊れ、「下がった」の判定も嘘になる |
| **base / fork（決定3・4）** | 分岐が安いのは共有プレフィックスがあるからだが、繋がっていないので共有するものが無い。キャッシュ読みが効いているのは SDK のシステムプロンプト部分だけ |

## 直しかたの候補（まだ決めていない）

**A. SDK の `resume` を使う。** メッセージには `session_id` が載っている。
スレッドごとに最後の session_id を持ち、次の `run()` で `resume` に渡す。

- 利点：SDK が文脈もキャッシュも面倒を見る。いちばん素直
- 論点：session_id は**ベンダ固有の識別子**である。決定6 は「ランタイム固有の型・語彙を
  この層の外に出さない」と言っているので、イベントログに直接置くと外へ漏れる。
  Runner の中に閉じた対応表として持つか、`run.step` の detail のような
  「解釈しない記録」として置くか、決める必要がある
- 論点：導出できない値なので規則3 には触れない（写しではなく、それ自体が真実）

**B. 毎回メッセージ列を組み立てて渡す。** `query()` の `prompt` は
`string | AsyncIterable<SDKUserMessage>` を取るので、履歴を流し込める。

- 利点：ベンダ識別子を持たずに済む。イベントログだけが真実であり続ける
- 欠点：**キャッシュの前方一致を自分で守る責任を負う。** 決定4 が base に追記しか
  許さないのは前方一致のためで、その規律をここでも自分で保つことになる

**turnIndex は、どちらを採っても直す必要がある。** `run()` の中の連番ではなく、
スレッド内の通し番号にする。イベントログを畳めば導けるので保存はしない（規則3）。

## なぜ先に決めないか

決定3・4（base と fork）の実装がまだ無い。`resume` で繋ぐと「いまの続きから」に
なるが、**要件 R1 は fork の既定を base からにしろと言っている。** つまり
「続ける」経路と「base から切る」経路の両方が要る。片方だけ先に作ると、
もう片方を足すときに作り直しになる可能性が高い。

**Phase 2（Factory）に入る前に決める。** Factory は投げっぱなしの自律作業なので、
続きから走ることが前提になる。

## 画面の側で、いま正直に出していること

委譲先が実装した3点は、この穴を隠していない：

- スレッドに `turnCount` 件のターンがあるのに、**このページを開く前のものは出せない**旨を
  画面に出している（黙って空の会話に見せていない）
- ツールの呼び出しは「ターン境界」としか出せない。Runner が
  `translate()` で content block を捨てているため、ツール名も入力も結果も
  イベントに載っていない
- `turnIndex` が信用できないので、図の横軸は受信順で振り直してある
