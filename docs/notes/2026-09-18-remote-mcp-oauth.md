# ログインが要るリモート MCP（OAuth）（2026-09-18）

仕様は `docs/specs/v4-architecture.md`「ログインが要る相手（OAuth）」、
`docs/specs/v4-security.md` の脅威表、`docs/specs/v4-frontend.md` §6.23。
前提の工事（https）は `docs/notes/2026-09-18-https-for-oauth.md`。
ここには**なぜそうしたか・却下した案・実際に踏んだもの**を残す。

## 自分で考えたところは2つだけ

**プロトコルは SDK が全部持っていた**（`client/auth.js` に OAuth 2.1 + PKCE、
RFC 9728 のリソース探索、RFC 8414 のサーバ探索、RFC 7591 の動的クライアント登録）。
**5分で通り過ぎるべきところ**で、実際そうした（規則12）。

banto が決めたのは：**どこに預けるか**と、**人にどう見せるか**。

## どこに預けるか

**Vault。** refresh token は長命の秘密なので金庫の仕事そのもので、
`${secret:…}` と同じ刻印・絞り込み・監査に乗る。

ところが**金庫には値を書き換える口が無かった**（`updateAlias` は注記だけ）。
これは「人が預けたものを黙って書き換えない」という**正しい設計**で、
ここを素直に緩めると `${secret:}` で塞いだ穴が戻る。

### 却下した案

- **別の置き場を作る**（Module のデータ置き場に暗号化して置く）——
  **秘密の第二の置き場**になる。`${secret:}` で「第二の口を作らない」と
  決めた理由がそのまま当てはまる。しかも banto が自分で暗号を持つことになる
- **`assertHuman` を緩める**——2026-09-15 に「台帳と紐付けを変える口は人の刻印が
  あるときだけ」と決めたばかりで、そこを広げる理由が無い
- **delete してから create**——途中で落ちるとログイン情報が消える

### 採った形

**置き換えてよい範囲を種別で区切る。** `putSecret` は `oauth-token` しか扱わず、
既にその置き場に在るものが別の種別なら**断る**。つまり**人が預けた秘密には、
この口から構造的に届かない**。

あわせて `AliasKind` に `oauth-token` を足し、**人の登録画面の選択肢からは外した**
（`humanCreatable: false`）。**一覧からは隠さない**——どこにログインしているかは
見えていて、**消せばログアウト**であるべき（規則13）。

## 人にどう見せるか

**banto はサーバで、人は別の端末のブラウザにいる。** Claude Code のように自分で
ブラウザを開けないので、`redirectToAuthorization` は **URL を覚えるだけ**にして、
画面が「ログインする」ボタンとして出す。

**背景の接続では新しいログインを始めない。** 立ち上げのたびに認可 URL を作ると、
**人が途中まで進めたやり取りを上書きする**（PKCE の途中の値は1組しか持てない）。
背景の接続の provider は**印（`state`）を持たない**——SDK 側で `state` は省略可
なので、**追っている流れのときだけ生やす**形にした。構造的に混ざらない。

## 実際に踏んだもの

### 1. 戻り先だけは合言葉を持てない（設計の穴）

E2E がブラウザで押したとき、戻り先が `{"error":"unauthorized"}` を返した。
**相手の認可サーバからのブラウザ遷移**なので、`Authorization` ヘッダを持ちようが
ない。API を直接叩く試験では header を付けていたので**そこだけ通っていた**
——画面から押して初めて出た（規則13 の値打ちそのもの）。

合言葉を第三者のリダイレクトに載せる案は**そちらのほうが危ない**ので採らない。
**代わりの鍵は `state`**——推測できず、1回で使い切る。OAuth がこのために持って
いる仕組みをそのまま使う（規則12）。認証の**手前**に置いた。

### 2. 「直したのに直らない」（3回とも再現）

ログインして繋ぎ直しても、まだ「ログインが要ります」のまま。原因は
`connectDeclaredModule` の

```ts
if (failed && failed.fingerprint === fingerprint) return undefined;
```

——**一度失敗した Module は、宣言が変わるまで試さない**。これは正しい規則
（間欠的な再試行を増やさない）だが、**ログインは宣言を変えない**。
`finishOAuth` で明示的に忘れるようにした。

> `releaseModule` が失敗記録を消しているように見えたが、あれは
> **繋がっている接続を畳むとき**の掃除で、**失敗して繋がっていないもの**には
> 届いていなかった。「消しているはず」で済ませず、落ちる試験が教えてくれた。

### 3. 中継のゲートに当たった

金庫への保管は 窓口 → 金庫 の中継を通るので、承認ゲートが
「どのターンからの呼び出しか特定できません」と断った。**聞く相手も、出せる
会話も無い**（背景の接続中に起きる）。

`canvas` の緩め（人が押した）とは**別の根拠**として、
**`host` origin かつ両側が同梱のときだけ**通す形を足した
——ゲートが聞いているのは「Module A に B を呼ばせてよいか」であって、
banto が自分の部品を使うことではない。**第三者が絡んだら今までどおり聞く**。

### 4. 試験の書き方で2回つまずいた

`Response.text()` を2回読んで `Body is unusable`。どちらも
**エラーメッセージの中で1回、本体で1回**読んでいた。自分のミスだが、
**落ちたときに理由を出そうとして落ちる**のは間抜けなので記録する。

## 見たこと（規則1・規則14）

E2E `e2e/specs/oauth-remote-mcp.spec.ts`（4件）。相手は試験が立てる
**認可サーバ＋資源サーバ**（`e2e/oauth-mcp-fixture.ts`）——本物を叩かない（規則6）。

- ログイン前は**繋がらず、「ログインが要る」とそうと分かる形で**断る
- 「ログインする」で**押し先が返り**、戻り先は banto の1本、`code_challenge_method=S256`
- 戻ってくると**金庫に `oauth-token` として入る**（人の一覧で見える）
- そのあと**実際に繋がって、AI から tool が呼べて中身が返る**
- **画面から押しても同じ**（新しいタブ → 結果の文字 → 実際に繋がる）
- 知らない印で戻ってきたら通さない
- **PKCE は fixture が本当に検証している**（`S256` を計算して突き合わせる）
  ——確かめない相手だと、壊れていても通ってしまう

## 残しているもの

- **Project ごとのログインができない。** 押す場所が banto 全体の設定面なので、
  どの Project のログインか決められない。黙って共通に置くと**全 Project が同じ
  アカウントを共有する**ので、`scope: "project"` の Module は理由を言って断る
- **ログアウトの口が無い。** 金庫からその alias を消すのがログアウト
- **相手のコードが入れ替わっても気付けない**（リモート全体の話。`codeId` は
  URL しか見ていない）
- **タイムアウトと再接続を決めていない**（リモート全体の話、2026-09-17 から継続）
