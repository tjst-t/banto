# 2026-09-10 鍵と閉じ込めの穴（A群）——4件と、途中で変えた1つの決定

`docs/tasks.json` の `ui-tool-call-visibility-boundary`／`module-meta-strict-values`／
`vault-os-surface-hardening`／`filesystem-path-scope`。`landlock-guard-wiring` は
同日の別ノート（`2026-09-10-landlock-guard-wiring.md`）。

**4件に共通していたのは「強制が、置くべき層に無い」こと。** 可視性はフロントエンドの
自制に、パスの境界は OS の許可リストに、型の正しさは「たぶん正しい値が来る」に
乗っていた。

## 1. 画面 API の可視性（決定は済んでいた、実装が無かった）

合言葉さえあれば画面から任意の tool 名を呼べたので、AI には見せていない
`module` 可視性の道具（`resolveAlias`——秘密の値そのものを返す）が**ブラウザ経由で
呼べた**。host が API 境界で毎回ライブに検査する形にした（`agent`・`admin` だけ通す、
名乗っていない tool 名も拒否）。**全部塞がない**のが要点——`admin` を止めると
設定画面（alias の登録）が動かなくなる。

## 2. 書き間違いを「無指定」と同じに扱わない

`visibility: "modle"` が既定（`agent`＝AI に見せる）に落ちていた。**既定は「キーが
無いとき」の話**であって「値が壊れているとき」の話ではない。入口（Module を繋ぐとき）で
止め、実行時に読む側は**いちばん狭い側**へ倒す。`scope`・`handlesSecrets` の型違いも同じ。

**ここでも「有るのに配線されていない」を1つ見つけた**——`assertAllVisibilityExplicit`
（`handlesSecrets: true` の Module は全 tool に明示的な visibility が要る、という
決定の実装）は書かれているのに**誰も呼んでいなかった**。`landlock-guard-wiring` と
同じ形。**実装済みの検査が本番で呼ばれているか**は、今後もときどき grep する価値がある。

## 3. Vault の OS の面

**Vault は Landlock の対象外**（鍵を持つので閉じ込めの外に置く）。OS が止めてくれない
ぶん、自分で塞ぐしかない4つ：グループ名の `../`／平文の一時ファイル／並行書き込みの
取りこぼし／ssh-agent の増殖。

平文の一時ファイルをやめるところで詰まった：**sops は標準入力を直接読めない**
（`no file specified`）。`/dev/stdin` を渡す手は、**Node の `spawn` が作る stdin が
パイプではなくソケット対**なので `ENXIO` になる——**シェルからは通るのに Node からは
通らない**、という形で確かめた。名前付きパイプ（FIFO）なら中身はディスクに残らない。

試験も1つ学びがあった。「終わった後に平文が残っていない」では**以前の実装も通る**
（正常終了なら消えるので）。見たいのは「そもそも作られないこと」なので、
**書いている最中を `fs.watch` で見張る**形にした。

## 4. FileSystem のパス契約——途中で決定を変えた

未決だったのは「引数を根からの相対に限るか」。最初は**相対だけを受ける**と決めて
実装し、単体もE2E（の一部）も通った。

**が、全部の E2E を回したら2件落ちた。** 原因は AI の書き方で、**根の中のファイルを
絶対パスで指してくる**（`/tmp/…/one.txt`）。断られると同じ呼び出しを繰り返して
行き詰まる。

**守りたいのは「根の外へ出さない」であって「書き方」ではない**——そう気づいて、
契約を「**根の中を指しているかどうかだけを見る**」に変えた。相対でも絶対でもよく、
`..` も記号リンクも実体（realpath）で解いて判定する。セキュリティの性質は変わらず、
AI の自然な書き方を邪魔しない。

**この訂正は、全部の E2E を回さなければ見つからなかった**——単体と、触った spec だけ
では緑だった。
