# 任務と見回り——Dots の「会話をやめても進む」「自分から調べる」を banto に（2026-10-20）

仕様はアーキ仕様 §4.4・v4-frontend.md §6.47。ここは経緯。

## きっかけ

ChatGPT の Dots（2026-09-29 の OpenAI DevDay で発表。GPT-6 Astra で動く常時稼働の個人エージェント）を調べ、banto の今の機能と比べた
（Fork「Dots の比較」）。banto が既に持つもの：定期実行（自動化）・専用の計算機（Project のコンテナ・別のサーバ・Browser）・
複数のエージェント（Fork・サブエージェント・Factory・判断役）・使用量の管理（複数の Claude アカウント）・取り消せる Memory。
足りないもののうち、ユーザーが気にしたのが次の2つ：

- **会話をやめても進む**：Dots は目標を持ち続け、次の確認を自分で組む。banto の AI はターンが終わると、人・裏の仕事の返事・
  自動化でしか起きない。自動化は繰り返しの仕組みで、作るたびに必ず人に聞くので、終わりのある仕事には重い
- **自分から調べる**：Dots は人が使っていない間に、つないだアプリを読むだけの形で見て、急ぎのことを知らせる（Proactive research。
  その間は送信・編集・操作ができない）

Dots の権限の仕組み（操作ごとの4段の Custom Rules・オフにできない Auto-review）も比べたが、今回の範囲には入れない。読むだけの印は
その土台になる。

## 決めたこと（ユーザー・2026-10-20）

- 土台・任務・見回りをまとめて仕様に書く
- 任務を始めるときに1回承認すれば、枠（回数・期限・最短の間隔）の中の `schedule_followup` は聞かずに通す

## 仕様を書くときに選んだこと（レビューで見てほしい）

- **`start_mission` は「承認をすべて自動で許可する」がオンでも聞く**——自動化を作るのと同じ線（人が見ていない時間に繰り返し動く）
- **読むだけの根拠は、同梱の Module の宣言か、人が tool ごとに許したものだけ**——第三者の `readOnlyHint` は使わない（§5.3）
- **宛先を AI が選べる tool は読むだけではない**——WebFetch・WebSearch・`browserOpen` は URL や検索語に中身を載せて外へ運べる。
  見回りが外の文に操られても、外へ運べないようにするため
- **断るのは agent-proxy**——`allowedTools` に入れた tool は `canUseTool` を通らないので、SDK の設定だけでは守れない
- **読むだけの回では人に聞かずに断る**——人が見ていない回で判断待ちを積まない
- **見回りから任務へは必ず人を挟む**（お知らせの「やって」「任務にする」）
- **任務の回は受信箱に出さない**（何も起きなかった回）——15分ごとに受信箱が埋まるのを防ぐ
- **見回りの手帳は Memory に入れない**——Memory は決まったことだけ

## Fable のレビュー1回目（直せば入れてよい）で直したこと

- 守りを4か所に：SDK の `allowedTools` は狭めても何も禁止しない（聞かずに通す一覧）、既定の `auto` は分類器が `canUseTool` を呼ばずに
  許しうる——組み込みは `tools` で置き換え、core の in-process のサーバ（代理を通らない）は読むだけの tool だけで組み、Module は代理で、
  最後に PreToolUse
- 見回りの Fork はどの起こし方でも読むだけ。まとめと `banto.turn-decisions` を出さない（判断役の答えが外の文を読んだ文脈のまま
  制限なしで動く道があった）
- 読むだけの回が書いた URL は、banto が知っている場所だけリンクに（人に押させて外へ運ぶ道）
- 読むだけの回の中継先も読むだけに限る（host が宛先の印を見る）
- 印の候補の直し：`listServices`（毎回 reconcile で systemctl を打ちうる）・`listPublished`（Caddy の経路を書きうる）・`getNetworkRequest`
  （見出しを伏せない）を外し、Browser の読む tool はブラウザを起こさない形を条件に、`readDocument` は PDF と docx だけ
- 受信箱の新しい種類は既存の「お知らせ」（仕組みの異常）と名前が重なるので「気づき」に。§2.4・§6.41・§6.0 を更新、バッジには数えない
- 任務：`report_turn` が `continue: false` でターンを終えるので、任務の状態が悪ければ `report_turn` が断る。Stop hook は1本にまとめる。
  起こすかは `deliver` の手前で判断し、空いていなければ次の刻み。出来事の待ちは段2の照合と `awaitedModules` に乗せる。`start_mission` は
  tool の中でカードを出す（`canUseTool` の自動の許可を通らない）
- Repositories の GitHub の tool は、呼んだ Project のリポジトリだけ・決まった欄だけ

## Fable のレビュー2回目（直せば入れてよい）で直したこと

- `readDocument` の読むだけは PDF の文字だけ（docx も変換役を通る。`asImage` も変換役に中継する）
- 見回りの Fork の読むだけの印は `thread.created` に刻み、見回りを消しても残す（消すと外の文を読んだ Fork がふつうの会話に戻る穴）。`mode` は作ったあと変えない
- `decisions` のあるまとめは予約が無くても受け付ける（枠の外で人に聞く道が、まとめの断りと衝突していた）
- 時計で期限を過ぎたときは、ターンの外からレビュー待ちを出す／更新する
- 見回りの会話にはまとめの prompt と Stop hook を付けない
- 「答えていない決めこと」は判断役の `movedOnReason` と同じ手がかりで判定する
- 「やって」の引用は外から来たものと同じ囲み、`start_mission` のカードは form の部品、人の「今すぐ起こす」は最短の間隔に縛られない

## Fable のレビュー3回目（main に入れてよい）で足したこと

- 「やって」の引用は既存の `quotes` に乗せる・判断役は枠を延ばす問いを人に任せ、カードに「枠を延ばす」・立て直した見回りの Fork にも印

## 土台（#420）を実装して決めたこと・残したこと（2026-10-20）

- **読むだけの回の承認**：仕様は「承認が要る呼び出しは聞かずに断る」としていたが、そのままだと承認モードが「毎回聞く」の会話から立てた
  読むだけの回では、読むだけの tool まで判断待ち→断りになり、何も読めない。使える tool（4か所の守りが通すもの）は SDK の
  `allowedTools` で聞かずに通すことにした（仕様 §4.4 に1行足した）。それ以外が `canUseTool` に来たら人に聞かずに断る
- **守りの置き場**：判定は `core/src/relay/read-only.ts` の1か所。PreToolUse の Module の tool の一覧は、ターンを始めるときに Module の
  今の tool から引く（引けない Module の tool は通さない）。中継は呼び元の呼び出しの会話を host の台帳（`threadFor`）で引き、候補が
  複数ならどれかが読むだけなら読むだけ
- **試験**：見回りがまだ無いので、試験だけの口（config.json の `testOnlyReadOnlyThreads`・`POST /api/test-only/read-only-thread`）で
  読むだけの印を付けた会話を立てる。偽の Runner は SDK の `tools`（基底の集合）と PreToolUse を真似るようにした
- **URL の決まりで、まだ繋がっていないところ**（人に上げる、規則8）：「その Project のリポジトリの GitHub の場所」は判定の関数
  （`apps/frontend/lib/turn-summary.ts` の `knownPlaceUrl`）が受けられるが、画面がそのリポジトリを知る道がまだ無い（Repositories の
  読むだけの tool、#424 で台帳と Project の結びつきを引く口を作るときに繋ぐ）。いまは banto の画面のこの Project の中（`/p/<id>…`）だけを
  リンクにし、GitHub は文字のまま（安全側）。「Project の root の中のファイル」は画面に URL の形が無いので、文字のまま。また読むだけの回は
  `report_turn` を出さないので、まとめの票は今は出ない——決まりが効くのは見回りの段の「気づき」の画面から
- **Browser**：`touch()`（使われなければ止める時計の数え直し）は読むだけの回でも呼ぶ。ブラウザは起こさない

## 実装（2026-10-20、Backlog #421 任務）

- 仕様に書いていなかったので決めたこと（仕様 §4.4 に書いた）：
  - 起きた回の結果は `mission.woke` と別の出来事 `mission.wake_settled` にした。数えるのは起こした時点（`mission.woke`）で、結果は
    ターンが終わるまで分からない——同じ出来事を2回書いて「2回目は結果だけ」と読む形は、fold が数え間違える余地を残すのでやめた
  - 出来事が来た予約は、banto が `mission.followup_set` で「来たもの＋起こす時刻」を添えて置き直す。最短の間隔の待ちを host の
    メモリに持つと、待っている間に起き直したら来た出来事が消えるため
  - 会話・Project を閉じたら、出来事を書かずに fold が任務を `stopped` に畳む（`thread.closed`・`project.closed` が真実）
  - 時計の刻みで期限を過ぎて止めるのは、ターンが走っていないときだけ。走っていればそのターンの終わり（`turnEnded`）で止める
    ——結末はそのターンのカードに添わる
  - 期限切れの「ターンの外のカード」は、開いているカードがあればそれに結末を添える（`inbox.review_mission_set`）
- 「止まっています」にするのは、最後まで行った（completed）ターンだけ。人が止めた・失敗したターンでは動いたまま残す（失敗のカードは
  今どおり出る。期限が来れば時計が止める）
- 受信箱の「開いている画面では出さない」は任務の結末のカードにも効く——人が Base を開いたまま任務が終わると、画面がそのカードを
  「見た」にする（E2E では設定の画面に移ってから起こして確かめた）
- E2E で 15 分を待たないために、`BANTO_TEST_MISSION_MIN_INTERVAL_MINUTES`（最短の間隔の下限）を足した。E2E だけが 0 にする
- 偽の Runner への指示は予約のメモの中に入れ子にする。`fake-runner.ts` は最後の印を読むので、外側の指示の中の印は `\u005b` で書く
  （`e2e/specs/mission.spec.ts` の `nestedTurn`）

## 実装（2026-10-20、Backlog #424 Repositories の読むだけの GitHub の tool）

- **仕様に穴があった（人に上げる、規則8）**：仕様は「宛先はそのリポジトリの GitHub の API だけ」としていたが、非公開のリポジトリを
  読むトークンは Vault にあり、Repositories が引く `resolveAlias` は値を返すので読むだけの印を持たない。#420 の「読むだけの回の中継は
  宛先の印を見て断る」のままだと、読むだけの回では台帳のアカウントで読めない（公開のものしか読めない）。決めたこと：
  - **緩めるのは、banto 本体で動く同梱の banto 全体の Module が、同梱の Vault の `resolveAlias` と持ち主のものだけを書き換える口
    （`callerOwned`）を呼ぶ中継だけ**（`core/src/relay/read-only.ts` の `mayRelayOwnCredentialInReadOnly`）。読むだけの条件 3 が守るのは
    「AI に返らないこと」で、値は呼び元の Module の中で見出しに使うだけ。ログインの取り直しの書き戻しは条件 1 の「環境」に数えない
  - **却下した案**：(a) 鍵なしで読む（非公開を読めず、見回りの役に立たない）、(b) 呼び出しの印（callId）を付けずに Vault を呼んで
    読むだけの回だと分からなくする（守りをくぐる形。規則2 の裏返し）、(c) Repositories の `resolveAlias` だけを名指しで通す（core が
    Repositories を名指ししない線を崩す）
  - **承認はそのまま**：まだ許していない値は読むだけの回では聞かずに断る。初回はふつうの会話で人が許す（E2E もその順）。見回りを
    作る画面（見回りの段）で「初回はふつうの会話で一度読ませて許す」ことを人にどう伝えるかは、見回りの段で決める
- **台帳と origin の両方を見る**：リポジトリは呼んだ Project の根から台帳の行で決めるが、コンテナの中の AI は `.git/config` の origin を
  書き換えられる。ブランチを送る口は origin を読むだけだったが、読むだけの tool は**台帳の行の GitHub の場所と origin が同じとき
  だけ**読む（食い違えば断る）——別のリポジトリをこのアカウントで読ませない
- **欄の外の引数は断る**（黙って捨てない）。`additionalProperties: false` を名乗り、Module の中でも確かめる（Runner が schema で
  弾く保証は無い）。断るのは GitHub と Vault に行く前
- **CI のログは読まない**：GitHub のログの口は別の相手（blob の置き場）へ送り直すので「宛先はそのリポジトリの API だけ」に合わない。
  job と step の結論までにした。リダイレクトは追わない（`redirect: "error"`）
- **まだ繋がっていないところ**（上の #420 の項の続き）：読むだけの回が書いた URL のうち「その Project のリポジトリの GitHub の場所」を
  リンクにするには、画面が Project のリポジトリを知る道が要る。今回の tool は AI に見せる口で、画面に Project のリポジトリを渡す口は
  作っていない（スコープの外、規則7）。GitHub の場所は今も文字のまま（安全側）。見回りの「気づき」の画面を作るときに、Repositories に
  画面向けの口を足すかを決める
- **間欠的に落ちる試験（直していない、規則6・7）**：`@banto/module-repositories` の `npm test` を続けて流すと、`clone.test.ts` の
  「非公開は選んだアカウントのトークンで clone する」「リダイレクトの先の別の相手にはトークンを渡さない」が「資格情報の窓口が残っている」で
  落ちる（この日 全体を14回流して3回）。clone.test と publish.test だけを3回流したときは3回とも通った。窓口のフォルダ（`banto-git-cred-*`）は
  共通の `os.tmpdir()` に作られ、`node --test` は試験のファイルを別々のプロセスで同時に走らせるので、clone.test の「前後で増えた窓口」の
  数え方に、同時に走るほかのファイル（publish・branch-sync）の窓口が入りうる——試験の数え方の穴で、窓口の片づけの穴ではない見込み
  （確かめてはいない）。#424 のコード（github-read）は git の資格情報の窓口を作らない。Factory の決まったテストのコマンドには入っていない

## 実装（2026-10-20、Backlog #423 見回り）

- 仕様に書いていなかったので決めたこと（仕様 §4.4 に書いた）：
  - 1日の数（`dailyFindingLimit`）は手帳の `notifiedAt` から数える——別に数えを持つと、手帳と食い違う（規則3）。同じ `key` は7日に
    1回しか出ないので、「今日 `notifiedAt` のある行の数」が今日出した数にそのまま一致する。時刻でないきっかけ（出来事・Webhook）の
    見回りはタイムゾーンを持たないので、banto が動いている場所の日付で数える
  - 「片づけた」にした `key` も7日の間は出し直さない（7日は `notifiedAt` から数える）。人が片づけた直後に同じものが戻ってくると、
    片づけた意味が無い
  - `notify` は見回りの Fork のターンにだけ組む。見回りを消したあとの Fork（読むだけのまま）では、出す先の見回りが無いので組まない
    ——`allowedTools` にも載せない
  - 見回りは判断役になれない（`banto.turn-decisions` を待つ見回りは作るときに断る）。読むだけの回は `answer_decision` を持たず、
    判断役の道を断つという §4.4 の考えとも合う
  - 「やって」「任務にする」は新しい口を作らず、画面が既存の口（Fork を立てる・任務を始める・会話に送る）を順に呼ぶ。引用だけは
    画面が文を渡さず `{ finding: id }` を渡し、host が受信箱の中身から組む——画面の文を信じると、気づきの引用を装った文を送れる
  - 「任務にする」の目標・終わりの条件は欄を増やさず、気づきの題と「やるならこう」から作る（仕様の欄は枠の3つだけ）
  - 見回りの届ける文の見出しは「見回り「名前」」にした（自動化の届けものの題と分ける）
- 偽の Runner の指示は人が書いた指示に入れる。host が後ろに手帳を足すが、偽の Runner は印のあとの1行だけを読むので乱れない
- **#423 で触っていない間欠的な単体試験**（規則6の記録）：`packages/core/src/delivery/turn-continuation.test.ts` の「打ち切った札：Module が
  続けないと答えたら…」が、単独で 8 回中 2 回落ちた（2026-10-20、別の worktree のフル E2E が同じ機械で走っている間。全体の実行では
  2回とも落ちた）。`askTimeoutMs: 30` の間に「続けない」の答えが返らないと「答えない」扱いになる形で、待ちの長さに結果が左右される。
  #423 は `delivery/` に手を入れていないので直さず、ここに残して人に上げる
- **E2E（`e2e/specs/patrol.spec.ts`）はまだ一度も回していない**：書いたが、同じ機械で別の worktree のフル E2E が同じ port の枠を
  使っていて（`http://127.0.0.1:4816/healthz is already used`）、終わるのを待っている間に作業が切れた
