# 2026-10-16 別のサーバの Module は繋がってから続けるかを聞く（Backlog #324）

仕様は `docs/specs/v4-architecture.md` §2.5「2.」の「別のサーバの Module は繋がるまで待つ」（形も同じ所）。ここは決めた理由と、
採らなかった案。

## 起きたこと

- 2026-10-15 14:31 の起こし直しで、Factory の実行 82e714e6 の3件が「subagent に続けるかを聞けませんでした：120 秒待っても
  答えが来ませんでした」で止まった
- 2026-10-16、待たずに流した Shell のコマンド（Browser の E2E）が、更新のたびに「途中で終わりました——Module が止まったため」に
  なった（2回続けて）
- Project は別のサーバ banto-dev-vm。更新すると新しい版のコードを VM に送ってから Module を起こすので、120 秒（起こす時間も
  入れた期限）に間に合わない。VM の中の仕事（systemd の単位）は動き続け、結果のファイルも残っていた。コードを送り直さない
  起こし直し（10/14）では続いていた

## 決めたこと・理由

- **期限を「繋がるまで」と「繋がってから」に分ける**（別のサーバの Module だけ）。この機械のコンテナの振る舞いは変えない
  （完了条件 4）。繋がるまでの上限は 30 分——送り込みそのものは「2 分進まなければ止める」見張りが `remote-ssh.ts` に既にあり、
  全体の時間では切らない（遅い回線で 4 分かかった実測）。30 分は経路が途切れたままのときの上限
- **待つ間、ほかの Thread を待たせない**：前は全部の問いの答えを待ってから、留めた Thread を一斉に解いていた。別のサーバを
  30 分待つ間、この機械の Module の札しか持たない Thread まで留まるので、答えの出た接続から解くように変えた
- **人が送ったら待たせない**：仕様どおり。切れたターンの続きを先に積んでから人のターンを始める——積まずに始めると、人の
  ターンが最後のターンになって切れたターンが二度と見つからず、続きが失われる。積んでおけば「人が送ったターンが続きを
  引き継ぐ」（§2.5「1.」）の既存の形に乗る
- **届け直しは同じ問い（`resumeAfterRestart`）に `afterLost` を付けて渡す**：Shell と Subagent の今の答え方（終わっていれば
  すぐ届け、動いていれば見張って届け、記録が無ければ続けない）が、仕様の「届け直す」の振る舞いとそのまま一致する。別の tool を
  足すと、Subagent が「問われなかった記録を片づける」ので、2つの問いが同じ Module に並ぶと片方の記録が消える
- **題は host が付ける**：仕様は「Module が『起こし直しで途切れたあとに終わっていました』として届ける」だったが、host は
  覚え直した札が打ち切った札だと知っているので、3つの Module に同じ文を書かせず host の1か所で付けた（仕様の形の項に書き直した）
- **「届け直せる」印は `reply.awaiting` で消す**：問い直す直前に返事待ちに戻すので、別の「使った」出来事を足さない。問い直しの
  途中で host が落ちても、返事待ちとして次の起き直しに乗る（二重には届かない——札は1回しか使えない）

## 採らなかった案

- **送り込みの進み具合を見て期限を延ばす**：進み具合は `onCodeTransfer` で取れるが、止まったときの打ち切りは送る側が既に
  持っている。二重に見張ると、どちらの理由で打ち切ったかが分からなくなる
- **待つ間に切れたターンを先に続ける**（AI に「繋がるのを待っています」と伝えて走らせる）：§2.5「2.」の順番（札の判定 →
  続き）を崩す。答えが「続けない」だったとき、AI に「続いています」に近い文を見せたあとで「途中で終わりました」が届く
- **Module 宛ての札（Factory → Subagent）も届け直す**：仕様は Thread 宛てだけ。Module 宛ての札は呼び元の Module に
  「途中で終わりました」（`lost: true`）が渡り、Factory はそれで段を進める——あとから結果が来ても受ける形が無い
