# Browser の人の画面を人の端末の倍率で描く（Backlog #266、2026-10-11）

稼働中（release d598c23b）の人の画面の絵がドットバイドットでなく、にじむ。ユーザーの決定（案A）：ブラウザに人の端末の
倍率でページを描かせる。決めたことは `docs/specs/v4-modules.md` §4.1「高精細の画面」。ここには測ったこと・却下した案・
途中で踏んだものを残す。

## 測ったこと（プローブ。展開せず /opt/google/chrome の Google Chrome 155、Xvfb、Module の起こし方そのまま）

### 倍率をどこで効かせるか

1280×800 のページ・文字の多いページで、screencast（`maxWidth`・`maxHeight` は 4000 で頭を押さえない）の絵の大きさ：

| 形 | ページの `devicePixelRatio` | 絵 |
|---|---|---|
| 今まで（起動の引数なし・Playwright の `setViewportSize`） | 1 | 1280×800 |
| 〃＋自分の口から `Emulation.setDeviceMetricsOverride`（`deviceScaleFactor` 2） | 2 | **1280×800**（大きさも中身もほぼ同じ） |
| `--force-device-scale-factor=2`＋Playwright の `setViewportSize`（`deviceScaleFactor` 1） | **1** | 2560×1600 |
| `--force-device-scale-factor=2`＋自分の口から `deviceScaleFactor` 0 | 2 | 2560×1600 |
| `--force-device-scale-factor=3`＋自分の口から `deviceScaleFactor` 0 | 3 | 3840×2400 |

- **エミュレーションの `deviceScaleFactor` では絵は大きくならない**。ページに 2 と見せるだけで、描いた画素は1倍——偽の値になる。
  2026-10-08 の「`deviceScaleFactor: 2` でも 1280×800」はこれだった
- **起動の引数なら本物の画素で来る**。ただし Playwright の `setViewportSize` は `deviceScaleFactor` を 1 に上書きするので、
  そのままでは文字は2倍で描かれるのにページの `devicePixelRatio` は 1（画像は1倍のものを選ぶ）。自分の口から 0（上書き
  しない）を送ると本物の 2 になる
- 2つの口の上書きは、後に送ったほうが効く。自分の口を閉じると Playwright の上書きに戻る

### 1枚の大きさ（JPEG、screencast の絵）

| 絵 | ページ | 画質70 | 60 | 50 | 40 |
|---|---|---|---|---|---|
| 1280×800（1倍） | 文字の多い | 337KiB | 283 | 247 | 213 |
| 1280×800（1倍） | 雑音 | 458KiB | 388 | 341 | 293 |
| 1920×1080（1倍） | 文字の多い | 692KiB | 581 | 506 | 436 |
| 2560×1600（2倍） | 文字の多い | 1060KiB | 903 | 796 | 698 |
| 2560×1600（2倍） | 雑音 | 1819KiB | 1538 | 1349 | 1161 |
| 3840×2160（2倍） | 文字の多い | 1934KiB | 1846 | 1625 | 1425 |
| 780×1400（2倍） | 文字の多い | 273KiB | 233 | 205 | 180 |
| 3840×2400（3倍） | 文字の多い | — | 1590 | 1412 | 1244 |

画素あたりは倍率が上がると小さくなる（1倍 0.33・2倍 0.26 KiB／千画素、画質70）が、2倍の 1280×800 のページは画質70で
1 MiB を越える。

## 決めたこと・却下した案

- **倍率は起動の引数**（上の表）。起動のときにしか決められないので、開いている画面のうち一番大きい倍率を置き場に覚え、
  次に起こすときに使う。**起こし直して合わせる案は却下**——開いているページ（AI が開いたもの・人が打ちかけたもの）が消える
- **ページの大きさは自分の口の上書き1つにする**。最初は「Playwright の `setViewportSize` の後に自分の口から
  `deviceScaleFactor` 0 を送り直す」形にしたが、倍率2で起こしたページから `devicePixelRatio` が 1 に見えることがあった
  （試験で約30回中2回。プローブでは 45 回中0回で、どの順で競ったかまでは掴めていない）。2つの上書きが競う形そのものを
  やめ、Playwright の `setViewportSize` を使わず、大きさは Module が覚える。替えた後、ブラウザの単体を12回流して0回
- **1 MiB の上限は上げない**（流れの口は Terminal と共有）。代わりに画素数の上限を 2560×1600 で押さえ、画質を 70→60 から
  始めて、越えたら下げて張り直す。最初から画質を見積もる案（画素数×千画素あたりの大きさ）は、ページによって2倍近く違うので
  却下——越えたら下げるほうが確か
- **3倍は描かない**（実測は仕様の表）。3倍の端末（iPhone 等）は 2 で描いて引き伸ばす。携帯に「画面に合わせる」をしたとき
  だけ 3 が得になる（1170×2532）が、そのときも毎秒の枚数は 2 の約半分
- **AI の絵（`browserScreenshot`）は CSS ピクセルで撮る**。倍率の2乗の絵を AI に読ませても得るものが無い

## 途中で踏んだもの

- **起こして数秒の間に1枚だけ、窓の素の大きさの絵が来る**（2560×1488＝ページ 1280×744 の2倍。744 は起こした直後の厚い窓の枠の
  内側）。倍率2で10回中1〜2回・1倍で10回中0回。自分の上書きを外しても・`deviceScaleFactor` を 2 と書いても起きた——起動の
  引数と、Google Chrome の窓の枠が細くなるときの組み合わせ。頭はページの大きさ（1280×800）を言うので、そのまま送ると絵が
  縦に伸び、その間の入力の座標がずれる。Module で JPEG の大きさを読み、ページと比の違う絵を捨てるようにした（直後に正しい絵が
  続いて来る。10回中0回）。**1倍でも起きる**——E2E の Module のログに、起こし直した直後の 1倍で 704×409（1280×744 を縮めたもの）を
  捨てた記録があった（プローブの10回では出なかった）。「画面に合わせる」の直後の、張り直す前の絵（ページ 390×588 に 390×244）も
  ここで捨てている
- **試験「画面に合わせる」が倍率3で落ちた**（倍率を 2 までにする前、12回中7回）。前の試験の携帯の画面（倍率3）を覚えた後、
  タブを全部閉じてブラウザが終わり、倍率3で起き直していた。ログで見ると、URL 欄で開いたタブの最初の絵が「合わせる」より先に
  既定の大きさ（1280×800）で送られ、その後の 390×640 の絵は、試験の偽の画面が受け取りの印を返さないので溜まったまま
  届かなかった。本物の画面は印を返すので次の絵が届く——試験の偽の画面に印を返させた。**タブができてから「合わせる」が効くまでの
  間に既定の大きさの絵が1枚出るのは前からの振る舞い**（倍率で遅くなって見えやすくなった）。直していない（#266 の外）
- `npm test` を最初に回したとき、tools.integration と view の2つの試験のファイルが同時に動いて 600 秒で止まったことが1回あった。
  上の2つを直した後は12回続けて 13〜24 秒で通っている
- **E2E で最初「2560×1600 が来ない」と見えた**のは試験の誤り：倍率2の 1440×900 の窓の中で、Canvas の絵を出す場所は約 800 CSS
  ピクセルの幅しか無く、絵はその物理ピクセル（1600×1000）で来ていた——画面より大きな絵は送らない（仕様の「大きさ」）。
  試験は「絵を出す場所の CSS の大きさ×2 以上・1280 より大きい・ページの2倍まで」を見る形に直した

## 人に上げること

- ページから見える `screen` が 1280×800（Playwright がページの大きさに合わせて上書きしていた）から、仮想の画面の 1920×1080 に
  変わった（倍率に関わらず）。人の機械に近い形だが、ページから見える値が変わる
- 低い倍率で動いている間に高い画面が開くと、ブラウザが使われずに止まるまでは低い倍率のまま（仕様の「まだ決めていない」）
- 2倍で映している間は毎秒の枚数が約半分、押してから次の絵まで約160ms（1倍は約55ms）。にじまないことと引き換えの重さ
