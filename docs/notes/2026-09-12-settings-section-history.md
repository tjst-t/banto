# 設定の節の行き来を、履歴に残す（2026-09-12）

決まったことは `docs/specs/v4-frontend.md` §6.16（「節の行き来は、履歴に残る」）と
§6.19（焦点の示し方）。ここはその経緯。

## きっかけ

ユーザー指摘：「設定画面のサブメニュー間の遷移もちゃんと履歴に残るようにしてください。
**特にモバイルで不便**」。

狭い画面の設定は「一覧 → 選ぶと中身」の1カラムで、節を開いている間は左メニューが
出ない。節を `router.replace` で開いていたので、そこで「戻る」を押すと**設定ごと
飛び越えて会話まで戻る**。戻りたいのは一覧なのに、いちばん戻りたい場面で戻れない。

## 考えた案と、選んだもの

| 案 | 却下／採用の理由 |
|---|---|
| 全部 `push`（一覧へ戻るのも `push`） | **却下**。履歴に「節を閉じた」が積み増さる。戻るを押すたびに同じ節が開いたり閉じたりして、会話まで戻るのに押す回数が倍になる |
| 節を開くのは `push`、一覧へ戻るのは `back` | **採用**。自分が積んだぶんを戻すだけなので、履歴は「会話 → 設定 → 節」の素直な列になる |
| 画面が節を自分で覚え、履歴は触らない | **却下**。開いている節は URL が持つ（§6.16、規則3）——ここを崩すと、サイドバーから節を変えられなくなる |

**深い URL を直接開いたとき**（`?section=` 付きで来た）は、戻るぶんが無い。
自分で押した `push` の数を数えて、0 なら `replace` に落とす——数えずに `back` すると、
**設定に来る前の別サイトへ戻ってしまう**。

## 測ったこと

- 追加した E2E（`project-modules.spec.ts`「設定の節の行き来は、履歴に残る」）で
  携帯幅の往復を確認：`1 passed`
- **反証**：`push` を `replace` に戻してビルドし直すと、同じ試験が
  「節の行き来が履歴に残っていない」で落ちる（`1 failed`）。試験が本当にこの変更を
  見ていることを確かめてから戻した（規則1）

## 巻き込んだもの（記録）

1. **`module-settings-canvas.spec.ts` が落ちた。** 「戻る」1回で会話へ帰る前提で
   書いてあったため。**これは仕様どおりの副作用**なので、試験のほうを人がやる経路
   （サイドバーでその Project を押す）に直した。
2. **`thread-lifecycle.spec.ts` が落ちた**（全体実行のときだけ）。
   `getByRole("button", { name: "履歴" })` が**部分一致**なので、新しく足した試験が
   作った Project 名「履歴の spec」にも当たり、`.first()` がそれを掴んでいた。
   待ちを延ばすのではなく、`exact: true` にして名前も衝突しないものへ変えた（規則6）。
   単体では通り、全体では落ちる——**共有の host に他の spec が残したものが効く**
   という、この作りの弱いところが出た形。

## ついでに直したもの

入力欄の焦点の**青い輪**（`ring-3`）。要素の外に出るので、ダイアログの縁や狭い枠の
中では端が切れて見えた（ユーザー指摘）。輪をやめ、枠の色だけを変える。
焦点そのものは消していない。
