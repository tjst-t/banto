## A. アカウントを後から選ぶ

- **見えないアカウントは断る**。指定しても clone し直しも公開もできない——選び間違いのことが多い。断るときは理由
  （非公開で権限が無いか、GitHub App がそのリポジトリに入っていない）と次の手（見えるアカウントを選ぶ）を言う
- **見えるが書けないなら、指定はして、そう言う**。却下した案：書けないなら断る——公開のリポジトリを自分の
  アカウントで clone し直したい（レート制限・非公開のフォーク前の確認）ことはあり、読めることには意味がある。
  ただ「公開・push はできない」は画面が必ず言う（`permissions.push` を返す）
- **確かめられないなら断る**。確かめずに書くと「使えるはず」の嘘になる（規則2）
- **読むだけに戻すと印（`readOnly`）を残す**。却下した案：アカウントの欄を消すだけ——一覧と Import は「持ち主と同じ
  login のアカウントがあれば書く」ので、次に一覧を開いたときに黙って付け直してしまう（人が外したものを戻す）。
  印のある行には自動で書かない。選び直せば印は消える

## B. このマシンから削除

### 数え方

- **push していないコミットの数は重ねない合計**（`rev-list --count --branches --not --remotes`）。ブランチごとの数
  （`refs/heads/<b> --not --remotes`）は、枝分かれしたブランチで同じコミットを2回数える——試験で main に2つ・
  そこから分けた spike に1つ積むと、ブランチごとは 2 と 3 で、足すと 5（本当は 3）。画面にはブランチごとの数を
  並べ、確かめの要否と数は合計で決める
- upstream が無く、リモートに同じ名前も無いブランチを「リモートに無いブランチ」として別に数える（push 済みの
  コミットだけでできたブランチでも、名前は失われる）
- detached HEAD は `symbolic-ref -q HEAD` が 1 のとき、`rev-list HEAD --not --branches --remotes`
- 変更・追跡していないものは `status --porcelain=v1 -z --untracked-files=normal --ignore-submodules=all`（ignore 済みは
  数えない、フォルダは1つ）。**`git status` はリポジトリの設定の filter の clean を起こす**（中身が同じで時刻だけ
  変わったファイルを比べに行くとき——試験で実測。対照の素の `git status` では走る）。`filter.*` の名前を
  `config --name-only --get-regexp` で読み、`clean`・`smudge`・`process` を空、`required` を false に上書きしてから数える
  ——空にした driver は使われず、中身の比べは素のまま行われる（実測）。名前が読めなければ status を走らせない
- **submodule の中は数えない**。中の `.git/config` から何が起きるかを同じ手当てで止めきれる確信が無い。数えて
  いないと言い（`problems`）、名前を打たせる
- 数える git は1つ60秒まで（`GIT_TIMEOUTS.losses`）。却下した案：全体の上限——大きいリポジトリで status だけが
  長いことがあり、全体で切ると何も数えられない。切れたら「無い」と言わず、数えきれなかったと言って名前を打たせる

### 確かめ

- 何も無ければ1回。あれば**リポジトリ名を打たせる**。名前を打たせる条件に、**使っている Project・どの Project が
  使っているか分からない**も入れた——Project の Root が無くなるのは失われるもの（コミット等）と同じくらい重い
- **確かめは Module が決める**：`delete_repository` は消す直前にもう一度数え、`confirmed` と（要るなら）`typedName` が
  揃っていなければ断る。画面が「何も無かった」と言っても信じない。調べたあとに増えていたら「調べたあとに増えた
  かもしれません」と言って打たせ直す

### 断る場所

- ユーザーの指示どおり、シンボリックリンク・台帳の場所と realpath の違い・置き場の外・ホーム・`/`。加えて置き場
  そのもの・ホームの上（`/home` 等）・台帳に無いもの・リポジトリでないもの（中身が分からず数えられない）
- **置き場の外は、Import したリポジトリでも消さない**。Import は場所を動かさないので、置き場の外のものは人が自分で
  置いた場所——banto が作ったものではない。「一覧から外して、ほかの道具で消してください」と言う。ここは人に
  確かめたい（Import したものも消したい、という声はありうる）
- worktree は worktree だけを消し、本体で `git worktree prune`（本体は消さない）。本体を消すときは、使えなくなる
  worktree を数えて名前を打たせる

### 使っていた Project

- Module は Project に触らない。**消したあと、core の「Project を閉じる」の確かめを開く**（`dev.banto/close-projects`）。
  却下した案：Module が core の閉じる口を中継で呼ぶ——Module が Project を動かす道になり、「core は Repositories を
  名指ししない」「Project を作る口を足さない」と同じ理由で足さない。閉じるかは人がそこで押す
- 確かめの文言に「このマシンから削除したため」を入れていたのを、E2E を書きながら外した——core が Module の都合を
  名指ししている。理由は頼む前に Module の画面が言っている（「Project も閉じる」の説明）
- 開く決まりは `dev.banto/open-new-project` と同じ（会話の中の画面は押した直後だけ・開いている間は断る・開く場所の
  無い面は断る）。2つの頼みで同じ決まりを写さないよう、`lib/backend/canvas-requests.ts` に1つにまとめた（規則3）

## C. 新しい Project の画面のタブ

- **印は既存の `_meta["dev.banto/canvas"]` の3つ目の値 `"folder-provider"`**。却下した案：新しい欄
  （`_meta["dev.banto/folder-provider"] = { name, description, icon }`）——MCP の資源には `name`・`description`・`icons`
  の標準の欄がもうあり、写すと食い違う（規則3）。画面の置き場所（入口・設定・新しい Project）は1つの欄で言う
- **アイコンは data: の画像（svg・png）だけ**、2万字未満。外の URL は渡さない（画面に外へ読みに行かせない）
- **返す口は banto の拡張の request `dev.banto/folder-prepared`**。却下した案：
  - MCP Apps の `ui/message`・`ui/update-model-context`——どちらも会話（モデル）へ渡す意味。ここは会話の外
  - 通知（返事の無い一方通行）——枠の外から送られたときに「受け取っていない」を画面に返せない（規則2）
- **中の画面は一覧の clone・新しいリポジトリのダイアログと同じもの**を、枠の中に出す形（`app.ts` の `PREPARE`）。
  却下した案：別の画面を作る——同じ判断（もう手元にある・ぶつかる・GitHub に同名）を2か所に持つ。枠の中では
  題・「やめる」・「Project も作る」を出さない（core の下の段が作る）。もう手元にあるなら「この場所を使う」で
  clone せずに返す
- **そのフォルダを Root にした Project が既にあれば、新しくは作らずそれを開く**（閉じていれば再開）——core が自分の
  一覧で調べる
- Repositories を無効にした（instance に宣言が無い）ときにタブが出ないことは、core の単体試験で見た（名乗る Module が
  無ければ空）。E2E では core の起動し直しが要るので見ていない

## 踏んだこと

- **段階3のコードの不具合を、間欠で落ちる試験で見つけた**（規則6）。「失敗の分類」の試験が 10回中2回落ちた。
  clone の出力の溜めすぎ防止が、行に分ける前に上限で切っていたので、`fatal:` の行が切られて分類が「分からない」に
  なっていた。最初の直し（上限を行に分けた後に）で 20回中11回に悪化——改行の来ない1行が上限を越えたまま残った。
  行に分け、残りの溜まりを上限で切り、1行ごとにも 2000字で切る形にして 20回中0回
- 行の「…」が新しいダイアログの後ろで開いたまま残り、閉じたあとのクリックを遮った（プローブの撮影で見つけた）
- 子を入れ替えるときに「出さない」を `null` で渡し、画面に「null」の字が出た（プローブの撮影で見つけた）
- **壊して落ちるかを見る道具が嘘をついた**——2つ。どちらも「全部生き残った」「落ちた」を見て気づいた（規則15-6）
  - `node --test` の既定の出力（spec 形式）に `not ok` が無く、壊しても「落ちない」と読んでいた。TAP にし、壊さない
    写しで「全部通る」を先に見るようにした
  - **`npx tsc` は package.json のある場所へ移ってから走る**——写しの tsconfig ではなく本物の tsconfig でビルドし、
    **壊した版を本物の `dist` に書いていた**（その間に背景で E2E が走っていた）。気づいて `dist` を作り直し、
    E2E もやり直した。tsc を直接呼び、写しの外に書いたら止まるようにした
- 並行するセッションが同じ作業ツリーで core の `app.ts` を変えてコミットした。E2E を壊すときに共有のファイルを
  写して戻すやり方は、その間の相手の編集を戻しうる——今回は消していないことを確かめたが、以後は使わない

## レビューを受けて直したこと（2026-10-03、Fable のレビュー 15件）

核心の安全（リンクを辿らない・置き場の外を断る・確かめをサーバ側で決め直す・人の刻印）は効いていると確認された。
直したのは数え漏れ・消し方・画面の縛り。上の節のうち、ここで変わったものは仕様（§2.4）が正。

- **タグだけが指すコミットを数えていなかった**（プローブで確認された、高）——数を `--branches --tags` の重ねない合計に。
  どのリモートにも無いコミットを指すタグを名前で出す（注釈つきタグは剥がして見る）。ブランチ・タグの外の ref（notes・
  `refs/original` 等）にだけあるコミットは、あれば `problems`（数は出すが中身は見ていない）。ref が多いリポジトリで
  引数が溢れないよう、名前を並べずに `--exclude=… --all` で
- **reflog にだけあるコミットは `problems` にしなかった**（レビューの案からの変更）。amend・rebase の前のコミットは
  ほとんどのリポジトリの reflog にあり、あるたびに名前を打たせると「何も無ければ1回」が実質無くなる。数えずに、
  画面と仕様で毎回「数えていない」と言う（LFS の未 push・ignore 済み・submodule の中と同じ扱い）
- **リモートに無いブランチ**：`endsWith("/x")` が `origin/feature/x` に当たっていた。リモートの名前を設定から読み、
  `refs/remotes/<リモート>/<ブランチ>` の完全一致に。上流はいまリモートの ref としてあるものだけ（消えた上流は無い）
- **submodule**：`.gitmodules` が無くても index に mode 160000 があれば言う（`ls-files --stage`）。出力の上限は数える
  ときだけ 256MB に上げた（ファイルの多いリポジトリで溢れて「数えられない」にならないように）
- **下のフォルダを Root にした Project**（monorepo）も「使っている」に数え、閉じる対象にも入れる
- **本体を先に消した worktree** は git から見て「git でないフォルダ」になり消せなかった。`.git` が指す記録の場所が
  無いものを「本体の無い worktree」とし、数えられないと言って名前を打たせて消せるように
- **マウント**：`fs.rm` はマウントを越えて消す。`/proc/self/mountinfo` でフォルダそのもの・中のマウントを見つけて断り、
  消すときも自分で歩いて（リンクはリンクだけを消す）別の dev の手前で止まる。**試験で本物のマウントは作れない**
  （この環境では非特権のユーザー名前空間が使えない——`unshare -rm` が uid_map の書き込みで断られる）ので、マウントの
  一覧の場所と歩くときの lstat を差し替えて見た。本物の bind mount での確認は残っている
- **worktree の記録**：`git worktree prune` は見えていないだけのほかの worktree の記録まで消す（実測——外付けの場所に
  ある worktree 等）。`git worktree remove --force -- <場所>` は、フォルダが無ければその1つの記録だけを消す（git 2.43 で
  実測。別の消えた worktree の記録は残った）
- **画面の縛り**：人が断った（作らず・閉じずに閉じた）あと、同じ Module の画面からの同じ頼みは 30 秒受けない
- **用意されたフォルダにも広い根の警告**（高）：第三者の Module が `/` や home を返しうる。E2E の core では置き場の下が
  「広い」にならないので、**画面が用意されたフォルダについて host に聞くこと**を見たうえで、その答えだけを差し替えて
  警告が出るのを見た（広さの判断そのものは core の root-scope の試験）
- 名乗りの名前（1〜40字・core のタブ名と同じなら Module を添える）・説明（200字）、返されたパスの揃え方（`..` は断る）、
  アカウントの指定中に行が外されたら成功にしない、削除のあと一覧の読み直しより先に Project を閉じる案内へ
- **直さなかったもの**：第三者の画面からの close-projects を断ることの E2E——E2E に任意の頼みを送れる第三者の Module が
  無い。決まり（会話の中の画面は押した直後だけ・断ったあと30秒）は画面の lib の試験で見ている
