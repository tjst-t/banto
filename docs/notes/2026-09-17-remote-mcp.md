# URL に繋ぐ Module（リモート MCP）（2026-09-17）

仕様は `docs/specs/v4-architecture.md`「URL に繋ぐ Module（リモート MCP）」と
`docs/specs/v4-security.md` の脅威表（「Module が machine の外へデータを出す」）、
画面は `docs/specs/v4-frontend.md` §6.22。
ここには**なぜそうしたか・却下した案・実際に踏んだもの**を残す。

## なぜ要ったか

「AccuWeather を繋ぎたい」に、`npx` で動く stdio サーバとして答えようとして
詰まっていた（2026-09-16 の実測——`npx` が閉じ込めの外にあって起動できない）。
**外部サービスの MCP は、たいてい URL でしか繋がらない**（プロセスを配らない）。
受けなければ、その一群まるごとに答えられない。

## 何が他と違うのか

他のすべての Module は「banto がプロセスを起こす」前提で設計されている。
リモートはそこが崩れる：

- **閉じ込めが掛からない。** Landlock は自分が起こしたプロセスにしか効かない
- **呼ぶたびに引数が外へ出る。** 会話から来た内容を含む
- **コードが更新されても、こちらは気付かない**（`codeId` は URL しか見ない）

なので「閉じ込めを外せるようにする」ではなく、**閉じ込めの代わりに置く柵**を
決める、という形にした。柵は**人の明示の承知**——これは技術的な防御ではなく
判断の記録だが、**ここで守れるのはそれしかない**（相手のサーバで何が起きるかを
banto は一切観測できない）。だから「弱い柵で守れているふりをしない」ことのほうを
徹底した：閉じ込めの札を出さず、一覧に「外へ送ります：<host>」を出す。

## 却下した案

### リモートの tool を `agent` 可視の既定に載せない

2026-09-15 の脅威表に、入れるときの候補としてそう書いていた。**採らなかった。**

理由：**閉じ込めた stdio の第三者 Module も、ネットワークは素通しで使える**
（Landlock は通信を縛らない——この表の「Landlock が縛らないもの」）。つまり
「外へ出しうる」はリモート固有ではない。リモートだけ可視性の既定を変えても
**守れる範囲は広がらず、規則だけが2つになる**。

同じ理由で **Project ごとの選択の既定も反転させなかった**。
「どの Project が外部へ届いてよいか」は**リモート固有ではない問い**として、
未決に残してある。

### リモートにも閉じ込めの札を付ける（`confinement` を書かせる）

貼り付けた設定の既定に `confinement` を入れると型が揃って実装は楽だったが、
**掛からないものを「掛かっている」と読ませる**ことになる（規則13）。
宣言に書いてあったら**断る**ようにした。

### `${secret:…}` を URL にも置けるようにする

やめた。URL は**経路上の記録に残る**（代理サーバ・アクセスログ・エラー文）。
置けるのは `headers` の値だけ。

### リモートにも中継の合言葉を渡す

やめた。合言葉は「どの Module からの呼び出しか」の身元そのものなので、
第三者のサーバに持たせると**そのサーバが banto の中の Module を呼べる**。
結果として**リモートは `dependsOn` を書けない**——書けるのに効かない形には
しない（規則13 の裏）。

## 実際に踏んだもの

### 1. 資源を持たないサーバで、設定画面がまるごと 500 になった

`cf-docs`（Cloudflare Docs）を繋いだ直後、`GET /api/ui-settings` が
`MCP error -32601: Method not found` で落ちた。**実際の公開サーバは `tools` しか
名乗らないことが多く、`resources/list` を投げると断る**。banto は全 Module に
無条件で投げていた。

**MCP は capability negotiation を持っている**（規則12——名前がある機構）。
`getServerCapabilities()` が `resources` を名乗っていなければ投げない、に直した。
**握りつぶしはしない**——名乗った相手が失敗したらそのまま投げる（1本の故障が
「資源ゼロ」に化けると、画面から何も見えなくなる）。

> これは**リモートだから起きた**のではなく、**リモートを繋いだから見つかった**。
> 同じことを名乗らない stdio サーバでも起きていたはず。

### 2. `secretsAllowedFor` がリモートを閉め出していた

「閉じ込めの無い外部 Module に秘密は渡さない」という 2026-09-16 の規則に、
リモートがそのまま当たった。**当たり方が間違っている**——あの規則の理由は
「**こちらで動く**第三者のコードに鍵を渡すと、その鍵でこちらの何を触られるか
分からない」だった。コードがこちらに無いなら、その心配は無い。

リモートは通し、代わりに**秘密を引く前に egress の承知を見る**形にした
（`connectRemoteDeclaredModule` の順序がそうなっている）。

### 3. 試験用のリモートサーバは、1リクエストにつき1組

`sessionIdGenerator: undefined`（stateless）で `McpServer` と
`StreamableHTTPServerTransport` を**使い回すと2通目の POST が 500 になる**。
リクエストごとに作る形に直した（SDK の作法どおり）。

## 見たこと（規則1・規則14）

**本物の公開サーバで実測**（`banto/packages/core` を使った30秒のプローブ）：

| 相手 | 結果 |
|---|---|
| `https://docs.mcp.cloudflare.com/mcp` | 繋がる（tools 2本）。**`search_cloudflare_documentation` を banto の中継越しに呼んで 15,634 文字の答えが返った** |
| `https://mcp.deepwiki.com/mcp` | 繋がる（tools 3本） |
| `https://mcp.context7.com/mcp` | 繋がる（tools 2本） |
| `https://remote.mcpservers.org/fetch/mcp` | 繋がらない（`fetch failed`） |

**E2E は本物を叩かない**（`e2e/specs/remote-mcp.spec.ts`）。相手は試験が立てる
ローカルのサーバ（`e2e/remote-mcp-fixture.ts`）——**外の都合で落ちる試験は、
機構の故障と見分けが付かない**（規則6）。見ているのは：

1. **承知していなければ足せない。** 断り文句に**相手の名前**が出る。断ったのに
   登録だけ残っていないことも見る
2. 承知すれば繋がり、**AI から実際に tool が呼べて、中身が返る**
3. **`${secret:…}` がヘッダで相手に届く**——**受け取った側**（fixture）から
   確かめる（規則1——送った側の自己申告を信じない）。同時に、取り出した設定に
   秘密そのものが混ざっていないことも見る
4. **消したら承認も忘れる**——同じ名前・同じ URL でも聞き直す

## 残しているもの

- **リモートは「いつコードが変わったか」を観測できない。** `codeId` は URL しか
  見ないので、相手の実装が入れ替わっても承認は生き続ける。stdio では
  `command`/`args` の印で捕まえていたところが、ここでは捕まえられない
- **「どの Project が外部へ届いてよいか」は未決**（上記のとおり、リモート固有の
  問いではない）
- **OAuth を要る相手には繋げない。** いまは静的なヘッダだけ。実際の
  `AccuWeather`（claude.ai のコネクタ）はここに当たる。公開の3本
  （Cloudflare Docs・DeepWiki・Context7）は認証なしで繋がる
- **タイムアウトと再接続を何も決めていない。** 相手が遅い・落ちているときの
  扱いは、いまは SDK の既定のまま
