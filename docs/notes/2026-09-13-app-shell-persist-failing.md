# E2E が人のフロントを借りていた——`app-shell-persist` が落ちた真因（2026-09-13）

**直した。** 症状は `app-shell-persist` の失敗だが、**原因は試験環境の作りのほう**。

## 症状

```
specs/app-shell-persist.spec.ts:17 面をまたいでも、外枠（レール）は作り直されない
  data-persist-probe が navigation 後に消えている（AppShell が作り直されている）
specs/app-shell-persist.spec.ts:49 開いている「新しい Project」は、面を移っても入力ごと残る
  ダイアログごと消えている
specs/sidebar.spec.ts:28
  Execution context was destroyed, most likely because of a navigation（単独では通る＝巻き添え）
```

3つとも**同じ1つの症状**——クライアント側のルーティングではなく、**ページ全体の
再読み込み**が起きていた。Next はチャンクを取れないとハードナビゲーションに落ちるので、
React のツリーが作り直され、DOM に付けた印もダイアログも消える。

## 真因

**E2E はフロントを新しく起こさず、人が使っている 4175 を借りていた**
（`reuseExistingServer: true`）。`banto.tjstkm.net` が向いている先そのもの。

```
banto.tjstkm.net → 127.0.0.1:4175 ← E2E もここを借りる
```

4175 は 2026-09-07 から**本番ビルド配信**（`next build` + `next start`）。
`next start` は**起動時に読み込んだビルドを配り続ける**ので、開発中に
`npm run build` を回すと**配っているものとディスクが食い違う**。

実測：プロセスは 04:28 起動、`.next/BUILD_ID` は 05:33 更新——**1時間ずれていた**。

つまり **人の画面を壊しながら試験していた**。試験が落ちたのは結果にすぎない。

## 前提が違っていた

`e2e/config.ts` にはこう書いてあった：

> Next 16 はディレクトリごとに1つしか dev サーバを許さない（別 port でも
> 二重起動を拒否する）——なので専用 port を別に起こすのではなく、既存の
> （4175、常時起動している前提）をそのまま使う

**成り立っていなかった。** 別 port で2つ目を起こして、**両方 200 で同時に動いた**
（Next 16.3.3 で実測）。本番の 4175 にも影響しなかった。

## 直したこと

- `next.config.ts` に `distDir`（`BANTO_NEXT_DIST_DIR ?? ".next"`）
  ——**人の `.next` を書き換えない**
- E2E は **port も dist も実行ごとに分けて自分で起こす**（core と同じ規律）。
  `reuseExistingServer: false`——**黙って相乗りしない**
- **本番ビルドで試験する**（`next build` + `next start`）。dev で試験すると、
  人が見ているものと違うものを見ることになる

## 測った結果

| | 借りていたとき | 独立させたあと |
|---|---|---|
| `app-shell-persist` ほか4件 | **4/4 落ちる** | **4/4 通る** |
| 1件目の所要 | 11.6s（再読み込みで待たされる） | **1.5s** |

## 学び

**「間欠だ」で止めずに、環境の依存関係まで遡る。** 最初は
「frontend の remount 条件」を疑ったが、層が違った。決め手になったのは
**プロセスの起動時刻とビルドの更新時刻を並べて見たこと**——コードを読んでも
出てこない種類の食い違いだった（規則1——測る前に犯人を決めない）。

**そして、試験が人の環境を壊せる構造そのものが問題だった。** 試験は
人の環境を借りない（規則7 の裏返し——自分の都合で人の側に触らない）。

## `distDir` の渡し方で、さらに2つ踏んだ（記録）

最初は**実行ごとに違う絶対パス**（`/tmp/banto-e2e/<pid>/next`）を渡した。2つ壊れた：

1. **Next は絶対パスをプロジェクト相対として解釈する。**
   `apps/frontend/tmp/banto-e2e/…` が作られ、**869 ファイルを commit しかけた**
2. **Next は `tsconfig.json` の `include` に置き場を書き足す。**
   実行ごとに違う名前だと、**回すたびにリポジトリが汚れて増えていく**

なので **相対パスの固定名（`.next-e2e`）** にした。書き足しは2行で止まり、
それ以上増えない。**実行ごとに分けないので、同じワークツリーで2つの E2E を
同時に回すとビルドを奪い合う**——port とデータは分かれているので混ざりは
しない。承知のうえの割り切り（そのかわりビルドキャッシュが効く）。

**隔離のつもりで渡した値が、隔離になっていないことがある。** 渡したあと、
**どこに何ができたかを見る**（`git status` を見て気づいた）。

## 途中でやった失敗（記録）

「別 port で起こせるか」を確かめるとき、`BANTO_NEXT_DIST_DIR` を渡したが
**そのときはまだ `next.config.ts` が読んでいなかった**ので無視され、
**`.next`（人の本番ビルド）に dev の成果物を書き込んだ**。
`npm run build` で作り直して復旧した。

**確かめるための操作でも、人の環境に書く可能性がある。** 隔離するつもりの
変数が効いているかを、書き込む前に確かめる。
