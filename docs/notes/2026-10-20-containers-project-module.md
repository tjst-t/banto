仕様は `docs/specs/v4-security.md` §1「別のサーバの中のコンテナ」の「コンテナの作りと上限」の「実装済み（#368）」。ここは決め方と

## 実装者が決めたこと（人に上げる）

- **`containers` との間で移すのを断った**（仕様は「移すときも根の重なりを断る」と書くが、移す手順そのものは向こうで VM の
  ユーザーとして tar の展開・rsync の受け手・`git worktree repair` をする）。条件3（見せたフォルダに書くのは中から）を満たさない
  まま通すと、コンテナが使えるようになった今は中の AI が仕込んだ symlink・`.git/config` を VM のユーザー（incus グループ＝管理用の
  口に届く）で辿る。移す形を中から書くように作り直すまで（#369 の範囲）、`targetRuntimeProblem` で名指しして断る
- **流れの口・鍵の窓口も、作るまで断る**：流れの口（`-L`）の先は Module の置き場の中の待ち受けで、sshd は VM のユーザーとして
  symlink を辿って繋ぐ——中の AI が `/var/lib/incus/unix.socket` への symlink に差し替えられる（#365 の測定の 2. と同じ形）。
  鍵の窓口は VM の置き場の `s` に出ても中からは見えないので、黙って転送しても使えない
- **中のユーザーを作る**：`images:ubuntu/24.04` には uid 1000 のユーザーが居ない。起動役は `/run/user/<uid>` のユーザーの systemd を
  使うので、`getent passwd 1000` が無ければ `banto` を作る（この機械では host の uid と同じ番号のユーザーが中に居ないことも
  あるが、そちらは起動役を使わないので今のまま）
- **上限の実行場所ごとの上書きはまだ無い**（VM の資源から既定の決め方で計算するだけ）

## 踏んだもの

- **`mkdir -p` は途中の symlink を辿る**：Module の置き場を作る台本を「作ってから `cd -P` で辿った先が元と同じか」で確かめる形で
  書いたら、単体試験（途中に外への symlink）で symlink の先に `deeper` ができていた——確かめる前に作ってしまう。根から1段ずつ
  `-L` を見てから `mkdir` する形に直した
- 偽の ssh に環境変数で偽物の置き場を渡そうとしたら届かなかった（`sshEnv` が PATH・HOME 等しか渡さない——本物と同じ）。偽物の
  台本にパスを書き込む形にした

## レビューの指摘（2026-10-20）：配布物を差し替えたあと、中から空に見える

- registry から取ってきた配布物は、VM で `rm -rf <dir> && mv <staging> <dir>` とフォルダごと差し替える。そのフォルダは
  もうコンテナに読み取り専用の disk device で付いていて、`ensureDisk` は元のパスが同じなら付け直さない——中は消された古い
  inode を見続け、版を上げた直後に Module が中で起きられない（コンテナを起こし直すまで直らない）。この機械の host-container は
  その場に書くので付いたままで生きている——containers にだけ出る不具合だった
- 直し方：`syncPackageDir` は置き換えたかを返し、置き換えたら `ensureDisk(..., { remount: true })` で同じ名前の装置を外して
  付け直す。単体試験は packageDir が無い形しか通していなかったので、偽の incus に「付けたときの inode を覚える」を足し、版を
  上げたら付いている inode が今のフォルダのものかを見る試験を足した（直しを外すと落ちることを確かめた）

## レビューの指摘（2026-10-20、2回目）：ほかの Project が差し替えた分を拾えていない

- 1回目の直し（bb507c69）は「この接続が置き換えたら付け直す」だった。配布物の置き場（`<置き場>/module-packages/<Module 名>`）は
  Module 名だけで決まり、同じ VM の全 Project で共有——p1 の接続が差し替えると、p2 の接続が次に通ったときは VM のフォルダが
  もう新しい版で、置き換えずに false を返し、p2 のコンテナは消された古いフォルダを見たままだった
- 直し方：置き換えたかではなく、**コンテナが今の VM のフォルダを見ているか**で決める。用意するたびに1往復で VM の
  `stat -c %i <dir>` と `incus exec <c> -- stat -c %i <dir>` を比べ、違えば `ensureDisk(..., { remount: true })`。中にまだ
  付いていない（中で引けない）なら付けるのは `ensureDisk` に任せる。bind mount は付けたときのフォルダ（inode）を見続け、
  消したフォルダの inode は付いている間は使い回されないので、比べるのは番号だけでよい（実機の btrfs の上で同じに見えるかは
  banto-ct-test で確かめる）
- 試験：偽の incus の `stat` は付けたときの inode を返す。2つの Project が同じ配布物を使い、p1 で版を上げたあと p2 を用意すると
  付け直す・そのあとは付け直さない。1回目の直しの形に戻すとこの試験だけが落ちることを確かめた

## 試験の環境の依存（2026-10-20）

- 決まったテストのコマンドが、この機械では `socket-dir.test` の2本で落ちていた（#368 では触っていないファイル。main でも同じ）。
  試験が置き場を `os.tmpdir()` の下に作り、ここでは TMPDIR が約 120 バイトあるので、「`s` に収まる」はずの置き場がそれだけで

  TMPDIR を変えずに通した
