# 2026-10-05 止めても中継の承認カードを会話に残す（Backlog #213 の続き）

9674c2c9 では、承認カードが出ている間に止めると、止めたターンを記録から組み直すときにカードが消えていた。
ユーザーの決定：**「止めたことを忘れそうなので残してほしい」**——消さずに答え済みの形で残し、開き直しても残す。
決まったことは `docs/specs/v4-frontend.md`「Module 間中継の承認」（さらに続き）と `docs/specs/v4-architecture.md`
「止めたターンの記録」。

## 確かめたこと

- 中継のカードは、どの決着（人が答えた・host が畳んだ・ターンが先に終わった・止めた）でも、会話を記録から組み直すと
  消えていた——記録（`MessageEntry`）には文と画面つきの tool の呼び出ししか載らない。止めたときだけでなく、
  ターンが終わって開き直したときも同じ（`backlog.spec.ts` で、開き直すとカードが0枚になっていた）。仕組みは1つなので揃えた
- 止めたときの答えは、すでに「人がターンを止めました」だった（`settleStoppedTurn` がこのターンの判断待ちを畳む）。ただし
  畳むのは CLI を止めたあとで、その前に CLI が去ったことを host が見て（a4a4ab57）「承認を聞いた呼び出しが、人が答える前に
  終わりました」で先に畳むことがあった——どちらになるかは競争
- 記録に残したカードが最初、開き直したあと見つからなかった：会話の「N tool calls」のまとまりは、答えを待っている間だけ自動で
  開き、組み直した会話では畳まれて始まる。カードはその中にあった（host は正しく返していた——30秒のプローブで確かめた）

## 決めたこと

- **記録には判断待ちの id だけを残す**（`MessageEntry.judgmentIds`、`message.appended` の `judgmentIds`）。中身（宛名・答え）は
  受信箱の Event Store にすでにあり、写すと食い違う（規則3）。`GET /api/threads/:id` が受信箱から引いて `judgments` として添える。
  画面に id の並びは渡さない
- 書くのはターンを走らせている側（`turn-runner.ts`）——ターンの外から来た判断待ち（side event）のうち `source: "relay"` だけ。
  Project をまたぐメッセージの承認も同じ道で来るが、指示の範囲（中継の承認）に留めた。tool の承認（canUseTool）も残していない
- **止めたときの言葉は「人がターンを止めました」のまま**（足さない）。ユーザーの例は「止めたので答えませんでした」だったが、
  同じ出来事（人が止めた）で tool の承認にはもうこの言葉が残っていて、言葉が2つになると記録を読むときに別の出来事に見える。
  `RELAY_CALL_ENDED_REASON`（聞いた呼び出しが終わった）は「人が止めた」ことを言わないので使わない
- 競争をなくす：止めたら、CLI を止めるより**先に**このターンの判断待ちを「止めた」で畳む（`closeRaisedJudgments`）
- **組み直した会話では、答え済みのカードは「N tool calls」の中に畳んで出す**。最初は「判断待ちのカードを含むまとまりは開いて
  出す」にしたが、`turn-reattach.spec.ts` が落ちて、仕様に既に決まりがあると分かった（v4-frontend.md の流し直しの節：
  「答え済みの判断は、ほかの tool 呼び出しと一緒に畳んで出す（答えを待っているものだけが開いて出る）」）。黙って上書きせず
  （規則8）決まりに合わせた。止めた印（「ここで止めました」）は本文なので畳まれずに見える。**開いて出すかはユーザーに上げる**

## 却下した案

- **カードの中身ごと記録に写す**：受信箱と二重になる。答えが後から付く（host が畳む）ので、写した側を書き換える道も要る
- **記録に載せず、画面が受信箱の判断待ちから会話の位置を推して描き足す**：2026-09-26 にやめた形（受信箱が変わるたびに会話を
  作り直し、送信が消えた）。位置も推測になる
- **止めたときの言葉を新しく足す**：上の理由

## 試験

- 単体：`turn-stop.test.ts`（CLI を止めた瞬間には「止めた」で畳まれている／カードの id が止めた印と同じ発言に残る／中継でない
  ものは残さない）、`app.test.ts`（Thread を返すとき受信箱の中身と答えを添え、id の並びは返さない）
- E2E：`relay-cards.spec.ts`——止めたらカードが「回答：人がターンを止めました」で残り、開き直しても残る。受信箱で答えたカードも
  開き直して残る。`backlog.spec.ts`——ターンが先に終わって畳まれたカードが開き直しても残る
- 戻すと落ちる：記録に残す（E2E・単体）、CLI より先に畳む（単体）

## 試験で見つけた、直していない間欠的な失敗

`delivery/thread-messages.test.ts` の「止められたら待つのをやめて断り、判断待ちも畳む」が、ときどき落ちる。判断待ちを畳む
書き込み（`answerJudgment`、投げっぱなし）を 10ms 待つだけで見ているため。この直しの前の版（b930fa05）でも同じ assertion で
落ちた（交互に20回ずつ流して、前の版 2/20・この版 5/20）。この直しはその道に触っていない。原因は待ち方（規則6）なので、
記録だけ残す

`turn-reattach.spec.ts` の「判断待ちに答えたあとに開き直しても…」が、ほかの spec と同じ回で1度だけ、最初の承認カードが60秒出ずに
落ちた（325行目。この直しが触っていない tool の承認のカード）。同じ組み合わせでもう1回・単独で1回流して、どちらも通った。
2回中1回で、原因は調べていない（規則6：記録だけ残す）

`background-work-human.spec.ts` の「待たずに頼みました」が2つ見えて落ちる失敗（2026-10-05-relay-card-followups.md で記録したもの）も
この回で何度か出た。調べたこと：trace では、サブエージェントの中継の承認（subagent → vault-directory の lookupAlias、main の
1ecc4ab1 から出る）のカードが出ている間に tool のまとまりが自動で開き、`runSubagent` の結果がまとまりの中と AI の文の
2か所に見えていた。記録にカードを残すこの直しを外した版でも5回中1回落ち（main（aeb70fae）は5回中0回、前の版は5回中1回）、
この直しが持ち込んだものではないと判断した。直していない（規則6：記録だけ残す）
