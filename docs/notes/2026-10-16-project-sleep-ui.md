# スリープの画面（Backlog #355 project-sleep-ui）——実装で決めた細部と残したもの

2026-10-16。仕様は v4-frontend.md §6.43「スリープ」（origin/main）、見本はモック `fork/project-org`。

## 実装で決めた細部（§6.43 に書いていないところ）

- **「起こしています」の間＝この画面が `modules/prepare` を投げて返るまで**（`lib/backend/project-waking.ts`）。host の
  `project.woke` は prepare の頭ですぐ積まれるので、行は先にグループへ戻り、Module が立つまでそこで「起こしています」を出す。
  会話の上の帯は、それに加えて「眠っている写しのままターンが走っている」（送って起こした・届いたもので起きた）間も
  「起こしています」——起きた知らせ（`projects.changed`）が届けば消える
- **prepare が返ったら一覧を host に合わせてから印を外す**。逆だと、一瞬「スリープ中です」の帯に戻って見える
- **眠らせる手順は1つ**（`components/banto/shell/use-sleep-project.tsx`）：sleep-preview の `blockers` があれば理由を toast で
  1行出して眠らせない → `stops` があれば小窓 → POST。押すまでの間に断られたら（409）その理由。行の「…」・「スリープ中」への
  ドラッグ・グループの「中の Project を全部スリープに」が同じ手順を通る。全部スリープにで止まるものがある Project が混ざれば、
  小窓は1枚で「名前：止まるもの」を並べる
- **「スリープ中」の見出しは、眠っている Project があるときだけ出す**（モックと同じ）。だから眠っているものが1つも無いときは
  ドラッグで眠らせる先が無い——行の「…」から眠らせる
- **スリープ中の行の「閉じる…」は、その Project の設定の「一般」を開く**——閉じる確かめの小窓はそこにある（同じ手順を通す、
  規則3）。行に別の小窓を作っていない
- **スリープ中の行の「グループへ移す」は眠ったまま入れ先だけ変える**（起こさない）。ドラッグでグループへ落としたときだけ起こす
- **眠っている Project の設定**：Module を通る節（Module の設定・Skills・Module 一覧など）の上に「眠っています。起こすと見られます」
  と「起こす」。名前・根・閉じる（一般）と Memory は Module を通らないので出さない。起きたら（どこで起こしても）設定画面の一覧を
  取り直し、節を作り直す（Skills は開いたときに1回取るだけなので）
- **Module の画面（ModuleCanvas）が 409 asleep を受けたら**、同じ「眠っています・起こす」を出し、起こしたら読み直す
- **`/` から先頭の Project へ飛ぶとき、眠っているものは飛ばす**（起きているものがあれば）——開くと起きるので
- Command Palette は眠っている Project の下の行に「スリープ中 · 選ぶと起こして開きます」（行き先は今どおり `/p/<id>`、
  開いた画面の prepare が起こす）
- 資源の画面は `sleeping` を「スリープ中」の1行、`asleep` の付いた行に「スリープ中（自動化のため一部起きています）」

## 残したもの（別のタスク）

- 「スリープ中」の見出しの「…」（14日開いていない Project を——聞く／自動／何もしない）と、眠らせるかの問い——`projects.autoSleep`
  がまだ無いので出していない（規則13、Backlog #356）
- 自動化のため一部起きている印（稲妻）・確かめの小窓の「〈Module〉は自動化のため止めません」と、Service の文を出さない分け——
  Backlog #357
- 受信箱の「自動では起こしませんでした」——host の側がまだ出していない

## core の口をそろえた

- `GET /api/threads/:id/ui-resource` だけ眠っている Project で 404 unknown module を返していた。兄弟の口と同じ `refuseIfAsleep`
  を入れて 409 asleep に（app.test.ts の「眠っている Project：設定・入口・…」に足した）
