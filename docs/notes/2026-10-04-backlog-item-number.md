# Backlog の項目に通し番号（2026-10-04）

仕様は `docs/specs/v4-modules.md` §4.4「番号」。ここは決め方と、実装で選んだこと・選ばなかったこと。

## ユーザーが決めたこと

- slug の `id` は残し、`number`（正の整数）を足す。画面は `#42`
- 振るのは「いまある最大＋1」、閉じた・やめた項目の番号も使い直さない。振るのは compare-and-swap の中（やり直しで振り直す）
- 重なり・0 以下は検証で断る（前からある問題は関係のない変更を止めない）。number の無い項目は読める。人も AI も書き換えられない
- AI の tool は id の代わりに番号（42・"#42"）も受ける。返り値の文に `#42`
- 今ある項目への一度だけの振り直しはスクリプトで。順は「作った順」——createdAt の無いものが先で、その中は
  Backlog の形に移す前の docs/tasks.json（`c38e1aff^:docs/tasks.json`）の並び

## 実装で選んだこと

- **番号の無い項目は `number` の欄を書かない**（`null` を書かない）。振る前に1件でも書くと、全部の項目に `"number": null`
  の行が増える差分になるため。読むときは無い＝`null`
- **文字列はまず id、無ければ番号**として読む。id の決まりは数字だけの id を許すので、`"42"` が id のこともある。
  `"#42"` は id になれない（`#` が使えない）ので曖昧さは無い
- **番号は書く直前に読んだ一覧で引く**——AI が番号で依存を指しても、ブランチには id で書く（形は変えない）
- **振り直しで、古い一覧と id が合わなかった行は同じ題の項目に合わせる**。元の docs/tasks.json には
  `module-registry-install` が2行あり、移すときに後のほうが `module-registry-install-npm` に付け直された。id だけで
  合わせると、これは「元のファイルに無い」側（後ろ）に落ちて、作った順が崩れる。題で合わせると元の位置（#100）に入る
- **画面の「番号で開く」は絞り込みの小窓の先頭の欄**。いまの画面に一覧の検索は無いので、`#` キーでその欄を開く。
  触れる画面（キーの無い携帯）でも「絞り込み」から同じ欄に届く

## 選ばなかったこと

- **次の番号を文書に持つ**（`nextNumber` の欄）：最大＋1 は一覧から導ける（規則3）。消す tool が無いので、最大の項目が
  消えて番号が戻るのは、人が git で手で消したときだけ
- **振り直しで番号のある項目も振り直す**：番号は人と AI が既に使っている指し方になりうるので、振ったものは動かさない

## 振り直しを手元の写しで試した結果

`git clone --mirror` した写しの backlog ブランチ（eb4c9cb7）で `--legacy 'c38e1aff^:docs/tasks.json'`：
201 件に #1〜#201。createdAt の無い 168 件が #1〜#168（`module-registry-install-npm` は #100）、createdAt のある 33 件が
#169〜#201。差分は各項目に `"number"` の1行が増えるだけ（+201 行）。2回目は「もう全部番号があります」で何も積まない。
