# テーマの作り方

banto の見た目は**トークン（CSS 変数）**でできている。面の CSS には分岐が1つも無いので、
**変数を上書きするだけで見た目を替えられる**——色だけでなく、書体・字の段・余白・角・
高さ・行間、それに「番頭の印」「符牒の札の置き方」「面の敷き方」といった組み方の役まで。

作り方は2通りあり、**できることが違う**。

| | 置き場所 | 作り直し | できること |
|---|---|---|---|
| **持ち込み**（おすすめ） | `<BANTO_DATA_DIR>/themes/` | **要らない** | **トークンの上書きだけ** |
| 組み込み | `packages/banto-web/src/theme/` | 要る | トークン ＋ **形の層**（面のクラス名を名指し） |

**持ち込みでセレクタは書けない**（ADR-0012 決定54）。`:root` に変数を置く規則以外は、
画面側で落として理由をログに出す。意地悪ではなく、**こちらの改装で黙って壊れないようにする**
ため——面のクラス名を名指しした家が崩れたことを見張れるのは、リポジトリの中にある家だけ。
組み方まで変えたいときは §4 の組み込みにする。

---

## 1. 持ち込みのテーマ（作り直し不要）

ファイルを2つ置いて、画面を開き直すだけ。

```
<BANTO_DATA_DIR>/themes/
├── themes.json      ← 台帳（どんな家があるか）
└── sumizome.css     ← 中身（変数の上書き）
```

`BANTO_DATA_DIR` の既定は `/var/lib/banto`（systemd 運用時）。

### 1.1 台帳（themes.json）

```json
{
  "families": [
    {
      "id": "sumizome",
      "name": "墨染",
      "description": "墨の濃淡だけで組んだもの。色を持たない",
      "changes": "色",
      "css": "sumizome.css",
      "contract": 1,
      "variants": { "light": "sumizome-light", "dark": "sumizome-dark" },
      "swatch": {
        "light": ["#F2F1EE", "#8C3A2E", "#3A3A3A"],
        "dark":  ["#17181A", "#D97A68", "#B9BCC0"]
      }
    }
  ]
}
```

| 欄 | 何を書くか |
|---|---|
| `id` | 家の識別子。英小文字・数字・ハイフンのみ。保存値に入る |
| `name` | 設定に出す名前 |
| `description` | 何を狙った意匠かを一行で |
| `changes` | **何が変わるか**（「色」「色と書体」など）。選ぶ前に伝わるように |
| `css` | 中身のファイル名（`themes/` からの相対） |
| `contract` | **当てにしているトークンの版**（いまは `1`）。合わないと載らない。§1.4 |
| `variants` | 明暗それぞれの `data-theme` の値。CSS のセレクタと一致させる |
| `swatch` | 設定の見本札に出す3色（地／朱／藍）。明暗それぞれ |

**明暗は必ず両方**要る。テーマは「家」で、明暗はその中の別だから——片方しか無いと、
上段の明暗ボタンを押したときに行き先が無くなる。

### 1.2 中身（sumizome.css）

`:root[data-theme="<variants の値>"]` に変数を書く。**組み込みの家を丸ごと写して、
変えたいところだけ書き換えるのが早い**（`packages/banto-web/src/theme/tokens.css`）。

```css
/* 墨染（明） */
:root[data-theme="sumizome-light"] {
  --paper:    #F2F1EE;
  --paper-1:  #FAFAF8;
  --paper-2:  #E6E5E1;
  --rule:     #DCDAD5;

  --sumi:     #1A1A1A;
  --sumi-2:   #4C4C4C;
  --sumi-3:   #8A8A8A;

  --ai:       #3A3A3A;  --ai-t:   #E4E4E4;
  --shu:      #8C3A2E;  --shu-t:  #F2E2DF;
  --on-shu:   #FFFFFF;
  --murasaki: #55465C;  --mur-t:  #E3DEE4;
  --kohaku:   #7A5A22;  --koh-t:  #EFE9DC;
  --koke:     #3E5A45;  --koke-t: #E2E8E3;

  color-scheme: light;
  --scroll-thumb: #C9C7C1;
}

/* 墨染（暗）— 同じ役を裏返す */
:root[data-theme="sumizome-dark"] {
  --paper:    #17181A;
  /* … 以下同じ並びで … */
  color-scheme: dark;
  --scroll-thumb: #3A3C40;
}
```

書かなかった変数は**組み込みの既定が残る**（`:root` に定義されているため）。
色だけ替えたいなら色だけ書けばよい。

### 1.3 契約の版（`contract`）

持ち込みの家が当てにしているのは**変数の名前**なので、こちらが名前を変えると壊れる。
そこで台帳に版を書いてもらい、**合う家だけを載せる**。

| いまの版 | 意味 |
|---|---|
| **1** | `tokens.css` にある変数の名前（`--paper` `--ai` `--banto-mark` …） |

- 版は**名前を消した・付け替えたときだけ**上がる。値が変わっただけでは上がらない
- 書いていない家・合わない家は**載せない**。理由はログに出る（`[themes] … 契約の版が違います`）
  ——半分だけ効いた家が出るほうが困るため

### 1.4 書けるもの・書けないもの

| | 例 | 通るか |
|---|---|---|
| `:root[data-theme="…"]` に変数 | `--paper: #F2F1EE;` | ✅ |
| `:root` に `color-scheme` | `color-scheme: dark;` | ✅（変数にできないので特例） |
| 面のクラスを狙う | `.shell-topbar { display: none }` | ❌ 落とす |
| 全体を狙う | `body { background: red }` | ❌ 落とす |
| 変数に素の宣言を混ぜる | `:root { --sumi: #111; position: fixed }` | ❌ **規則ごと**落とす |

落としたものは `[themes] <ファイル名>: 変数の上書き以外は使えません…` としてログに出る。

### 1.5 反映

置いたら画面を開き直すだけ。ホストの再起動は要らない（台帳は毎回読み直す）。
設定の「見た目」に並ぶ。

台帳が壊れていたら**その家だけ飛ばして**ログに理由を出す（`[themes] …`）。
画面は組み込みの家で動き続ける。

## 2. 変数の一覧

`packages/banto-web/src/theme/tokens.css` が唯一の出どころ。役ごとにまとめてある。

### 色（5役）

| 変数 | 役 | 塗ってよいか |
|---|---|---|
| `--ai` / `--ai-t` | 藍：番頭が動いている・選ばれている | 小さいものだけ |
| `--shu` / `--shu-t` / `--on-shu` | 朱：**あなたの判断待ち** | どこでも |
| `--murasaki` / `--mur-t` | 紫：止まった（失敗・エラー） | 塗らない |
| `--kohaku` / `--koh-t` | 琥珀：気をつける（期限・逼迫） | 塗らない |
| `--koke` / `--koke-t` | 苔：済んだ | 塗らない |

**この意味づけは変えないこと。** 色を替えるのは自由だが、役を入れ替えると
「朱＝あなたの番」という読み方が崩れる（spec-design §1.1）。

### 紙と墨

`--paper` / `--paper-1` / `--paper-2` / `--rule` / `--sumi` / `--sumi-2` / `--sumi-3`
／ `--code-bg` / `--code-ink` / `--shadow-rest` / `--shadow-pop`

### 字

`--t-note` 11 ／ `--t-meta` 12 ／ `--t-body` 13 ／ `--t-read` 15 ／ `--t-head` 19 ／ `--t-title` 26
／ `--ui`（道具立て） `--sho`（番頭の言葉） `--mono`（機械） ／ `--lh-body` `--lh-sho`

### 余白・角・高さ

`--s1`〜`--s8`（4の倍数）／ `--r-seal` `--r-ctl` `--r-face`
／ `--h-bar`（上段） `--h-tab`（上段の押しもの） `--h-tabbar`（キャンバスのタブの帯）
`--h-ctl` `--h-ctl-sm`

### 組み方の役（形もトークンで替わる）

| 変数 | 何が変わるか | 和紙 | 符牒 |
|---|---|---|---|
| `--face-margin` / `--face-radius` | 面の敷き方 | 浮いた紙（余白＋角丸） | 枠に嵌まったバッファ |
| `--bubble-radius` | POの吹き出しの角 | 右下だけ落とす | 一様 |
| `--banto-mark` ほか | 番頭の印 | 藍の落款「番」 | `»` |
| `--bar-bg` / `--bar-ink` / `--bar-on` / `--bar-raise` | 状態行（符牒の上段） | 使わない | 黒地の帯 |

`--banto-mark` は `--banto-mark-bg` / `--banto-mark-ink` / `--banto-mark-size` /
`--banto-mark-t` / `--banto-indent` と組。符牒の札の一辺は `--key-size`
（**出すのは `f`・⌥ のときだけ**で、これは家で変えられない）。

**ここに無い形を変えたくなったら、それは変数が足りない合図**（spec-design 第一原理）。
持ち込みではセレクタを書けないので、先に変数を増やす話になる。

### ブラウザが描くもの

`color-scheme`（**必ず書く**——書かないとスクロールバーが明色のまま浮く）／ `--scroll-thumb`

## 3. 密度や書体ごと替える

色だけでなく全部替えられる。組み込みの「符牒」がその例で、
`tokens.css` の `fucho-light` / `fucho-dark` を見るのが早い。変えているのは：

```css
  --ui: "M PLUS 1 Code", …;   /* 全部を等幅に */
  --sho: "M PLUS 1 Code", …;
  --t-body: 12px;             /* 字を一段小さく */
  --lh-body: 1.6;             /* 行間も詰める */
  --s1: 3px; … --s8: 24px;    /* 余白の刻みごと縮める */
  --r-ctl: 3px; --r-face: 4px;/* 角を落とす */
  --h-bar: 30px; --h-tabbar: 32px;  /* 帯を詰める */
```

符牒はこれに加えて**形の層**（`theme/fucho.css`）を持ち、黒い状態行・平らなタブ・
1本の罫の境目まで替えている。**そこまでやるのは組み込みだけ**（§4）。

## 4. 組み込みとして配る

全員に配りたいなら、コードに入れる。3箇所だけ。

1. `packages/banto-web/src/theme/tokens.css` に **2ブロック**（明・暗）
2. `packages/banto-web/src/theme/themes.ts` の `FAMILIES` に **1エントリ**
3. `npm run build:web`

面の CSS には触らない。触りたくなったら、まず**トークンが足りていない**ことを疑う
（spec-design 第一原理）。

### 4.1 それでも組み方を替えたいとき（形の層）

トークンで届かない組み方——黒い状態行、平らなタブ、1本の罫の境目——は、
**組み込みの家だけ**が `theme/<家>.css` を1枚持って替えられる（ADR-0012 決定51）。

- 全部 `:root[data-theme^="<家>"]` の下に閉じる。他の家へ1行も漏らさない
- `main.tsx` から**面の CSS より後に**読む
- **層に書くのは実際に変えるものだけ。** 既定と同じ値を言い直さない
- **値は書かない。** 色や寸法が要るなら、まずトークンへ出す（`--bar-bg` がその例）
- 名指ししたクラス名は `tests/theme-shape.spec.ts` が見張る。面から消えたら落ちる

## 5. 確かめること

新しい家を作ったら、この4つを見る。

1. **朱が判断待ち以外に出ていないか**（取次の数字と判断の札だけ）
2. **紫が朱より強くなっていないか**（止まったものは急がせない）
3. **明暗どちらでも読めるか**（`--on-shu` は明暗で反転が要ることが多い）
4. **スクロールバーが浮いていないか**（`color-scheme` を書き忘れていないか）
