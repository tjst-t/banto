# 入力欄に画像を貼り付けて送る（2026-09-26）

ユーザー要望「Prompt 入力ボックスにペーストで画像を貼り付けられるようにして」。
`docs/tasks.json` の `composer-image-attachment`（2026-09-06 起票・backlog）をそのままやった。
決めたことは `docs/specs/v4-frontend.md` §6.4「画像を添えて送る」と
`docs/specs/v4-architecture.md` §2.1「大きなバイト列はイベントに入れない」。ここは経緯と測ったこと。

## 出発点

- assistant-ui の入力欄は**貼り付けを最初から持っている**（`ComposerPrimitive.Input` の
  `addAttachmentOnPaste`、既定で有効）。効いていなかったのは、添付の受け皿（attachment adapter）を
  `useLocalRuntime` に渡していなかったから。＋ボタンも同じ理由で**押せないまま出ていた**
- 受け皿だけ渡すと「貼れるが AI に届かない」になる（規則13）。送る口・記録・Runner・リロード後の
  表示まで通した

## 測ったこと（プローブ、SDK 0.3.281 同梱の CLI 2.1.281、Haiku 4.5）

SDK の `query()` に user メッセージを `[{type:"image", source:{type:"base64",…}}, {type:"text",…}]`
で渡し、CLI の会話の記録（`<CLAUDE_CONFIG_DIR>/projects/…/*.jsonl`）に残った画像を調べた。

| 渡したもの | AI の答え | 記録に残った画像（＝API に送られたもの） |
|---|---|---|
| 4000×3000 PNG、2.3MB（文字＋点のノイズ） | 画像の文字を正しく読んだ | **2000×1500 JPEG、0.49MB** |
| 800×600 PNG、7KB | 正しく読んだ | **800×600 PNG、7KB（そのまま）** |
| 2600×2400 PNG、15MB（全面ノイズ・圧縮が効かない） | 正しく読んだ | **2000×1846 JPEG、0.50MB** |

**CLI は大きい画像を自分で長辺 2000px の JPEG に縮めてから送る。小さいものはそのまま。**
API の「会話の画像が 20 枚を超えたら1枚 2000px まで」の制限にも、1枚 10MB（base64）の制限にも、
CLI の段で収まる。CLI の中にも「many-image requests（2000px）を超えたら /compact を」という文言がある。

## 決めたこと・却下した案

| 論点 | 採った | 却下した案と理由 |
|---|---|---|
| 置き場 | 中身の SHA-256 を名前にして `<dataDir>/images/` に置き、イベントは名前だけ（Claim Check） | **イベントに base64 で入れる**：起動時の fold・スナップショット・`GET /api/threads/:id` がすべて画像の大きさで重くなる。スクリーンショット20枚の会話を開くたびに数十MBを返すことになる |
| 縮めるか | 縮めない | **ブラウザで縮める**：上の実測どおり CLI が同じことをする。二重にやるうえ、記録に残るものが人の送ったものでなくなる |
| 形式 | host が中身の先頭（magic number）から決める | **画面の `file.type` を信じる**：中身と違えば、AI のターンが API で落ちるまで分からない（規則3） |
| 表示の取り直し | 合言葉つきで取って `blob:` にする | **`<img src=".../api/images/:id?token=…">`**：合言葉が URL に載り、履歴・ログに残る |
| 貼り付け | 文字があれば文字、文字が無いときだけ画像 | **assistant-ui の既定**（ファイルがあれば文字を捨てて添付）：Excel・Word のコピーは文字と一緒にその絵も載るので、表を貼ったつもりが画像に化けて文字が消える。代償：Finder でファイルをコピーして貼ると、ファイル名の文字が入る（ファイルは ＋ かドラッグで） |
| 上限 | 1枚 10MB・1回 10 枚。正は host、画面は同じ値で先に知らせる | 画面が値を持たない（host の 400 だけ）：送ったあとで断られ、書いた発言ごと入力欄から消える。値の写しは食い違いうるが、食い違っても host が理由をつけて断るので黙らない |
| 復元した画像の印 | `banto-image:<id>`（`useAttachmentSrc` が見て取りに行く） | 本物の URL をそのまま入れる：取り直しを忘れた描き手が `<img>` に直接入れると、401 の壊れた絵になり原因が見えにくい |

10MB は「スクリーンショットはほぼ収まり、15MB まで CLI を通ることを実測した」の間で丸い数を取った。
10 枚は目安（claude.ai は 20）。困ったら変える。

## 細かいところ

- **画像だけの発言**（文なし）を通すため、turn-runner の「渡すものが無い」判定と人の発言の記録を、
  文が空でも画像があれば通すようにした
- **届いたもの（`<banto-delivery>`）と画像だけの発言が同じターンに乗る**と、画像は文より前に置かれる
  ので誰のものか分からなくなる。`composeTurnPrompt` に「先頭の画像 N 枚は人が添えたもの」を足した
- 閉じた Thread の概要（最初と最後の発言）で、画像だけの発言が空に見えないよう「（画像 N 枚）」にした
- E2E（`composer-image-paste.spec.ts`）は偽 Runner に「受け取った画像の形式とバイト数」を言わせ、
  **貼ったバイト数と一致するか**を見る。画像だけの発言には偽 Runner への印を書けないので、
  指示ではなく既定の振る舞いにした

## 実機（本物のモデル）で見たこと

別のデータディレクトリ・別ポートの host（4199）と画面（4197、別のビルド成果物）を立て、
Playwright の実ブラウザで確かめた（ユーザーの会話は汚していない）。

- 黄色地に「ZEBRA-314」と描いた 900×400 PNG を貼り付けて送る → AI「ZEBRA-314 です。黄色の背景に、
  黒い太字で…」
- リロード → 送った発言に 900×400 の画像が `blob:` で出る
- 次のターン（resume）で「さっきの画像の背景は何色？」→「黄色です」——**画像は CLI のセッションに
  残っていて、続きのターンでも見える**（banto が毎ターン送り直す必要は無い）

**踏んだこと**：検証用の host の `dataDir` を `/tmp` に置くと、Project の Module がコンテナに
マウントできず受信箱に「繋げませんでした」が3件出る（Incus の区画はホストの `/home/ubuntu` の下しか
許さない）。画像の確認は Module を使わないので影響は無かったが、Module まで見る検証なら
`dataDir` を `/home/ubuntu` の下に置く。
