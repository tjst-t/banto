# Vault の管理画面の選択欄（2026-10-07）

ユーザーが実機の暗い配色で「移す」の小窓の移す先を開いて出した3つの要望と、その決め方。仕様は
`docs/specs/v4-modules.md` §2.1（「一覧に出すのは、導出値だけにしない」・「グループの『版』」）に書いた。

## 1. 選択欄の見た目

- **採ったもの**：Chromium の customizable select（`appearance: base-select`・`::picker(select)`・
  `::picker-icon`・`option::checkmark`）。ユーザーが案A を選んだ。見た目は行の「…」メニューと同じ
  （角 8px・余白 4px・影・hover の地 `rgba(128,128,128,.16)`・host の色の変数）
- **採らなかったもの**：自前の部品に作り直す（案B）——キーボード・読み上げを作り直すことになる
- **対応しないブラウザ**（Firefox・Safari）は `@supports (appearance: base-select)` の外の指定だけを読む。
  option の地と字（2026-10-06 の直し）はその外に残した
- **閉じた欄は `<button><selectedcontent>`**——対応するブラウザでだけ JS で先頭に足す。足さないと、
  長いグループ名（Project の既定グループは UUID）が欄からはみ出して ▼ が見えなくなった（実測）。
  選択肢の入れ替えは `setOptions`（先頭の button を残す）——`replaceChildren` だと消える
- **読み上げ**：Chromium の読み上げの木（CDP `Accessibility.getFullAXTree`）では、button を足しても
  select は combobox 1つのまま（素の select と同じ）。**Playwright の `getByRole("button")` は中の button を
  数える**（名前は選んでいる選択肢）——既存の E2E が「やめる」で2つ掴んだので、完全一致にした

## 2. 選択肢の文言

- 主は Vault での本当のグループ名（UUID も省かない）、版付きなら「（環境 prod）」。この Project・Global の
  置き場だけ「— この Project」「— Global」の添え（base-select では span で薄く、素の select では字のまま）
- 以前の言い換え（「この Project 専用（Banto開発）」「別の Project 専用（2ced47c4…）」）は消した——一覧の表の
  グループ列（2026-09-20 から本当の名前）と、選択肢と、Infisical の画面が突き合わなかった
- グループ欄（版を別の欄で選ぶところ）の添えは、版を外した名前どうしで比べる

## 3. 「移す」「参照を作る」の版

- 置き場の変更と同じ形（グループ欄＋版の欄、版を名乗る Vault のときだけ）。版ごとの値の数（countVariants）は
  ここには出さない（置き場の変更だけ）
- 「移す」の最初の選択は いまの置き場（版だけ・グループだけ変えるときに、もう片方を選び直さずに済む）。
  以前はグループ欄の先頭だった
- kit・窓口は `g@版` の toGroup を既に受けていた。置く先の空きの検査（`assertPlaceIsFree`）も置く先の版を
  `alsoGroups` で読んでいた。参照の試験が無かったので足した（台帳の `add` も同じ文言で断るので、kit の検査を
  外しても値は守られる——kit の検査が効いているのは「断る前にグループを作らない」ところ。それを試験にした）

## 決めきれなかったこと（人に上げた）

- **まだどこも紐付けていない版付きの置き場へ移す・置くと、banto の一覧から見えなくなる**（一覧に出る版付きの
  置き場は紐付けたものだけ、2026-10-06 の決定）。止めるか、注意だけにするかは決めていない。いまは**押す前に
  注意を出すだけ**で、止めない（Vault には在り、そこに Project を紐付ければ出てくる）
