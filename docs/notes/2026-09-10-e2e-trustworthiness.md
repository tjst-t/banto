# 2026-09-10 E2E を「緑なら信じてよい」状態にする

`docs/tasks.json` の `e2e-run-isolation` と `e2e-content-assertions`。前者は
**実行が互いを壊す**問題、後者は**壊れていても緑になる**問題。どちらも
「試験があるのに守られていない」形なので、まとめて片づけた。

## 1. 実行の切り離し

- **`workers: 1` を明示。** `fullyParallel: false` はファイル**内**の順序を固定する
  だけで、ファイル単位では複数 worker が並走していた。全 spec が同じ core・
  同じ**受信箱**を共有しているので、判断待ちを起こす spec 同士が互いの1件を
  掴みうる（実際、今回 `module-connect-failure` の「受信箱に1件だけ」が、別 spec の
  お知らせを数えて落ちた）。
- **実行ごとに port と置き場を割り当てる。** `BANTO_E2E_RUN_ID`（最初に読んだ
  プロセスが決めて env に置き、webServer と worker が引き継ぐ）から core・sandbox の
  port と `/tmp/banto-e2e/<runId>/` を導く。**同時に2本走らせて確かめた**
  ——4748/4749 と 4752/4753 を掴み、両方通った。同じ枠に当たったときは
  `reuseExistingServer: false` のまま**その場で止まる**（黙って相乗りしない）。
- 置き場は1日より古いものだけ自動で片づける（走っているかもしれない実行には触らない）。

**速さは 2.2分 → 3.7分に落ちた。受け入れる**——その速さは「他の spec の判断待ちを
掴む」危険と引き換えのものだった（規則6）。

## 2. 中身を見ていなかった4件

**全部、直す前のコードで「落ちること」を確かめた**（規則1）。

| spec | 何が穴だったか | どう直したか | 壊して確かめた |
|---|---|---|---|
| `project-thread-fork`（Clear） | `getByText("Clear")` が**押したメニュー項目の文字**に当たる。Clear が何もしなくても緑 | 会話の**横線そのもの**（`data-testid="thread-marker"`）＋ host 側で resume-point が切れ、clear が記録に残ること | Clear を no-op に → 「Clear の横線が会話に出ていない」で落ちた |
| `thread-lifecycle`（Fork 再オープン） | 画面全体から **Base の語**を探していた。Fork は Base の上に重なるだけで `toBeVisible` は覆いを見ない——**再度開いた Fork が空でも緑**（規則14 の由来と同型） | **前面の1枚**（`data-testid="panel-overlay"`）に限って、**Fork でしか出ない語**を探す | 再度開いた Fork を空にする → 旧アサーションは**通った**まま、新アサーションだけが落ちた |
| `shell-confinement` | 「会話に外の中身が出ていない」しか見ていない——**AI が tool を呼ばずに断っただけ**でも緑 | AI を挟まず、**AI が通るのと同じ経路**（代理サーバ）で `runCommand` を直接呼び、外は失敗・中は成功を見る | Landlock の包みを外す → **会話は今までどおり緑のまま**、新しい③だけが落ちた |
| `module-canvas-inline` | 「承認は出ない」を押した**直後**に1回見るだけ——最初の poll が即座に通る | 呼び出しが**終わってから**もう一度見る | 画面からの呼び出しでも判断待ちを出すようにする → 「終わった後に判断待ちが増えている」で落ちた |

とくに3件目が象徴的で、**閉じ込めを外しても会話由来の検査は緑のまま**だった
——「やってもできない」を人の言葉で確かめてはいけない、の実例。

## 画面に足した2つの印

`data-testid="thread-marker"`（Clear/Compaction の横線）と
`data-testid="panel-overlay"`（前面の1枚）。**どちらも「文字で探すと別のものに
当たる」を構造で断つためのもの**で、見た目は変えていない。

## 残したもの

- **frontend の単体テストがゼロ**・**core の turn-runner / runner-adapter に単体
  テストが無い**（レビュー §3.3 の [中]）は、この2件の外なので触っていない
  （`core-turn-runner-unit-tests` / `frontend-interaction-hardening`）。
- **試験対象ビルドの鮮度を機械が検査しない**（4175 に何が立っていても信用する）も
  未着手。今回は手で `npm run build` → 起動し直してから測った。
