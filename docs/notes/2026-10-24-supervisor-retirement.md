# 番頭の廃止(2026-10-24)

番頭(Backlog のストーリー `banto-supervisor` #505、v4-architecture.md §4.5)を廃止する。既存の判断役(§4.3)を土台に、

実コードの削除と一般化の実装は、本ノートとは別の Backlog で行う。着手は「main乖離の再発防止」(下記)が完了してから。

## 調査で分かった事実(訂正)

この決定に至る調査の途中、**ローカルの `main` ブランチ参照が実際の origin/main より大きく古い状態**で調べてしまい、
一時的に誤った前提(「番頭は release 限定、メタ Project は main 限定、一度も共存していない」)をユーザーに報告した。
正しく origin/main・origin/release を取り直した結果、事実は次のとおりだった:

- **番頭は main・release の両方に実装済み**(`packages/core/src/supervisor/` 等が両方に存在)。
- **メタ Project(#526〜#539)は実装コミットが実在するが、GitHub(origin)の main にも release にも、どのブランチにも
  含まれていなかった**。実装コミット(`dea2926ca`「kind:"meta"を足す」ほか)は、このサーバのローカルの `main` ブランチ
  (`.worktrees/localmain`、ワークツリーのブランチ `main`)にだけ存在していた。
- 原因は、ローカルの `main` ブランチが 2026-10-15 10:12 UTC 時点のコミット(`ef16bea81`)で origin/main から分岐した
  まま、以後470件以上のコミットが直接積まれ続けていたこと。本来の運用(Memory #58971)は `.worktrees/<名前>`(ブランチ
  `fork/<名前>`)で作業して push する形だが、ローカルの `main` ブランチ自体に直接コミットする運用が続いていたらしい。
  調査時点で、ローカル `main` は origin/main に無い独自コミットを182個、逆に origin/main はローカル `main` に無い
  コミットを421個持ち、完全に分岐した2本の履歴になっていた。
- Backlog #539 の最後のメモコミットには「release への反映はブロック、番頭と重なる3点の決定を人に上げる」と記録が
  あり、当時の AI も衝突を認識して push を保留していたが、その後誰も origin への push 作業を引き継がなかったため、
  GitHub 上には何も残らなかった。

この件(「main 乖離の再発防止」)の原因調査・再発防止策の設計と実施は、別の会話(Fork)に任せている。メタ Project の
ローカル専用コミットを origin に復旧・push するかどうかは、再発防止とは別に、人と相談のうえ判断する。
