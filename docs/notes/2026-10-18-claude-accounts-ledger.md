# Claude のアカウントの台帳と置き場（Backlog #398）

仕様は `docs/specs/v4-security.md` §2「Claude のアカウントを複数持つ」の 3.・7.・8.。実装で決めた細部とその理由。

## 台帳に置き場の道を書かない

仕様の下書きは台帳の欄に「置き場」を挙げていた。書かずに、種類（`host`／`banto`）と id から決める形にした。

- `host` の置き場は起動のときの `hostClaudeCredentialsPath()`（E2E は `BANTO_CLAUDE_RELAY_CREDENTIALS`、人は
  `CLAUDE_CONFIG_DIR` で変えうる）。道を台帳に写すと、最初の起動のときの道が残り、環境を変えても古いほうを読む（規則3）
- `banto` の置き場は `<データ置き場>/claude-accounts/<id>/` で、id から一意に決まる

仕様の欄の説明はこの形に直した。

## 最初の1つの id は `host`

外せない・人の CLI の置き場、という特別なものなので、乱数の id にせず固定にした。カードの dedupeKey
（`claude-login-upstream-unauthorized:host`）も起こし直しをまたいで同じになる。分ける前のカード
（`claude-login-upstream-unauthorized`）は、最初の1つで通ったときに一緒に閉じる。

## 選び方はまだ「既定の並びの先頭」

Project の並び・閾値での切り替え・429 の送り直しは #401。それまで中継は既定の並びの先頭を使う。
移したあとの既定の並びは `host` だけなので、足すまで今と同じに動く。

## 取り直すかどうかは全部のアカウントで1つ

`relayRefreshDecision`（SDK の版・`BANTO_CLAUDE_RELAY_REFRESH`・置き場を別の道から指す）は全部のアカウントに同じに効かせた。
足したアカウントは banto だけの置き場なので「本物を別の道から指す」の理由は当たらないが、SDK の版の確かめは同じ手順に
掛かるため。分けるかは #400（足すログイン）で要るかを見て決める。

## 取り込み

Factory はローカルの `main`（origin/main と分かれている）の上で作ったので、取り直し役と仕様の節を先に cherry-pick して
積んでいた。GitHub の main へは、このタスクのコミットだけを origin/main の上に載せ直して入れた（ぶつかり無し）。

## ブラウザでログインして足す・ログインし直す・外す（Backlog #400）

仕様は §2 の 4.。HTTP の口だけ（画面は別のタスク）。実装で決めた細部：

- **手続きは `loginId` で引く**：貼られた state で手続きを探す形にすると、「期限切れ」と「state が合わない」を分けられない
  （期限切れで消した手続きの state は、知らない state と見分けがつかない）。`start` が `loginId` を返し、`finish` は
  `loginId` と貼られたものを受ける。秘密（verifier・state）は10分で消し、「期限切れ」と言うための印だけ1日残す
- **state 違い・形違いでは手続きを残す**：別のタブの写しを貼り間違えただけなら貼り直せるように。state を当てても
  認可コードが無ければ何もできないので、残しても幅は広がらない。交換に行ったら成否によらず使い切る
- **メールアドレスは profile の口から読む**：token の口の返事にも `account` が入る（#397）が、仕様どおり profile を正にした
  （契約の種類と上限の段も同じ返事から取れる）。organization_type の写し方は同梱の CLI の `_F` を読んで確かめた
- **`~/.claude` は同じメールアドレスの見分けに入れない**：台帳にメールアドレスを持たない（profile を読んでいない）。
  同じ人が host と足したもので2つになりうるが、host の置き場（人の CLI のもの）を banto が置き換えるよりよい
- **置き換えは鍵の中で書く**：取り直し役が古い refresh token を投げている途中に rename で置き換えると、取り直し役の
  書き戻しが上書きしうる。CLI の書き込み用の鍵（`.storage-write.lock`）を取って書けば、取り直し役は書き戻すときに
  refresh token が替わったのを見て新しいほうを採る（`replaceCredentialsFile`）
- **取り直すかどうかは引き続き全部のアカウントで1つ**：足したアカウントだけ分ける理由は見つからなかった（SDK の版の
  確かめは同じ手順に掛かる）

## 会話の本体を中継に通す（#399、2026-10-18）

- **本体用の合言葉はメモリに持つ**（置き場に書かない）。使うのは core の子の CLI だけで、core を起こし直せば CLI も
  起こし直る。書くと「起こし直しても同じ」が要らないのに漏れる置き場が1つ増える。コンテナ用は Service がコンテナの起動で
  勝手に起きるので書く（今まで通り）
- **コンテナ用の合言葉が host の loopback から来たときに、中継で先に断る分岐は足さなかった**。送り元の縛り
  （`sourceMatches`）がコンテナのアドレスと比べるので、loopback はそこで 403 になる（単体試験で確かめた）。先に断る分岐を
  足すと、既存の単体試験（全部 127.0.0.1 から送り、`sourceMatches` を真にしている）を作り直すことになる
- **観測**：本体の分は `runnerStats` として API にだけ出した。画面に出すかは決めていない（Project 設定の今の表示は
  コンテナの分のまま）
- **E2E の偽の上流は `e2e/fake-anthropic.ts` 1つ**。会話（`messages` のある本文）には文で返し、見出し
  `x-e2e-upstream-status` があるか本文が会話でなければ、受けた Authorization とパスを返す（`claude-login-relay.spec.ts`）。
  E2E の core（`start-core.ts`）と、本物の CLI を当てる自前の host（`runtime-move-back.spec.ts`）がそれぞれ1つずつ立てる
- **`listModels()`（モデルの一覧を聞くだけの `query()`）も付随の通信を止めた**。API は呼ばないが、機能の旗・bootstrap は
  直に出るため。中継は通さない（推論しない）
- **フル E2E（2026-10-18、この作業の環境）**：314 件中 297 通過・12 落ち・5 走らず。落ちた 12 件は1つ前のコミット
  （この変更なし）でも流して比べた——11 件はそちらでも落ちた（documents の道具用のコンテナが Module の置き場に `cd` できない・
  wide-root で shell が立たない・眠り・別のサーバ 等。この作業の環境の HOME が深い道の下にあることによるものと見ている。
  調べてはいない）。残りの `turn-decisions.spec.ts` は間欠的に落ちる：5 回ずつ流して、このブランチ 3/5・1つ前 3/5 が落ちた
  （`inbox.review_judged` が `decided-by-automation` のあとに `deferred`・`incomplete` を余分に持つ）。この変更とは別の不具合
  として残す（規則6——直していない）
