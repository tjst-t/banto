# Claude のアカウントの台帳と置き場（Backlog #398）

仕様は `docs/specs/v4-security.md` §2「Claude のアカウントを複数持つ」の 3.・7.・8.。実装で決めた細部とその理由。

## 台帳に置き場の道を書かない

仕様の下書きは台帳の欄に「置き場」を挙げていた。書かずに、種類（`host`／`banto`）と id から決める形にした。

- `host` の置き場は起動のときの `hostClaudeCredentialsPath()`（E2E は `BANTO_CLAUDE_RELAY_CREDENTIALS`、人は
  `CLAUDE_CONFIG_DIR` で変えうる）。道を台帳に写すと、最初の起動のときの道が残り、環境を変えても古いほうを読む（規則3）
- `banto` の置き場は `<データ置き場>/claude-accounts/<id>/` で、id から一意に決まる

仕様の欄の説明はこの形に直した。

## 最初の1つの id は `host`

外せない・人の CLI の置き場、という特別なものなので、乱数の id にせず固定にした。カードの dedupeKey
（`claude-login-upstream-unauthorized:host`）も起こし直しをまたいで同じになる。分ける前のカード
（`claude-login-upstream-unauthorized`）は、最初の1つで通ったときに一緒に閉じる。

## 選び方はまだ「既定の並びの先頭」

Project の並び・閾値での切り替え・429 の送り直しは #401。それまで中継は既定の並びの先頭を使う。
移したあとの既定の並びは `host` だけなので、足すまで今と同じに動く。

## 取り直すかどうかは全部のアカウントで1つ

`relayRefreshDecision`（SDK の版・`BANTO_CLAUDE_RELAY_REFRESH`・置き場を別の道から指す）は全部のアカウントに同じに効かせた。
足したアカウントは banto だけの置き場なので「本物を別の道から指す」の理由は当たらないが、SDK の版の確かめは同じ手順に
掛かるため。分けるかは #400（足すログイン）で要るかを見て決める。

## 取り込み

Factory はローカルの `main`（origin/main と分かれている）の上で作ったので、取り直し役と仕様の節を先に cherry-pick して
積んでいた。GitHub の main へは、このタスクのコミットだけを origin/main の上に載せ直して入れた（ぶつかり無し）。

## ブラウザでログインして足す・ログインし直す・外す（Backlog #400）

仕様は §2 の 4.。HTTP の口だけ（画面は別のタスク）。実装で決めた細部：

- **手続きは `loginId` で引く**：貼られた state で手続きを探す形にすると、「期限切れ」と「state が合わない」を分けられない
  （期限切れで消した手続きの state は、知らない state と見分けがつかない）。`start` が `loginId` を返し、`finish` は
  `loginId` と貼られたものを受ける。秘密（verifier・state）は10分で消し、「期限切れ」と言うための印だけ1日残す
- **state 違い・形違いでは手続きを残す**：別のタブの写しを貼り間違えただけなら貼り直せるように。state を当てても
  認可コードが無ければ何もできないので、残しても幅は広がらない。交換に行ったら成否によらず使い切る
- **メールアドレスは profile の口から読む**：token の口の返事にも `account` が入る（#397）が、仕様どおり profile を正にした
  （契約の種類と上限の段も同じ返事から取れる）。organization_type の写し方は同梱の CLI の `_F` を読んで確かめた
- **`~/.claude` は同じメールアドレスの見分けに入れない**：台帳にメールアドレスを持たない（profile を読んでいない）。
  同じ人が host と足したもので2つになりうるが、host の置き場（人の CLI のもの）を banto が置き換えるよりよい
- **置き換えは鍵の中で書く**：取り直し役が古い refresh token を投げている途中に rename で置き換えると、取り直し役の
  書き戻しが上書きしうる。CLI の書き込み用の鍵（`.storage-write.lock`）を取って書けば、取り直し役は書き戻すときに
  refresh token が替わったのを見て新しいほうを採る（`replaceCredentialsFile`）
- **取り直すかどうかは引き続き全部のアカウントで1つ**：足したアカウントだけ分ける理由は見つからなかった（SDK の版の
  確かめは同じ手順に掛かる）

## 会話の本体を中継に通す（#399、2026-10-18）

- **本体用の合言葉はメモリに持つ**（置き場に書かない）。使うのは core の子の CLI だけで、core を起こし直せば CLI も
  起こし直る。書くと「起こし直しても同じ」が要らないのに漏れる置き場が1つ増える。コンテナ用は Service がコンテナの起動で
  勝手に起きるので書く（今まで通り）
- **コンテナ用の合言葉が host の loopback から来たときに、中継で先に断る分岐は足さなかった**。送り元の縛り
  （`sourceMatches`）がコンテナのアドレスと比べるので、loopback はそこで 403 になる（単体試験で確かめた）。先に断る分岐を
  足すと、既存の単体試験（全部 127.0.0.1 から送り、`sourceMatches` を真にしている）を作り直すことになる
- **観測**：本体の分は `runnerStats` として API にだけ出した。画面に出すかは決めていない（Project 設定の今の表示は
  コンテナの分のまま）
- **E2E の偽の上流は `e2e/fake-anthropic.ts` 1つ**。会話（`messages` のある本文）には文で返し、見出し
  `x-e2e-upstream-status` があるか本文が会話でなければ、受けた Authorization とパスを返す（`claude-login-relay.spec.ts`）。
  E2E の core（`start-core.ts`）と、本物の CLI を当てる自前の host（`runtime-move-back.spec.ts`）がそれぞれ1つずつ立てる
- **`listModels()`（モデルの一覧を聞くだけの `query()`）も付随の通信を止めた**。API は呼ばないが、機能の旗・bootstrap は
  直に出るため。中継は通さない（推論しない）
- **フル E2E（2026-10-18、この作業の環境）**：314 件中 297 通過・12 落ち・5 走らず。落ちた 12 件は1つ前のコミット
  （この変更なし）でも流して比べた——11 件はそちらでも落ちた（documents の道具用のコンテナが Module の置き場に `cd` できない・
  wide-root で shell が立たない・眠り・別のサーバ 等。この作業の環境の HOME が深い道の下にあることによるものと見ている。
  調べてはいない）。残りの `turn-decisions.spec.ts` は間欠的に落ちる：5 回ずつ流して、このブランチ 3/5・1つ前 3/5 が落ちた
  （`inbox.review_judged` が `decided-by-automation` のあとに `deferred`・`incomplete` を余分に持つ）。この変更とは別の不具合
  として残す（規則6——直していない）
- **origin/main の上に載せ直した版のフル E2E（2026-10-18、Project のコンテナ）**：322 件全部通過（37.5 分）。上の 12 件の落ちは
  Factory の作業場所の環境によるものだった。#405 の上に載せ直したあと、組み立てと core の単体テスト 1035 件も通過

## Project ごとの並びと閾値で切り替える（#401、2026-10-18）

- **Project の並びと閾値は台帳（`claude-accounts.json`）に持った**。Project 設定の値は `runtimeConfig` の上書きにもできたが、
  アカウントを外したときに「並びから抜く・空なら既定に戻す」を台帳の書き込み1回で済ませたかった（アカウントの id を
  2か所に持つと、外したときに片方だけ残る）
- **選ぶ規則は純粋な関数に切り出した**（`select.ts`）。全部越えのときの「一番早く使えるようになる時刻」は、越えている窓
  （と rejected）が**全部**戻る時刻——5時間が先に戻っても週が越えていればまだ使えない。分からない時刻は一番遅い扱い
- **切り替えの見分けは「最後に返事を返したアカウント」と比べる**。選んだ時点で比べると、429 で送り直した要求が
  「host→B→C」の2回に数えられる。上限の 429 で断られた返事は数えない。起こし直した直後の1回目は比べる相手が無いので数えない
  （覚えておくと、起こし直しをまたいで並びを変えたときに古い前提で理由を付けることになる）
- **ログインしていないアカウント（トークンが無い）は、送り直しの対象では飛ばして次へ**。最初のアカウントでも並びに
  次があれば次へ行く（理由 `unavailable`）。並びに1つだけなら今までどおり理由を返す
- **全部越えのカードは Project を持たない**（鍵は並びの中身だけ）。仕様の「Project の並びごとに1枚」——既定の並びを
  使う Project が複数あっても1枚。題には最初に気づいた Project の名前を出す
- **カードを閉じに行く時計**：要求が来なくても戻ったら閉じるため、一番早いリセットの1秒あとに見直す。時刻が分からなければ
  時計は置かず次の要求で見直す
- **実測（E2E）**：本物の CLI は1ターンに推論1回（`/v1/messages`）と文脈の量の数え（`count_tokens`）を約5回送る。中継は
  どれでも選び直すので、**ターンの途中で切り替わる**（仕様どおり）。E2E は「このターンはこのアカウント」と決め打ちせず、
  推論の要求に答えたトークンと、切り替えの記録を見る。全部越えは、3つの値を中継が知るまでターンを重ねてから見る
- **画面はまだ**（Backlog #403・#404）。切り替えの記録は Thread の `accountSwitches`（`GET /api/threads/:id`）と
  `GET /api/projects/:id/claude-accounts` の `lastSwitch` に出る。画面がまだ読まないので、繋がっていない要素は無い

## 設定の画面（#403、2026-10-18）

仕様は v4-frontend.md §6.46（origin/main の eba12241。このブランチの土台には入っていなかったので、`git show` で読んで作った——
仕様書の節そのものはこのブランチでは足していない）と、見本の mock/app/claude-accounts（da0209fc、同じく土台に無い）。

- **仕様と実態の食い違い（人に上げる、規則8）**：§6.46 は足したあと「並びにはまだ入っていません」とボタン「既定の並びの最後に
  足す」を出すと書くが、#398 の台帳（`ClaudeAccountStore.add`）は足すと**既定の並びの末尾に入れる**（#401 の E2E もそれを前提に
  している）。どちらかに黙って寄せず、画面は**台帳の実際**を出す形にした——足したアカウントが既定の並びに入っていれば
  「既定の並びの最後に入りました」、入っていなければ §6.46 の文とボタン。いまは前者しか出ない。どちらにするかは人が決める
- **使用率の読み直しを実装した**（§2 の 7.、それまで未実装）：§6.46 の「使用率を読み直す（n分前に読みました）」と、使って
  いないアカウントのメーターのため。中継は通さず、アカウントごとの取り直し役からトークンを得て直に呼ぶ。開いたときにまず
  覚えている値で描き、それから読み直す。「n分前」は最後に全部を読み直した時刻（core のメモリ、起こしてから）
- **行の「ログインし直す」で違うアカウントを断る**のは core でした（`accountId` を添える）。画面だけで比べると、断る前に
  トークンを置き換えてしまう（同じメールアドレスなら置き換える道があるため）
- **「最近の切り替え」は Project の読みモデルに直近の5件**：#401 は最後の1件（`lastClaudeAccountSwitch`）だけを持っていた。
  5件の配列に替え、前の形の snapshot は読み戻すときに1件目にする。HTTP の `lastSwitch` はそのまま（配列の最後）
- **1段目はただのリンク**：ダイアログを開いたときに手続きを始め（認可の URL）、「ログインの画面を開く」はその URL への
  `<a target="_blank">`。押してから取りに行くと、待っている間にブラウザが新しいタブを止めることがある。期限切れ・交換に
  行った失敗・違うアカウントは手続きが使えなくなるので、始め直して1段目からにする
- **`~/.claude` の行の右には何も置かない**（見本どおり）：はじめ「ログインし直すのは host で claude auth login」を置いたら、
  広い幅で名前の列が潰れた（実ブラウザで見た）。その案内は受信箱の「取り直せなかった」カードにある
- **閾値のスライダーは止まってから 400ms で保存**：動かしている間の値だけ画面に持ち、保存の返事のあとは host の値に戻す
- **Escape で名前の編集を取り消さない**：設定の面は Escape で一発で閉じる（`use-escape-leave-settings`）。取り消しは置かず、
  離れたら保存する
- 設定の左の一覧に「Claude のアカウント」が2つ並ぶ（banto 全体と Project の層）。層の見出しで分かれるので名前は変えなかった
- **E2E（このブランチ、2026-10-18）**：`claude-accounts-settings` は3回続けて通った（約10秒。期待を1つずつ壊すと、その行で
  落ちることも確かめた）。隣の spec（`claude-accounts-switch`・`claude-login-relay`・`project-modules`）も通過。フルは2回に
  分けて全部の spec を流した（1回目が上限の50分で切れたため、届かなかった26本と途中の2本を流し直した）——落ちたのは
  `browser-video:428`・`project-sleep:239`・`project-sleep-awaited-modules:105`・`sidebar-project-sleep:121`・
  `remote-module-disconnect:80`・`subagent-from-module:102` の6本で、土台（8469f770）でも同じ文で落ちる（この作業の環境の
  HOME が深い・Vault の SSH 鍵の置き場など、前からあるもの）。`remote-runtime-ssh:109` は1回目に落ち、1本だけで流すと通った
  （1回中1回、数えるにはもっと要る）
