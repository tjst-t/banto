# 会話の中の Claude のアカウントの印——画面（Backlog #404）

仕様は `docs/specs/v4-frontend.md` §6.46「会話の中」「受信箱」。実装で決めた細部と、仕様と食い違ったまま残したもの。

## 仕様の §6.46 がこの main に無い（人に上げる）

§6.46 は `fork/multi-claude-accounts` の `eba12241`（docs(spec): Claude のアカウントの画面）にあり、この worktree の main
（`8469f770`）の `v4-frontend.md` には入っていない（6.44 まで）。見本の `mock/app/claude-accounts` も同じく fork にだけある。
実装は fork の §6.46 と見本を読んで合わせた。仕様の本文を main に載せるのは、同じ §6.46 を使う #403（設定の画面）と
ぶつかるので、ここではしなかった（規則8——黙って寄せない）。

## 待ちは出来事の流れで写す（`rate_limit_wait.changed`）

待ちの帯（会話の入力欄の上）とサイドバーの1行は同じ写し（`lib/backend/rate-limit-waits.ts`）を読む。真実は Event Store
（`rateLimitWaitOf`）。host は `RateLimitContinuations` の `arm`（ターンが始まった・終わった・起動）と `cancel` のたびに
その Thread の今の待ちを流し、繋いだときの `hello` に一覧を載せる。Clear のあとも `arm` を呼ぶ（時計も外れる）。

**走っている間は待っていない**として流す。ターンの鍵（`ThreadTurns`）は `turn.started` を書く前に取られるので、その時点の
記録はまだ前のターン（上限で終わったもの）を最後に持つ。そのまま読むと、人が送った・「今すぐ続ける」で続けたターンの間も
帯が残る。単体テストで見ている（`rate-limit-continuation.test.ts`）。

## 切り替えの1行の warn の形は、切り替えたときだけ

warn の形（「並びのアカウントがどれも閾値を越えています。一番早くリセットされる『○○』で続けます」）は、中継が全部越えで
選んだアカウントへ**替えた**とき（`allOver` つきの切り替え）に出る。全部越えになったとき、一番早くリセットされるものが
いま使っているものと同じなら、切り替えが無いので1行も出ない（受信箱のカードは出る）。仕様は「並びの全部が閾値を越えた
ときは」とだけ書いていて、この場合をどうするかは決めていない。

## 受信箱のカードの「アカウントを足す」は置いていない

§6.46 のカードのボタンは「Project の設定を開く」「アカウントを足す」。「アカウントを足す」の行き先（設定「Claude の
アカウント」とそのダイアログ）は #403 で、この main にまだ無い——繋がっていないボタンは置かない（規則13）。#403 が入ったら
足す。「Project の設定を開く」も、Project の設定の「Claude のアカウント」の節（#403）が無いので、いまは「Claude のログイン」の
節がある「一般」を開く。

カードは banto 全体のお知らせのまま（`projectId` を持たない）。鍵が並びの中身で、閉じる側（`onBackUnderThreshold`）は鍵しか
知らないため。気づいた Project は `claudeAccounts.projectId` に持ち、カードの頭と「Project の設定を開く」に使う。名前・
使用率・閾値は `GET /api/inbox` が読むたびに台帳から添える。

## E2E は偽の Runner から中継を呼ぶ

本物の CLI を起こさずに切り替えを起こすため、偽の Runner に `relayRequests` を足した（渡された env の `ANTHROPIC_BASE_URL`
へ本体用の合言葉と Thread の印で `/v1/messages`）。中継の選び方・記録・カードは本物が動く。

`relayRequests` だけの指示は返事の文を持たない（`say` が無ければ AI の発言が記録に無い）——spec は `say` も添える。
1回目はこれを忘れ、画面に AI の返事も切り替えの1行も出ないのを「画面がたどれていない」と読みかけた（記録を見たら発言が
無かった。規則1——測る前に犯人を決めない）。

## 間欠的に落ちる単体テスト（直していない・記録だけ、規則6）

`rate-limit-continuation.test.ts` の「上限で止まったら、終わりに印と時刻…を書き、時刻が来たら同じ会話を続ける」が
**10回中1回**落ちた（この変更の単体テストの全体を流した1回でも1回落ちた。「続きのターンが終わるにならない」）。
このテストは #402 のもので、この変更で足した `onChange` を渡していない。リセットは今から約3秒後（秒に切り下げ）、
`until` の待ちは約3秒で、続きのターンを待つ余白がほとんど無いのが疑わしい——ただし測っていない。待ちは延ばしていない
（#402 の範囲。規則7）。

## E2E の結果（この版では最後まで流せていない）

`claude-accounts-thread-ui.spec.ts`：1回目は `say` を付け忘れて落ちた（上）。2回目で、切り替えの1行が2つとも開き直した画面に
出るところまで通った（ほかのところで落ちた）。3回目で、流れを最後まで読んだ画面に切り替えの1行が出ないと分かり、
`latest-state.ts` を直した（印が変わったら組み直す）。その版の4回目・5回目は、別の作業ツリーのフル E2E が機械の鍵を
持っていて始まらないまま終わった——**直したあとの版の E2E は通ったことを確かめていない。** フル E2E も流していない。
