# 承認をすべて自動で許可する（2026-10-05）

決まったことは `docs/specs/v4-frontend.md` §6.4「承認をすべて自動で許可する」（ほかに v4-architecture.md §2.5・§4.2、
v4-modules.md §4.3、v4-security.md の表）。ここは経緯と、採らなかった案。

## 頼まれたこと（ユーザー、2026-10-05）

Project の設定に1つのスイッチ。オンなら、人に「許可するか」を聞くものを全部自動で許可する——tool の確認・中継の確認
（秘密を返す `resolveAlias` も、案A）・Project をまたぐメッセージ（送り元の Project のスイッチで）・Publish の公開。
自動で通したものは覚えない。会話には何を自動で通したか分かる形で残す。対象外：パスキーの step-up・人が値を入れるもの・
AI からの Elicitation・Skill の取り込み。

## 決めた細部と理由

- **permissionMode の7つ目の値にしなかった**。`bypassPermissions` は「AI への信用」の軸で、中継の承認には効かないと
  2026-09-03 に決めている。こちらは「この Project では人が承認の役を降りる」という別のスイッチで、Thread ではなく
  Project に置く（頼まれた形）。approval-gate.ts の冒頭の「permissionMode は見ない」は残し、例外としてこのスイッチだけを書いた
- **判断待ちを出さずに通すのではなく、出して host がすぐ答える**。既にある記録（`inbox.judgment_raised`／`_answered`）と
  会話のカード（`judgment` → `answered` の流れ）にそのまま乗る——新しい記録の形を作らない。受信箱には未解決が残らない。
  答えは `{ behavior: "allow", autoApproved: true }` で、`judgmentAnswerText` が「自動で許可しました（承認をすべて自動で
  許可する がオン）」にする（流れの `answered` と、ターンをまたぐ `judgment.answered` が同じ言葉になる）
- **中継で、どの会話の呼び出しか分からないときも通す**（カードは出さない）。人に聞く場合は「聞く場所が無いなら通さない」
  だったが、それは人が見ていないところで配線が開くのを避けるため。スイッチがオンなら人は承認の役を降りているので、
  聞く場所の有無で結果を変えない。記録（`relay.call_recorded`）の理由には残る
- **Project の層だけを読む**（`layerValue`）。instance 既定に誰かが書いても効かない——全 Project で一度に人を外す口は作らない
- **値を持たない＝オフ**。オフにする PUT は Project の上書きを外す（`false` を書かない）
- **Publish：印を中継の先にも刻む必要があった**（実装の途中で分かった）。最初は「AI のターンの呼び出しに刻む」だけを
  考えていたが、窓口（publish-directory）が実装（publish-caddy）の `publishRoute` を中継で呼ぶと、実装は人の刻印
  `{admin: true}` が無ければ断る（AI のターンからは道を張れない、の線）。そこで host は、**AI のターンから始まった、
  スイッチがオンの Project のための中継**にも `dev.banto/autoApprove` を刻み、実装は「Project の刻印＋この印」でも
  その Project の道を張るようにした。どちらの印も host が自分の台帳（Project・出所）と設定から刻む——窓口や AI は名乗れない
  （Runner が添えた `_meta` は代理接続で作り直されて Module には流れない、を単体テストで確かめた）
- **Publish：公開してから頼みを書く**（`addPublished`）。公開に失敗したら何も残さず、tool のエラーで AI に返す。
  頼みは「公開済み・`autoApproved`」で残り、会話の承認画面が「自動で許可しました（…）——既定の設定で公開しています」と出す
- **画面の印**：入力欄の permissionMode のメニューの隣に「自動で許可中」（警告色）。設定の節と印は同じ小さな記憶
  （`lib/backend/auto-approve.ts`）を見るので、設定で切ると開いている会話の印もすぐ変わる。台本の Thread には出さない

## 採らなかった案

- **自動で通したものも grant として覚える**——頼まれた形に反する（覚えると切っても通り続ける）
- **Project をまたぐメッセージで「受け取ってよい Project」に足す**——同じ理由
- **Publish の窓口に Project の設定を読ませる**——Module は host の設定を知らない（境界は MCP）。印で渡す
- **受信箱にお知らせとして「自動で許可しました」を出す**——通すたびに受信箱が埋まる。会話のカードと記録で足りる

## 残したこと

- 答え済みのカードの見出しが「〜があなたの判断を待っています」のまま（人が答えたカードも同じ。既存の作りなので触っていない）。
  自動で通したカードでは特に紛らわしいので、見出しを答えに合わせて変えるかは別に決める
- Publish の公開を自動で通す E2E は無い（E2E の環境に Caddy の実装が無い）。窓口と実装の単体テストと、host が印を刻む
  単体テストで見ている
