# 幹・枝の定期監視（watchdog）と、終端に達した枝の自動畳み

## 1. 問題

banto では、幹や枝は「知らせ（notice）」が来たときだけ起こされる。知らせは職人・Kobo・環境プールの**イベント駆動**で届くため、**イベントの出所が消えると誰もその枝を起こさない**。

実例（2026-08-18）:

- task-0274 の詰まり解消のため起こし直しを任せた職人が、報告せず手を止めて消えた。枝（thread-203）は「次の報告を待ちます」のまま**永久に待ち続けた**（職人が消えたので報告は永遠に来ない）。
- 同じ日に、還す条件が満たされた枝が十数本、開いたまま残っていた（手動で一括畳みした）。

既知の欠陥として **imp-0059「返らないターンに見張りが無い」** が記録済み。lost-turn（起動時回収）はあるが**起動時だけ**で、止まったまま生きている枝には効かない。

つまり、**「時間で定期的に状況を見る」軸が banto に無い**。これが「職人が死ぬ→枝が永久待ち」「条件が満たされたのに畳まれない」の放置を生む。

## 2. 目標

1. **定期的に**幹・枝の状態を確認し、「詰まっている」ものを検知して**起こす（nudge）**。
2. **終端に達した枝を自動で畳む**（畳み忘れを機構で解消）。
3. 誤起き・誤畳みは避ける（事実ベースで判断し、推測で動かさない）。

## 3. 現状の仕組みと穴

| 仕組み | 何をするか | 穴 |
|---|---|---|
| 知らせ（notice） | イベントで該当の枝/幹を起こす | イベントが来ないと誰も起こさない |
| lost-turn（起動時） | 再起動で途中になったターンを回収 | 起動時だけ。止まったままの枝には効かない |
| ターンガード | 道具で終わったターンを再開 | 道具を呼ばずに止まった場合は対象外 |
| T3 の鍵ルール | 鍵（taskId/sessionId/envId）が終端に達したら「畳んでよい」と分かる印を添える | **印を添えるだけで畳まない**——番頭が畳むターンが回らないと残る |

## 4. 設計

### 4.1 定期 tick

banto-host に**周期監視**を置く。**間隔は 10 分**（設定可能）。起動時にも1回走らせる。

tick は既存の `server.nudge`（thread.consult の handoff・lost-turn と同じ経路）を再利用して枝/幹を起こす。

### 4.2 「詰まっている」の判定（事実ベースのみ）

推測で起こさない。以下の**具体的なシグナル**だけを検知する:

1. **待ち先が消えている**——枝が「職人の報告待ち」なのに、その session が worker 帳簿（worker.list / sessions）から消えている。
2. **ターンが返らない**——`turn_started` から `turn_ended` が無いまま一定時間（例: 15分）経過（imp-0059 の穴）。
3. **待ち先が終端に達した**——枝が開いたままなのに、その鍵（taskId / sessionId / envId）が終端状態（task closed / superseded、worker closed、env teardown）になった。
4. **長期間無活動**——最後の記録から一定期間（例: 24時間）経過しても開いたままの枝（畳み忘れの疑い）。

判定は帳簿（threads/index.json・event log・worker sessions）から機械的に引けるものだけを使う。

### 4.3 起こし方

検知したら該当の枝を nudge し、**事実だけ**を添える:

- 例: 「あなたの待ち先（worker 01a013a0…）は消えました。判断してください」
- 例: 「task-XXXX は closed になりました。この枝は役目を終えています。畳んでください」

**PO へのサマリは出さない**（PO 裁定 2026-08-18）。

nudge の履歴は記録し、**同じ枝を連打しない**（1回 nudge したら次の検知まで間隔を空ける）。

### 4.4 自動畳み

「畳む」を機構が直接行うのは、**結論が事実から一意に導ける場合だけ**。

- **対象**: T3 の用件の枝（banto/task-XXXX・職人 <id>・検証環境 env-XXX）で、**鍵が終端に達した**もの。
  - 結論は事実から導く: 「task-XXXX は closed になったため、この用件の枝は役目を終えた」（捏造ではない）。
- **猶予は取らない**（PO 裁定 2026-08-18）。鍵が終端に達したら即畳む。遅れて届く知らせは **T2 の開き直し**（既存機構）が畳んだ枝をまた開くので、「答えを知らない枝に入る」問題は生じない——知らせは起動した幹/枝に届き、畳まれていれば開き直すだけ。
- **対象外（自動畳みしない）**: 番頭が手で開いた議論の枝（thread.open）——還す条件が自由文で、機械的に「満たされた」と評価できない。これらは nudge で促すだけ（4.3）。
- 畳む前に、その枝が走行中（ターンが回っている）でないことを確認する。
- 未処理（remaining）を抱えている枝は、所在（where）が決まるまで畳まない（thread.merge の規律を守る）。

### 4.5 構成・設定

- 間隔（10分）・閾値（無活動時間・ターン放置時間）は設定可能にする（決め打ちにしない）。
- 検知ロジックは純関数でテスト可能にし、tick の実行は冪等にする（2回走っても同じ結果・副作用が無い）。

## 5. リスクと対策

| リスク | 対策 |
|---|---|
| 誤起き（正常な待ちを起こして余計なターンが走る） | 判定を 4.2 の具体的シグナルだけに絞る。正常待ちは起こさない |
| LLM コスト（起こすたびにターンが走る） | 間隔 10 分・検知対象を絞る・同一枝の連打を禁止 |
| 勝手に畳んで結論を捏造する | 自動畳みは「事実から一意に導ける結論」だけ。自由文の還す条件には使わない |
| ループ（詰まってる→起こす→また詰まる） | nudge 履歴を記録し、同じ枝を連打しない。連続で詰まる枝は PO へ上げる |
| 畳みの規律（remaining の所在）を壊す | 未処理を抱えた枝は畳まない（所在が決まるまで） |
| 即畳みで遅れた知らせが迷子になる | T2 の開き直しが畳んだ枝をまた開く（既存機構）。知らせは起動した幹/枝に届く |

## 6. 実装（PO 決定 2026-08-18）

- 間隔 10 分 / 自動畳みは即（猶予なし）/ PO サマリは出さない
- **フェーズ1（検知＋nudge）とフェーズ2（終端枝の自動畳み）を1本のタスクとして実装**する（分けない）。

## 7. 既存の関連

- **imp-0059**（返らないターンに見張りが無い）——本 proposal の 4.2-2 がこれを塞ぐ。
- **T3 の設計**（知らせを枝で受ける・鍵が終端に達したら閉じる・印を添えて番頭に畳ませる）——本 proposal は「畳ませる」を「畳む」へ能動化する。印の仕様はそのまま活かす。
- **T2 の開き直し**——畳んだ枝に知らせが来たら開き直す既存機構。自動畳みを「即」にできる根拠。
- **lost-turn / turn-guard**——起動時・道具末尾の回収は既存。定期監視はその補完。
- **thread.fold / thread.merge の規律**（結論必須・remaining の所在必須）——自動畳みでも守る。

## 8. 決定済みの事項（PO 裁定 2026-08-18）

1. 間隔: **10 分**（設定可能）
2. 自動畳みの猶予: **取らない**（鍵が終端に達したら即畳む。遅れて届く知らせは T2 の開き直しが吸収する）
3. PO サマリ: **出さない**
4. フェーズ: **1 と 2 を1本のタスクで**（分けない）

## 9. 実装の見込み

- 変更箇所: `packages/banto-host/src/**`（tick・検知・nudge 配線・自動畳み）、`tests/acceptance/**`。
- 統治コード（番頭本体の挙動）のため **PO レビュー付き**でタスク化する。
