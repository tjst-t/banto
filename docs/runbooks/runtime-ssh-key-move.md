# 実行場所の SSH 鍵を、core だけが使える置き場へ移す（banto-dev-vm 等の既にある登録）

**なぜ**：実行場所（別のサーバ）の SSH 鍵は、以前は Vault の**共通の置き場**のものを選んでいた。共通の置き場は
どの Project からも使えるので、どの Project の AI でも Vault に頼めば（Shell の `sshIdentity` 等）その鍵の ssh-agent を
開かせ、別の Project の実行場所に SSH のユーザーとして入れた（例：この機械の Project の AI が banto-dev-vm に入れた）。
2026-10-17 から、実行場所の鍵は **Vault のグループ `banto-runtime`**（core だけが使える置き場）にあるものだけを使う
（`docs/specs/v4-security.md` §1「向こうとの道」、Backlog #361）。

**この版にしたあと、移すまでの間**：その実行場所には繋がない（Module が起きない・確かめ直しが断られる）。設定の
「実行場所」の行・Project の会話に、次の理由が出る：

```
SSH 鍵「<alias>」を Vault から使えませんでした："<alias>" は Vault の実行場所の SSH 鍵の置き場（グループ "banto-runtime"）にありません。…
```

**登録は消さない・作り直さない**——登録が指しているのは alias の名前だけなので、鍵を同じ名前のまま置き場だけ移せば、
登録も Project もそのまま戻る。

**受信箱のカードの「移す」でもよい**（2026-10-17、Backlog #375）：登録済みの実行場所の鍵が `banto-runtime` の外にあると、受信箱に
実行場所ごとに1枚「別のサーバ <名前> に繋げません：SSH 鍵が置き場の外にあります」が出る。鍵が読める Vault のほかの置き場に
1つだけあれば、カードの **「移す」** で下の 3. と同じ操作が走り、すぐ繋ぎ直してカードが閉じる。**押す前に 2. を確かめる**
（参照があれば断られる。その鍵を Project の AI にも使わせていたなら、先に別の名前で預け直す）。「移す」が出ないとき
（複数の置き場にある・参照しか無い・どこにも無い）は、カードの理由を読んで下の手順で直す。

## 1. どの鍵を移すか確かめる

設定（banto 全体）→「実行場所」の各行を開き、「鍵」の欄の alias（`<名前>（Vault）`）を書き留める。
banto-dev-vm なら、その行の鍵。

## 2. その鍵を参照している置き場が無いか見る

Vault の管理画面（設定 →「Vault」）で、その alias の行を探す。**同じ名前の行が「参照」として別のグループにあれば、
先に消す**——参照があると、参照を置いた先の Project の AI がこの鍵を使えてしまうので、参照ごとは移せない
（移そうとすると「参照があります（<グループ> / <名前>）」で断られる）。

その鍵を **向こうで Project の AI にも使わせていた**（Backlog の送る鍵・Shell の `sshIdentity` で git push 等）なら、
消す前に、同じ値を**別の名前で、その実行場所を使う Project の置き場に**預け直し、Project の側の設定（Backlog の
「送るときに使う SSH 鍵」等）をその名前に変える。**共通の置き場には置かない**——どの Project の AI もその実行場所に
入れる形に戻ってしまう。

## 3. 鍵を `banto-runtime` へ移す

Vault の管理画面で、その alias の行の **「移す」** を押す。**「参照を作る」は使えない**——`banto-runtime` に参照を置くと、
元の鍵が共通・Project の置き場に残り、Project の AI からも使えるままになる（穴が塞がらない）ので、参照を作る小窓では
`banto-runtime` を選ぶと理由が出て押せず、押しても Vault が断る。値ごと置き場を変えるのは「移す」だけ：

1. 移す先の Vault は、いまの Vault のまま
2. グループ欄で `banto-runtime` を選ぶ。無ければ最後の「＋ 新しいグループを作る…」で `banto-runtime` を作る
   （綴りはこのとおり。版を選べる Vault では既定の版のまま）
3. 欄の下に「→ 実行場所（別のサーバ）の SSH 鍵の置き場です。…どの Project の AI からも使えません」と出ることを確かめて、移す

移したあと、その行の「使える範囲」は **「実行場所」** になる。

## 4. 確かめる

1. 設定 →「実行場所」→ その行の「確かめ直す」が通り、「使えます」に戻る
2. その実行場所の Project を開いて、Module が繋がる（会話の入力欄の上に繋がらない理由が出ない）
3. **ほかの Project から使えないこと**：別の Project の会話で AI に、Shell の `sshIdentity` にその alias を渡して
   コマンドを流させる——`alias "<名前>" はどの Vault にもありません` で断られる

## 新しく登録するとき

登録の画面の「SSH 鍵」に出るのは `banto-runtime` の鍵だけ。鍵の欄の下の「作る」（鍵があるときは「別の鍵を作る」）で、
`banto-runtime` に新しい鍵を Vault の中で作れる——出た公開鍵を向こうの `~/.ssh/authorized_keys` に足す。Vault の管理画面で
`banto-runtime` のグループに `ssh-identity` を作ってもよい（作る・移すは人の画面からだけ。Module・AI からは置けない）。
