# Spec: Canvas UI（キャンバスに開く面の共通規約）

番頭がキャンバスに出し入れする GUI（ADR-0010 決定5・12・17・18・25）の**共通の骨格**。
個々の面の中身は各モジュールの spec（`spec-file-browser` 等）に、ここには**どの面にも効く規約**だけを書く。

第一原理：**POから見ればどれも「番頭が出した面」でひと続き**。モジュールごとに見た目と操作が
違ってよい理由は無い。だから道具立て・一覧・空状態・失敗の出方・狭いときの畳み方を1組に揃え、
モジュールが増えても新しい語彙を足さずに済むようにする。

---

## 1. 面の骨格

```
ViewShell                     … 器いっぱい。スクロールは自分で持つ（器では持たない）
├ ViewBar                     … 上端の道具立て。狭いと折り返す
│   ViewTitle / SearchField / Segmented / Chip / Toggle / Button / Spacer
├ [ViewBar]                   … 2段目（絞り込みなど）
└ SplitView | Scroll          … 一覧＋詳細、または単票
```

実体は `packages/banto-web/src/views/ui.tsx`（部品）と `views.css`（意匠）。

- **器（`.canvas-body`）はスクロールしない。** 面が自分の中でスクロールする——器ごと流れると、
  見出しまで消えて位置を見失う
- 面は `endpoint`（提供元モジュールの到達先）からデータを取る。**番頭の Tool は呼ばない**（決定25）
- 判断は面に持たせない（D5）。並び順・絞り込み・ページ送りは、可能な限りホスト側の Tool に投げる

## 2. 一覧と詳細（`SplitView`）

- 広いとき：左に一覧（既定 300px、`size` で 250/300/340）、右に詳細
- 狭いとき：**一覧→詳細のドリルダウン**。詳細の頭に「‹ 一覧へ」が出る
- **両方を常に描き、CSS で出し分ける**——切り替えのたびに作り直すと、詳細のスクロール位置も
  読み込み済みの中身も毎回消える
- 「何を選んでいるか」と「いまどちらを見ているか」は**別の状態**として持つ。狭い画面で一覧へ
  戻っても選択は外れない
- **何も選んでいないときに、面の大半を空状態で埋めない。** 広い画面のファイル閲覧では
  約 1000×1050px が「ファイルを選ぶと中身が出ます」だけで埋まっていた（実測 2026-08-08）。
  そこに置けるもの（そのディレクトリの README など）があるなら置き、無ければ空状態は
  上寄せの小さいものにする——`WorkView` を作ったときと同じ話（PO報告 2026-08-07）

## 3. 狭さの判定はキャンバスの幅（ADR-0010 §8）

**ビューポート幅ではなくコンテナクエリを使う**（`container-name: canvas`）。チャット欄を広げて
キャンバスが細くなったときと、スマホで見たときは、POにとって同じ「狭い」——ビューポートで分けると
前者が崩れる。

- 閾値は `760px`（キャンバスの内幅）
- 狭いときは押せるものを 38px 以上に広げ、入力欄の文字を 16px にする（iOS の自動ズームを避ける）
- **その面の主目的である一覧の行だけは 44px。** 38px は「押せる」の下限であって、
  何十回も続けて押すものの寸法ではない
- **面が自分で組んだ当たり（`.cv-*` を使わない独自クラス）は、この規約から漏れる。**
  ファイル閲覧の一覧の行は 32px、入切の札は 21px のまま残っていた（実測 2026-08-08）
  ——共通部品を使わないなら、狭いときの寸法も自分で書く

### 3.1 狭いときは、読んでいる間だけ道具立てが退く（PO報告 2026-08-08）

390×780 でファイルを開くと、**本文に残るのは 411px＝画面の 53%** だった（`spec-file-browser` §2.4）。
畳めるものを畳んでも、屋号の帯 52px と面の頭が常に載っている。

- **中身を下へ送っている間、屋号の帯（`.topbar`）と、その面の「詳細側の頭」を退かせる。
  上へ少しでも送ると戻る。** 戻すための新しい操作は作らない——いましている仕草をそのまま使う
- **キャンバスのタブ列は退かせない。** どの面を見ているかは常に要る（§6）。
  `tests/mobile-layout.spec.ts` の「タブ列が居座る」はそのまま守る
- 退くのは**詳細（読むもの）を見ているときだけ**。一覧では退かせない
  ——絞る欄と見出しは、探している間ずっと要る
- `prefers-reduced-motion` のときは動かさずに切り替える

広い画面では退かせない。**そこでは縦が足りているので、隠す理由がない。**
- 設定面に埋まる中核のビュー（決定43）も同じ器（`.sp-content`）を container にしてあるので、
  同じ規約がそのまま効く

## 4. 状態の出し方

| 状態 | 出し方 | 理由 |
|---|---|---|
| 読み込み中 | `Loading`（骨組みの帯） | 一行の「読み込み中…」だと、何が出てくるか分からないまま画面が跳ねる |
| 空 | `EmptyState`（絵・見出し・**次の一手**） | 空白だけだと、壊れているのか空なのか分からない |
| 失敗 | `ErrorNote`（理由＋「もう一度」） | I2。握りつぶさない。タブを開き直させない |
| 注意 | `Note`（畳み忘れ・広すぎる許可など） | 機構で防げないものは**見えるようにする**のが対策そのもの（決定38e・I3） |

`useAction` は押して初めて起きる操作（承認・畳む・取り込む）の受け皿。**どれを押したかまで覚える**
——一覧の中の1件を押したとき、どの行が動いているか見えないと二度押しになる。

## 5. 語彙

| 部品 | 使いどころ |
|---|---|
| `Segmented` | 択一。**3つ以内**で、並べて比べたいもの（表示モード・tier） |
| `Chip` | 複数同時に選べる絞り込み・入切 |
| `Select` | 選択肢が多い・可変のもの |
| `Badge` | 状態・分類を1語で（`ok` / `warn` / `danger` / `accent` / `neutral`） |
| `StatusDot` | 生き死に。**動いているものだけ脈を打たせる** |
| `Card` | 1件分の器。一覧の行にも詳細の区画にも |
| `Modal` | 画面に重ねる面。**ドロップダウンは使わない**——押した場所の脇に開くものは、狭い画面で必ず端からはみ出す |
| `Disclosure` | 既定は閉じておく（開いたままだと本題が押し出される） |
| `CopyButton` | 写したことを見せる（押しただけでは起きたか分からない） |

数字は人の単位に落とす（`formatBytes` / `formatCount` / `formatRelative`）。
**分からないものは分からないと出す**（I1）——時刻・文脈長・件数を 0 と偽らない。

### 5.1 選んでも情報を消さない

一覧の行の末尾（サイズ・状態・ハッシュ・パス）は、その行を選んだ瞬間に
`rgba(128, 128, 128, 0.22)` で塗られて読めなくなっていた（`cv-row` / `fb-entry` / `gv-*` / `rm-*` の
6 箇所。実測 2026-08-08）。トークンに無い値であり（`spec-design` 第一原理）、消す理由も無い
——**選択は「いまこれを見ている」であって、「もう見なくてよい」ではない。**

淡い地（`--ai-t`）の上でも読める墨を1つ決め、共通で使う。面ごとに塗り分けない。

## 6. タブ列とカタログ（キャンバスの器）

- タブは折り返さず、**収まらない分だけ「▾」に収納する**（`useTabOverflow`。会話のタブと同じ計算）
  - 横スクロールは使わない——端に隠れたタブは、在ることも数も見えないまま指で探すことになる
  - ▾ は収まらないときだけ出し、数を出す。中身は「全部」ではなく**はみ出している分だけ**
  - **いま見ているタブは隠さない**。溢れたら最後に残っていたタブと入れ替える
  - ▾ の中身とタブ列は**同じ見た目**で描く（同じものが2通りに見えないように）
  - メニューは右端から左へ開く。ボタンは帯の右側に居るので、左寄せだと画面から出る
- タブにはカタログの絵（`icon`）を出す。狭い画面で字が切れても見分けがつく
- 「開く」（カタログ）は**タブ列とは別の器**に置く。横に流せる箱の中に置いたメニューは、その箱に
  切り取られて出てこない
- カタログは**画面に重ねる面（`Modal`）**で開く。分類ごとにまとめ、説明と「開いています」を出し、
  名前・説明で絞れる。既に開いている面は、増やすのではなくそこへ移ると分かるように
  - 脇に開くメニューは狭い画面で端からはみ出し、横スクロールが生えた（PO報告 2026-08-05）。
    重ねる面なら広さに関係なく収まり、下端の切替バーより上に出す（z-index）
- **開ける一覧に出すのは、この画面が描ける面だけ**（決定12・17）。カタログを配るのはホスト、
  描けるかを知っているのはUI——`component` は文字列で渡るので、**両者は食い違いうる**
  （古いまま動いているホスト、別のサーフェス、配線漏れ）。実体の無い面を並べると、
  押した先が「この面を描けません」になる（PO報告 2026-08-05）
  - 濾すのは offer する側＝UI。ホストに「どのUIが何を描けるか」を持たせない（決定17）
  - I2: 黙って消さない。カタログの面の下に件数と kind を出す——直せるのは「解決表に足す」か
    「モジュールの登録を外す」のどちらかなので、出所が分かる形で見せる
  - 機械でも見る：`tests/acceptance/canvas-view-components.spec.ts` が**ソース中の
    `component:` 宣言を全部拾って**解決表に在ることを確かめる（テストが組み立てたモジュール
    だけを見ていると、増やした人が足し忘れたまま通る）
- 何も開いていないときは、一覧を読ませるのではなく**そのまま押せる札**を並べる（決定25の人側の経路）
- スマホでは**キャンバスのタブが動いたらキャンバス側へ移る**。番頭が「開きました」と言っているのに
  何も見えないのが一番困る（最初の描画では動かさない——復元した会話でいきなり飛ばさない）

## 7. 面の一覧（現状）

| kind | 面 | 提供元 | 形 |
|---|---|---|---|
| `file.browser` | ファイル（**探す・移動する**） | workspace | 一覧＋詳細（`spec-file-browser`） |

| `git.viewer` | Git | workspace | 一覧（変更＋履歴）＋差分 |
| `place.permissions` | 書き込み許可 | workspace | 単票（要求・許可・履歴） |
| `repo.manager` | リポジトリ | repo-manager | 一覧＋詳細 |
| `env.manager` | 検証環境 | environment-pool | 単票（畳み忘れを最上段に） |
| `worker.viewer` | 職人 | worker-pool | 一覧＋出力 |
| `memory.viewer` | 記憶 | studio | 単票（絞り込み付き） |
| `skill.viewer` | SKILL | studio | 一覧＋本文 |

`LlmRegistryViewer` は同じ語彙で書かれているが、**カタログには出さない**——中核の設定区画

キャンバス機構の動作確認用だった `demo.*`（テスト用GUI・時計）は**畳んだ**（PO裁定 2026-08-05）。
実物が揃った時点で役目を終えており、カタログに並ぶと本物と混ざる。

## 8. 場所を選ぶ（`PlacePicker`）

`file.*` / `git.*` は場所を引数で受け取る（決定36e）。**`<select>` は使わない**——選択肢の
見た目は OS が描くので、2段にすることも束ねることも絞り込むこともできない。

- 押すと `Modal` が開き、絞り込み（名前・枝名・パス）と**リポジトリごとに束ねた一覧**から選ぶ
- **上位の場所は1つずつ並べ、ワークツリーだけをその下にぶら下げる。**「そのほかの場所」の
  ような受け皿は作らない——枝を切っていないリポジトリがそこへ落ちる（PO報告 2026-08-05）。
  リポジトリであることと、枝を切ってあることは関係がない
- 束ね方は届いた一覧から**導出する**（D3：モジュールに構造を足させない）
  - ① 別の場所の id が前方一致するなら、それが束ね元
  - ② ワークツリー（label が `（ワークツリー: 枝名）`）なら、id の末尾を落とした残りがリポジトリ
  - 本体は id 一致で探し、無ければ**パスの末尾が鍵と一致する場所**を本体とみなす——設定
    （`BANTO_PLACES`）で足した場所が同じパスを先取りすると、ghq 由来の本体は一覧に出てこない
- ワークツリーは**枝名を主役**にし、パスは副えるだけ。書けるかどうか（✎ / 読み取り専用）を各行に出す
- 「リポジトリ本体」の札は**下に枝があるときだけ**。枝の無い場所に付けると、リポジトリでない
  ものまで本体に見える
- 絶対パスは左から出す。末尾を残す小細工（`direction: rtl`）は先頭の `/` が末尾へ回って壊れる

## 9. 発話の描き方は会話と共有する

職人のセッション出力（`worker.viewer`）は「発話・思考・ツール呼び出し」という点で番頭との会話と
同じ構造をしている。**同じものは同じ見た目で出す**——`messages.tsx`（`StreamingMarkdown` /
`ReasoningRow` / `ToolRow`）をチャット欄と職人ビューアの両方から使い、器も `.chat-scroll` を共有する。
職人ビューア側がやるのは、セッションJSONL を並びに直すことだけ（`toolResult` は `toolCallId` で
呼び出しの行に差し込む）。

## 10. やらないこと

- **面に判断を持たせない**（D5）。何を開くかを決めるのは番頭、並び順を決めるのはホスト
- **モジュールごとの CSS を足さない**。足りない語彙は §5 に追加して全モジュールで共有する
- 閲覧専用の面（Git・記憶・SKILL・職人）に変更操作を生やさない（決定24・D10・D11）

## 11. 読む面と作業する面（ADR-0017 決定79）

器を入れると、面が2種類に割れる。

| | 何が要るか | どこに出すか |
|---|---|---|
| **読む面**（差分の抜粋・記憶・職人の手元） | 事実が数行 | **器として会話の中に**。列を食わない |
| **作業する面**（ファイル閲覧・Git・検証環境） | 探す・移動する・比べる。**幅** | **間**（列）として開く |

- **作業する面は、手前を背表紙に畳んで全幅を使う。** 400px の列に押し込まない
- **ただし「いま居た会話」は細い帯（既定 344px・上下限 260〜620px）として残す。** 面を見ながら
  「これ何？」と訊けないのは、番頭が主体の店として本末転倒。**主役が何かで幅を配る**
  ——そこで読むのではなく、**話しかけるための幅**。幅はつまんで変えられる
- **面はどこから開いたかを覚える。** 面は会話ごとのキャンバスに載る（決定2）ので、
  幹から開けば枝は視界から外れ、枝から開けば枝が細い帯として左に残る。畳んだ面を
  開き直すと、そのときの組み合わせが復元される
- **探す面と読む面を分ける。** `file.browser`（探す・移動する）と `file.viewer`（1つを読む）は
  目的が違うので別種にする——決定17 が「シェルと職人ビューアは目的が違うので別コンポーネント」
  としたのと同じ理屈
- **幹・枝・面は重なりで表す。** 狭い画面（760px 以下）は重ね、上端に幹が覗く

**却下した案：面をモーダルで覆う。** 戻り道が見えない。背表紙なら経路が残る。

## 12. 器の語彙（ADR-0017 決定78・81）

**器は中核が有限の語彙として持ち、番頭は選ぶだけ。生成UIではなく選択UI。**
番頭に画面を組ませると、同じ話が毎回違う見た目になり、第一原理（POから見ればどれも
番頭が出した面でひと続き）が崩れる。**モジュールは器を作らない**——§10「モジュールごとの
CSS を足さない」の延長で、足りない語彙は ADR を通してここに足し、全モジュールで共有する。

実体は `packages/banto-web/src/Utsuwa.tsx`（見せ方）と
`packages/banto-host/src/canvas-utsuwa.ts`（形の検算）、型は `protocol.ts` の `UtsuwaView`。

### 12.1 13 種

| 器 | いつ使うか | 上限 |
|---|---|---|
| `list` 行の一覧 | 同じ形のものが複数あり、1つずつに状態が付く。**いちばん使う** | 10 行 |
| `facts` 鍵と値 | 1件についていくつかの事実。三部構成もこの器 | 12 件 |
| `table` 表 | **列どうしを見比べる**ときだけ。比べないなら行の一覧のほうが軽い | 4列・8行 |
| `diff` 差分 | 何がどう変わるか。**抜粋であることを隠さない** | 24 行 |
| `choice` 選択肢 | **あなたの番のときだけ。** 朱はここにしか出ない | 3つ |
| `stats` 数の札 | 数そのものが答えのとき | 3つ |
| `meter` 目盛 | 上限に対してどこまで来たか。**上限が分からないときは使わない** | — |
| `spark` 推移 | 数字1つでは「良くなっているか」が言えないとき。1本だけ | 30 点 |
| `timeline` 経過 | **並びを変えてはいけない**とき | 10 件 |
| `image` 画像 | 見せたほうが速いとき。`alt` は必須 | 1枚 |
| `doc` 文書 | 散文の**抜粋**。全部は `file.viewer` の面へ | 1200 字 |
| `quote` 引用 | 出どころのある文字をそのまま。**出どころを必ず添える** | 600 字 |
| `open` 面への口 | 膳に載らないとき。**これがあるから他の器が小さくいられる** | — |

**作らない器**（棒／円グラフ・散布図・箱ひげ・ツリー・カンバン・マークダウン全描画・
自由な図の生成）とその理由は ADR-0017 決定78。判定は1つ：**「見比べる作業」は面、
「判断に要る事実」は膳。**

### 12.2 どの器にも効く規約

- **膳＝器1つ。** 並べたいときは続けて出す。**入れ子は許さない**（許した瞬間に生成UIへ戻る）
- **どの器も「畳んだ姿」（狭いときの1行）を持つ。** 判定は**コンテナクエリ**（`container-name: talk`。
  §3 と同じ規約）——ビューポートではなく**会話の帯の幅**で決まるので、細い帯でもモバイルでも
  同じものが効く。器を1つ足すコストが2倍になるのは**歯止めとして望ましい**
- **どの器も「いつの」を出す。** 器は**そのときそう見えた記録**で凍る（会話の一部・D3）。
  面は**いまの状態**（自分で `endpoint` から取る・決定25）。**枝の札だけは参照なので生きる**
  ——記録と参照を混ぜない
- `state` は **5役だけ**（`run` / `turn` / `stop` / `warn` / `done`）。モジュールの独自の状態名は
  通さない——通すと色の意味が崩れる。**当てはまらない語は無色で素通しする**：モジュールの語を
  5役へ写す対応表は中核に置かない（置けば中核が各モジュールの語彙を知ることになる）。
  誰が写すのかはまだ決まっていない。**嘘の色が点くほうが、色が点かないより高くつく**
- **膳は小さい。** ツール戻り値は 4000 文字で切り詰められる（`TOOL_PAYLOAD_MAX_CHARS`）ので、
  **この線は規約ではなく機構が引く**。切ったことは隠さない（I1）
- **落とした行・列・鍵は添え書きで必ず告知する**（I1）。番頭が書いた添え書きは消さずに足す
  ——番頭が何か書いていたことは、落としたものを黙っていい理由にならない
- **分からないものは分からないと出す**（I1）。`null` は「—」と描き、勝手に埋めない

### 12.3 どの器で描くかは番頭が都度指定する

- モジュールは素のデータを返すだけで、**器のことを知らない**。同じ戻り値でも文脈によって
  出したい器は変わり、**モジュールは文脈を知らない**（D5）
- **データは再送させない。** 番頭は `canvas.show` で「どのツール結果を・どの器で・どこを」
  だけを言い、実体はホストが**退避済みの結果**（ADR-0010 決定47(a) の `artifacts/`）から引く
- **「どこを」（`path`）は省けることがある。** 行の配列が一意に決まるなら器が自分で見つける。
  候補が複数あるなら**勝手に選ばず断り、候補の鍵を名指しする**（→ §12.4）。
  どんな鍵があり・どれが行の配列かは**退避の栞に載る**——番頭はそれを見て `path` を書く
  （器が見るのは素性のほうで、栞の本文を読んでも鍵名は分からない）
- **器は載せるだけで、要約しない。** `facts` は入れ子の鍵があれば**描かずに断る**——
  畳んで「12 件の配列」のような数を作れば、それは**器が作った数字**であって観測ではない（I1）。
  平たい値だけなら従来どおり通る
- **判断待ちの器（`choice`）は `canvas.show` から出せない。** 判断を求めるものは取次1本
  （ADR-0015 決定73）で、押されたときに効く口（`InboxEffect`）を持てるのは取次だけ

### 12.4 描けない戻り値は会話に出し、番頭にも返す

- **どのモジュールの・どの Tool の・どの器で・何が足りないか**まで書く。直せるのは登録した
  人なので、出所が分かる形で（I2）
- **番頭にも同じものが返る**ので言い直せる（別の器にする・面へ送る）
- **会話は止めない**——回復可能なので I2 の「回復不能なら failed にして止まる」には当たらない
- **黙って素の JSON を出さない**（壊れた見た目が既定になる）。素の値は畳んで置く
