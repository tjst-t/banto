# Spec: 意匠（色・字・余白の唯一の出どころ）

banto の全画面——チャット・キャンバスに開く全GUI・設定・履歴・取次——に効く意匠の規約。
**個々の面がここに無い値を持つことを禁止する。**

第一原理：**意匠は好みではなく体系**。「その場で決めた値」が積み上がると、画面は動いていても
製品に見えなくなる。実体は `packages/banto-web/src/theme/tokens.css` で、ここはその読み方と、
なぜそう決めたかを書く。

---

## 0. 経緯と裁定

2026-08-05、PO から「全体的にUIがいまいちで、プロダクトとの品質を満たしていない」との指摘。
実装の CSS を数えたところ、**好みではなく体系の欠落**だった。

| # | 数えたもの | 実測 |
|---|---|---|
| 1 | `font-size` の種類 | **17 種**（10px〜32px、0.5px 刻みを含む） |
| 2 | `border: 1px solid` | **107 箇所**（styles.css 49・views.css 58） |
| 3 | 色のリテラル（`#hex`） | **39 種** |
| 4 | 絵文字を道具の絵に使っている箇所 | **18 ファイル**（🕘⚙️💬📄 ほか 36 種） |
| 5 | `--accent`（藍）の用途 | 屋号・選択タブ・主ボタン・リンク・フォーカス枠・コード地の **6 種** |

方向の違う5案を作って PO に上げ（`prototype/redesign/`）、次の裁定を得た。

| | 問い | 裁定 |
|---|---|---|
| ① | 番頭の言葉を明朝にしてよいか | **してよい。**使ってみてから戻したい場合は言う |
| ② | 朱を「判断待ち」専用に空けてよいか | **よい。ただしエラーも一目で分かる色にすること** |
| ③ | 暗色を後からでよいか | **明るいのが主、暗いのが従** |
| ④ | 取次を既存の受け口と一本化してよいか | **一本化する。分ける理由がない** |
| ⑤ | 会話とキャンバスの主従を、いま測るか | **後でやる**（→ inc-0023 に積んである） |

## 1. 色は 5 役しかない

色は飾りではなく **「誰の番か・どう止まっているか」** を言う。役を増やすときは ADR を起こす。

| 役 | 変数 | 明 | 暗 | 意味 |
|---|---|---|---|---|
| 藍 | `--ai` | `#1E3A5F` | `#8FB0D9` | 番頭が動いている。選ばれている。番頭の落款 |
| **朱** | `--shu` | `#B03A26` | `#E4674F` | **あなたの判断待ち。これだけ** |
| 紫 | `--murasaki` | `#5A3E63` | `#A98CB4` | 止まった（失敗・エラー・incident） |
| 琥珀 | `--kohaku` | `#A05A12` | `#E0A24B` | 気をつける（期限が近い・文脈が逼迫） |
| 苔 | `--koke` | `#4A6B45` | `#7FB08A` | 済んだ。繋がっている |

### 1.1 塗り（べた）の許し方（最重要）

| | 塗ってよいか |
|---|---|
| **朱** | **どこでも塗ってよい。** 判断待ちの札・その主ボタン |
| 藍 | **小さいものだけ**塗ってよい。主ボタン・送るボタン・落款・数の札 |
| 紫・琥珀・苔 | **塗らない。** 点・左罫・字と、淡い地（`--*-t`）まで |

大きな面の「選ばれている」（左ナビ・一覧の行）も**塗らない**——淡い地（`--ai-t`）＋色字にする。
広い面積を藍で塗ると、朱より先に目に入ってしまい、序列が崩れる。

こうしておけば、色が 5 つあっても **いちばん強いのは常に「あなたの番です」** になる。
朱が画面から消えている状態は「番頭が全部引き受けた」の意味を持ち、それ自体が情報になる。

### 1.2 紫は朱より必ず弱い（②の答え）

「止まった」は **急がせる色ではない**。職人の失敗は知らせなければならないが、
POを呼び立てるのは朱の役目。だから気づける程度に色を残しつつ、朱より弱くする。

初出は既存プロトタイプが incident に使っていた江戸紫 `#6D4A9E` をそのまま引き継いだが、
**悪目立ちする**と PO から差し戻された。原因は二つで、両方を直した。

- **色そのもの**：地が暖色の低彩度で揃っているのに、紫だけが寒色の高彩度だった → 明度と彩度を落として `#5A3E63` に沈めた
- **淡い地**：`#EFE9F6` は**白から作った**寒色のラベンダーで、和紙の地に属していなかった → `#E4DDDF` に直した

### 1.3 淡い地は紙から作る

`--*-t` の淡い地は、**白に色を溶いて作らない。紙に色を混ぜて作る。**
白から作ると、寒色の面が地から浮く（1.2 の後者がそれ）。

### 1.4 状態は色と形の両方で出す

色だけに預けない。色が見えない人にも、白黒に印刷しても通る。

| 状態 | 形 | 色 |
|---|---|---|
| 進んでいる | ● 円（塗り） | 藍 |
| あなたの番 | ● 円（塗り＋暈し） | 朱 |
| 止まった | ◆ 菱（抜き） | 紫 |
| 気をつける | ■ 角（抜き） | 琥珀 |
| 済んだ | ○ 円（抜き） | 苔 |

### 1.5 紙と墨は 3 段ずつ

| 変数 | 明 | 使いどころ |
|---|---|---|
| `--paper` | `#EFEBE1` | 地 |
| `--paper-1` | `#F8F6F0` | 立つ面（上段・カード・会話の器） |
| `--paper-2` | `#E4DFD2` | 沈む面（入力・溝・二次ボタン） |
| `--rule` | `#DCD6C7` | **実際の境目にだけ**引く線 |
| `--sumi` | `#191712` | 本文 |
| `--sumi-2` | `#4A463D` | 副次 |
| `--sumi-3` | `#8A8474` | 注記 |

**ふだんの区切りは紙の濃さの差で出す。** 線は面と面が本当に接するところにしか引かない
（107 箇所あった 1px 枠の大半はこれで消える）。

## 2. 字は 6 段しかない

中間を作らない。半端な 0.5px 刻みを禁止する。

| 変数 | 値 | 使いどころ |
|---|---|---|
| `--t-note` | 11px | 注記・札・道具の脇 |
| `--t-meta` | 12px | 道具立て・副次の説明 |
| `--t-body` | 13px | 本文・一覧の行・POの発言 |
| `--t-read` | 15px | 読ませる本文（番頭の言葉）・札の見出し |
| `--t-head` | 19px | 面の見出し |
| `--t-title` | 26px | 面の題 |

### 2.1 声の主が書体で分かる（①の答え）

| 変数 | 書体 | 誰の声か |
|---|---|---|
| `--sho` | Shippori Mincho → Hiragino Mincho ProN → Yu Mincho → serif | **番頭の言葉**。落款（`.banto::before`）を伴う |
| `--ui` | Zen Kaku Gothic New → Hiragino Sans → Noto Sans JP | POの言葉・道具立て・見出し |
| `--mono` | IBM Plex Mono → SFMono-Regular → Menlo | 機械が出したもの（ID・時刻・パス・コード） |

明朝は**番頭の発話にだけ**使う。見出しや道具立てに広げない——書体の違いが「誰が言ったか」を
指すことをやめてしまうため。

## 3. 余白・角・影

- **余白は 4 の倍数だけ**（`--s1`=4 … `--s8`=32）。7px も 9px も 11px も作らない
- **角は 3 つだけ**：`--r-seal`=2px（落款）／`--r-ctl`=6px（部品）／`--r-face`=10px（面）。
  丸ボタン（999px）はやめる——タブもボタンも全部が丸いと、押せるものの区別が消える。
  例外は数の札（`.inbox-n` など、丸が数字の器として働く場合）だけ
- **影は 2 段だけ**：`--shadow-rest`（置いてある）／`--shadow-pop`（浮いている＝メニュー・被さる面）

---

## 4. 絵は線で描く。絵文字を使わない

絵文字は環境で字面と色が変わり、ベースラインもずれる（実装には中心合わせの手当てが入っていた）。
和紙の地に対して彩度も浮く。

- **24 の升目・1.5px の線・`fill: none`・`stroke: currentColor`**
- 色は継承させる。絵に色を直接持たせない
- 実体は `packages/banto-web/src/icons.tsx`。ここに無い絵が要るときは**足してから使う**

---

## 5. 明と暗（③の答え）

**明が原典。暗はそこから導く。** 別の意匠ではなく、同じ役を裏返しただけで、
**役は増えも減りもしない**（朱＝判断待ち、紫＝止まった、は明暗どちらでも同じ）。

- 朱の上に載せる字だけは明暗で反転する（`--on-shu`）——暗色の朱は明るいので白が読めない
- **`color-scheme` を必ず宣言する。** これが無いと、ブラウザが描くもの（スクロールバー・
  入力欄の中身・選択の枠）が明色のまま描かれ、暗色の画面でそこだけ白く浮く
- **`::-webkit-scrollbar` は使わない。** 1つでも書くと macOS の重ねて出るスクロールバーが
  常時出る古い形に変わる。`color-scheme` と `scrollbar-color` だけで足りる

案2「夜番」の灯り（稼働中を暖色で示す）は**採らなかった**。状態はすでに 5 役で言えており、
光の温度を足すと役が二重になる。

## 6. テーマは差し替えられる

意匠は1つに決まったが、**仕組みとしては差し替えられる**ようにしておく（PO要望 2026-08-05）。

### 6.1 決め

- **テーマは「家」で、明暗はその中の別。** 和紙の明と和紙の暗は別のテーマではなく同じ家の裏表
  ——だから明暗ボタンを押しても家は変わらない（PO報告 2026-08-06：符牒を選んだあと
  明暗を切り替えると和紙に戻ってしまっていた）
- 家を替えても**明暗の別は持ち越す**。見た目を選んだだけで暗色が外れない
- テーマは `<html data-theme="...">` の1属性で切り替わる。**面ごとの CSS に分岐を書かない**
  （D5：Surface に判断を持たせない）——`[data-theme=…]` を `styles.css` に散らすのではなく、
  家の側が上から被せる
- 家が持てるのは2つ。**トークン**（色・書体・字の段・余白・角・高さ・行間）と、
  **形の層1枚**（`theme/<家>.css`。ADR-0012 決定51）
- 一覧は `theme/themes.ts` が持つ。**足すのは1エントリと、トークン2ブロック（明・暗）**。
  形まで変える家は、そこに CSS を1枚足す
- 既定は端末追従（`prefers-color-scheme`）。POが明示的に選んだらそれを覚える
- 状態は**ひとつ**（`theme/ThemeProvider.tsx`）。`useTheme()` を2箇所で呼ぶと、
  それぞれが別の選択を握って食い違う（実際に踏んだ）

### 6.2 状態の置き場所（D3）

テーマの選択は**画面側の状態**で、ホストは持たない。
`localStorage` に「選択」だけを置き、**解決結果（いま明か暗か）は保存しない**——OS の設定が
変われば導出し直すべき値なので。

```
banto.theme = "<家>:<明暗>"     例: "fucho:system" / "washi:dark"
実際に当たるテーマ = 家.variants[ 明暗が system なら端末から導出、でなければその値 ]
```

---

### 6.3 テーマは持ち込める（作り直し不要）

`<BANTO_DATA_DIR>/themes/` に `themes.json`（台帳）と CSS を置くと、画面を開き直すだけで
選べるようになる。ホストの再起動もビルドも要らない。

- ホストは配るだけ（`/api/themes` と `/api/themes/<name>.css`）。**解釈は画面側**（D5）
- 名前は信頼しない。ベース名だけに落として置き場所の外へ出さない
- 台帳が壊れていたら**その家だけ飛ばして**ログに理由を出す。画面は組み込みの家で動く（I2）
- **持ち込みの家に許すのはトークンだけ**（ADR-0012 決定54）。`:root` に変数を置く規則以外は
  画面側で落とす——**組み方まで許すと、こちらの改装で黙って壊れる**（外の家には
  §6.5 の見張りが効かない）。組み方まで変えたいなら組み込みにする
- **契約に版がある**（決定55）。台帳に `contract` を書く。当てにしているのはトークンの
  名前なので、名前を消した・付け替えたときに版を上げる。合わない家は載せずに理由を出す

作り方は **`docs/notes/how-to-make-a-theme.md`**。

### 6.4 いま載っているテーマ

| 家 | 明 | 暗 | 家の違いで変わるもの |
|---|---|---|---|
| 和紙 | `washi-light` | `washi-dark` | 色と書体（原典） |
| 符牒 | `fucho-light` | `fucho-dark` | 色・書体・字の段・余白・角・高さ・行間 ＋ **組み方**（形の層） |

符牒は案5（`prototype/redesign/05-fucho.html`）の意匠。**トークンだけでは和紙と見分けが
付かなかった**——案5を案5たらしめているのは配色ではなく、黒い状態行・平らなタブ・
1本の罫の境目・`»` の印といった**形**だったため（PO報告 2026-08-06）。形は `theme/fucho.css` が持つ。

**符牒の札は常置しない**（PO裁定 2026-08-06）。案5の見本では札が出ているが、あれは ⌥ を
押している最中の姿。どの家でも `f`・⌥ のときだけ浮かせる（§8.1）——常置すると、押せるものを
探していないときにも画面が記号で埋まる。行の中に置く案も採らない：タブの幅が変わり、
`useTabOverflow` の勘定まで動いて、押そうとしたタブが収納へ落ちる。

### 6.5 形の層と、クラス名の契約（ADR-0012）

- 形の層は `:root[data-theme^="<家>"]` の下に閉じる。**他の家へ1行も漏らさない**
- 読み込み順は **トークン → 面 → 家の層**（`main.tsx`）
- **層に書くのは実際に変えるものだけ。** 既定と同じ値を言い直さない
  ——書いた分だけ面のクラス名に縛られる
- **面のクラス名は家に対する契約**になった。面を組み替えると家が黙って崩れるので、
  `tests/theme-shape.spec.ts` が見張る。契約の一覧は**層そのものから導く**（D3）ので、
  表を別に持たない
- **器（DOM）が無いものは家では作らない**（決定53）。案5の下端のコマンド行は、
  CSS で帯だけ置くと押せない飾りになるので**置かない**（PO裁定 2026-08-06）

## 7. 取次（受け口）

番頭に用があるものを、**出所を問わず**受ける唯一の口。Kobo のアテンションキューとは別物で、
どの店（モジュール）も・番頭自身も・職人も・検証環境も・外の道具も同じ口へ積む。

**POの判断を求めるものは、出所を問わずここ1つ**（決定73）。モジュールが自前の
「許可を求める画面」を持たない——書き込み許可（決定38c）は長らくそこから外れていて、
番頭が面を開かない限りPOは頼まれたことに気づけなかった（PO報告 2026-08-09）。

- 一通は spec-ui §3 の三部構成（**経緯／起きたこと／求める判断**）を必須とする。
  画面を遡らずその札だけで判断できないなら、札として成立していない
- **常設は上段のボタンと数字だけ。** 開くまで画面を取らない（PO報告「画面をとりすぎる」）
- 押すと**会話と面が同時に開く**。片方だけ動いた状態を見せないため、両方ホストが動かす
  （設定の面だけは画面が動かす——会話に被さる面はキャンバスのタブではない）
- **押されたことはその場で効く**（決定73）。選択肢は「押されたらホストが呼ぶ口」を
  持てる（`InboxEffect`）——承認のように番頭には呼べない口（決定29e）を、番頭の
  次のターン任せにしない。**効かせられなければ畳まない**（許したのに書けない、を作らない）
- 答えは**番頭にも伝わり、ターンが回る**（会話へ知らせが入る）。伝えないと同じことを
  もう一度訊いてくるし、伝えるだけで回さないと「押したのに進まない」になる
- **判断待ちは、見ているところにも出す**（`PendingDecisions`）——取次を開かないと
  気づけない、では判断が滞る。出す先は2つ：
  - 見ているキャンバスの面に関わる件は、その面の中に
  - その会話に関わる件は、**会話の流れの中に立てる**（ADR-0017 決定80。同日の
    「入力欄のすぐ上に固定」を差し替えた）。番頭が判断を求めたなら、それは会話の
    最新の発言なので、放っておいても一番下にある——遡ったときだけ↓ボタンが朱になり
    「判断待ち N」と言う。**読みと入力の間に常設はひとつも無い**
- 一通は**どこへ飛べるか**を持つ（会話／キャンバスの面／設定の区画）。押す前に見せる

| Tool | 誰が使うか |
|---|---|
| `inbox.post` | 番頭・モジュール。**自分では決められないものだけ**（D1 / D9 / P3） |
| `inbox.list` | 番頭。POに何を待たせているかの確認 |
| `inbox.resolve` | 番頭。**POが会話の中で答えたときだけ**（画面のボタン経由は自動で畳まれる） |

**押されたときに何を呼ぶかは画面へ配らない**（`InboxItemView` は `effect` を落とす）。
配ると画面から任意の口を叩けることになり、承認を番頭から機構で分けた意味が無くなる（I1）。

実体：`packages/banto-host/src/inbox.ts` / `inbox-tools.ts`、画面は `Inbox.tsx`。
記録は追記だけのイベントログ（`inbox.jsonl`）で、起動時に読み直す——導出できる状態を
ファイルに持たないため（D3）。同じ用件を二度積まないための合印（`key`）だけは持つ。

## 8. ⌘K（横断して引く）

会話・畳んだ会話・面・取次・操作をひとつの入口から引く。**骨格は変えない**——
既にある場所への近道でしかなく、ここから新しい状態は生まれない。

- 判断待ちを**先頭に置く**。横断して引くとき、POを待たせているものが最初に出る
- 引ける先は**画面がすでに知っているものだけ**。ここからデータを取りに行くと、
  開くのに待たされる入口になり、近道の意味がなくなる
- 上段に `⌘K` の札を出す。覚えなくても押せば見える

### 8.1 符牒（キーの札）

**押せるものに符牒（キー）が浮き、その1文字で押せる。** 覚えなくても出せば見える
——キー操作の一番の壁は「何が割り当たっているか分からない」ことなので、一覧を別の場所に
用意するのではなく、押せるものの上に直接出す。**どの家でも効く**（符牒の家だけの機能にしない）。

出し方は2つ。**同じものが出る**。

| 出し方 | どこで効くか |
|---|---|
| **`f` を押す**（本筋） | **どのブラウザでも**。素の1文字はブラウザが持っていない。**もう一度 `f`**・符牒を押す・Esc・画面のどこかを押すと畳む |
| **⌥ を押している間** | Chrome / Firefox / Safari。**Vivaldi では出しても Alt メニューが降りてくる**（PO報告 2026-08-06） |

`⌥` を本筋にできない理由：Alt はブラウザ自身の操作（メニューを開く）で、
**ブラウザによってはページの `preventDefault` が効かない**。止められるものは止めているが、
機構で担保できない以上、止まらない環境がある前提の入口（`f`）を用意する（I1）。

- 割り当ては `data-key` 属性で宣言する。**押す側が自分の符牒を持つ**ので、
  どこかに割り当て表を作らない——ボタンが増えたときに表を直し忘れることがない
- `event.code` で見る。macOS の ⌥＋英字は別の文字（å ç ∂ …）になるため、刻印どおりの位置で当てる
- **出ていない間は素のキーを一切横取りしない。** 文字を打っている最中（入力欄の中）も何もしない
- `f` の入口は ⌘K の帯にも書いてある（`f で符牒`）——覚えていなくても辿り着ける

いま振ってあるもの：

| 符牒 | 先 |
|---|---|
| `1`〜`9` | 会話タブ |
| `n` | 新しい会話 |
| `q w e r y u p a` | キャンバスのタブ（左から） |
| `o` | キャンバスに開く |
| `c` | 番頭への入力欄（器を押して中へ移る） |
| `i` / `h` / `s` / `t` / `k` | 取次 / 履歴 / 設定 / 明暗 / 横断して引く |

**符牒は重ねない。** キャンバスのタブに上段の列をそのまま使うと `o`（開く）や `i`（取次）と
ぶつかるので、取られていない字だけを左から振っている。**`f` はどのボタンにも振らない**
——符牒の入口そのものなので、振ると出した直後に自分が押されて消える。

**会話へ飛んだら、そのまま話しかけられる**（PO要望 2026-08-06）。キーで会話へ入ったのに、
話しかけるのにマウスへ持ち替えるのでは近道にならない。宣言で書く：`data-key-then="c"`
（押したあと、続けてこの符牒を打つ）。いま付いているのは会話タブ（`1`〜`9`）と新しい会話（`n`）。

- **面へ飛ぶときは移さない。** キャンバスのGUI・取次・設定は**見に行った**のであって、
  話しかけに行ったのではない。入力に焦点を奪うと、そのまま打った文字が番頭へ飛ぶ
- ⌘K から会話を開いたときも同じ（`onOpenThread` / `onReopenThread` / `onNewThread`）

**札は必ず器の内側に描く**（PO報告 2026-08-06）。例外を作らない。

- 横に流さない列（キャンバスのタブ）は `overflow` を切っているので、外へ出した札は食われる
- **家が変われば切れるかどうかが変わる。** 符牒の家は上段を 52px から 44px へ詰めるので、
  器の外へ吊った札（`top:-5px`）は画面の外へ出て切れていた。
  **持ち込みの家（§6.3）は高さをこちらが決められない**ので、位置で凌ぐ手は使えない
  ——内側に置くことだけが、どの家でも成り立つ
- 右端が塞がっているもの（× を持つタブ）だけ左へ寄せる。上下は動かさない
- 内側に置くと絵や字の上に載るので、紙の輪を1つ回して下から切り離す
- 札の字は `--t-note`。ここだけ中間の値（9px 等）を持たない（§2）

実体：`packages/banto-web/src/keyHints.ts`。

### 8.2 絞って選ぶ一覧（引くものは全部これ）

モデル選択・⌘K・場所選び・キャンバスに開くものは、**どれも「絞る欄 ＋ 一覧 ＋ 確定」**という
同じ形をしている。同じ形のものが場所ごとに違う触り心地をするのが一番覚えにくいので、
作法を1つに揃える（PO要望 2026-08-06）。

- **画面に対して置く。押した脇に開かない**——脇に開くものは狭い画面で必ず端からはみ出し、
  横スクロールが生えて**画面全体が横へずれる**（モデル選択で実際に踏んだ）。⌘K は自前の面、
  他は `Modal`
- **開いたらそのまま打ち始められる**（絞る欄に焦点が入っている）
- **`↑` `↓` で当たりを動かし、`Enter` で確定、`Esc` で閉じる。** 何も打っていなくても
  先頭に当たっている＝開いて Enter だけで決まる
- **絞ると当たりは先頭へ戻る。** 前の位置を覚えていると、1文字打つたびに関係のない行が当たる
- **束ねてあっても、当たりは目に見えている順に動く**（プロバイダ別・リポジトリ別に
  まとめていても、通し番号は描画順）
- 当たりは**色と形の両方**で出す（地の色＋左の罫）——「いま使っているもの」も地の色を
  持つので、色だけだと見分けが付かない（1.4）
- 面の脚に `↑↓ で選ぶ · Enter で決める · Esc で閉じる` を出す。一覧を送っても消えない位置に置く
- **IME の変換中は横取りしない。** 変換候補の上下も確定の Enter もこの欄へ来る

実体：`packages/banto-web/src/listNav.ts`（`useListNav`）。絞る欄は `SearchField` の
`onKeyDown` に差し込む。

### 8.3 外に出るリンクは別のタブで開く

Banto は**開きっぱなしで使う面**（会話・キャンバス・下書き・スクロール位置）を持っている。
番頭の応答や読んでいるファイルの中のリンクを同じタブで開くと、それが丸ごと消える——
戻ってきても、送っていた会話も書きかけも元には戻らない（PO要望 2026-08-06）。

- 判断は**自分のオリジンかどうか**の1点。相対パスも `#見出し` もこの面の中なので、そのまま
  ——同じ面の中の行き先まで別タブにすると、押すたびに同じ画面が増える
- `rel="noreferrer"` を必ず付ける（開いた先から `window.opener` でこちらを触らせない）
- どの Markdown（番頭の応答・知らせ・思考・SKILL.md・読んでいる `.md`）でも同じ振る舞い

実体：`packages/banto-web/src/links.tsx`（`MarkdownLink` / `isExternalHref`）。

## 9. 破ってはいけない順序

意匠の規約が衝突したときの優先順位。

1. **朱は判断待ちにしか使わない**（1.1）——これが崩れると画面から「あなたの番」が読めなくなる
2. **状態は色と形の両方**（1.4）——色が見えない環境でも通ること
3. **ここに無い値を面が持たない**（第一原理）——1つ許すと 17 段・107 枠に戻る
