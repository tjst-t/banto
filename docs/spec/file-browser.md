# Spec: File Browser（ファイル／プレビュー面）

番頭のキャンバスに開く基本GUI「ファイル」（`file.browser`）の仕様。`spec-chat-ui` と対をなす。

第一原理：**実体はホスト側にあり、GUIは表示と操作だけを持つ**（D3・D5）。ファイル一覧・中身の実体は
workspace モジュールのデータAPI（`file.*` ToolのHTTP口）にあり、GUIは `useModuleTool` 経由でそれを取得する
だけ。閲覧はどの場所にも届き、**変更（書き込み・新規・削除・アップロード）は PO が場所ごとに許した範囲に
限られる**（決定38・`file.write`、`place.request_write`）。

第二原理（2026-08-08 新設）：**この面の主役はファイルの中身であって、道具立てではない。**
道具立てが縦を取るほど、一度に読める行が減る。狭い画面ではそれが致命になる。

---
前提（決定25・27）：GUIと番頭は同じ Tool 契約を共有——GUIは `{endpoint}/tools/{Tool名}` の HTTP 口、
番頭はホスト内で同じ実装を直接呼ぶ。経路が違うだけで契約は1つ。
`file.browser` は `places` のデータAPIから読む（場所が指定されなければ PO が PlacePicker で選ぶ）。
---

## 1. この面が守る4つの約束

意匠と操作の判断が割れたときは、この順で decide する。

1. **中身に画面を明け渡す。** 道具立ては常設を最小にし、必要になったときに出す
2. **いまどこにいるかは、いつでも読める。** 省くのは頭であって、末尾（いまいる所）ではない
3. **押すものは指で押せる。** 狭いときの一覧の行は 44px、その他の当たりは 38px 以上
4. **見えているものは、いま取ってきたもの。** 前のディレクトリ・前のファイルを黙って出さない

## 2. 画面構成

### 2.1 広いとき

```
┌──────────────────────────────────────────────────────────┐
│ [📍banto] 🏠 / docs / spec / place                        │ 1段だけ
├──────────────────────────┬───────────────────────────────┤
│ [🔍 絞る／Enterで探す][隠]│ README.md   [整形|原文]  […]  │
│  📁 src/              ›  │                               │
│  📝 README.md    11 KB   │  （ファイルの中身）            │
│  ⚙️ tsconfig.json 659 B  │                               │
└──────────────────────────┴───────────────────────────────┘
```

### 2.2 狭いとき（一覧）

```
┌────────────────────────────┐
│ [📍banto] 🏠 … / place     │ 46px
│ [🔍 絞る／Enterで探す][隠] │ 46px
├────────────────────────────┤
│  📁 packages            ›  │ 44px
│  📝 README.md      11 KB   │
└────────────────────────────┘
```

### 2.3 狭いとき（中身）

```
┌────────────────────────────┐
│ [‹一覧] README.md [整形|原文] […] │ 46px
├────────────────────────────┤
│  （ファイルの中身）         │
└────────────────────────────┘
```

**狭いときは、中身を読んでいる間だけ上段（場所・パンくず）を畳む**（2026-08-08 の決め直し）。
旧版は「両カラムにまたがって出しっぱなし」としていたが、実測で 150px——画面の 19%——を、
読んでいる最中には二の次の情報が占めていた。畳んでよいと判断した根拠は3つ：

- 何を読んでいるかは**ファイル名が答えている**（頭に出ている）
- どこにいるかは**「‹ 一覧」を押せば1手で戻って読める**
- 場所（place）を読みながら変えることは無い——変えるなら一覧へ戻る

広いときは畳まない。**そこでは縦が足りているので、出しておかない理由がない。**

### 2.4 縦の予算（狭いとき・390×780）

**PO報告 2026-08-08 の芯はここ**——「操作部分が場所を取りすぎて、ファイルの表示領域が小さすぎる」。
字の大きさ（§5.6）とは別の話で、こちらが主。

ファイルを読んでいるときの実測と、決め：

| 区画 | いま | 決め |
|---|---|---|
| 屋号の帯 | 52px | 52px（送っている間は退く。§6.5） |
| キャンバスのタブ列 | 45px | 45px（**退かせない**。どの面を見ているかは常に要る） |
| 上段（場所・パンくず） | 108px | **0px**（読んでいる間は畳む。§2.3） |
| 「‹ ファイル一覧」の行 | 41px | **0px**（中身の頭に取り込む。§5.2） |
| 中身の頭（名前・整形/原文・`…`） | 55px | **46px**（送っている間は退く。§6.5） |
| **中身** | **411px（53%）** | **569px（73%）／送っている間は 660px 前後（85%）** |
| 下端の切替バー | 56px | 56px |

一覧を見ているときは：上段 46px ＋ 絞る欄 46px ＋ 一覧（残り全部）。

**この予算を超える道具立てを常設しない。** 増やしたいものは「押したら出る」か「送ったら退く」に
する。**新しく足すものは、必ずこの表のどこかから引く。**

## 3. 道具立て

### 3.1 上段は1段。伸ばすのは道でなく紙

| もの | 広いとき | 狭いとき |
|---|---|---|
| 場所（`PlacePicker`） | 札。最大 260px | 札。**伸ばさない**（`flex: 0 1 auto`・面の 40% まで）。名前は省略記号で切る |
| パンくず | 全段 | 末尾優先で畳む（§3.2） |
| 探す | — | — |

**「探す」ボタンは廃止する**（§4.3 で欄に統合）。押して2段目を生やす作りは、狭いときに
道具立てを 3 段にしていた。

### 3.2 パンくずは末尾優先で畳む。横に流さない

`spec-canvas-ui` §6 がタブ列に対して決めたことと同じ理由——**横に流したものは、隠れていることも
数も見えないまま指で探すことになる**。パンくずでは症状がもっと悪く、切れて消えるのが
「いまいるディレクトリ」だった（§0 #5）。

- **末尾（いまいる所）と、その1つ上は必ず出す。** 足りない分は**頭から**畳む
- 畳んだ分は `…` の1押しにまとめ、押すと**重ねる面（`Modal`）**で全段を出す。作法は
  `spec-design` §8.2（絞る欄＋一覧＋確定・↑↓ Enter・Esc）に揃える
- いちばん上（場所のルート）は絵の札のまま残す。狭いとき 38px（PO報告 2026-08-05）
- `overflow-x: auto` は使わない

```
🏠 … / nested / place        （深いとき）
🏠 / docs / place            （収まるとき）
```

### 3.3 絞る欄は一覧の中に1つだけ

道具立ての段ではなく、**一覧ペインの上端**に置く。詳細を読んでいる間は出ない。

## 4. 一覧（リストビュー）

### 4.1 エントリと並び順

エントリは `{name, type: "dir"|"file", size?}`。

**並び順はホストが決めて返す。画面は並べ替えない**（D5・`spec-canvas-ui` §1）。
規約は「ディレクトリが先、その中は名前順」。実体は `file-tools.ts` の `file.list`。

### 4.2 行

- 絵（`iconOfFile`）＋名前＋末尾（ファイルはサイズ、ディレクトリは `›`）
- ディレクトリは名前を太らせる
- 名前は省略記号で切る。**横スクロールを生やさない**
- 行の高さ：広いとき 32px、**狭いとき 44px**（§1 の約束③。一覧の行はこの面で最も押すもの
  なので、共通の 38px より厚く取る）
- 選ばれている行は淡い地（`--ai-t`）＋色字（`spec-design` §1.1。**塗らない**）
- **選んでも末尾の情報を消さない。** いまは `rgba(128,128,128,0.22)` で塗って消している（§0 #10）
  ——トークンに無い値であり（`spec-design` 第一原理）、消す理由も無い

### 4.3 絞ると探すを1つの欄にまとめる

旧版は3つの口（この一覧を絞る／探す→中身／探す→名前）と「隠しも」を**同時に常設**していた。
狭い画面で 2 段を食い、しかも「どれに打てばよいか」が読めない。

**欄は1つ。打つと絞り、Enter で探す。**

| 操作 | 何が起きるか | 呼ぶもの |
|---|---|---|
| 打つ | いま出ている一覧を打鍵ごとに絞る（サーバへ投げない） | — |
| `Enter` | **このディレクトリ以下**を探す。既定は中身（正規表現・大小無視） | `file.grep` |
| 結果の見出しで「名前」へ切替 | 同じ語でファイル名を探す（`*` を含まなければ前後に補う） | `file.find` |
| 隠し（チップ） | ドット始まり・`node_modules` 等も対象にする | `file.list` / `file.find` / `file.grep` の `includeHidden` |

- 置き書きは `この一覧を絞る（Enter でこの下を探す）`。**次の一手を欄が自分で言う**
- **探し方（中身／名前）は探す前に選ばせない。** 結果の見出しに `[中身|名前]` を出し、
  外したときだけ切り替える——使うたびに択一を先出しすると、道具立てが1段増える
- 「隠しも」は `Toggle`（チェックボックス）をやめて `Chip` にする。
  当たりが 21px しかなく、指で押せない（§0 #4・`spec-canvas-ui` §5：入切は `Chip`）
- 探した結果は一覧の代わりに出し、見出しの「× やめる」で元の一覧へ戻る
- **狭い画面では探した時点で一覧側へ戻す**——結果が開いていたファイルの裏に隠れないように

### 4.4 絞りはその場所のもの。動いたら外れる

**ディレクトリを移ったら絞りは外れる。** いまはエントリを押したときしか外れず、
パンくずで移ると前のディレクトリ向けの絞りが残って、移った先が空に見える。

外れる契機：エントリを押した／パンくずで移った／`…` から移った／場所を変えた／探すのをやめた。

### 4.5 キーで辿る

`spec-design` §8.2 が「絞る欄＋一覧」に定めた作法を、この面にも効かせる（`useListNav`）。

| キー | 先 |
|---|---|
| `↑` `↓` | 当たりを動かす |
| `Enter` | ディレクトリなら入る、ファイルなら開く |
| `→` | ディレクトリに入る |
| `←` | 親へ戻る |
| `Esc` | 絞りを外す（空なら一覧へ焦点を返す） |

**絞ると当たりは先頭へ戻す。** IME の変換中は横取りしない。

### 4.6 一覧の省略（truncation）

`file.list` の `truncated` が true のとき「… 上限を超えたため一部のみ表示（全 N 件）」を出す。
件数は `total`（全件数）。

**画面側の絞りは、届いた分にしか効かない。** 上限で切られた先にあるものは、絞っても出てこない
——だから省略が出ているときは、絞り欄の置き書きを `Enter でこの下を全部探す` に変える。
届いていないものへ手が届く経路を、その場に出す。

## 5. 中身（プレビューと原文）

種別判定（`filePreview.ts`）は**純粋関数**で UI から独立（DOM・shiki 非依存）。ブラウザでも node:test
でも読める。

### 5.1 種別判定 `kindOfPath`

| 種別 | 拡張子 | 描画 |
|---|---|---|
| `markdown` | md | GFM（remark-gfm）Markdown、コードブロック内は mermaid→shiki |
| `mermaid` | mmd, mermaid | mermaid.js 描画（動的 import、エラーは生コード表示） |
| `csv` | csv, tsv | papaparse でテーブル表示（1行目をヘッダ強調、列数は最大に揃えて） |
| `diff` | diff, patch | unified 色分け（gv-add / gv-del / gv-hunk 流用） |
| `html` | html, htm | 隔離した `<iframe>` で描画（§5.9）。source はマークアップ |
| `image` | png, jpeg, jpg, gif, webp, avif | `<img>`（§5.10）。source は無い |
| `code` | ts, js, py, … | shiki ハイライト（行番号なしの preview、行番号付きは source） |
| `plain` | その他 | 素のテキスト。source 固定 |

`html` / `image` は**中身を `file.read` で運ばない**（§5.8 の raw の口を src にする）。
`image` はバイナリなので `file.read` では端から読めず、`html` は iframe に URL を渡す形でしか
相対パスの資産が解決しない。

**文法は出てきた言語だけを1つずつ引く**（`fileHighlight.ts` の `LANG_LOADERS`）。以前は
全言語を一括で読み込んでおり、コードブロックが1つ現れただけで24言語ぶん（圧縮後 178KB）が
降っていた。よくある組み合わせなら 24KB で済む——効くのは転送量だけでなく、**24個の文法を
組み立てる CPU** も要らなくなる（遅い端末ではこちらが響く）。

別名（```ts / ```bash / 大文字のフェンス）は `LANG_ALIASES` で手前で解く。**全部載せの頃は
shiki が文法から別名を登録してくれていた**が、引く前に何を引くか決めるいまは自前で解かないと
素のまま出る。扱えない言語は今までどおり素のまま表示（fallback）。

### 5.2 中身の頭（`fb-file-head`）は1段

左から：**「‹ 一覧」（狭いときだけ）・ファイル名・`[整形|原文]`・`…`**。

- **折り返し・本文をコピーは `…` の中へ入れる。** 読んでいる間に押すものではない
- ファイル名は**末尾を必ず見せる**。長いときは頭を `…` で落とす（`…/views/FileBrowser.tsx`）
  - **`direction: rtl` は使わない。** 先頭の `/` が中立文字として末尾へ回り、
    `home/ubuntu/…/` のように壊れる（`spec-design` が `PlacePicker` で既に禁じた実測。
    この面の `.fb-file-path` / `.fb-hit-path` に残っている）
- 全体のパスはツールチップと `…` の中で読める

### 5.3 preview / source 切替

- preview / source トグルはローカル state。ファイル切替でリセット
- **原文（source）の折り返しは既定で入**（PO裁定 2026-08-05）。横に流れると、読むのに縦横
  二方向へ動かすことになる
- preview では行番号を**出さない**
- **2000行超**のファイルは preview を無効化し source に落とす（`PREVIEW_MAX_LINES=2000`、task-0050 a4）
- **モード切替時にスクロール位置を割合（fraction）で復元**する——preview と source では行の高さが違う
  ため、再カウント単位ではなく割合で。復元は切替のたびに**1回だけ**（非同期描画完了の再実行で
  手動スクロール位置を巻き戻さない）

### 5.4 行を指されて開いたときは原文で開く（2026-08-08 新設）

`params.line`（と `endLine`）付き、または `file.grep` の結果から開いたとき——つまり
**「この行を見て」と言われて開いたとき**は、`source` で開く。

いまは種別が markdown / code なら `preview` で開き、**行の強調は source にしか無い**ので、
番頭が行を指しても整形された本文が出るだけで、どこを指されたのか分からない。

- 強調行があるときの初期モードは `source`
- 帯に `N 行目に合わせています` と出し、`整形で読む` を並べる（読み物として読み直せる）
- 強調は**その基点のファイルを見ている間だけ**。別のファイルを選んだら解除
- **強調行へ寄せるのは、基点が変わったときだけ。** いまは中身が伸びるたびに寄せ直しており、
  「続きを読む」を押すと強調行まで引き戻される（§5.5）

### 5.5 読み込む範囲と「続きを読む」

`file.read` は1回で全部は返さない。**行数（既定 400、`maxLines`）とサイズ（200,000 bytes）の
両方**で切る。サイズは行数より強く、`maxLines` を大きくしても 200,000 bytes までしか返らない。

- **総行数（`totalLines`）はファイル全体から数える。** 切った後の残りから数えると、画面も番頭も
  「これで全部だ」と誤る
- 返した範囲は `from` / `to`（1始まり）。続きは **`offset` に `to + 1`** を渡して読む
- 画面は帯に「`to` / `totalLines` 行まで読んでいます」と出し、**「続きを読む」**で継ぎ足す
  （1回 2000 行、ホストのサイズ上限に当たればそこで止まる）。読み切ったら「すべて読み込みました」
- **継ぎ足しても、いま読んでいる位置は動かさない。** 足した分は下に伸びるだけ
- 基点を取り直したら（別のファイル・別の強調行）継ぎ足しは捨てる。前の基点に繋げると行がずれる
- **1行だけで 200,000 bytes を超える場合はその行を途中で切る**（`partialLine`）。`offset` は行単位
  なので**その行の残りへは進めない**——画面も番頭にもそう伝える。中身を追うなら `file.grep`

### 5.6 読ませる字は読ませる大きさで

読んでいるファイルの本文は `spec-design` §2 でいう**「読ませる本文」**であって、一覧の行ではない。
狭いときの実測（390px）は下記で、**中身も一覧も、この面はどこも小さい**。

| もの | いま | 狭いときの決め |
|---|---|---|
| markdown の本文 | 13px | **15px**（`--t-read`） |
| 原文（source）・コード | **12px** | **15px**（`--t-read`。等幅のまま） |
| 一覧のファイル名 | 13px | **15px**（`--t-read`） |
| 一覧のサイズ | 11px | **12px**（`--t-meta`） |
| markdown の見出し | 19px | 19px（`--t-head`。据え置き） |

広いときはいずれも据え置き（13px / 12px / 13px / 11px）。**狭いときだけ一段上げる。**

原文とコードを 12px に据え置く案は**撤回した**（2026-08-08）。理由にしていた「字を大きくすると
1行に入る情報が減る」は、**折り返しが既定で入っている狭い画面では成り立たない**——
360px の幅では 12px でも 46 文字しか入らず、どのみちコードは折り返る。折り返る前提なら、
残る差は読めるかどうかだけ。

- markdown の本文は**器の幅を使い切る**（PO報告 2026-08-09「謎の空白が右側にできる」）。
  `78ch` の行長上限は**撤回した**（2026-08-09）——読み物としては筋が通るが、この面は
  **自分で幅を決められない**。キャンバスの1枚として、POが引いた仕切りの中に居る。
  広げたのに本文が伸びなければ、余りは「読みやすさ」ではなく**壊れて見える空白**になる。
  行長を詰めたいときは仕切り（`SplitView` の掴み）を狭める側で決める
- **面の外の倍率で凌がせない。** ピンチで拡大すれば読めるから小さくてよい、にはしない
  ——拡大した画面では一覧も道具立ても画面外へ出る

### 5.7 描画規約

- 読込中・言語非対応でも**素のコードを出して読める状態を保つ**（ハイライト不可時は plain text fallback）
- `mermaid`・`csv` は動的 import（初回ロードに載せない）
- diff は行ごとに色分け（naive 判定）
- mermaid の図・CSV の表は**器から溢れさせない**。溢れるものは**その箱の中だけ**横に送れるようにし、
  面ごと横へずらさない

### 5.8 そのまま配る口（`file.raw`）— 別タブ・HTML・画像・ダウンロードの土台

**PO要望 2026-08-08。** ①ファイルの中身をブラウザの別タブで開きたい ②HTML は静的配信扱いに
してほしい。どちらも「`file.read`（構造化データ）とは別に、**バイトをそのまま返す口**が要る」に
帰着する。画像プレビューとダウンロード（旧 §11.2 の escalate 待ち）も同じ口に乗るので、
まとめてここで決める。

#### 5.8.1 口

```
GET {module endpoint}/raw/{place}/{path…}          そのまま返す（inline）
GET {module endpoint}/raw/{place}/{path…}?dl=1     ダウンロード（attachment）
```

- **GET だけ。書き込む口はここに生やさない**
- パスは**クエリではなく経路で表す**——HTML の中の相対パス（`./style.css`・`img/a.png`）が
  そのまま解決する必要がある。クエリに押し込むと相対参照が全部壊れる
- 場所（place）の閲覧可否とパスの正規化は **`file.*` Tool と同じ実装を通す**（D3・D5）。
  ここだけ別の判定を書くと、Tool で塞いだ穴がこちらで開く
- `file.read` の上限（400行・200,000 bytes・`PREVIEW_MAX_LINES`）は**かからない**。
  minify 済みの1行ファイル（§11.3）に手が届く経路は、当面これになる

#### 5.8.2 型は allowlist。sniff させない

拡張子 → `Content-Type` の表を持ち、**表に無いものは `text/plain; charset=utf-8`**。
`X-Content-Type-Options: nosniff` を必ず付ける。

| 拡張子 | 型 | 備考 |
|---|---|---|
| html, htm | `text/html; charset=utf-8` | §5.8.3 の隔離が要る |
| css | `text/css; charset=utf-8` | HTML の連れ。無いと意匠が当たらない |
| js, mjs | `text/javascript; charset=utf-8` | HTML の連れ。不透明なオリジンの中だけで動く |
| json | `application/json; charset=utf-8` | HTML の連れ（データを読む一枚もの） |
| woff2, woff, ttf, otf | 各フォント型 | HTML の連れ。不活性 |
| png, jpeg, jpg, gif, webp, avif | 各画像型 | 不活性。そのまま inline |
| pdf | `application/pdf` | ブラウザの表示器に任せる |
| **svg** | **`text/plain`** | **画像として配らない**——SVG はスクリプトを持てる |
| そのほか | `text/plain; charset=utf-8` | md も ts も、生で読ませるならこれで足りる |

**HTML の連れを表に載せたのは PO報告 2026-08-09**（「同じフォルダから配信する CSS が
当たらない」・inc-0046）。`nosniff` を付けている以上、`text/plain` で配った `.css` は
ブラウザが**意匠として使うことを拒む**——「HTML を静的配信扱いにする」（§5.8 の PO要望②）は、
連れが載っていないと成り立たない。**隔離は緩んでいない**：スクリプトが動くのは §5.8.3 の
不透明なオリジンの中だけで、そこでは元から inline の `<script>` が動く。外に置いた `.js` を
拒む理由が無い。連れ自体を直に開いても `allow-scripts` は付かない（§5.8.3 で緩めるのは
HTML と PDF だけ）。

**svg は据え置き。** `<img>` の連れとしてだけでなく**それ自体を文書として開ける**ので、
ここを緩めるのは §5.8.3 の隔離に触る決め＝D1（再度PO裁定が要る）。HTML の中の
`<img src="chart.svg">` が出ないのは、この決めの副作用として残る。

#### 5.8.3 HTML は別のオリジンとして配る（安全側の決め）

**そのままの HTML を Banto と同じオリジンで配ってはいけない。** 配ると、リポジトリの中の
HTML（外から取り込んだもの・職人が生成したもの・依存の中の一枚）が
**Banto のオリジンで動くスクリプト**になり、`localStorage` も、同じオリジンの
`/api/…`（`file.write`・`place.*` を含む）も、POのセッションのまま触れる。
閲覧のための機能が、書き込みの経路になる。

決め：**`Content-Security-Policy: sandbox allow-scripts allow-popups` を付けて配る。**

- `allow-same-origin` を**付けない**。付けないと文書は**不透明なオリジン**になり、
  Banto の `localStorage`・Cookie・API に届かない。中身（スクリプト込み）は動いて見える
- 面の中の preview も同じで、`<iframe sandbox="allow-scripts">`（`allow-same-origin` なし）＋
  src は同じ raw URL。**ヘッダと属性の二重掛け**——どちらかが欠けても閉じている側に倒れる
- これで足りない要求（HTML から Banto の API を呼びたい等）が出てきたら、
  **別ポート／別ホスト名で配る**まで戻る。オリジンを分けずに緩めない
- 落款（Banto の画面）と紛れないよう、別タブで開いたものは Banto の意匠を持たない
  ——そのまま配っているので当然だが、**「これは Banto の画面ではない」ことが見た目で分かる**
  のは、この決めの副産物として都合がよい

これは one-way（公開I/F・外部から到達しうる面）なので D1。**PO要望として起票され、
上の隔離を前提に採る**。隔離を外す変更は再度 D1 に戻る。

#### 5.8.4 面からの出し方

- **「別タブで開く」はどのファイルにも出す。** 大きいファイル・崩れた整形・見たいだけのもの
  は、ブラウザに任せた方が早い
  - 種別が `html` / 画像 / pdf のときは**中身の頭に直接**出す（押す価値が高い）
  - それ以外は `…` の中（§5.2）

##### 別タブでも整形で読む（PO要望 2026-08-09）

> マークダウンとかを別タブで開いたときにソースファイル表示になるけど、別タブでは
> マークダウンに限らずすべてプレビュー表示にしてほしい

**別タブの行き先を種別で分ける。**

| 種別 | 行き先 | 理由 |
|---|---|---|
| markdown / mermaid / csv / diff / code / plain | **整形して読む1枚**（`FilePage`） | raw は `text/plain`（§5.8.2）＝ブラウザは原文しか出せない |
| html / 画像 / pdf | `file.raw` のまま | ブラウザ自身が既に整形して見せる。1枚に載せると iframe の中に押し込むことになる |
| バイナリ | `file.raw` のまま | 整形の姿を持たない |

1枚（`FilePage`）の決め：

- **会話もキャンバスもホストへの接続も持たない。** 要るのは `file.read` だけ。ファイルを1つ
  見るために会話の状態まで復元しない
- **描き手は面と共通**（`FileBody.tsx`）。同じファイルが面と別タブで違う姿を持つと、
  どちらが本物か分からなくなる
- 位置は URL が持つ（`?file=…&place=…&ep=…`）。**位置の真実は URL**（`viewLocation.ts` と同じ）
- **到達先（`ep`）は受け取る側が疑う。** 自分のオリジンの中を指す経路以外は「別タブの位置では
  ない」と見なして、いつもの画面を出す——外を指せるなら、細工した1本のリンクで
  「Banto の画面が別のオリジンへPOのセッションで問い合わせる」ことになる
- 頭に**「生ファイル」と「保存」**を残す。整形が崩れたときの逃げ場を潰さない
- 整形の上限（§5.3 の 2000行）はここでも効く。超えたら原文で出す
- リンクは `target="_blank" rel="noreferrer"`（`spec-design` §8.3 と同じ作法）。
  **開きっぱなしで使う面を潰さない**のが理由なのは、外部リンクのときと変わらない
- 「ダウンロード」も `…` の中（`?dl=1`）
- **キャンバスのタブを増やす経路とは別物。** 2つのファイルを Banto の中で並べたいときは
  `file.browser` をもう1枚開く（番頭に頼む／カタログから）。ブラウザの別タブは
  「Banto の外でそのファイルを見る」ためのもので、役が違う

### 5.9 HTML は面の中でも描く

種別 `html`（拡張子 html / htm）を `kindOfPath` に足す。

| モード | 出るもの |
|---|---|
| 整形（preview） | `<iframe>`（§5.8.3 の隔離つき）で描画。高さは面いっぱい |
| 原文（source） | マークアップを shiki（`lang: html`）で |

- 頭に**「別タブで開く」を直接出す**——面の中の枠より、ブラウザの1枚のほうが読める場合がある
- iframe の中は**別の文書**なので、面の折り返し・行強調・「続きを読む」は効かない。
  行を指されて開いたとき（§5.4）は `source` で開く（この面の一般則がそのまま効く）
- 2000行超でも preview を殺さない（§5.3 の `PREVIEW_MAX_LINES` は**画面が組む行**への
  上限であって、iframe には関係がない）

### 5.10 バイナリと画像

- 画像（png / jpeg / gif / webp / avif）は種別 `image` として **`<img src={raw URL}>`** で出す。
  頭に大きさとバイト数、「別タブで開く」
- それ以外のバイナリは「バイナリのため表示できません」＋バイト数のまま。
  ただし**「別タブで開く」と「ダウンロード」は出す**——見られないことと、
  取り出せないことは別

## 6. モバイルは縮小版ではない

`spec-canvas-ui` §3 の共通規約（コンテナクエリ・760px・入力欄 16px 以上）に従いつつ、
この面が守るものを具体で書く。**「広い画面のものを詰めた姿」ではなく、狭いときの姿を別に決める。**

### 6.1 狭さの判定はキャンバス自身の幅

ビューポート幅ではなくコンテナクエリ（`container-name: canvas`・760px）。チャット欄を広げて
キャンバスが細くなったときと、スマホで見たときは、POにとって同じ「狭い」。

### 6.2 押せる大きさ（狭いとき）

| もの | 大きさ | いまの実測 |
|---|---|---|
| 一覧の行（`.fb-entry`） | **44px** | 32px ✗ |
| パンくずの各段 | 38px | 34px ✗ |
| パンくずのルート（🏠）・`…` | 38px | 38px ✓ |
| 場所の札 | 38px | 38px ✓ |
| 絞る欄 | 38px・字は 16px 以上 | 38px・19px ✓ |
| 隠し（チップ） | 38px | 21px（Toggle）✗ |
| 「‹ 一覧」 | 38px | 41px ✓ |
| `[整形|原文]` の各片 | 38px | 32px ✗ |
| `…`（その他） | 38px | — |

### 6.3 一覧と中身はドリルダウン

- 仕組みは `spec-canvas-ui` の `SplitView`。**両方を常に描き、CSS で出し分ける**
  （作り直すとスクロール位置も読み込み済みの中身も消える）
- 「開いているファイル」と「いまどちらを見ているか」は**別に持つ**。探し直しても、前に見ていた
  ファイルは閉じない
- 戻りは中身の頭の中の「‹ 一覧」（§5.2）。**独立した行にしない**——41px の行を1本使っていた
- ペイン内スクロールは素直な垂直スクロールのみ。**面そのものは縦にも横にも動かさない**

### 6.4 送ると道具立ては退く（読んでいる間だけ）

畳めるだけ畳んでも、狭い画面ではまだ 46px の頭が残る。**読んでいる最中の頭には仕事が無い**
——名前はもう読んだし、整形/原文は最初に決めている。

決め：**狭いとき、中身を下へ送っている間は「中身の頭」を退かせる。上へ少しでも送ると戻る。**

- 効くのは**中身のペインだけ**。一覧では退かせない（絞り欄と場所は、探している間ずっと要る）
- 戻す仕草は、いま既にしている仕草と同じ（上へ送る）。**戻すための新しい操作を作らない**
- **キャンバスのタブ列は退かせない。** どの面を見ているかは常に要る（`spec-canvas-ui` §6）。
  `tests/mobile-layout.spec.ts` が見張っている「タブ列が居座る」はそのまま守る
- 屋号の帯（`.topbar`）も同じ規則で退く。決めは `spec-canvas-ui` §3 側に置く
  ——この面だけの話ではないため
- 退いている間も、**戻る導線を失わせない**。端末の「戻る」に頼らせない
  （上へ送れば頭が戻り、そこに「‹ 一覧」がある）
- `prefers-reduced-motion` のときは動かさずに切り替える

これで読める高さは 569px → **660px 前後**（画面の 85%）。横向き（短辺 390px 前後）では
この差がそのまま成立の分かれ目になる——退かせないと本文が 190px しか残らない。

### 6.5 面ごと横へずれるものを置かない

`tests/mobile-layout.spec.ts` が見張っている「横スクロールが生えていないこと」は、この面では
**パンくず・長いファイル名・mermaid・CSV・原文の非折り返し**の5つが破りうる。
どれも**その箱の中で処理する**（畳む・切る・箱だけ横に送る）。

## 8. 状態の出し方

`spec-canvas-ui` §4 の表（`Loading` / `EmptyState` / `ErrorNote` / `Note`）に従う。この面で足すのは2つ。

### 8.1 古い中身を出さない（§1 の約束④）

`useModuleTool` は引数が変わっても、次が届くまで**前の結果を持ち続ける**。そのため

- 別のディレクトリへ移ると、届くまで**前のディレクトリの一覧**が出たままになる
- 別のファイルを選ぶと、頭は新しい名前なのに**中身は前のファイル**という瞬間ができる

**いま見せているものが、いま頼んだものかを確かめてから描く。** `file.list` / `file.read` は
どちらも `path` を返しているので、**要求したパスと一致するときだけ描く**（D3：判定用の状態を
別に持たず、返ってきたもので導く）。一致しない間は `Loading`。

### 8.2 開けなかったときの帯は、いつまでも出さない

`params.path` が開けないと「『X』を開けませんでした（いちばん上から表示しています）」を出すが、
これが**その後ずっと一覧の上に残る**。場所を変えた直後は前の場所のパスを stat するので、
毎回この帯が出る。

- 帯は**その stat の結果に対してだけ**出す。POが自分でどこかへ移ったら畳む
- 場所を変えたときは、前の場所のパスで stat し直さない（新しい場所のルートから始める）

### 11.1 D1 に触れるもの（PO 承認と場所の許可が要る）

書き込み・削除・アップロードは one-way な外部副作用（D1）。`place.request_write` で場所ごとの
許可を得てから。VSCode の explorer（`fileImportExport.ts`・`fileActions.ts`・`explorerViewer.ts`）を参照に整理した候補：

| 操作 | 内容 | 前提 |
|---|---|---|
| **アップロード** | 複数ファイルを選択→target フォルダへ書き込み。進捗・上書き確認・1件なら即開く | 書き込み許可 |
| **ダウンロード** | 単ファイルは blob 保存。フォルダ／複数は構造を保った zip | 閲覧権限のみで可だが**ホストに新しい口が要る**（下記 11.2） |
| **ドラッグ&ドロップ** | OS からの投入＝アップロード。ツリー内の移動＝移動／コピー。自己・祖先への移動と readonly は弾く | 書き込み許可。**狭い画面では代替の導線が要る**（DnD は指では成立しない） |
| **新規ファイル／フォルダ** | リスト最下部にインライン入力・検証（空／重複／不正文字→Error、末尾空白→Warning） | 書き込み許可 |
| **リネーム** | インライン編集で名前検証・確定 | 書き込み許可 |
| **削除** | 確認ダイアログ（件数・「未コミットの変更があります」警告） | 書き込み許可（D1） |
| **複数選択** | 複数への一括操作 | — |

実装時の制約：**操作がすべて Tool 契約（`file.write` 等）に落ち、GUI 側に判断・実体操作を置かない**（D5）。

## 12. 現実装の持つ「特筆すべき知識」

- stat→親を確かめてからツリーを組み立てる順（`file.stat`→`file.list`→`file.read`）

- 骨格（道具立て・一覧・空状態・失敗の出方・ドリルダウン）は `spec-canvas-ui` の共通部品で、
  この面に固有なのは**ファイルの読み方**だけ
