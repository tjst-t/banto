## A. 会話の構造

| # | 要件 | 出所 |
|---|---|---|
| **A1** | プロジェクトを単位として並べられる | 【PO】 |
| **A2** | 1つのプロジェクトの中に、複数の会話が同時に存在できる | 【PO】 |
| **A3** | 会話は分岐できる。同じ文脈から複数の試みが並ぶ | 【PO】 |
| **A4** | **分岐は安く切れる。** 枝を増やすことが費用の理由で躊躇されない | 【計測】【査読】 |
| **A5** | 全プロジェクト・全会話を横断して「**いま自分を待っているもの**」が1画面で分かる | 【査読】 |
| **A6** | **判断待ちは1本の行列に集まる。** 出所は問わない | 【裁定】 |
| **A7** | 判断待ちが**滞留したとき**、端末へ届く（push）。**発生時には鳴らさない** | 【裁定】 |
| **A8** | 会話は閉じても残り、読み返せる／再開できる | 【裁定】 |

### A6. 判断待ちの行列

出所が違っても、人にとっては同じ「自分が見ないと進まないもの」である。3本の列を作れば見に行く先が3つになり、目的に逆行する。

| 出所 | 例 |
|---|---|
| 会話 | 「この方針でよいか」 |
| Factory | マージ承認（B4 で待つ設定のとき） |
| 機構 | **F1 の警報**（文脈が下がっていない 等） |

### A7. 発生ではなく滞留で鳴らす

| 段 | 動作 | 条件 |
|---|---|---|
| 0 | 何もしない | 普通の進行。俯瞰面に状態として載るだけ |
| 1 | 行列に立つ | 判断待ちが発生 |
| 2 | **端末へ push** | 段1 が一定時間**解消しなかった**／人が明示指定 |

> **Slack はメンションが「発生」で鳴る。Banto は「滞留」で鳴る。**
> 目的は「人が思い出さなくてよい」であって「即座に反応させる」ではない。しきい値は人が変えられる。

**受け入れ**：5プロジェクト・20会話が同時に存在する状態で、判断待ちが1画面に列挙される。画面を閉じていても、滞留した判断待ちが端末に届く。

## B. Factory（平行開発の自動化）

| # | 要件 | 出所 |
|---|---|---|
| **B1** | プロジェクトに Factory を紐づけられる | 【PO】 |
| **B2** | 依頼を投げると **ワークツリー作成 → 実装 → テスト → main へマージ** が自動で進む | 【PO】 |
| **B3** | サブエージェントが自動で起動し、**複数の依頼が同時に走る** | 【PO】 |
| **B4** | **既定では人を待たない。** Factory ごとの設定で、マージ前に待たせられる | 【裁定】 |
| **B5** | 途中で落ちても、落ちた地点から再開できる | 【裁定】 |
| **B6** | 何が起きたかを後から追える | 【裁定】 |
| **B7** | 複数の依頼が同じ main を触るので、**順序づけと衝突の解決**を持つ | 【PO】B2+B3 から必然 |

**B4 の理由**：認知負荷を下げるのが目的なので、既定で人を呼ぶのは目的に反する。ただし待たせたい Factory もあるので設定で選べる。待つ場合の受け皿は A6 の行列。

**受け入れ**：3つの依頼を同時に投げて3つとも main に入る。1つ失敗させても他の2つは進む。落として再起動しても、途中から続く。

## C. モジュール

| # | 要件 | 出所 |
|---|---|---|
| **C1** | モジュールは登録単位。**接続・道具・GUI・設定**を1つで持ち込む | 【PO】 |
| **C2** | **AI からも人からも同じものが使える。** 真実は1つ | 【PO】 |
| **C3** | GUI は人が開くこともできるし、**AI が開くこともできる** | 【PO】 |
| **C4** | 設定画面に自分の区画を出せる | 【PO】 |
| **C5** | 標準モジュールを同梱する（下表） | 【PO】 |
| **C6** | 第三者がモジュールを足せる。**Banto 中核は無変更** | 【PO】 |
| **C7** | 開発以外の領域も同じ仕組みで載る | 【PO】 |
| **C8** | **1モジュール＝1プロセス。ロジックは core に1つ。面は core への薄いアダプタ** | 【査読】 |
| **C9** | **最小実装は「道具の面」だけ。** GUI は後付けでよい | 【査読】 |
| **C10** | モジュールは**他のモジュールの道具の面を直接呼べる**。Banto は経路に入らない | 【PO】Repo→Vault から |

### C8. 二重実装を規約ではなく構造で防ぐ

```
モジュール（1プロセス）
  ├── core        ドメインロジック。ここに1つだけ
  ├── 道具の面     core への薄いアダプタ（AI 向け）
  └── データの面   core への薄いアダプタ（GUI 向け）
```

- **2つの面を別プロセスに分けることを禁じる。** 同一プロセスなら状態を共有せざるを得ず、二重実装が物理的に面倒になる
- **面の形は共通化しない。** 縛るのは実装の単一性であって、インターフェースの形ではない
- **面にロジックを置かない**（唯一の規約）

### C5. 標準モジュール

| モジュール | 役割 | Phase |
|---|---|---|
| **Repo** | **リポジトリ（clone・リモート・閲覧・コミット）と worktree。GitHub 身元の割り当て** | **0/1**（worktree は 2・鍵は 3） |
| Shell | | **0/1** |
| ファイル | | **0/1** |
| Environment | 検証用環境を立てる | 3 |
| 公開 | Environment を外部へ（Caddy / port / Cloudflared 等） | 3 |
| WorkerPool | サブエージェントを起動する | 3 |
| Vault | 秘匿情報を管理し、必要に応じて注入する | 3 |
| Browser | **AI と人が同時に使える** | 3 |
| Backlog | 今後実装するものやバグを記憶する | 3 |

**Phase 0/1 で作るのは3つだけ**（【査読】）。Factory が1本通るのに要る最小集合。**契約は先に決め、中身は後**——モジュールを増やす前に、Factory の一本の体験を磨き切る。

**Repo と Git を分けない理由**：`log`/`diff`/`blame`/`branch` の閲覧も、clone も worktree も
鍵の割り当ても、すべて「リポジトリという1つの対象への操作」である。分けると core が2つになり、
C8 に逆行する。**Channel（プロジェクト）の実体を提供するのも Repo。** Factory は worktree を
Repo に頼む——Factory に git の知識を持たせない。

### 複数 GitHub アカウント（要件 D5）

| 持ち物 | どこ |
|---|---|
| どのリポジトリにどの身元を使うかの**割り当て表** | Repo |
| 公開鍵の GitHub への登録 | Repo |
| **秘密鍵そのもの・鍵ペアの生成** | **Vault** |

**鍵ペアを作るのは Vault。Repo は公開鍵しか受け取らない。** Repo が生成すると秘密鍵が一度
Repo を通る。Vault が生成すれば秘密鍵は Vault から一度も出ない——D3 を運用ではなく構造で守る。
実行時も `ssh-agent` を Vault が持ち、Repo は socket のパスだけ受け取る。

**受け入れ**：新しいモジュールを1つ足すのに、Banto 中核のコードを1行も変えない。
2つの GitHub アカウントに属するリポジトリを、同時に clone / push できる。

## D. 実行と安全

| # | 要件 | 出所 |
|---|---|---|
| **D1** | 検証用の環境を立てられる | 【PO】 |
| **D2** | 立てた環境を外部から見えるようにできる | 【PO】 |
| **D3** | 秘匿情報は Vault が持ち、必要なときだけ注入される。**鍵そのものが AI の文脈に出ない** | 【PO】 |
| **D4** | AI が触れる範囲は、明示的に許した範囲に限られる | 【裁定】 |
| **D5** | **複数の GitHub アカウントを使い分けられる。** 割り当ては Repo、鍵は Vault | 【PO】 |

**Claude の複数アカウントは要件に入れない**（【裁定】）。実測で文脈が本来の十数倍に膨らんで
いたので、F1 の観測を入れて圧縮が効いた状態で測り直してから判断する。**対症療法より根治を先に。**
必要になったときは、Runner の引数に資格情報が1つ増えるだけで足りる——G の「スレッド生存中は
不変・変更＝新スレッド」がそのまま効くので、新しい概念は要らない。

> **GitHub の身元と Claude の身元を1つの概念にまとめない。** 前者は**対象で決まる静的な経路**、
> 後者は**資源の残りで決まる動的な選択**。共通しているのは「Vault が持ち、AI の文脈に出ない」
> （D3）だけで、それは既に書いてある。

## F. 費用と持続性

| # | 要件 | 出所 |
|---|---|---|
| **F1** | 文脈が単調に増え続けない。**増え続けていることを機構が検知する** | 【計測】 |
| **F2** | **観測は Banto Core が外側から行う。材料は各ターンの `usage`。LLM を呼ばない** | 【裁定】 |
| **F3** | 使用量が見える | 【計測】 |
| **F4** | 平行数を上げても、費用が線形以上に増えない | 【計測】【査読】 |

### F1. 警報は2種類要る

| 種類 | 例 |
|---|---|
| **量** | 文脈サイズが閾値を超えた／root が肥えた |
| **不在** | **文脈が一度も下がらないまま N ターン経過した**（＝圧縮が発火していない） |

**鋭いのは不在のほう。**「増えている」は正常な会話でも起きるが、「一度も下がらない」は機構の故障を名指しする。

**背景（計測）**：自動の文脈圧縮が 1,210 ターン中 **0 回**しか発火せず、1M 上限に張り付いていた。1セッションで 826M トークン。**何も失敗しなかったので、1か月近く誰も気づかなかった。**

> **「起きなかったこと」は自動では見つからない。期待を明示したときだけ検知できる。**

警報は A6 の行列に入る。

## G. 会話の根（root）

分岐を安くするための構造。

```
Thread = root（依頼・制約・決まったこと。小さく安定）
       + tail（そこからの作業履歴）
```

| # | 規則 |
|---|---|
| **R1** | **fork の既定は root から。**「いまの続きから」は明示オプション |
| **R2** | **root は追記のみ。書き換えない**（追記なら既存の枝のキャッシュは壊れない） |
| **R3** | 追記できるのは「**決まったこと**」だけ。「経過」は入れない |
| **R4** | **既存の枝は追記を見ない。** 古い root のまま完結する |
| **R5** | **書き換えは許すが、そのとき枝は継承しない。** 書き換え＝新しい会話の始まり |
| **R6** | 既定では AI が「根に戻すべき」と判断して追記し、**人が消せる**。明示操作も持つ |
| **R7** | **プロジェクトについて恒久的に真なことは、root ではなくリポジトリのファイルに書く** |
| **R8** | root のサイズを計測し、閾値を超えたら A6 の行列に出す |

### R3 の判定

**「次の枝がこれを知らないと困るか」** の一問。要約による圧縮ではなく**種類による選別**なので、安く、判断がぶれない。

| root に入る | 入らない |
|---|---|
| 依頼・制約 | 作業の経過 |
| この方針は採らない、と決めたこと | 試したことの全部 |
| この API はこう動く、と確かめたこと（※R7 も見る） | ツール出力 |

### R7. 3つの置き場

| 置き場 | 何を | 範囲 | 読み手 |
|---|---|---|---|
| **root** | この会話で決まったこと | 1会話とその枝 | その会話の枝 |
| **リポジトリのファイル** | プロジェクトについて恒久的に真なこと | プロジェクト | 全会話・人・将来の自分 |
| ~~記憶ストア~~ | 人の好み・やり方 | — | **作らない** |

**記憶ストアを作らない理由**：置きたかったものの大半は、実はファイルに置くべきものだった。リポジトリはすでに永続で、人も AI も読め、git で履歴が残り、レビューもできる。専用ストアを作ると**リポジトリと二重管理**になる。残る「人の好み・やり方」は要件から出てこなかった。

## 通底する原則

要件ではないが、設計判断のたびに戻る2つ。

> **観測は、観測される機構の外側に置く。** 中に置くと、機構が止まったとき観測も一緒に止まる。
>
> **任せてよいのは仕事であって、仕事が行われていることの確認ではない。**

## Phase と完了条件

**完了条件は「要件を満たす」ではなく「計測が実際に走り、数値を返す」**（【査読】）。この会話で担保されたのは設計であって、実装で再現される保証ではない。

| **3** | 残りの標準モジュール6つ | |
| **4** | 旧 Banto を止める | |
