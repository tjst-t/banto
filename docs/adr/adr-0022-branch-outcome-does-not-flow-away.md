# ADR-0022: 枝の結末は**流れる場所にしか無い**。知らせと置き場を分ける

> status: **accepted**（2026-08-14。PO 裁定）。決定番号は 108（ADR-0017）の続きから採る。
> ADR-0017 決定77 の「幹に還るのは結論1行」は変えない。**足りていなかったのは、その1行の
> ほかに置き場が無かったこと。**

## 文脈

PO の訴え（2026-08-14）：

> 枝が番頭の判断で merge されるのをやめて、ユーザの判断必須にしたい。
> 依頼したのがどうなったのか分からないことが多いので。

続けて、幹で：

> 幹に戻っても別の話題があると、流れちゃうんだよな。
> 閉じた枝を確認するのが面倒くさいというのが本質なのかな？ 悩ましい。

### 何が起きていたか（実測・2026-08-14）

`thread.merge` がしているのは1つだけだった——**親の幹の帯に `branch_result` の行を1つ積み、
開いている画面へ配る**（`threads.ts:892` / `server.ts:421`）。取次には積まず、幹の番頭の
ターンも回さない（`thread.consult` は nudge を打つのに、`merge` は打たない）。

そして、その1行を受け止める場所が全部ふさがっていた：

| 経路 | 実際 |
|---|---|
| 幹の帯を遡る | 唯一の正規経路。**他の話題が挟まると流れる**（時系列の発話なので当然） |
| レールの点 | `state === "open"` の枝だけ。**畳んだ瞬間に消える**——PO が見る前に消える |
| 履歴の面 | `closedThreads.filter(t => t.kind === "trunk")`（`App.tsx:850`）。**畳んだ枝は0件**。コード内に「畳んだ枝は幹の記録に結論1行として残るので、ここへは並べない」と明記＝上の経路へ意図的に一本化してあった |
| ⌘K | 名前を覚えていれば引けるが、押すと**開き直してしまう**（確認のつもりが再開）。結論文も出ない |

**「畳んだ枝の一覧」は GUI のどこにも存在しない。** PO の「面倒くさいのが本質」は正しく、
しかも構造がそうなっていた。

一方で、**データは既に足りている**——`closedThreads` は幹・枝を問わずクライアントへ届いて
おり、`ThreadView` に `conclusion` も載っている。欠けていたのは表示だけ。

### なぜ承認制を採らないか（PO 裁定）

当初の要望は「畳むのを PO の承認必須にする」だった。番頭からは「取次の札は**答えると消える**
ので、翌日『あれどうなった』を見る場所はやはり無い。承認は**止める力**であって
**あとから辿る力**ではない」と返し、PO の裁定：

> 取り次ぎに出すのは、報告と枝へのリンクだけでいいかも。つまり、承認制ではなく、
> 閉じた通知だけをだす。そうすれば、必要に応じて再開できるし。
> 履歴に置くのはオッケーだけど、今見てる幹の枝が分かりやすく見えるようにして

**畳むのは取り返しがつく**（`reopen` がある）ので関所を置かない、という判断。番頭はここで
手を止めなくてよく、PO は結果を落とさない。

## 決定

### 決定109: 枝を畳んだら、取次へ**知らせ**を1通積む（承認ではない）

`thread.merge` は今までどおりその場で畳む（承認待ちの状態は作らない）。加えて取次へ1通積む：

- 出所はその枝。本文は**結論**と、詳細（調べた・決めた・残った）が在ればその旨だけ
- `opens.threadId` にその枝を入れる——**押せば中が読める**のがこの一通の本体
- 求めるのは判断ではないので、答えは「読んだ」の1つ。**再開したければ枝を開いてから**
- **「読んだ」に答えても番頭のターンは回さない**（PO裁定 2026-08-14・実装時に発覚）。
  取次の答えは通常 `notify` で番頭のセッションへ入れターンを回す（決定73）が、それを
  知らせにも適用すると、結末が出ている畳んだ枝のハーネスへ毎回1ターン無意味に走り、
  かつ読みに行くたび発話が増えて「結論は凍る」という本ADRの前提が崩れる。
  記録（`inbox.resolve`）だけして終わる。`notify` 自体（決定35b：畳んだスレッドにも
  知らせは届く）は変えない——止めるのは取次の notice を解決するこの経路だけ

### 決定110: 取次は「判断」と「知らせ」を持ち、**知らせは判断待ちに数えない**

ADR-0015 決定73（POの判断を求めるものは取次1つ）を拡張する。取次は「PO に用があるもの」の
受け口であって、判断だけの箱ではない。ただし**数と並びは分ける**——知らせをレールの件数
（`inboxPending`）に混ぜると、判断待ちの数が意味を失い、取次そのものが埋没する。

- 判断（`actions` で答えるもの）は今までどおり数え、上段に置く
- 知らせは数えず、下段に置く。読めば片付く

### 決定111: 畳んだ枝は**履歴に結論つきで並ぶ**。開くのは「読む」であって「開き直す」ではない

- `App.tsx:850` の `kind === "trunk"` の絞りを外し、畳んだ枝も並べる（決定30c の「履歴は畳んだ
  ものの置き場」へ戻す）。行には**結論文**を添える——一覧のまま結末が読めることが要点
- 開く操作は**読む**を既定にし、`reopen`（開き直し）は明示の操作として分ける。⌘K の
  「畳んだ会話」も同じ——確認しに行って状態が変わるのは事故

### 決定112: **いま見ている幹の枝**は、流れない場所に一覧で出す

幹の会話の中（時系列の帯）だけでは、他の話題が挟まった時点で見えなくなる。幹の画面に
**流れない一覧**を持たせる：

- いま開いている枝（還す条件つき）と、**片が付いた枝（結論つき）**を、その幹のぶんだけ並べる
- 押せばその枝へ行ける。畳んだ枝は読む（決定111）
- レールの点は今までどおり**開いている枝だけ**——点は「抱えているもの」の量を表すもので、
  ここに済んだものを積むと本数が読めなくなる（決定77 不変条件③を壊さない）

## 影響（変更する場所）

| 場所 | 変更 |
|---|---|
| `packages/banto-host/src/threads.ts` | `merge` から、畳んだことを知らせるフックを出す（`onBranchResult` の隣） |
| `packages/banto-host/src/inbox.ts` | 一通に「知らせ」の種別を足す。数と並びを判断と分ける |
| `packages/banto-host/src/server.ts` | 畳みのフックで取次へ知らせを積む（`inbox` を持っているのはここ） |
| `packages/banto-web/src/App.tsx` | 履歴のフィルタを外す（決定111）／幹の画面の枝一覧（決定112） |
| `packages/banto-web/src/ThreadHistory.tsx` | 行に結論を添える。読む／開き直すを分ける |
| `packages/banto-web/src/CommandPalette.tsx` | 「畳んだ会話」を押したときに開き直さない |

## 受け入れ（この ADR が満たされたと言える条件）

1. 枝を畳むと取次に1通増え、**判断待ちの件数は増えない**。押すとその枝が開く
2. 畳んだ枝が履歴に**結論つきで**並ぶ。開いても `state` が `open` に戻らない
3. 幹の画面で、その幹の枝が（開いているもの・片が付いたもの）一覧で読める。他の話題を
   いくら重ねても消えない
4. 幹の帯の `branch_result` の1行は今までどおり（決定77 は変えない）
