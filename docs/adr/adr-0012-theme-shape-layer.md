# ADR-0012: 家（テーマ）は「形」も持てる。面のクラス名を家に対する契約とする

> status: **accepted**（2026-08-06。PO 裁定）。spec-design §6.1「テーマが上書きできるのは
> トークンだけ」を差し替える。

## 文脈

spec-design §6 で「テーマは家で、上書きできるのは `tokens.css` の変数だけ」と決めた。
色・書体・字の段・行間・余白・角・部品の高さが変数になっているので、**密度ごと変わる家**も
載せられる——その証拠として案5「符牒」を組み込みの家として載せ、§6.4 に
「案5の意匠を、面の CSS を1行も触らずにトークン2ブロックだけで載せている」と書いた。

**これは言い過ぎだった**（PO報告 2026-08-06）。POの言葉：

> 符牒ですが、プロトタイプとだいぶデザイン違いますよ。いまは和紙とちょっと色が違うだけに見えます。

実測すると、トークンは正しく当たっていた（色は `prototype/redesign/05-fucho.html` の12値と完全一致、
書体・字の段・行間・余白・角・高さもすべて入れ替わる）。にもかかわらず和紙と見分けが付かないのは、
**案5を案5たらしめているものが、ほぼ全部「形」だから**である。

| 案5の姿 | 何で決まるか |
|---|---|
| 上端が黒い状態行、屋号は藍のチップ | 形（面の CSS） |
| 会話タブが平らな矩形＋右罫 | 形 |
| 符牒の札が藍のチップで出る | 形（※常置はしない。下記） |
| 番頭の発話の印が `»`（藍の落款ではない） | 形（`content`） |
| 面と面の境目が1本の罫 | 形 |
| 下端のコマンド行 | **器（DOM）そのものが無い** |
| 上段の右端に出す中身（職人の数・モデル・文脈%） | **器（DOM）そのものが無い** |

つまり「トークンだけ」という制約のもとでは、家の違いは**配色と書体と密度**に留まる。
それを「意匠が丸ごと差し替わる」と謳っていたのが食い違いの正体である（P3）。

## 決定

### 51. 家は「形」の層を1枚持てる（2026-08-06、PO裁定）

- 家は `tokens.css` のトークン2ブロックに加えて、**`theme/<家>.css` を1枚**持てる。
  そこで面のクラス名を名指しで上書きしてよい。
- **層の中身は `:root[data-theme^="<家>"]` の下に閉じる。** 他の家へは1行も漏らさない。
- **面ごとの CSS には分岐を書かない**（D5 は据え置き）。`[data-theme=…]` を `styles.css` や
  `views.css` に散らすのではなく、家の層が上から被せる。読み込み順は
  トークン → 面 → 家の層。
- **新しい機構は増えない。** 持ち込みの家（§6.3）は既に CSS を1枚配って `<link>` で挿す
  仕組みを持っており、組み込みの家に同じ口を開けるだけである。

### 52. 面のクラス名は家に対する契約とする（2026-08-06、PO裁定）

決定51 の帰結として、`.shell-topbar` / `.thread-tab-wrap` / `.msg--banto` のような
**面のクラス名が、家から名指しされる公開I/Fになる**。面を組み替えると家が崩れる。

- **崩れても気づけないのが一番困る。** だから見張る試験を持つ（`tests/theme-shape.spec.ts`）。
  - 契約の一覧は**層そのものから導く**（D3）。`theme/*.css` に出てくるクラス名を読み取り、
    実際の画面に在ることを確かめる。名前を変えたら、消えた名前を名指しで落ちる
  - 家の層が**他の家へ漏れていない**ことも見る
- **層に書くのは、実際に変えるものだけ。** 既定と同じ値を言い直さない——
  書いた分だけクラス名に縛られる。
- クラス名を変えるときは、家の層も一緒に直す。試験がそれを強制する。

### 53. 器（DOM）が無いものは、家では作らない（2026-08-06、PO裁定）

案5の下端のコマンド行は、この画面に器が無い。CSS の `content` で帯だけを置くことはできるが、
**押せない飾りにしかならない**——あるだけで「押せそうなのに押せないもの」が1つ増える。

- 家の層は**在るものの姿を変えるだけ**。無いものを生やさない
- 同じ理由で、**符牒の札は常置しない**（PO裁定 2026-08-06）。案5の見本で札が出ているのは
  ⌥ を押している最中の姿であって、常に出ている画面ではない。行の中に置く案も採らない
  ——タブの幅が変わって `useTabOverflow` の勘定が動き、押そうとしたタブが収納へ落ちる
- 器から作りたくなったら、それは家の話ではなく面の話。App に器を足すかどうかを別に決める
- 下端のコマンド行は**足さない**（PO裁定：いま実質の機能が無いため）

### 54. 持ち込みの家に許すのはトークンだけ（2026-08-06、PO裁定）

決定51 の力は**組み込みの家にだけ**与える。`<BANTO_DATA_DIR>/themes/` に置かれた家は、
`:root` に変数を置くところまで。

- 理由は1つ、**こちらの試験が効かないから**。面を組み替えたときに崩れたと分かるのは
  リポジトリの中にある家だけ（決定52 の試験）。外の家は黙って壊れ、書いた人にも
  こちらにも分からない
- 濾すのは**画面側**（D5：ホストは配るだけ、解釈は画面）。受け取った CSS を
  ブラウザ自身の構文解析にかけ、`:root`（＋`[data-theme="…"]`）で**変数だけを置く規則**を
  残し、他は落とす。`color-scheme` だけは変数にできないので通す
- **規則ごと落とす。** `:root { --sumi: …; position: fixed; }` のように素の宣言が混ざったら、
  変数の部分も通さない——半分だけ効くほうが読めない
- 落としたものは黙らない（I2）。何を直せばよいかまでログに出す
- 濾す前の CSS が一瞬でも効かないよう、`media="not all"` で読ませてから挿し直す

### 55. 契約に版を付ける（2026-08-06、PO裁定）

持ち込みの家が当てにしているのは**トークンの名前**なので、名前を変えたら壊れる。

- 台帳（`themes.json`）に `contract` を書く。画面側の `THEME_CONTRACT` と合う家だけ載せる
- **版を上げるのは、変数の名前を消した・付け替えたときだけ。** 値を変えただけでは上げない
- 合わない家・版を書いていない家は**載せず**、理由を出す（I2）
  ——半分だけ効いた家を出すほうが困る
- 版を上げたら `docs/notes/how-to-make-a-theme.md` の表も直す

## 帰結

- **良くなること**：家を切り替えると本当に別の道具に見える
- **代償**：面のクラス名が変えにくくなる。変えるなら家の層も直す。試験がそれを教える
- **限界**：器が無いものは出せない。案5の下端のコマンド行と、上段右端の状態表示は、
  面に器を足すまで出ない（決定53）
- **持ち込みの家は力を持たない**（決定54）。組み方まで変えたいなら組み込みにする。
  代わりに、こちらの改装で黙って壊れることもない——当てにするのはトークンの名前だけで、
  それには版が付いている（決定55）
- **層は薄いほどよい**（`docs/notes/theme-system-comparison.md`）。層に繰り返し出てくる形は
  トークンへ昇格させる（`--h-tabbar` / `--face-margin` / `--banto-mark` …）。
  昇格させた分だけ契約面が減り、面を組み替える自由が戻る
- spec-design §6.1 の「上書きできるのはトークンだけ」と §6.4 の「面の CSS を1行も触らずに」は
  この ADR で差し替える
