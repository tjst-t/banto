# ADR-0016: 間欠的な失敗は**機構が壊れている合図**。ノイズとして片付けない（P6）

> status: **accepted**（2026-08-09。PO 裁定「インターミッテントな問題を放置するのは
> ギルティです」）。**規則を1つ足す**（P6）。決定番号は 75（ADR-0015）の続きから採る。

## 文脈

PO の問い（2026-08-09）——「毎度、何か機能を作るたびに、回帰テストで別のところの問題が
発見されるのは何なんだろう」。

数えた。incident 26件のうち **「新しく壊れた（`class: bug`）」は3件だけ**で、最大は
`spec-drift` の8件。つまり見つかっているのは「今回の変更が壊したもの」ではなく、
**ずっと壊れていたのに誰も見ていなかったもの**である。

- inc-0040：狭い画面の規約が、共通部品を使わない当たりには**一度も効いていなかった**
- inc-0045：番頭が喋り出すと10回に1回止まる。直前の機能追加とは無関係で、最初からそう

機能を作るときだけ、ビルドし直し・実際に動かし・試験を何十回も回す。**10% で起きる
事象は、普段の1回の確認ではまず見えない。**「作るたびに出る」のは発生の話ではなく、
**観測の話**だった。

### 本当の問題：検知していたのに捨てていた

同じ形が3回起きている。

| | 何を捨てたか | 実際は |
|---|---|---|
| inc-0020 | 「タイミング依存だから」 | ハーネスの初期化順に依存する本物の競り |
| inc-0031 | 「並列だとテストが遅いから」——**待ちを延ばす直しが2回入った** | 誰も職人を畳んでいなかった（task-0072） |
| inc-0045 | 「既存の不安定さ。スコープ外」と番頭が報告した | 10回に1回、本文が止まって二度と動かない |

inc-0031 は教訓まで書いてある：「**待ちを延ばす直しは、症状を隠す方向にしか働かない。**
20秒に延ばしたことで頻度が下がり、余計に機構の問題に見えなくなった」。

**それでも同じことが起きた**（inc-0045）。教訓が incident の本文にあるだけで、規則に
なっていなかったから。P4 が言うとおり、繰り返される失敗は説得ではなく規則・機構にする。

## 決定76: 間欠的な失敗を「テストの都合」として処理しない（P6）

> **P6. 間欠的に落ちる試験は、機構が壊れている合図として扱う。** 待ちを延ばす・
> リトライを足す・「まれに落ちる」と記録して先へ進む、のいずれもしない。原因を突き止め、
> 突き止められないなら incident を積んでから進む。

読み方：

- **「単体では通る」は無罪の証拠にならない。** 競りの窓が狭いことの証拠でもある（inc-0031）
- **待ちを延ばす直しは禁じ手。** 症状を隠す方向にしか働かず、次に見つけるのを難しくする
- **スコープ外は理由にならない。** 触らないこと（P1）と、黙って通り過ぎることは別。
  直さない選択はあってよいが、そのときは incident を積む（P3 と同じ形）
- **「既存の不安定さです」と報告して終わりにしない。** それは分類であって根拠ではない。
  根拠は計測——何回中何回落ちるか、直したあと何回中何回か（I1：自己申告を根拠にしない）

**適用範囲は試験に限らない。** 「たまに起きる」「再現しない」で片付けようとしたものは
すべてここに当たる（PO報告の再現しない不具合・工房の稀な失敗・環境の気まぐれ）。

## 却下した案

**「flaky と分かった試験を隔離する枠（quarantine）を作る」。** 逃げ場を作ると、そこに
溜まる。いま在る26件の incident はどれも「見に行けば分かった」もので、足りていないのは
置き場ではなく**見に行く決め**のほう。

**「retry を機構で禁じる（playwright の retries を 0 に固定する）」。** すでに 0 で、
壊れていたのは機構ではなく解釈のほう。ここで足すべきは機構ではなく規則
——**P4 の逆向きの適用**にあたるので、規則で足りるうちは規則にする。

## 帰結

- `docs/principles.md` と `docs/DESIGN_PRINCIPLES.json` に P6 を足す
- `CLAUDE.md` の「毎タスクで特に効くもの」にも出す（頻度が高いため）
- 番頭・職人の双方に効く（D9〜D11 のような役割限定ではない）
