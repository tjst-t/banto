# ADR-0004: 使えるLLMは全体設定、モデルはセッション/タスクごとに動的自動選定

## 文脈

全体像設計プロトタイプの初期版は、モデル（endpoint）をプロジェクトごとに設定していた。POが「プロジェクト個別にモデルを固定するのは不自然。**bantoが使えるLLMは全体設定で持ち、セッション/タスクごとにどのサービスのどのモデルを使うかを動的に自動判定すべき**」と指摘した。VISION tech_constraints「モデルはopencodeエンドポイント経由で差し替え可能にする」とも整合する。

## 決定

- banto が使えるLLM（サービス×モデル：Anthropic API、opencode エンドポイント、Local LLM 等）は**全体設定**で登録する。プロジェクトはモデルを固定しない。
- モデル選択は、**役割の既定を起点に、タスク種別 × 難度 × コスト上限からセッション/タスクごとに動的に自動選定**する（例：検討＝上位、実行者＝中位で難タスクは自動昇格、監査＝上位固定寄り、要約系＝ローカル優先）。
- 選定ポリシー・tier変更の効果は**改善ループで keep / tune / revert 評価**する（spec-improvement-loop §5）。

## 帰結

- (+) モデル調達が一箇所。プロジェクトが増えても設定が増えない
- (+) 安価な役割はローカルLLM優先などコスト最適化を機構化でき、改善ループで評価・調整できる
- (+) opencode 経由の差し替え自由度を保つ（VISION）
- (−) 自動選定アルゴリズム（種別×難度×コスト→モデル）の具体は未確定。初期は役割既定＋単純規則から始め、改善ループで育てる
- (−) 誤選定（難タスクに弱モデル）のリスクは、失敗時の自動昇格と監査ゲートで吸収する
- プロジェクト固有のモデル要件が生じた場合は overrides として最小限で足す余地を残す。方針変更はこのADRの supersede を要する
