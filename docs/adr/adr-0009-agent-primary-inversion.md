# ADR-0009: 番頭主体への構造逆転（AI Agent を主、開発システムを従に）

> status: **accepted**（2026-07-27。PO 裁定）。本 ADR は探索ブランチ `explore/agent-primary` で一度 `accepted` 化された同名 ADR の**再起票**である。旧ブランチは記憶サブシステム（Quirefold）を自作する前提で番頭核の詳細設計まで進めたが、パラメータ空間と実装難易度が実用に対して過大と判断され、PO により**別プロジェクトへ切り出す形で撤退**した。構造逆転の決定そのもの（本ADR）は正しかったため`explore/agent-primary-v2`へ引き継ぎ、記憶を自作しない前提で書き直した。詳細な経緯・却下記録は旧ブランチ（`explore/agent-primary`）に残る。

## 文脈

S6cfce9 全体像プロトタイプ（ADR-0002）の検討の終盤、UIパラダイム（コックピット vs チャットファースト）を詰めるうちに、より根本の**構造の逆転**が浮上した。従来は「banto＝開発システムが主、AI Agent はその部品」だったが、PO の意図は「**コンテキストを超えて高精度な記憶を持つ AI Agent（番頭）が主体となり、開発システム全体を統括する。チャットで不便なところを既存UI（アテンションキュー等）で補う**」。将来は開発以外の領域も同じ番頭に取り込みうる＝真の番頭への第一歩としての開発システム。

この構造自体への異論はなかった。頓挫したのは「番頭の記憶をどう実装するか」——自作の記憶サブシステム（Quirefold）を設計したところ、検索アーム・入場スコア・ワーキングセットのヒステリシス・睡眠スケジューリング等のパラメータが相互に作用し、机上調整では収まらない複雑さになった。同日中に提出された簡略化提案（Quirefold Core）も却下されており（複雑さの質問自体は正しいが、削減の形が既存の判断根拠と衝突していた）、**このレイヤーを自作すること自体が過大投資**という判断に至った。

## 決定

**記憶を持つ AI 番頭（steward）を主体、開発システム（Kobo＋UI）を従とする構造を採用する。ただし番頭のハーネスと記憶機構は自作せず、既存の実績ある技術を採用する。**

- 4層：PO（主人）／番頭AI（記憶あり・PO代理・アーキ/方針/大きな判断・差配）／**Kobo**（決定的統治基盤。旧称 daemon）／職人＝WorkerAgent（memoryless・実装/調査/行単位レビュー）。
- **二軸で banto の存在理由を守る**：体験・差配の軸は番頭が主、執行の軸は Kobo が主（ゲート・真実＝イベントログ）。番頭でも帳簿はごまかせない（D2/D3 保持）。
- **番頭の決定境界**：利用体験を変え、かつ本物のトレードオフのときだけ PO へ。それ以外は番頭が決定（D9。D1 は番頭の判断でのみ D9 に劣後、職人には D1 がそのまま効く）。pre-release は壊してよい。
- **番頭は細かい仕事をしない**：調査/実装は職人へ委譲しコンテキストを節約（D10）。
- **記憶を持つ番頭／memoryless な職人の非対称**を原則とする（D11）。
- **Kobo と番頭核は完全分離。結合は Tool／SKILL の公開 I/F のみ**（決定①、[ADR-0010](./adr-0010-pluggable-harness.md) で詳述）。
- **番頭のハーネスは自作せず、差し替え可能にする**（決定②。旧 ADR-0009 の「完全自作」を撤回）。第一実装は pi coding agent。記憶機構も自作せず既存の実績あるシステムを採用する（参照実装は Hermes Agent）。詳細は ADR-0010。

## 帰結

- (+) 「チャット vs コックピット」が解ける：主体は番頭、既存UIは番頭が差し出す走査可能な盤面。
- (+) Kobo の決定的統治（D2）と職人の memoryless 監査可能性（I1）は保持。既存資産（Kobo 実装済み・ADR-0001〜0008・specs）は**再利用**（全捨て不要）。
- (+) ハーネス・記憶を自作しないことで、旧ブランチで頓挫した「自作記憶システムの調整地獄」を構造的に避けられる。将来ハーネスや記憶システムを差し替える余地も残る。
- (−) VISION・principles は番頭主体へ改訂済み（本ADRに伴う）。UIの操作パラダイム・プロトタイプのシェルは今後作り直しが要る。
- (−) 記憶の同期/マージ設計・自己像や driver パラメータの管理は、採用する既存システム（pi coding agent／Hermes Agent 参照）の実装詳細に委ねる。banto 側の原則としては規定しない（D12）。
