# Vision — Banto（番頭）

> **2026-07-27 に全面改訂**（[ADR-0009](./adr/adr-0009-agent-primary-inversion.md) accepted）。旧版は「一人のPOがAIエージェントのチームを率いて開発するための統治環境＝ガバナンスレイヤー＋POコックピット」だった。構造が逆転し、**主体は番頭**になった。経緯は [agent-primary-inversion](./notes/agent-primary-inversion.md)。

## 目的

**記憶を持つ AI 番頭（steward）が主体となり、決定的な統治基盤の上で、PO の代理として店を切り盛りする。** 第一の店はソフトウェア開発。PO はその番頭を統べ、**利用体験を変える本物のトレードオフだけを裁く**。

名の由来は商家の番頭——店の切り盛り一切を担い、全部を覚え、客の相談を受け、職人に仕事を差配し、大事な判断だけを主人に上げる役。

- **番頭は覚えている。** コンテキストの切れ目を越えて一貫する記憶を持つ。PO が同じ経緯を二度説明しなくてよい。記憶機構は自作せず、**実績のある既存の記憶システムを採用する**（参照実装は Hermes Agent）。
- **番頭は分身する。** 関心事ごとにインスタンスへ分かれて並行し、決定はイベントログで直列化され、学びは共有記憶へ収束する。割り込みが PO の文脈を壊さない。
- **番頭は細かい仕事をしない。** 調査・実装は記憶を持たない職人（worker）へ差配し、自分の文脈は記憶と判断のために使う。
- **番頭のハーネスは差し替え可能。** Kobo・職人・UI とのやりとりは Tool／SKILL の公開 I/F のみを介する。第一実装は pi coding agent だが、番頭の思想は特定ハーネスに縛られない。
- **開発は最初の領域にすぎない。** 番頭の核（記憶・会話・差配・決定的統治基盤）を開発固有の道具から分離して設計するので、将来他領域の店を同じ番頭に増設できる。

## 番頭でも帳簿はごまかせない

**「番頭が主」は「統治もお任せ」ではない。** banto が生まれた理由は、開発手法がプロンプトの遵守期待に依存し、ゲート・監査の実施が構造的に保証されないことだった。主体が番頭になってもこの理由は消えない。したがって二軸で分ける：

- **体験・差配の軸では番頭が主** — 話す相手・覚える主体・仕事を回す主体。
- **執行の軸では Kobo（決定的統治基盤）が主** — ゲート・ステートマシン・真実＝イベントログ。

PO が黙ってゲートを飛ばせないのと同じく、**番頭も飛ばせない**。制御ループに LLM は置かない。

## 非目的（Non-goals）

- **チーム利用・マルチテナントは対象外。** PO 一人の道具として設計する
- 汎用の tmux/worktree マネージャにはしない。それは Palmux2 の領分
- JIRA 的なプロジェクト管理ツールにはしない。階層は Epic→Task の2段まで、Epic に状態管理を持たせない
- 汎用 CI／クラウド管理基盤にはしない。評価環境はライフサイクル動詞の契約だけを定義し、実装はプロジェクトに委ねる
- インナーループ（編集・テスト・修正の回し）の品質で Claude Code 等と競わない
- **番頭を「もう一人の人格」として演出することは目的ではない。** 記憶と一貫性は PO の帯域を守るための手段であって、それ自体が価値なのではない
- **記憶システムを自作しない。** 既存の実績あるシステム（参照実装は Hermes Agent）を採用し、独自機構の開発・調整に時間を投じない

## 価値の優先順位（衝突したときはこの順で決める）

1. **PO の判断主権** — 主権は常に PO にある。番頭は PO の代理として決めるが、**利用体験を変え、かつ本物のトレードオフであるものは必ず PO へ返す**（D9）。番頭が決めたことは PO が後から可視・訂正できる
2. **ガバナンスの確実性** — ゲート・分類・監査が「必ず行われる」ことを構造で保証する。黙って迂回できる経路を作らない。番頭も例外ではない
3. **PO のレビュー帯域の保護** — 希少資源は PO の注意力。タスクサイズ・WIP・UI・そして**番頭がどこまで自分で決めるか**は、すべてこの帯域の配分装置として設計する
4. **番頭の自律性** — 上位3つを侵さない範囲で、番頭が自力で決着できる範囲を最大化する
5. **実行スループット** — 並列度や速度は最後。帯域と統治を犠牲にした高速化はしない

> 優先順位1は旧版で「最終判断は常に人間。エージェントは勧告・提案までとし、判断を代行しない」と書いていた。**構造逆転でこの書き方は失効した**——番頭は代理として決める。主権が保たれる仕組みは「決めさせないこと」ではなく、**返す境界（D9）／事後の可視と訂正**の2点に移った。

## 成功の姿

朝、番頭に「昨日の続き」とだけ言う。番頭は前回どこで止まったか、なぜその判断をしたかを覚えていて、そこから話が始まる。相談の途中で別件の判断が要れば、番頭が分身してカードで現れる——目の前の話は壊れない。

日中は別の仕事をする。番頭は職人に調査と実装を差配し、ゲートを通し、詰まったところだけを判断待ちの行列に積んでいく。POはその行列やバックログの状態を、番頭が制御するUIでいつでも見にいける。

夕方、その行列を上から潰す。多くは「これでいい」の一言で済み、本物のトレードオフが1件だけ回ってくる——番頭は選択肢とそれぞれの帰結を並べていて、経緯を遡らなくてもそれ単体で判断できる。spawn・監査・環境の後始末を自分でやった記憶がない。

そして月に一度、番頭が自分の失敗パターンから自分の規則と機構を改善した形跡を、diff で確認して承認している。
