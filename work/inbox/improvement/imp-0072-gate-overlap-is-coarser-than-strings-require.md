# ゲートの重なり判定が、文字列で解ける分まで諦めている

## imp-0071 との関係（これは続きであって、蒸し返しではない）

`imp-0071`（広いスコープの1本が、工場ぜんぶを直列化する）は、**積み方**の話として畳まれた。
その §2 に、機構側についてこう書いてある:

> **重なりの粒度**：いまは glob の文字列で重なりを見ているため、`packages/**` と
> `packages/banto-host/src/thread-store.ts` は必ず重なる。**実際に触ったファイルで解けるのは
> 着手後**なので、ゲートの段階では文字列で判定する以外にない——だからこそ 1（積み方）が効く。

**「文字列で判定する以外にない」までは正しい。「だから今の判定でよい」は正しくない。**
いまの実装は、**文字列だけで交わらないと証明できる組**まで重なりと見なしている。
`packages/**` の例が救えないのは事実だが、救える組が別にあり、それを取りこぼしている。

## 実測（2026-08-16・task-0178 を積んだとき）

共有ブラウザ K2（`task-0178`）を、`imp-0071` の教訓どおり**意図して狭いスコープ**で積んだ:

```
packages/banto-host/src/browser/**
tests/acceptance/browser-chromium-launcher.spec.ts
```

ゲートの答えは **12 本待ち、理由は全部 `scope_overlap`**。内訳は2種類ある:

| 相手 | 相手のスコープ | 実際に交わるか | どちらの問題か |
|---|---|---|---|
| task-0159 | `docs/adr/**`, `packages/**`, `docs/spec/**`, `tests/**`, `work/inbox/**` | **交わる** | 積み方（imp-0071） |
| task-0160 | `packages/banto-host/src/backlog*.ts`, `tests/acceptance/backlog-*.spec.ts` | **交わらない** | **判定（この文書）** |
| task-0161 ほか | 会話の記録まわりの `packages/banto-host/src/*.ts` | **交わらない** | **判定（この文書）** |

`packages/banto-host/src/browser/**` と `packages/banto-host/src/backlog*.ts` は、
**どんなパスも同時には満たさない**。`backlog*.ts` は1セグメントで `.ts` で終わるので
ディレクトリ `browser/` には決してあたらない。**着手を待たずとも、文字列だけで言い切れる。**

さらに、塞ぐ状態（`UNREVIEWED_STATES`）には **`review-ready` / `in-review` も入る**。
先頭の `task-0159` は `review: po` なので、**実装が終わってもPOが判断するまで列は解けない**。

## 数字で言うと：**同時5本のつもりが、実効1本**（2026-08-16・task-0169 の滞留から）

**`tests/acceptance/` の下に何か1つでも置く契約は、互いに必ず重なると判定される。**
`globPrefix` はワイルドカードを**含むセグメント単位**で literal を切るため、
`tests/acceptance/backlog-*.spec.ts` の前置詞は `tests/acceptance/` になり、
ワイルドカードを持たない `tests/acceptance/inbox-post-canvas-params.spec.ts` はその前置詞で始まる
——**交わらないと文字で言い切れる組が、ディレクトリ名だけで重なりにされている。**

**ほぼ全部のタスクが受け入れ試験を1本置く。** だから**工場の実効的な同時実行数は1本**になり、
`meta/config.yaml` の **`max_concurrent_sessions: 5` は効いていない**。設定は書いてあるのに、
ゲートの手前で列が1本に絞られるので、5本並ぶ機会がそもそも来ない。

**「設定が効いていない」ことに誰も気づいていなかった**——2026-08-16 だけで3件目である
（`watchStaleBranches` の時計・`review: banto` の誤読・これ）。**この数字が直しの優先度を語る。**

実測（task-0169＝PO 必須のレビューが積めない穴の直し）：積んだ時点で **10 本待ち**、
2時間後で **8 本待ち**。前が1本およそ30分で解けるので、着手までおよそ3〜4時間。
デッドロックではない（作成順の温度差で循環しない）が、**待ちの長さは同時実行数1本の帰結**である。

## 今日の実害（正直に書く）

**12 本待ち × 1本あたり実測およそ30分＝K2 が 5〜7 時間止まる。**
（進み方の実測：`task-0160` は 00:47 に6本待ちで入り、2時間25分で1本待ちまで来た）

そしてこの待ちは、**2つの原因の掛け算**である。片方だけを直しても半分しか効かない。

1. **積み方の失敗（幹「banto開発」＝番頭自身のもの）。**
   `task-0159`（決定番号を本当に一意にする）に **`packages/**` を丸ごと渡した**。
   決定番号の振り直しが実際に触るのは docs と一部のコードだけだが、
   「どこに散っているか分からない」という不確かさを、**広いスコープで埋めた**。
   これは `imp-0071` に既に記録があり、幹は「動いているものを止めて契約を直すと監査もやり直しに
   なり、かえって遅くなる」として今回は直さないと判断している。**判断は妥当だが、原因は番頭にある。**
2. **判定の過保護（この文書）。**
   1 が無かったとしても、`task-0160` 以降の**交わらない 11 本**が K2 を塞いでいた。
   つまり**積み方を完璧にしても、この待ちは消えない**。

## なぜ起きたか

`packages/banto-daemon/src/gate-evaluator.ts` の `globsOverlap` は、
**最初のワイルドカードより前の literal 前置詞だけ**を見て、片方がもう片方の前置詞なら重なりと答える:

```
globPrefix("packages/banto-host/src/browser/**")   → "packages/banto-host/src/browser/"
globPrefix("packages/banto-host/src/backlog*.ts")  → "packages/banto-host/src/"
→ 後者が前者の前置詞なので「重なる」
```

コメントには **`intentionally over-conservative` / `false parallel is better than false independence`**
と書いてあり、**設計としてわざとこうしてある**。向きは正しい（並行させてはいけないものを
並行させるより、待たせる方が安全）。問題は**過保護の向きではなく、量**である。

いまの実装は「最初のワイルドカードが出た時点で、それ以降の情報を全部捨てる」。
`backlog*.ts` の `*` はセグメントの中にしかかからず、`/` は跨がない——**その情報が捨てられている。**

## どうするか（案。実装は別途）

**セグメントごとに突き合わせる。** 両方のグロブを `/` で分割し、位置ごとに

- 両方が literal → 一致しなければ**交わらない**と確定できる
- 片方が `*` を含むセグメント → そのセグメント**だけ**は何にでもあたるとみなす（`/` は跨がない）
- どちらかが `**` → そこから先は諦めて「重なる」（ここは今のままでよい）

これだけで、上の表の「交わらない」11 本は交わらないと答えられる。**`packages/**` は今までどおり
全部と重なる**ので、`imp-0071` の教訓（積み方を狭くする）は薄まらない。**両方要る。**

副産物として、いまの `globPrefix` の穴も塞がる:
パスの途中に `*` があると（`src/*/b.ts`）`src/` まで切り詰められるため、
`src/foo/b.ts` と `src/bar/c.ts` が重なり扱いになる。セグメント突き合わせなら
最終セグメント（`b.ts` と `c.ts`）で交わらないと言える。

**危ない向きへは倒さないこと。** 迷ったら「重なる」と答える既定は変えない。
変えるのは「交わらないと**証明できた**ときだけ、交わらないと言う」ところだけ。

あわせて `imp-0071` §2 の1つ目（積むときに「いま列の何本と重なるか」を返す）は、この文書でも推す。
**今回、12 本待ちに気づいたのは積んだ後に `kobo.task` を読んだからである。**

## 見合うか

- 効き：狭く積んだ仕事が、無関係な仕事に待たされなくなる。今日の実例で **12 本待ち → 1 本待ち**。
  加えて**同時実行数が設定どおり（5本）に戻る**——いまは実効1本なので、効きは待ち時間だけでなく
  工場全体の処理量に効く。
- 手間：純関数1本の差し替えと、その試験（交わる組・交わらない組・`**` の組）。1〜2h。
- 危なさ：判定を**緩める**向きなので、間違えると並行してはいけない2本を並行させる。
  だから「証明できたときだけ」に限り、試験で組を固定する。

## この過保護が、今日ひとつ例外を通させた（例外の記録）

**共有ブラウザ K2 は、工場を通さずに作った。** 経緯と理由をここに残す——
**例外を通した理由が後から読めないと、次から例外が当たり前になる。**

- **何を**：`task-0178`（共有ブラウザ K2・本物の chromium を起こすアダプタ）。
  Kobo に積んだが、上記のとおり 12 本待ちになった。
- **なぜ外でやったか**：K2 は「**PO が面でブラウザを見て触れる**」ことそのものが値打ちの回で、
  PO はそれを待っていた。列のまま待つと**触れるのは早くて同日夕方**になる。
  PO の判断は「**Cでお願い**」＝工場の外で作り、今日中に触れる方を採る。
- **代わりに何で担保したか**：ゲートを通らないぶん、**番頭が `env.verify`（使い捨て環境・
  `environment: test`）で回した結果を唯一の担保**とする。職人の「通りました」は根拠にしない（I1）。
  ブラウザ試験は器で走らない（`imp-0068`）ので、画面の挙動は職人のワークツリー（ホスト側）で
  回した出力を報告に貼らせ、**最後は番頭自身が面で触って確かめる**。
- **着地の段取り**：職人は**ワークツリーで枝を切ってコミットまで**。
  **main へ入れるのは幹が判断する**（工場の外で main を触ると、番頭が書いた未追跡ファイルと
  ぶつかって ff-only マージが壊れる。実例あり）。
- **帳簿**：`task-0178` は畳むまで工場に残し、着地後に幹が
  `kobo.settle(handled_directly)` を踏む。**契約（受け入れ8条）は Kobo の記録に残っている。**

**この例外は、この文書が直そうとしている過保護が消えれば要らなくなる。**
逆に言えば、直さない限り同じ例外がまた要る。それがこの起票を上げる理由である。
