# 索引が「予定」を「事実」の顔で書いていて、読む側が区別できない

## なぜ起票するか

2026-08-16 の事故（inc-0075）の調査で、**会話の索引（`threads/index.json`）が持つ値のうち、
「事実」ではなく「予定」や「その場の初期値」でしかないものが、事実と同じ顔で書かれている**
ことが2箇所で見つかった。

**そして、この2つは同じ日に2度、人と番頭の判断を歪めた。**

- 番頭は「記録は0件」「最後に記録されたのは数分前」を並べて読み、**「矛盾している＝事故が
  進行中だ」と誤って判断した**
- その報告を受けた側も、**「いま失われつつある会話がある」と誤認した**

実際には**どちらの値も嘘ではない**——**言葉と中身が合っていない**だけだった。

**個別の直しだけでは足りない。** 次に別の欄で同じことが起きる。**「この値は事実か、予定か」を
読む側が区別できる形**にしたい。

## 現物（2箇所）

### 1. `lastActivityAt` — **構築時刻を「最後に記録された時刻」の顔で見せている**

- `threads.ts:334` の**フィールド初期化子** `lastActivityAt: string = new Date().toISOString();`
- **索引に保存されていない**（`StoredThread` にも `persistIndex` の upsert にも無い）
- → **再起動のたびに、全会話が「読み戻した瞬間の時刻」へ振り直される**
- 実測：thread-126 の値は**ホストの起動時刻と同一ミリ秒**だった
- `thread-tools.ts:175` がこれを **「最後に何かが記録されたのは …」** と表示している

**実害**：`watchStaleBranches`（`threads.ts:1545`・1時間おき）は、この値で「黙って止まった枝」を
**日単位**で測る。**時計が再起動のたびに0へ戻るので、再起動が1日1回より多い限り、この見張りは
構造的に一度も鳴らない。**（断絶期間の再起動間隔は平均およそ1.7時間だった）

→ 個別の手当ては **task-0172 の a7・a8** に入れてある。

### 2. `sessionFile` — **「割り当てた予定の道」を、在るものの顔で書いている**

- 索引 **106件が `sessionFile` を持つが、実体があるのは 52件・無いのが 54件**
  （`sessions/` の中身も52件で、実体ありの側とぴったり一致）
- pi のセッションファイルは**実際に pi が動いたときにしか作られない**のに、索引には
  **読み戻しのたびに割り当てた名前**が書かれる
- 実体なしの側は特定の再起動時刻（`2026-08-15T22-56-37-*`）に集中しており、
  **その回に割り当てられた名前が、使われないまま残っている**

**実害**：いまのところ「読んだ人が『壊れている』と誤解する」だけだが、**それは今日まさに起きた**。
thread-126 の調査で、番頭は「sessionFile の実体が2つとも無い」を欠陥の証拠として扱いかけた。

## 直しの向き（案・実装していない）

**個別に潰すのではなく、規律を1本通したい。**

- **索引に書くのは「事実」だけにする。** まだ起きていないもの・まだ作られていないものは
  **書かない**か、**予定だと分かる欄名にする**（例 `plannedSessionFile` / `assignedAt`）
- **事実である値は、事実として保存する**（`lastActivityAt` を索引に持たせ、読み戻しで振り直さない）
- **表示する側は、値の意味と違う言葉を使わない**。「最後に何かが記録されたのは」と出すなら、
  **本当に記録の時刻**であること。そうでないなら**言葉を変える**
- 索引に載る欄を**一度棚卸しする**——「これは事実か、予定か、その場の初期値か」を欄ごとに
  はっきりさせ、**予定・初期値の欄には、そう分かる名前かコメントを付ける**

## なぜ「規律」として起票するか

`lastActivityAt` と `sessionFile` は**別々の欄**だが、**壊れ方が同じ**である。
個別に直しても、**次に誰かが索引へ新しい欄を足すとき、また同じ形になる**。

**判断の材料になる値が、事実なのか予定なのか分からない**——これは機構の穴というより、
**読む側（人・番頭）の判断を静かに歪める性質**であり、実際に今日それが起きた。
