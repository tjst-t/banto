## 何が起きたか（実測）

2026-08-15 14:52:16 UTC、枝 thread-105 が `system.restart` を呼んでホストを再起動した
（main は `dd98aa3b`＝imp-0056 の直しが乗った状態）。再起動は正常に完了し（PID 2590272、
起動処理完了 14:52:21、エラー・再起動ループ無し）、**imp-0056 の回収は実際に働いた**——

```
Aug 15 14:52:21 banto node[2590272]: [banto] thread-107: 前回の再起動で失われたターンを起こし直します（…）
```

しかし**回収されたのは thread-107 の1本だけ**で、**再起動を撃った当の thread-105 は復帰
しなかった**。台帳 `/var/lib/banto/turns.jsonl` を機械的に集計すると、14:52:21 以降に始まった
ターンは thread-107 / 101 / 85 / 112 / 110 / 61 の6本で、**thread-105 と thread-104 は1本も
無い**。thread-105 の最後の記録は 14:52:11.184Z（source: system）で、そこで途切れている。

thread-105 は「再起動後にやること」（環境の孤児の確認・回収の実測・枝の生存確認・職人の
起こし直し）を自分の記録に控えとして残したまま、**誰にも起こされずに止まった**。実際には
別の枝（thread-110）が幹の差配で肩代わりしたが、それは人手（幹の判断）であって機構ではない。

## なぜ漏れるのか

imp-0056 で入れた回収 `lost-turn.ts:findLostTurn` が拾うのは
**「外から入った一言で終わっていて、番頭の応答が1件も無い会話」**。既存の
`turn-guard.ts:resumeInterruptedTurn` が拾うのは**「最後のメッセージが toolResult」**の会話。

`system.restart` を撃った会話はそのどちらにも当てはまらない：

- 最後にあるのは**番頭自身の道具呼び出し**（外から入った一言ではない）
- その道具の**結果は返ってこない**（プロセスごと消えたので toolResult が記録されない）

つまり `system.restart` は「自分を殺す道具」であり、**自分の復帰だけは自分で用意できない**。
回収の網は「落とされた側」を想定していて、「自分で落とした側」を見ていない。

## どう直すか（案）

- **A. restart を撃った会話は復帰後に無条件で1本回す。** 再起動の意図（誰が撃ったか）を
  データに落としてから終了し、起動時にそれを読んで1本 nudge する。既に
  「再起動の一言は呼んだ会話へ返す」(`163c11fe`) があるので、その配達を**再起動をまたいで
  永続化する**形になる。
- **B. 意図の永続化。** 撃つ前に「復帰後にやること」を会話の記録ではなく機構が読む場所へ
  残す（thread-105 は控えを**会話の記録に**書いたが、機構はそれを読まない）。
- **C. 冪等性の検討を添える。** やり直すと二重に効く道具——コミット・マージ・再起動——は、
  回収で1本回されたときに同じ手を打ち直す恐れがある。回収で起こされたターンには
  「これは回収である・既に済んだ手は打ち直さない」ことが分かる印を渡すこと
  （`system.restart` の再入防止＝再起動直後の restart は断る、も併せて）。

## 見分け方（再現）

`system.restart` を撃った会話の id を控えておき、再起動後に `journalctl -u banto.service` の
回収ログと `/var/lib/banto/turns.jsonl` を突き合わせる。その id が出てこなければ再現。
