# ツールコール後にターンが継続せず応答が止まる（ハーネスのターンループ）

## 内容

2026-08-02、職人（task-filebrowser-preview-tickets-2026-08-02）の完了報告を受けて番頭が検証中に発生。番頭ホストが git status / file.read のツールコールを実行し、結果が返った後、**次の応答を生成せずにターンが終了した**。PO の WebUI ではチャットの送信ボタンが「送る」のまま（＝応答生成中でないアイドル状態）で、PO が「どう？」と声をかけるまで停止していた。

- **発見**: PO（2026-08-02）。番頭自身はツールコール後に停止していたことを自覚できていなかった（「検証していた」と答えたが、実際はツールコール結果を受けた後の継続生成が発生していなかった）
- **発生状況**: 職人の完了報告（自動でターン開始）→ 番頭がツールコール（git status・file.read を並行実行）→ ツール結果受領後、応答が生成されず停止
- **切り分けが必要**: pi coding agent（ハーネス）のバグか、banto の実装（ターンループ処理）が間違っているか
- **関連**: imp-0010（WS error ハンドラ未登録でプロセス全体がクラッシュ）と同系統の可能性。2026-08-02 セッション冒頭で職人（task-status-backfill）がテスト実行中にプロセス終了した件（worker 側のターンループ）とも関連の可能性

## 調査対象

- `packages/banto-host/` のターンループ実装（pi SDK の呼び出し。ツールコール結果をプロンプトへ戻して継続ターンを生成する処理。stopReason: toolUse の扱い）
- pi coding agent（opencode）側のターンループ仕様・既知のバグ（node_modules 内の実装）
- ツールコール結果を送った後、pi が継続ターンを返す条件

## 現状の措置

- 特になし（発生時は PO が「どう？」と声をかけて復帰。再発時も同様に会話の続きを投げれば復帰する見込み）

## 対応方針

- 調査タスクとして職人へ委譲し、**pi のバグか banto の実装ミスかを切り分ける**
- banto 側なら修正タスク（層C、governance 相当）、pi 側なら pi の更新・回避策を検討
- 再現条件が特定できたら、回帰テスト（層C 改善のマージ前に再現 E2E シナリオ追加）を検討
