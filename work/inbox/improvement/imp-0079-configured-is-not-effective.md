# 「設定した」と「効いている」は別物（2026-08-16 に7件出た同じ形）

## 一般則

> **設定・検査・上限・作法は、「書いた」ことではなく「効いている」ことを確かめないと、
> 効いていないまま何日でも動く。しかも見た目は正常である。**

2026-08-16 の一日で、**同じ形の不具合が7件**出た。**どれも「壊れて止まる」のではなく、
「効いていないのに、効いているように見える」形で潜んでいた**。列挙する価値があるのは、
**次に何かを入れたときに『効いているか』を確かめる癖が、この一覧の長さでしか正当化されない**からである。

## だから、どう確かめるか（種類ごとの「実体」）

| 何を入れたか | **書いた場所ではなく、ここを見る** |
|---|---|
| systemd の設定・cgroup の上限 | `systemctl show <unit> -p <Prop>` と `/sys/fs/cgroup/.../memory.max`（**ファイルの有無ではない**） |
| 層B設定（`meta/config.yaml` 等） | **その値が効いた痕跡**（同時に走った本数・拒否された記録）。設定ファイルの中身ではない |
| 受け入れ条件・検証コマンド | **走った件数と結果**（0件で緑になっていないか）。ゲートのログ |
| 試験 | **別の器・別の権限で走らせても同じ結果か**（root / 非 root、コンテナ / ホスト） |
| 稼働機の設定 | **リポジトリにも同じものが在るか**（無ければ作り直しで消える） |
| コード中の前提コメント | **いまの実測**（数字が書いてあるコメントほど古びる） |

## 手（この文書自体の扱い）

- **個別の直しは各記録にある**（上の表の「→」の先）。**この文書は、次に何かを入れる人が読むための一般則**である。
- **入れたものが効いているかを機械が見張る**のがいちばん強い。**すでにその方向の仕事は積んである**
  （`task-0177`＝機械が1本も検証していない契約を通さない、`task-0196`＝恒久の上限を実測に合わせる）。
  **同じ形で、「設定したが効いていない」を機械が言えるようにできるものが他にもあるはず**——
  **見つけたらこの表に足すこと。**
