# 決定番号を振り直した（旧→新の対応表と、承知のうえの割り切り）

## なぜ番号がずれたのか

**採番に検査が無かった。** ADR の中で採られる「決定NNN」は、書く人が「直前の ADR の続き」を
目で見て決めていた。並走した枝はそれぞれ**別の ADR を「直前」とみなす**ので、同じ番号を
別々の内容で名乗ることになる。記録の id（imp / inc / prop / adr）の重複は task-0152 で
`tests/acceptance/record-id-uniqueness.spec.ts` が押さえたが、**その内側にある決定番号の層は
誰も見ていなかった**。

実際に起きていた衝突:

| 番号 | 一方 | もう一方 |
|---|---|---|
| 決定47 | ADR-0010「文脈の管理をコンパクションから退避と章立てへ移す」 | ADR-0011「モデルは列挙ではなく採用と検索で扱う」 |
| 決定69 | ADR-0014「契約は改訂できる」 | ADR-0013「役割ごとに、モデルを名前で当てられる」 |
| 決定113 | ADR-0023「番頭と PO を分ける線は経路である」 | ADR-0026「Kobo へ仕事が入る口は `kobo.enqueue` だけ」 |
| 決定120〜123 | ADR-0025「知らせは幹のターンを起こさない」ほか | ADR-0026「契約を直すのも道具の入力から」ほか |

加えて ADR-0010 の**決定39 が同じ節を2回書いていた**（見出しも本文も同一。1箇所だけ
`caddy_admin.go` のパスの書き方が違った）。

**task-0153 は一度この解消を試みて失敗している。** 置いた試験の走査が `### 決定N` 書式だけを
見ており、`### N. タイトル` 書式（ADR-0010〜ADR-0013 の67番）を候補にすら入れていなかった。
拾えたのは63件で、空振り防止のしきい値50をすり抜けて**黙って緑になった**。
——**採番の検査を書くときは「拾えた件数」を必ず疑うこと。**

## 旧→新の対応表（2026-08-16・task-0159）

**残す側は「参照の所在」で決めた**——`packages/**`・`docs/spec/**`・`tests/**` からの参照が
指している側を残し、指していない側／参照の少ない側を空き番号へ移した。

### ADR-0026: 決定113〜123 → 決定127〜137

| 旧 | 新 | | 旧 | 新 |
|---|---|---|---|---|
| 113 | 127 | | 119 | 133 |
| 114 | 128 | | 120 | 134 |
| 115 | 129 | | 121 | 135 |
| 116 | 130 | | 122 | 136 |
| 117 | 131 | | 123 | 137 |
| 118 | 132 | | | |

外から ADR-0026 の決定番号を引いている行は**1つも無かった**（「決定113」は全部 ADR-0023 を、
「決定120〜123」は全部 ADR-0025 を指していた）ので、参照の付け替えは要らなかった。

### 決定47: ADR-0011 側を 138 へ

`### 47. モデルは「列挙」ではなく「採用と検索」で扱う` → **決定138**。
ADR-0010 の決定47（退避と章立て。47a / 47b / 47c / 47d の枝番を含む）は**動かさない**——
参照が21箇所あり、ADR-0011 側は5箇所だった（churn の小さい側を動かす）。

### 決定69: ADR-0013 側を 139 へ

`### 69. 役割ごとに、モデルを名前で当てられる` → **決定139**。
ADR-0014 の決定69（契約は改訂できる）は**動かさない**——決定70〜72 と連番で、
`docs/spec/daemon-core.md` と `packages/banto-daemon/skills/kobo-enqueue/SKILL.md` が
「決定69〜72」とまとめて指している。ADR-0013 側は外部参照ゼロだった。

### ADR-0010 決定39: 二重記載を1つ削除

番号は変えず、重複した節（L625〜655）を削った。残したのは**内容の多い側**（Palmux の
参照パスを `palmux2/internal/runtime/incus/caddy_admin.go` とフルで書いていた方）。

## PO が承知のうえで受け入れた割り切り

**過去のコミットメッセージ・`work/tasks/**`・`docs/notes/handoff.md`・`docs/proposals/**`・
`prototype/**` に残る旧番号は書き換えない。**

したがって、**2026-08-16 より前に書かれた文書を読むときは、この表で読み替えること**:

- 「決定47」は **ADR-0011 側（＝いまの決定138）を指している可能性がある**。
  ADR-0010 側なら `47a` `47(b)` のような枝番が付いているか、文脈が退避・章立て・
  コンパクションの話になっている
- 「決定69」は **ADR-0013 側（＝いまの決定139）を指している可能性がある**。
  ADR-0014 側なら「決定69〜72」とまとめて出てくるか、文脈が契約の改訂の話になっている
- 「決定113〜123」で ADR-0026（入口の一本化）の話をしているものは、**+14 した番号
  （127〜137）がいまの番号**

## 以後の採番規約

1. 決定番号は `docs/adr/**` を走査した**最大 +1** から採る。
   **「直前の ADR の続き」から採ってはいけない**——並走した枝がそれぞれ別の ADR を
   「直前」とみなすため、同じ衝突をもう一度起こす
2. **欠番は埋めない**（いまの欠番は 49・50・114〜119）。埋めると、旧番号が残っている
   過去の文書の読み替えが二重に壊れる
3. 他所で決まった決定を**引用しているだけ**の見出しは、
   `tests/acceptance/decision-number-uniqueness.spec.ts` の `CITATION_HEADINGS`
   （ファイル＋見出しの全文の対）に載せる。**一覧に在るのに実在しない見出しがあれば
   試験が落ちる**——除外は黙って増やせる抜け道なので、腐りを機械が見つける形にしてある
4. 次に採るべき番号は試験が毎回出す（いまは **140**）

## 機械で守る

`tests/acceptance/decision-number-uniqueness.spec.ts`。落とすのは
①ADR をまたいだ決定番号の重複 ②走査の空振り（拾えた番号が120件未満。いまは131件）
③引用の除外一覧の腐り。欠番と「番号を読み取れなかった見出し」は落とさず一覧に出す。

## 残っている穴

**走査は `docs/adr/**` に閉じている。** `docs/notes/pi-coding-agent-design-v2.md` など
ADR の外で採られた決定番号との衝突は**この試験では拾えない**。いま実害が出ていないので
このタスクでは直さなかったが、ADR の外で決定番号を名乗る文書が増えるなら走査範囲を
広げる必要がある。
