# 記録が0件の枝は、失われたターンの回収から漏れる（imp-0056 の塞ぎ残し）

## 現物（2026-08-16・実測）

枝 **thread-126**（「取次の導線と一括クローズ」）は、**開かれた 507ms 後にホストが OOM で
殺され、種のターンが1文字も出ないまま消えた**。

| 時刻 | 出来事 |
|---|---|
| 00:48:37.795 | thread-126 が開かれる |
| **00:48:38.302** | **OOM killer が banto.service を殺す（507ms 後・カーネルログで確定）** |
| 00:48:45 → 00:48:51 | 再起動 → thread-126 開き直り |
| 01:16:21 → 01:16:35 | killed(signal) → 再起動 → 開き直り |
| 01:38:26 → 01:38:38 | killed(signal) → 再起動 → 開き直り |
| 〜02:16 | **この間、あの枝は一度も動いていない**（記録0件・記録ファイルも存在しない） |
| 02:16 | **幹から `thread.steer` で言伝を渡したら動き出した** |

**3回読み戻されて、3回とも回収されなかった。** 外から言伝を渡すまで、枝は止まったままだった。

## imp-0056 と同じ形。ただし**1段手前で落ちている**

| | 開いた時刻 → 殺された時刻 | 記録 |
|---|---|---|
| imp-0056（thread-104） | 13:59:53 → 13:59:54（**約1秒後**） | `知らせ[thread]`（seed の一言）が**1行残った** → **回収できた** |
| thread-126 | 00:48:37.795 → 00:48:38.302（**507ms 後**） | **0件**。記録ファイルも存在しない |

**imp-0056 の文書が置いている前提が、実装と食い違っている。**

> 「知らせの行は**残る**（記録は prompt より前・**即書き**）」

**即書きではない。** `record()` → `onRecord` → `persist()` は **`SAVE_DELAY_MS = 400`**
（`threads.ts:645`）で間引かれる。さらに **`open()`（`threads.ts:1117-1153`）は新しい枝を
flush しない**——`persistIndex` で索引だけ書き、記録は最初の発話まで書かれない。
だから thread-126 は**索引に在って記録ファイルが無い**。

thread-104 が救えたのは、たまたま SIGKILL まで約1秒あって **400ms の窓を越えたから**。
**126 は 507ms で、窓の際どいところに落ちた。**

**（正直に）** seed の知らせが「記録されたが flush されなかった」のか「そもそも記録される前に
死んだ」のかは**区別できない**（`handOff`（`thread-tools.ts:190`）が fire-and-forget なので、
どちらでも同じ姿になる）。**どちらであっても結論は変わらない。**

## 回収の網から漏れている（**コードで確定**）

`lost-turn.ts:212`
```ts
export function findLostTurn(entries: readonly TranscriptEntry[]): LostTurn | undefined {
  for (let i = entries.length - 1; i >= 0; i--) { ... }
  return undefined;
}
```
**`entries.length === 0` ではループ本体が一度も走らず、必ず `undefined` を返す。**
末尾が無いので**判定そのものが成立しない**。`recoverLostTurns`（同 `:269`）は
`const lost = findLostTurn(thread.transcript); if (!lost) continue;` で **ログも出さずに飛ばす**。

**他の2つの回収も届かない**：
- `resumeInterruptedTurn`（`bin.ts:1683` / `turn-guard.ts`）… **最後が toolResult のときだけ** → 記録0件では成立しない
- `resumeAfterRestart`（`bin.ts:1711`・`1891`）… **`system.restart` を自分で撃った会話のみ** → 該当しない

`recoverLostTurns` には `threads.list()` が渡されており（`bin.ts:1904`）、thread-126 は open で
`alreadyResumed` にも居ないので、**確かに走査されて、確かに素通りされている。**

→ **thread-126 は「開いているのに永久に動かない枝」だった。** 動かせるのは、幹から
`thread.steer` を渡すか PO が枝で発話するかだけ。**機構は二度と自分から起こさない。**

## なぜ困るか

**「開いた直後にホストが落ちると、その枝は永久に動かない。」**

- 枝は `thread.list` に「開いている」と出続けるので、**誰も異常だと気づかない**
- 番頭は「渡したら手を離す」ので、**渡した先が動いていないことに気づく契機が無い**
- 2026-08-15 だけでホストは12回落ちている。**再発しやすい**

今回は PO が別件で「あの枝はどうなっている？」と気にかけたので発覚した。
**気にかけられなければ、あの枝は止まったままだった。**

**見張りも効いていない。** `watchStaleBranches`（`threads.ts:1545`）は `lastActivityAt` で
「黙って止まった枝」を測るが、**この値は索引に保存されておらず、再起動のたびに振り直される**
（task-0172 の a7 で手当て中）。**2つの穴が重なって、1時間半のあいだ誰も気づけなかった。**

## 塞ぎ方（案・実装していない）

**本丸は「投げ直す文面が無い」こと。** thread-126 の索引には `openReason`・`returnCondition`
はあるが、**`thread.open` に渡した seed の一言はどこにも保存されていない**。だから記録が
0件だと、回収したくても投げ直すものが無い。

1. **seed を索引に持たせる（本命）**。`thread.open` の一言を `StoredThread` に保存し、
   `findLostTurn` の手前で「`state === "open"` かつ `transcript.length === 0`」を**専用の種類**
   （例 `kind:"never-started"`）として返して、その seed を `nudge` で投げ直す。
   **これが無いと、他をやっても枝は生き返らない。**
2. **もっと手前で塞ぐ**：`open()` が新しい枝を**その場で flush する**（空でもファイルを作る）。
   「索引に在るのに記録ファイルが無い」状態が構造的に消え、**task-0161** とも噛み合う。
   ただし空ファイルだけでは seed は戻らないので 1 と併用。
3. **間引きを1行目には掛けない**：会話の**最初の1件**だけ `persist` を経由せず即 `flush` する。
   imp-0056 が前提にしていた「即書き」を、実際にそうする。**400ms の窓に落ちる枝が
   構造的に消える。**
4. **黙って飛ばさない（I2）**：`recoverLostTurns` が「開いているのに記録0件」を見つけたら、
   **回収できなくても取次へ1通出す**。いまは完全に無言で、**現に今日まで誰も気づかなかった。**

**受け入れ条件の形**：「**開いた直後（400ms 未満）に SIGKILL → 起き直したら、その枝に seed が
投げ直されて1本ターンが回る**」を試験で固定する。imp-0056 の既存試験
（`tests/acceptance/branch-seed-turn.spec.ts`）は**記録が1件残っている前提**なので、
**0件の場合を足す**のが塞ぎ残しの潰し方。

## 副産物：inc-0075 の「千切れた行」の出どころ

この時刻は、inc-0075 で見つかっていた「00:48:50 の読み戻しで thread-61 の記録に読めない行が
1行あった」と噛み合う。

**00:48:37.795 に `parentTrunk.record({role:"branch"})`（`threads.ts:1149`）→ persist の 400ms →
約 00:48:38.20 に thread-61.jsonl（2.9MB）の全文書き込みを開始 → 00:48:38.302 に SIGKILL。**

**千切れた行の出どころは、まさにこの書き込みである。**（どこで切れたかは分かっていない）
