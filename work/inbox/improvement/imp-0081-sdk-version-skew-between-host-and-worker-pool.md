# 番頭と工房で Agent SDK の版がずれている（切り分けが読めなくなる）

## 事実（2026-08-16・現物の `node_modules` を読んで確認）

| どこ | `@anthropic-ai/claude-agent-sdk` | 同梱バイナリ |
|---|---|---|
| `packages/banto-host` | **0.3.229** | 311,175,440 bytes |
| `packages/banto-worker-pool`（とルート） | **0.3.226** | 297,831,432 bytes |
| npm の最新 | **0.3.233**（2026-08-14 公開） | — |

**番頭と工房で、同じ SDK の別の版が動いている。** 番頭は最新と4版差、工房は7版差。

## なぜ困るか

**「番頭では起きるが職人では起きない」（またはその逆）が観測されたとき、
それが版差なのか、作りの差なのかが読めなくなる。**

今日いちばん時間を使ったのは切り分けである——
「番頭のメモリは上流のバグか、こちらの解放漏れか」「職人が死ぬのはモデルか、袋の中で `npm` を回すからか」。
**変数が1つ増えるたびに、その切り分けが1回ぶん重くなる。** 版は、揃えられる変数である。

## いつやるか（**いまではない**）

**根治の3本が着地して、メモリが落ち着いてから。**

- **task-0165** — アイドルな会話の SDK セッションを畳む（本命）
- **task-0186** — 検証を袋の外で回し、結果も切り詰める
- **task-0168** — 同時に走る職人の本数の上限

**いま上げると、直しの効果と版差の効果が混ざって測れなくなる**（幹の判断・2026-08-16）。
**また、上流の 0.3.233 にメモリの直しは入っていない**——CHANGELOG（2.1.226〜2.1.233）に
リーク・RSS・OOM・プロセスの終了漏れに関する項目は無く、**上げてもこの問題には効かない**。

## やるときの中身

- **両パッケージを同じ版へ揃える**（ルートも含む）。**どの版に揃えるかは、そのときの最新と安定度で決める**
- **上げる前に、banto が掴んでいる API を確認する**：
  `query()`（`prompt` にストリーム渡し）／`Options`（`hooks.PostToolUse` / `hooks.Stop` / `resume` / `sessionId` / `mcpServers`）／
  `HookInput` / `HookJSONOutput` 型／`session.abort`／`session.getContextUsage()`
- **CHANGELOG は薄い版がある**（「バグ修正」とだけ書かれた版がある）ので、**記載外の内部変更は排除できない**。
  **上げた後に、番頭と職人の両方が実際に動くことを確かめること**（型が通るだけでは足りない）
- **上げた前後で、1本あたりの anon（`/proc/<pid>/smaps_rollup`）を測って比べる**。
  **いまの基準値は 199〜227 MiB**（2026-08-16 実測・5本）。**上げた効果を数字で言えるようにする**
