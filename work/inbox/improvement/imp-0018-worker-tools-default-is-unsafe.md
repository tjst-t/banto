# `worker.delegate` の `tools` を省略すると、職人は書き換えの口を全部持つ

## 内容

`worker.delegate` の `tools`（職人に使わせる道具の許可リスト）は**任意**で、
省略すると `read` / `bash` / `edit` / `write` / `grep` / `find` / `ls` が全部渡る。

道具自身の説明文が、そうなることを警告している（`worker-tools.ts:47-54`）:

> 職人に使わせるTool名の許可リスト。**省略すると read/bash/edit/write/grep/find/ls を
> 全部持つ＝調べるだけのつもりでも書き換えられる。** 読むだけで足りる仕事は
> `["read","grep","find","ls"]` のように絞ること

**つまり「絞るのが前提」の設計なのに、省略が最も危険な側に倒れる。**

## なぜ問題か

- **既定は安全側に倒すのが筋**（決定38「書き込みは既定で不可」と同じ思想）。
  場所の砦は既定で読み取り専用なのに、職人の道具は既定で全部持ちという食い違いがある
- `bash` を持った職人は `curl` で外へ出られる（`pool.ts:261` に明記あり）。
  `network: false` は web の口を渡さないだけで、bash 経由の外向きは塞いでいない
- **番頭が書き忘れると起きる**。実測では 813回中 276回が1個だけに絞れているので
  番頭は概ね絞れているが、忘れたときに気づく手立てが無い

## 直し方の候補（未決）

1. **既定を読み取りだけにする**（`["read","grep","find","ls"]`）。書き換えが要る仕事は
   明示的に `write`/`edit` を書く。**既存の呼び出しの挙動が変わる**ので、
   絞らずに投げている経路が壊れないかを先に測る必要がある
2. **省略を拒む**（必須にする）。いちばん明快だが、毎回書かせる負担が乗る
3. **粗い合言葉を足す**（`access: "read" | "write"`）。番頭が道具名を並べるのは
   細かい仕事（D10）でもあるので、意図を書かせる形にする

**3 が筋に見える**が、語彙を1つ増やすことになるので、まず 1 で足りるかを測りたい。

## 確かめていないこと

- 実際に `tools` を省略している呼び出しがどれくらいあるか（イベント台帳で数えられる）
- 既定を変えたときに壊れる経路（Kobo が起こす職人、`worker.wake` の復元経路）
