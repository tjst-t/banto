# ワークツリーに node_modules が無く、職人が「軽い確認」を指示どおりにできない

## 何が起きているか

Kobo が職人へ渡す指示には、こう書いてある（`daemon.ts:5294` 付近）。

> **軽い確認（1ファイルの型検査・`npm run test:one <1ファイル>`）で自分の変更を確かめる。**
> **一式（`npm ci` / `npm test` / `npm run typecheck` / `npm run build`）は自分で叩かない**

**この「軽い確認」ができない。** 職人のワークツリーに `node_modules` が無いからである。`npm run test:one` は `tsx` を要求するので、即座に `ERR_MODULE_NOT_FOUND` で落ちる。

**一式は叩くなと言われ、軽い確認は道具が無くてできない。** 職人には**自分の変更を確かめる手段が1つも無い**。

## 実測（2026-08-20・同じ日に2人）

- **task-0292 の職人**：「手元の node_modules が壊れており（**空・root 所有**）、`npm run test:one` によるローカルの軽い確認はできませんでした」
- **task-0295 の職人**：「このワークツリーに **node_modules が丸ごと存在しません**（`tsx` が無く即座に `ERR_MODULE_NOT_FOUND`）。他の task worktree（例 `task-task-0164`）を見ると、**npm install 済みの実ディレクトリ（353エントリ、`@banto/*` だけ自分の packages へ相対 symlink）**が用意されており、これが本来の状態のようです」

**2人とも「自分で `npm install` してよいか」と手を止めて聞いてきた。** どちらも正しい判断だが、**そのたびに番頭のターンが1つ消費されている。**

## 仕掛けを探したが、見つからない

`packages/banto-daemon/src`・`packages/banto-repo-manager/src` を `node_modules` / `npm install` / `npm ci` で引いたが、**ワークツリーを用意するときに依存を入れる処理は無い**（当たるのは指示文の中の文字列と、`layout.ts` の「探索で `node_modules` に潜らない」だけ）。

`task-task-0164` に実体があるのは、**誰かが手で入れたか、以前は別の仕掛けがあった**のどちらかに見える。

## 関連（この形は前にも触っている）

- **`worktree の node_modules 丸ごと symlink の罠`**：ワークツリー直下に本体への symlink があると、`@banto/*` が本体を向き、**自分の変更を読まずに試験が回る**
- **task-0264**：ワークツリー直下の `node_modules` symlink が残っていると、docker のゲートコンテナへマウントしたとき相対リンクが壊れて **180 spec 全滅**（`ERR_MODULE_NOT_FOUND`）。直しは環境プール側で `stripWorktreeNodeModulesSymlink` を呼ぶこと

**つまり「symlink を張る」は既に2回害を出しており、単純に戻すのは正しくない。** task-0295 の職人が観察した形（**実ディレクトリ＋`@banto/*` だけ相対 symlink**）が、その2つを避ける形になっている——**それが正解の姿である可能性が高い。**

## 直す方向（案。スコープを決めるには、ワークツリーを用意している箇所を特定する必要がある）

1. **ワークツリーを用意するときに依存も用意する。** 形は `task-task-0164` に倣う（実ディレクトリ＋`@banto/*` は相対 symlink）。**丸ごと symlink にはしない**（上の2件の再発）。
2. **用意できなかったら、指示文の側を変える。** 「軽い確認をせよ」と書いておいて道具が無いのは、**指示が嘘になっている**。用意しないなら「手元では確かめられない。検証はマージ前ゲートが回す」と書き切る方が正直で、**職人が毎回聞いてこなくなる。**
3. どちらにせよ、**職人が「確かめられなかった」と書けること**は残す（I1：確かめていないことを確かめたと書かせない）。

**1 と 2 のどちらを採るかは、費用の判断**である——全ワークツリーに依存を入れるのは容量と時間を食う。**「軽い確認」にどれだけの価値を置くか**で決まる。

## なぜ task ではなく imp か

**工程は止まっていない**（検証はマージ前ゲートが検証環境で回すので、担保は失われていない）。失われているのは**職人が自分で早めに気づく機会**である。

そして**直す場所をまだ名指しできない**——ワークツリーを用意している箇所を特定しないと `scope.paths` を狭く書けない。**スコープが甘いまま積むと、着手後に広げる相談が発生する**（今日それを3回やった）。**特定してから積む。**

## 教訓

**指示に書いたことが、渡した環境でできるとは限らない。**
「一式は叩くな／軽い確認はせよ」は、**軽い確認ができる環境**とセットで初めて成り立つ。**片方だけ入れると、職人は「できません」と言って止まるか、黙って確かめずに進むかのどちらかになる。**
