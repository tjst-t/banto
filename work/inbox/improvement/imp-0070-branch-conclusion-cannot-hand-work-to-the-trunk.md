# 枝の結論は幹に仕事を渡せない（畳んでも幹は動かない）

## なぜ起票するか

2026-08-16、task-0152 が着地したのに幹（番頭）が次の一手——banto の再起動＝稼働への
反映——を踏まなかった。PO の言葉:

> 「そのように段取りしました。流れ：task-0152 が着地 → 枝から私へ合図 → 私が再起動を踏む」
> と言ってくれていたのに、私が「0152 完了しましたね」と言うまでその先を実施して
> くれなかったのはなぜでしょうか。**私は枝からの通知を見て幹が自動で先に進んでくれることを
> 期待していました。**

段取りは書かれていた。書かれていた通りに動かなかったのは、**書ける口が無かった**から。

## 何が起きていたか（4つが重なった）

1. **知らせは幹のターンを起こさない**（ADR-0025 決定120）。`thread.merge` は幹の末尾に
   結論を1行積むだけで、幹のターンを回さない——**枝が畳まれても幹は動かない**
2. task-0152 を実際に握っていたのは、機構が T3 で自動的に立てた**用件枝 thread-119**。
   あの枝が承認もマージ確認も済ませ、**静かに畳んだ**。幹は起きなかった
3. 番頭が「着地したら合図をくれ」と頼んだ相手は、工場の流れを**観測する役の枝 thread-118**
   で、タスクを握っている枝ではなかった。**観測役は合図の契機を持っていない**
4. これは予測されていた副作用（`docs/proposals/2026-08-15-trunk-availability-plan.md:123`）。
   「未読で足りるか運用で見る」と先送りしてあったが、足りなかった

`thread.consult`（枝が生きているうちに幹へ聞く）は**既に幹を起こす**。穴は
**「畳むときに一手を渡す経路」が無いこと**だけだった。

## 直し（task-0158）

`thread.merge` に **`handoff`（幹が次に踏む一手）** を足した。

- **非空のときだけ**、畳んだあと幹のターンが**1本だけ**回る（経路は `thread.consult` と
  同じ `nudge`。`worker` / `kobo` / `env` / `system` ではないので決定126 の判定は保たれる）
- 空／未指定なら**従来どおり**——結論1行が積まれるだけで幹は動かない
- **一度きりの保証は帳簿（`ThreadRegistry.merge`）が持つ**。畳み直しても幹は二度起きない
- `nudge` が配線されていない構成で `handoff` を渡されたら**畳む前に断る**（I2）。
  枝は開いたままなので書き直して畳み直せる
- 往復の上限（`allowSend`）は掛けない。畳むのは1枝1回で、上限で弾くと**畳めなくなる**
  ——弾くべきは往復であって受け渡しではない

## 案 (a) を採り、(b) を採らなかった理由

- **(a) `thread.merge` に「幹の一手」を渡す欄を足し、非空なら幹のターンを1本起こす** ← 採った
- (b) `remaining` の所在が「幹」を指しているときだけ起こす ← 採らなかった

(b) を採らない理由は `packages/banto-host/src/remaining-whereabouts.ts` の現物から:

1. **所在の語彙は意図的に緩い。** `WHEREABOUTS_WORDS` には「幹へ」「幹で」「PO」「待ち」
   「委譲」「引き継」などが入っている。これは「**誰が残作業を持っているか**」を言えて
   いれば通す、という緩さ。ここを起床の条件に転用すると、**ごく普通の畳み方の多くで
   幹が起きる**——保つべき「幹は静か」（決定120）がその場で壊れる
2. **寿命が違うものを同じ欄に載せない。** `remaining` は「残っている作業」で、
   `thread.settle` で降ろすまで未処理として残り続けるもの。一手は「いま幹が踏むもの」で、
   幹が1回受け取れば消えるもの
3. **`remaining` の行からは「何をしてほしいのか」が読めない。**「task-0092 を積んだ」を
   受け取った幹は、自分が何を踏むべきか分からない

(a) は意図が明示で、機械で検査でき、既存の `remaining` 検査（imp-0036(d)）の意味を汚さない。

## 今日の運用の教訓（機構では直らない側）

**合図を頼む相手は、そのタスクを握っている枝でなければならない。**
工場を観測しているだけの枝に頼んでも合図は来ない——観測役は合図の契機を持っていない。
用件枝は機構が T3 で自動的に立てるので、**誰が握っているかは `thread.list` で確かめる**。

この教訓は `packages/banto-host/skills/trunk-and-branch/SKILL.md` に残した。
