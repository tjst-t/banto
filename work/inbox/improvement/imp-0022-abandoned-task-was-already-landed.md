# imp-0022 「未着手だから畳む」と書いたタスクが、実は main に着地していた（task-0148）

- 起票: 2026-08-14（番頭）
- 由来: 枝「Kobo あるべき論」に task-0148 の滞留の知らせが届き、捌こうとして気づいた
- 関連: imp-0019（キュー棚卸しの残り）・imp-0021（畳んだのに滞留の知らせが取り下がらない）
- 状態: open

## 何が起きたか

2026-08-14T09:25:10、番頭は task-0148（滞留を帳簿から導出して知らせる）を
**abandon（諦める）**で畳んだ。帳簿に残っている理由はこう書かれている：

> Kobo からは畳み、番頭の宿題として引き取る（2026-08-13 PO 了承の体制移行）。
> **未達の実体：滞留検知はまるごと未着手（dwell.ts も task_stalled も0件）。**

**この判定は誤りである。** 中身は既に main に着地している：

- `packages/banto-core/src/dwell.ts`（7,769 bytes）は main のコミット
  **4fbaf37「feat(kobo): 測る足場と、証拠に『何に対して』を刻む（第2便）」**で入っている
- `packages/banto-daemon/src/daemon.ts:1842` が `task_stalled` を積む
- `packages/banto-host/src/kobo-notice.ts:79` が知らせの対象にしている
- `packages/banto-core/src/events.ts:421` にイベント型がある

そして決定的な証拠として、**畳む 22 秒前（09:24:48）に task_stalled が実際に鳴っている**。
「task_stalled が0件」と書いたその瞬間、その task_stalled が番頭に届いていた。

## なぜ悪いか

1. **帳簿の分類が事実と食い違う。** 正しくは `kobo.settle(landed_elsewhere)`（外で決着）であって
   `kobo.abandon`（諦めた）ではない。両者は別々に数えられるので、
   「工場で諦めた仕事」の件数が実態より多く見える。
2. **訂正できない。** `kobo.settle` は closed から呼べない（「closed からは畳めません」）。
   畳んだ後に分類の誤りが分かっても、帳簿は直せない。この記録がその代わりである。
3. **imp-0019 が自分で警告していた失敗の実例である。** imp-0019 には
   「照合は『ブランチにコミットが載っているか』では足りない。**中身が既に main に
   入っていないか**まで見ること」と書いてある。task-0148 はまさにそこを外した。

## 考えられる原因（未確認）

棚卸しの照合は、タスク定義に書かれた `scope.paths` のファイルを探して行われたと思われるが、
**どのブランチ・どの時点のツリーを見たのかが帳簿に残っていない**。
当時の作業ツリーは `kobo-control-switches` ブランチにあり（現在は main）、
そこに dwell.ts が無かった可能性がある。〔推定〕

## やること

1. **畳むときの根拠に「どのコミット／どのブランチで確かめたか」を必ず書く。**
   「0件」のような否定的な確認ほど、見た場所を書かないと再検証できない。
2. **`kobo.settle` を closed からも呼べるようにするか、分類だけを訂正する口を用意する**（要検討）。
   いまは畳んだ後に事実が判明しても帳簿を直せない。
3. imp-0019 に残っている他の判定（task-0103 / 0105 / 0110 / 0111 / 0150 など、
   「番頭の宿題として引き取る」で畳んだもの）も、**同じ誤りが無いか main に対して照合し直す。**
   少なくとも1件で誤っていた以上、他が正しい保証は無い。
