# 検証環境を「苦労なしに立てて外に見せる」仕組み

## 内容
PO 希望（2026-08-01）: 「テスト環境を立てて外から見せて会話まで試せる」ことが苦労なしにできる仕組みを banto に持たせたい。

今回の一連の作業（テスト Banto を Caddy 経由で公開）で露見したギャップのうち、体験（UX）層のもの:

- **G1**: proxy exposer が WS を中継しない（中継 URL は偽テスト環境になる）。caddy exposer が正規の基本形だが、「どちらで公開するか」を選ぶ・検知する仕組みが無い
- **G8**: 「ワークツリー → 依存インストール → ビルド → 起動 → 公開 → URL 取得」が1操作になっていない。複数ツールに分散
- **G9**: 公開方式の違い（WS が通る/通らない）がユーザーに見えない（返ってくるのは URL だけ）
- **G10**: 検証環境の状態（起動中・公開中・期限・巻き添えリスク）の見える化が無い

## 対応（案）
- G1: caddy exposer を基本形にし、proxy exposer の WS 制約を明示する（または廃止・警告）
- G8: テスト環境を立てて公開する一連を1コマンド/1操作に（例: env.provision に公開方式を選ばせ、ワークツリー作成〜URL 取得までを1依頼で行えるように）
- G9: 公開方式の選択と明示（返り値に「WS も通る/画面のみ」を載せる等）
- G10: env 一覧の UI 強化（状態・期限・公開 URL・リスク表示）

優先度: P1。ただし、下位の堅牢性（G4〜G7 = imp-0011 / imp-0012 / 照合誤検出の修正）が先に片付くことが前提。
