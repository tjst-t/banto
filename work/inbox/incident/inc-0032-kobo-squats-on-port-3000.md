## 内容

**Kobo が 127.0.0.1:3000 に居たせいで、受け持つプロジェクトの検証が永久に落ちていた。**

`loamium/task-0002` のマージ前ゲートが `verify_failed:a3` で落ち続けた。追うと
loamium のテストに

> LOAMIUM_URL も portman も無ければデフォルト http://127.0.0.1:3000 に接続を試みる

というものがあり、**3000 に何も居ないこと**を前提にしている。Kobo が居るので
`server_unreachable` ではなく `http_error` が返り、必ず落ちる。

## なぜ悪いか

**3000 は最も一般的な dev サーバの既定ポート**（Express・Next.js・Rails・Grafana …）。
banto の仕事は**他人のプロジェクトの検証をこの機械で走らせること**なので、
banto が占有するポートはそのまま「受け持つプロジェクトが使えないポート」になる。
**いちばん混む番地に居てはいけない。**

しかも落ち方が悪い：検証が落ちるだけで、**なぜ落ちたかがゲートのログにしか出ない**。
「loamium のテストが壊れている」と読める形で失敗する。

## 直した（task-0073）

Kobo の既定ポートを **3000 → 4500**（`BANTO_PORT` / `BANTO_KOBO_PORT` / `BANTO_DAEMON_URL`）。
4100（番頭）・4200（WebUI開発）・4300（工房）・4400（検証環境）の並びに揃えた。

**D9 の判断**：Kobo は 127.0.0.1 のみで、POは :4100 とブラウザを使う。内部の番地なので
利用体験は変わらず、完全に可逆（設定2箇所＋既定値）。外に累積する副作用でもないので、
番頭の判断で決めた。

## 確かめたこと

`make` を入れたうえでポートを移すと、loamium の `npm test` が **1943 件すべて通った**
（4分）。移す前は 1942/1943 で、落ちる1件がこれだった。

## 根本策の下見（PO の問い「docker provider を使えばいいのかな？」・2026-08-07）

**方向は正しい。ただし「docker provider を使う」だけでは届かない。** 実際に
`env.verify` を docker で回して確かめた。

### docker が効く範囲（今日踏んだ4件との対応）

| 今日踏んだもの | docker で解決するか |
|---|---|
| 3000番の衝突 | **する。** compose は独自のネットワーク名前空間を持つので、コンテナ内で 3000 を掴んでもホストと当たらない（`network_mode: host` でない限り） |
| `make` 不在 | **する。** イメージが道具立ての契約になる。**直す場所がホストの apt からリポジトリの Dockerfile へ移る**のが本質的な利得 |
| 監査人の事故 | しない（task-0070 で直したもの） |
| ゲートの時間切れ | しない（task-0071 で直したもの） |

### 足りないもの（実測で分かった）

1. **ゲートが Environment Pool を経由していない。** `merge-gate.ts` は `sh -c` を
   ホストで直接叩く。**loamium には docker profile がもう在るのに、ゲートは見ていない**。
   ここが本体で、いちばん大きい
2. **compose の相対パス解決が壊れていた** → task-0074 で直した
3. **one-off コンテナの畳み忘れ** → task-0074 で直した
4. **loamium の `meta/` が未コミット。** worktree（ブランチのチェックアウト）に profile が
   無いので、職人の worktree で検証しようとしても profile が見つからない。**コミットが要る**
5. **10分の run 上限に当たる。** ホストで4分の `npm test` が、コンテナでは `npm ci` 込みで
   10分を超えた（exit 255・ログが途中で切れる）。spec-environment §5.1 の
   `defaultRunTimeoutMs`——上限の見直しか、イメージ側で依存を焼き込む工夫が要る

### 判断が要る点（D9：利用体験を変え、本物のトレードオフ）

- **ゲートの意味が変わる**（誰がテストを走らせるか）。spec-daemon-core §4.1 は
  「Kobo自身がテスト実行」と書いているが、spec-environment §3 の改訂が
  「守るべきは固有名詞ではなく**依頼者ではない信頼された第三者**」と既に読み替えているので、
  **矛盾はしない**
- **受け持つ全プロジェクトに profile が要る。** 無いプロジェクトはホスト実行に落とす、
  という段が要る（落とした事実は残す・I2）
- **検証時間が伸びる。** マージキューは直列なので、上限の設計に効く
