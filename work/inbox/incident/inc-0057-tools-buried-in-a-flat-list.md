## 内容

**番頭に渡している道具が100個あり、その中に埋もれた道具は呼ばれない。**

inc-0056（思考が本文に漏れる）を追う過程で、症状の一部が**道具の数と位置**で
説明できることが分かった。同じ100個・同じ質問文で、必要な道具の位置だけを変えた実測:

| 必要な道具の位置 | 呼べた率 |
|---|---|
| 先頭 | **16/16** |
| 10・25・50番目 | 各 2/6 |
| 39番目（元の並び） | **0/10** |
| 末尾 | 2/10 |

**壊れた出力（DSML の漏れ）は、道具を見つけられなかった回に集中していた**
——先頭では漏れ 0/6、39番目では 5/10。**症状であって原因ではない。**

## 世の中の計測と一致する

10〜15個を超えると精度が落ち始め、約200個で 41〜83%、約740個で 0〜20%。
banto は **100個・53KB**。劣化が本格化する帯にいる。

## 使われ方（11,168回・85種類）

| ドメイン | 呼び出し | 道具の数 |
|---|---|---|
| worker | 6,796回（60.9%） | 9個 |
| file | 2,019回（18.1%） | 6個 |
| env | 459回（4.1%） | 12個 |
| kobo | 262回（2.3%） | 11個 |
| **llm** | **52回（0.5%）** | **19個** |

**上位25個で 93.5%。** `llm.*` は道具箱の19%を占めて使用0.5%。

**60.9% が `worker.*`** であることは、D10「番頭は細かい仕事をしない」を数字が
裏書きしている。にもかかわらず道具箱は細かい仕事の道具で埋まっていた。

## 直し方（[ADR-0018](../../docs/adr/adr-0018-tool-audience-and-deferred-disclosure.md)・accepted）

**道具に宛先を持たせる。** 既定は `worker`。`steward` はモジュールが**宣言**し、
banto 側の設定で**許可**されたときだけ入る（モジュール単位／道具ごとの2段）。

**番頭に持ってほしいものだけを載せる。遅延開示（探して呼ぶ機構）は持たない。**

## 遅延開示を作って捨てた（2026-08-12）

一度は `tool.search` / `tool.call` を実装したが、**2巡のレビューを経て捨てた**。
詳細は ADR-0018「採らなかった案」。要点だけ:

- 探し方の質は **1位 47%・上位5に 74%**（レビュー側が選んだ38件の問い合わせ）
- レビューで欠陥 **12件**（1巡目7件・2巡目5件）。**2巡目は「1巡目の直しが開けた穴」**
- **実機で一度も検証していない**まま、約400行＋試験25件を抱えることになっていた

**捨てた決め手は「救おうとしていた尾が、尾ではなかった」こと。** `llm.*` 19個は
「番頭がたまに必要とする道具」ではなく**設定画面に属する操作**で、宛先で振り分ければ
尾そのものが消える。足りないときは**委譲する**（D10）——47%で当たる検索より、
100%で届く委譲のほうが確実。

## 自分の測り方についての反省（残す）

1. **8件で「上位5に 7/8」と報告した。** 95%信頼区間は 53〜98% で、何も言えていない
2. **評価の題材（問い合わせ）を自分で選んでいた。** レビューが選び直すと 74% に下がった
3. **実データで見つけた欠陥を、合成データの試験で塞いだことにしていた**（2巡連続で同じ形）
4. **n=6 で「効いた」と見えたものが n=12 で溶けた**（`strict: true` のとき・inc-0056）

**少ない試行の「効いた」を疑う。自分の測り方を自分で検証しない。**

## 別に気づいたこと

### `worker.close` 49% の正体（**調べた。暴走ループだった**）

**5,479回のうち 5,045回が3セッションに集中**し、その中に**同一引数で832回連続**という
走りがある。実際に畳まれた職人は全期間で 508人。

原因は機構側——`packages/banto-worker-pool/src/pool.ts:1179-1181` が、畳み済みの職人に
対して**黙って成功を返す**（`if (worker.state === "closed") return;`）。呼び出し側
（`worker-tools.ts:213-219`）は戻り値を見ずに `畳みました` を返すので、モデルは
「効いていない」と読んで繰り返す。`turn-budget.ts:36-41` が別件で書いている教訓
（「空の結果は『何も無かった』と読まれ、もう一度確かめに来る」）と同じ形。

いまは `createTurnBudget()` の `DEFAULT_REPEAT_LIMIT = 3` が同一引数の4回目を断るので
この形は塞がっているが、**導入は 2026-08-11 で、暴走の9日後**。根本（成功を返すこと）は
直っていない。**別に起票する価値がある。**

**この数字を根拠に使ってはいけない。** ADR-0018 は「60.9% が `worker.*`＝D10 を数字が
裏書き」と書いていたが、差し引くと最大の実使用は `file.*`（24.7%）＝番頭が自分で
ファイルを読んでいる回数で、**D10 の裏書きではなく反証**である。

### 職人の `tools` 省略は 31.1%

imp-0018 の「確かめていないこと」の答え。起動 1,187回のうち **369回（31.1%）が
`tools` 省略＝ランタイム既定の全部持ち**（read/bash/edit/write/grep/find/ls）。
