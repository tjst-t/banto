## 何が起きているか

`npx playwright test tests/trunk-branch.spec.ts` が **9 件失敗**する。理由はすべて同じで、
`.u-open` のロケータが**要素2つに当たる** playwright の strict mode violation。

- 観測したのは職人（session 783a2f45、taskId mobile-no-autofocus）のホスト上の実行
- **変更前の HEAD でも同一の 9 件が同一のメッセージで落ちる**ことを、Room.tsx を一時的に戻して
  dist を作り直したうえで確かめている（＝今回の変更とは無関係）

## 実測で確かめ直した（2026-08-16・SHA `fc673a71` を固定して5回）

**この起票の「9件・strict mode violation」という記述は、いまも正確**だった。
数も理由も一致し、当たっている2要素は `file.browser を開く` と `file.viewer を開く` の
**ボタン2つ**で、5回とも同一メッセージ。**完全に決定的**（5/5）。

計測条件：ワークツリー `/home/ubuntu/worktrees/banto/browser-flake`、`npm ci` →
`npm run build:web` で dist を作り直し、`npx playwright test --workers=2`（retries 0）を5回。
出力は `/tmp/browser-flake/run-{1..5}.{txt,json}` と `analysis.txt`。

**ただし、この起票の「主語」がずれていた。**

| | この起票の記述 | 実測（5回） |
|---|---|---|
| trunk-branch.spec.ts の失敗 | 9件 | **11件**（run-5 のみ10件） |
| ブラウザ試験ぜんたいの失敗 | （書いていない） | **17件**（run-5 のみ16件）/ 152件中 |

差の内訳：

- **+2件は「入力欄の速さ」**（`trunk-branch.spec.ts:815 / :827` の `toBeLessThan(100)`）。
  これは strict mode とは別の原因（ホストの負荷で揺れるしきい値）なので **`inc-0078` へ分けた**。
  片方は5回中4回失敗・1回成功の**間欠**で、実測値は 116〜326ms とばらつく。
- **+6件は trunk-branch.spec.ts の外**（`chat-ux.spec.ts` 5件・`settings-scroll.spec.ts` 1件）。
  モデル選択まわりで要素が出ないもので、**`inc-0074` の系列**（あちらは4件と書いてあるが実測5件＋1件）。

つまり「**元から赤いのは9件**」という理解は**過小**だった。正しくは
**恒常赤16件＋間欠1件**で、そのうちこの起票が扱うのは **strict mode の9件**。

すべて `tests/trunk-branch.spec.ts`。

- `[task-0088/a11]` 帯の幅はつまんで変えられる — `.room--trunk .u-open` が2要素 → click 不能
- `[task-0088/a11]` 面を開くと会話が細い帯として残り、話しかけられる — 同上
- `[task-0088/a12]` 幹から開いた面は枝を閉じ、枝から開いた面は枝を残す — 同上

## 見分けはついた（画面の退行ではなく、試験の絞り方が甘い）

当たっている2つは `file.browser を開く` / `file.viewer を開く` で、**どちらも出て当然のもの**。
＝ 画面の退行ではなく**ロケータが緩い**。

裏づけ：同じファイルの `:809` と `:822` は
`page.locator(".room--trunk .u-open", { hasText: "契約マッピングを読む" })` と**既に絞ってあり、
この2件は strict violation を起こしていない**。**直す形は同じファイルの中に既にある。**

## なぜ放置できないか

ブラウザ試験の一群が**恒常的に赤い**ので、画面を直すたびに「元から落ちているのか、自分が
壊したのか」を毎回切り分ける羽目になる。実際この枝でも切り分けに一往復を使った。
間欠ではなく決定的な失敗なので、直せば緑に戻る。

**さらに悪いことに、この赤は誰の目にも入らない。** マージ前ゲートの器
（`docker/Dockerfile.test` = node:24-alpine）には**ブラウザが入っておらず、導入初日から一度も
入っていない**ので、ブラウザ試験は**工場では1件も走らない**（`imp-0068`）。
つまりこの17件は「赤いまま放置されている」のではなく、**そもそも誰も見ていない**。

## 直し（未着手）

9件のロケータを `:809` / `:822` と同じ形（`hasText` で意図を名指しする）に絞る。**画面は触らない。**

**ただし、この直しは工場の機械検査では確かめられない**（器にブラウザが無いため）。
`imp-0068` の決着が要る——さもなければ「ホストで回した出力を報告に貼る」以上の証明ができない。
