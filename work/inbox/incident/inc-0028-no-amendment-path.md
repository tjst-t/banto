## 内容

**取り込み済みのタスクは、定義ファイルを書き換えても更新されない。** `task-watcher.ts` は既存タスクを見つけると mtime だけ記録して読み飛ばす。

```ts
const existing = this.daemon.getTask(projectId, fm.id);
if (existing) { projectStates.set(filePath, { mtimeMs, ingested: true }); return; }
```

これは**砦として正しく効いている**——番頭は `work/tasks/*.md` を書けるので（決定38）、後から `scope.paths` を広げてマージ前ゲートの検査を緩められては困る。ADR-0013 決定62c はこの性質に依拠している。

**しかし裏返しとして、正当な訂正もできない。** PO が「やっぱりここも直して」と言ったとき、いま表現する手段が無い。

## なぜ問題か

タスクを積む主体が番頭になると（ADR-0013 決定58）、**会話の中で要件が変わるのが普通の出来事になる**。訂正経路が無いと、番頭は「ファイルを書き換えたのに何も起きない」という**黙って失敗する経路**を踏む（I2 に反する）。

## 判断待ち（ADR-0013 の未決事項）

- **(a) 訂正は新しいタスクを積み、元を `superseded` にする（番頭の推し）**
  - `superseded`（escalate による置換）は既に状態機械の横断遷移として存在する
  - 着手後に契約が変わると「何に対して監査したのか」が曖昧になるため、置換として扱う方が帳簿の意味が保たれる
- **(b) `queued` / `ready` の間だけ再取り込みを許す**
  - 着手前なら契約を変えてよい、という考え方
  - ただし「着手直前に広げる」が可能なので、砦としては (a) より緩い

いずれを採るにせよ、**書き換えても何も起きないことが分かる**必要がある（ファイルの変更を検知したが取り込み済みだった、という事実をイベントに残す）。
