# 既定を自動着地へ反転すると、受け入れ試験が3回に1回ほど落ちる（毎回別の試験）

## 起きたこと

realign 第3便で `review.policy` の既定を `banto` → `auto` へ反転したところ、
**全量 `npm test` が3回に1回ほど落ちるようになった。落ちる試験は毎回違う。**

第3便で足した試験そのものは一度も落ちていない。落ちるのは**元からある、時間に依存した
試験**の方で、これまでに5種類が観測された。

| 落ちた試験 | 症状 |
|---|---|
| `audit-checklist-assets` / CHECK-MARKER-42 が監査人に届く | `test did not finish before its parent and was cancelled` |
| `worker-child-process`（inc-0066）/ 親の pid から子の pid を突き止められる | 失敗（1.0s） |
| 監査のやり直し / 試行回数が数え直される | 時間切れ（10.4s） |
| `env-notices` / 台帳に無い実リソース（孤児）が出来事として残る | 失敗（0.6〜1.0s） |
| `merge-queue-derive` / deriveQueue が帳簿から待ち行列を導ける | 順序の主張が崩れる |

## 計測（P6：根拠は分類ではなく数）

同じホスト（稼働中の banto が同居）。`npm test` を回した回数と、**第3便と無関係な試験が
落ちた**回数。

| 対象 | 走行 | 落ちた |
|---|---|---|
| `main`（8b42dd7） | 3 | **0** |
| `main`（4a75ac2・現在） | 4 | **0** |
| 第3便まるごと | 10 | **5**（別々の試験が1回ずつ） |
| 第3便から**新設試験3ファイルだけ外す**（製品コードは入れたまま） | 2 | **2** |
| 第3便のまま、**`DEFAULT_REVIEW_STAGE` だけ `banto` へ戻す**（新設試験も外す） | 2 | **0** |

**最後の2行が切り分けである。** 試験ファイルを増やしたことは原因ではない（外しても落ちる）。
**既定の反転そのものが引き金**で、そこだけ戻すと落ちなくなる。

## なぜ反転すると落ちるのか

反転前、契約に検査を持つ試験用タスクは監査を通ると `review-ready` で**止まっていた**。
反転後は `auditing → merging` へ進むので、**マージキューが実際に動く**——rebase・
マージ前ゲート・検証環境の立ち上げ・子プロセスの起動が、既存の試験の裏で走るようになった。

つまり試験一式の**同時に動くものの量が増えた**。落ちた5本はいずれも

- 本物のデーモン・工房・環境プールを起こし、
- **固定の待ち時間**（400ms・1s・10s）で結果を待つ

形をしており、機械の取り分が減ると待ち切れずに落ちる。`merge-queue-derive` に至っては
**稼働中のデーモンを 400ms 待ってから覗き、その瞬間の並び順を主張している**ので、
裏でキューが動く量が増えれば当然に崩れる。

**これらの試験は「機械が空いている」ことを暗黙の前提にしている。** 前提が書かれていないので、
工場が本来の仕事をし始めただけで壊れる。P6 の言う「機構が壊れている合図」はここを指す
——落ちた試験の中身が悪いのではなく、**待ち方が負荷に対して無防備**である。

## やってはいけないこと

- 待ちを延ばす／リトライを足す（P6 が名指しで禁じている）
- 「まれに落ちる」で先へ進む
- **既定の反転を戻す**（PO 裁定 2026-08-14。試験の都合で製品の判断を曲げない）

## 考えられる直し方（未着手）

1. **待ちを時計から外す。** 固定の ms ではなく、起きるべき出来事（イベントの出現）を待つ。
   `merge-queue-derive` は「400ms 待って覗く」をやめ、**動いていない帳簿の写しに対して
   `deriveQueue` を回す**形にすれば、そもそも競らない（純関数の試験に live daemon は要らない）
2. **重い試験を直列に寄せる。** 本物のデーモンを起こす試験を `--test-concurrency=1` の
   別プロファイルに分ける（e2e が既にこの形）
3. **同居している稼働中の banto を計測から外す。** ホストで回す限りノイズは消えない

## いま分かっていないこと

- 5本以外にも同じ前提を置いた試験があるか（数えていない）
- docker の使い捨てコンテナで回したときの再現率（番頭が回した1回では観測されていない）

## 直さない判断をした理由

realign 第3便のスコープ外（P1）。落ちる5本はいずれも `review.policy` とも
コンフリクト解消とも関係が無く、直すには待ち方の作り替えが要る。
**握り潰さないために起票する**（P6）。
