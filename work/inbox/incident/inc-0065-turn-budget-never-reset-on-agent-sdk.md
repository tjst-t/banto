# inc-0065 ターン予算が Agent SDK バックエンドで一度も数え直されず、人の指示ごと断られた

- 起票: 2026-08-13（番頭）
- 深刻度: 高（**安全装置が人の介入を殺した＝制御の反転**）
- 状態: 修正済み・未コミット（ブランチ `kobo-control-switches`）

## 起きたこと

`turn-budget.ts` は「1つのターンで道具を何回呼んだか」を数え、上限（当時60）を超えたら
例外で全部の道具を断る。新しい入力が来たら `reset()` で数え直す設計だった。

ところが実機で、PO が話しかけても数えが 61 → 62 と積み上がった。**番頭は人の新しい指示を
受け取っても何も呼べない**状態になり、残った出口は PO の手動 `kill -9` だけだった。

## なぜ起きたか

`turnBudget.reset()` を呼んでいたのは `bin.ts` の `countingSession`（`HostSession` の皮）
だけで、その皮は `new PiHarness({ session: countingSession })` にしか渡っていなかった。
`makeClaudeHarness()` は `assembleStewardContext` から**道具（`guardTurn` 済み）だけ**を
取って `ClaudeAgentHarness` を組むので、皮を一切通らない。

番頭のターンを回す入力は `server.ts` の `promptEvenWhileBusy()` → `thread.harness.prompt()`
の1点を通る。Agent SDK バックエンドではこの経路に `reset()` が無く、ターン予算は実体として
**セッション累積**になっていた。本番の既定がそちらだった。

## 直したこと（PO裁定 2026-08-13）

1. **数え直しをバックエンドの継ぎ目へ移した。** `withTurnBudgetReset(harness, budget)` で
   `BantoHarness` を包み、`piHarness` と `makeClaudeHarness()` の両方に掛ける。入力の出所
   （PO の発話・職人/工場の知らせ・言伝・枝への steer）に依らず全部 `prompt()` を通る。
2. **断り方を三段にした。** 60 で第一警告（結果は返す）、100 で第二警告（結果は返す）、
   **120 で初めて断る**。警告はその回数ちょうどで1回だけ添える。
   「同じ問いの繰り返し」（`DEFAULT_REPEAT_LIMIT = 3`）は据え置き——本物の暴走はこちらが
   捕まえる前提で、回数の側を緩めた。
3. 受け入れ試験に「**上限に当たった状態が、次の入力で必ず解ける**」を両バックエンドの
   偽ハーネスで足した(再発検知)。

## 残っていること

- **もっと漏れない掛け方**: `threads.ts` の `Thread` constructor / `replaceHarness` で包めば、
  3つ目のバックエンドが増えても自動で掛かる。今回はスコープ外として見送った。
- **警告の頻度**: いまは 60・100 で1回ずつ。読み飛ばすと 120 まで気づかない可能性がある
  （「60 以降は 20 回おきに再掲」もあり得る）。PO の好み次第。
