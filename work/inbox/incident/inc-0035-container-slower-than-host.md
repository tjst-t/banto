## 内容

**「コンテナは2.3倍遅い」と報告したが、その数字は私の測り方が悪かった。**
クリーンに測り直すと **1.7倍**。

inc-0034 で 631秒（10分31秒）と記録したが、**その測定中に banto の全テスト
（3分）と Playwright（4.3分）を並走させていた**。4コアの機械で、測っている対象と
同じ CPU を奪っていた。

| | 時間 | 倍率 |
|---|---|---|
| ホスト（idle） | **250秒**（4分10秒） | 1.0 |
| コンテナ（**並走あり・誤り**） | 559秒 | 2.3 |
| コンテナ（**idle・正**） | **430秒**（7分10秒） | **1.7** |

**教訓**：性能を測るときは、測っている機械で他を走らせない。I1 は「自己申告を信じない」
だけでなく「**自分の測定条件も疑う**」を含む。

## 何が遅いのかの切り分け（マイクロベンチ・実測）

当初「bind mount の I/O」と仮説を立てたが、**外れていた**。

| | ホスト | コンテナ | 倍率 |
|---|---|---|---|
| CPU（2億回ループ） | 2943ms | 3072ms | **1.04** |
| プロセス起動（node ×30） | 901ms | 999ms | **1.11** |
| ファイル作成 ×800（**bind mount**） | 120ms | 123ms | **1.02** |
| ファイル作成 ×800（コンテナ自身の層） | 117ms | 193ms | **1.65** |
| `git init` ×15 | 84ms | 202ms | **2.4** |

**bind mount は遅くない。CPU もプロセス起動もほぼ同じ。** 効いているのは
**コンテナ自身の書き込み層（overlayfs）と git**。loamium の受け入れテストは
一時ディレクトリに vault を作って git を回すので、ここに当たる。

## 一時ディレクトリの置き先を変えると縮む（`settings-api.spec.ts` 単体）

| 置き先 | 時間 |
|---|---|
| ホスト（idle・参考） | 66秒 |
| `/tmp`（overlayfs・既定） | 127秒 |
| bind mount（`/app` 配下） | 106秒（**−17%**） |
| **tmpfs（`/dev/shm`）** | **97秒**（**−24%**） |

`/app` は `/dev/sda1` が直接見えており（bind mount）、`/` だけが overlay。

## いま急いで直す必要は無い（task-0080 の副産物）

`setup` を入れたので **`npm ci` は provision へ移った**。マージ前ゲートが回す検証
コマンドは `npm test` だけになり、**7分10秒**——**既定の10分に収まる**。

**ただし余裕は厚くない**：idle で 430秒/600秒（28%）、機械が混んでいるときは
559秒（7%）まで詰まった。**縮めたくなったら tmpfs が第一候補**
（compose に `tmpfs: [/tmp]` を足すだけ。ただし RAM は7GBなので上限を切ること）。

**既定の10分を延ばす案は採らない**——inc-0031 の教訓（待ち時間を延ばす直しは
症状を隠すだけ）。
