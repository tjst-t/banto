# 終わったタスクの保持期間 — 提案

PO の問い「終わったタスクは消えず、100件を超えると動いているタスクを押し出す。
**何をいつ捨てるか**」への提案。

## いま起きていること（実測）

| | 状態 |
|---|---|
| ローテーション（月次/サイズでセグメントを切る） | **あり** |
| スナップショット（切替時に導出済み状態をダンプ） | **あり** |
| ロールアップ（spec-daemon-core §2.3 の3） | **無い** |
| アーカイブ・保持期間による削除（§2.3 の4） | **無い** |

実機はまだ小さい（`events/2026-08.jsonl` が 52KB・102件）。**いま困っているのは
容量ではなく場所の取り合い**——`kobo.list` の既定100件を終わったタスクが埋める。

## いちばん大事な区別

**3つが混ざっている。分けると、捨て方がそれぞれ違う。**

| | 何か | 捨ててよいか |
|---|---|---|
| **イベントログ** | 監査の記録。追記専用 | **番頭の判断では捨てない。** 自分の監査記録を編集させるのと同じ（I1・spec-environment §5 が台帳について同じ線を引いている）。期間で機械的に刈るのは可 |
| **導出済み状態（スナップショット）** | ログから作り直せる作業用の表 | **捨ててよい。** D3「導出できる値は保存しない」。ここが無限に育つのは設計の意図ではない |
| **画面に出すもの** | 見え方 | 捨てる話ではなく**既定の絞り込み**の話 |

**PO が困っているのは3番目**で、いま2番目が無限に育っている。1番目はまだ困っていない。
**この順で手当てするのを勧めます。**

## 提案（3段。上から順に、効果が大きく risk が小さい）

### 第1段：画面と `kobo.list` の既定を「動いているもの」にする（推奨・すぐ）

終端状態（`closed` / `merged` / `failed` / `superseded`）を**既定で外す**。
「終わったもの」は明示的に指定したときだけ出す。

- **何も捨てない。** 見え方だけ変える。可逆
- 100件の枠を動いているタスクが使えるようになる——**PO の困りごとはここでほぼ解決する**
- 札の `12 / 340 件`（task-0078）は残す。**隠したことを黙らせない**
- D5：判断を Surface に置かない。既定は Kobo 側（`kobo.list` の既定引数）で持ち、
  GUI/CLI は同じ既定を見る

### 第2段：古い終端タスクを「畳む」（fold）——記録は残し、作業用の表から降ろす

終端に着いてから**保持期間**を過ぎたタスクは、スナップショットから**要約1行に畳む**：

```
id / title / 終端状態 / 着いた時刻 / 最終コミット / イベント範囲(from..to)
```

- **イベントログは1バイトも消さない。** 畳むのは導出済み状態だけ。全履歴が要るときは
  イベント範囲からリプレイして戻せる
- スナップショットの大きさが**動いているタスク＋要約**で有界になる（§2.3 の「有界」の意図）
- 走らせる場所は**セグメント切替（ローテーション）と同じ tick**。新しいループを作らない
- 期間は層B（`meta/config.yaml`）。**既定案：終端から30日、ただし直近50件は期間に
  関わらず畳まない**——静かな月に board が空になるのを防ぐ

### 第3段：セグメントのアーカイブと削除（§2.3 の 3・4・いちばん後）

- 閉じたセグメントを zstd で固める
- 保持期間（**既定案：生ログ1年**）を過ぎたら削除。
  **例外：open なタスクが参照するイベントを含むセグメントは対象外**（spec の記述どおり）
- ロールアップ（統計の抽出）は**改善ループが動き出してから**。いま作っても読む人が居ない
  ——spec も「v1では不要」と書いている

## 勧める線

**第1段だけ先に入れる。** 実機は 52KB / 102件で、第2段・第3段は**まだ要らない**
（容量で困っていないうちに畳む機構を入れると、動かないまま腐る）。

第2段の引き金は「スナップショットが重くて起動が遅い」と**実測で言えたとき**。
数字を決め打ちで先に入れない——TTL の既定を spec を見ずに4時間にして番頭に
指摘された件（limits.ts のコメント）と同じ失敗の形になります。

## 決めていただきたいこと

1. **第1段を入れてよいか**（既定を「動いているもの」に。何も捨てない）
2. 第2段・第3段は**実測で困ってから**でよいか。それとも先に入れるか
3. 第2段を入れるなら**保持期間の既定**（案：終端から30日／直近50件は残す）
