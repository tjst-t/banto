# マージキューの弁（`kobo.set_merge_queue`）を握るときに、先に知っておくこと

2026-08-16、枝「緑が信用できない」が `task-0197` を工場の外で着地させるために弁を握った。
**握る前にコードを読んで確かめたことと、握ってみて分かったこと**を残す。
**次に誰かが弁を握るとき、同じ10分と同じ17分を使わずに済むように。**

---

## 1. 閉じても、走行中のマージは宙に浮かない（**コードで確認**）

握る前にいちばん怖かったのは「いま merging のタスクが、閉じた瞬間に宙に浮くのではないか」だった。
**浮かない。**

```ts
// packages/banto-daemon/src/merge-queue.ts:278
export async function processMergeQueue(log, opts) {
  const allEvents = log.readAllEvents();
  // 弁が閉じているプロジェクトは**待ち行列から外す**（inc-0063 の非常停止）。
  const queue = deriveQueue(allEvents).filter(
    (entry) => opts.isProjectEnabled?.(entry.projectTag) ?? true    // :287
  );
```

- **弁は `processMergeQueue` の入口で1回だけ見られる。** 中では見直されない
- 閉じているプロジェクトは**先頭を飛ばすのではなく、待ち行列から外す**
  （閉じたプロジェクトのタスクが頭に居座って、**他のプロジェクトのマージまで止める**のを避けるため）
- tick 側（`daemon.ts:4218` 付近）は **`_mergeQueueRunning` で再入を防ぐ**ので、
  前の呼び出しがゲートを回している最中（30分かかることもある）なら、**新しい tick は丸ごと飛ばされる**

**したがって**：merging の最中に閉じても、**その1本は最後まで走り切って ff まで行き**
（＝**main が最後にもう一度動く可能性がある**）、**次の tick から新しいマージが始まらない**。

**「merging が空になる瞬間を張って待つ」必要はない。** 閉じてから、走行中の1本が終わるのを待てばよい。

## 2. **弁は工場しか止めない。人は止まらない**（実測）

閉じた直後、main は動いた。

```
4aa19006 → d4ac13db  docs(work): prop-0003 に…追記する
```

**弁が止めるのは Kobo のマージキューだけ**で、**番頭・職人・人が打つ直接コミットは素通りする**。
`work/inbox/**` への記録コミットは日常的に打たれるので、**閉じただけで「main が凍った」と思ってはいけない。**

**静粛を作るには、弁（機構）＋依頼（人）の両方が要る。**

## 3. **弁を閉じる者は、開ける段取りを同じターンの中に持つこと**（実測。**いちばん高くついた**）

2026-08-16、弁を閉じた枝が**そのターンを終えたところで止まり、工場が17分完全に凍った**
（queued 27本・implementing 0本）。**閉じた本人が止まったのが原因である。**

**枝も幹も、知らせが来ないと目を覚まさない。**
つまり **閉じたターンの終わりに「次に自分を起こすもの」（走っている職人・待っている検証）が
1つも無ければ、工場は止まったまま誰も気づかない。**

**握るときの作法：**

1. 閉じる前に、**開けるまでの段取りを全部書き出す**（この会話に書けばよい）
2. **各段の終わりに、必ず自分を起こすものを走らせておく**（職人の報告はターンを起こす）
3. **それが作れない段が来たら、そこで開ける。** 途中でも開ける
4. **落ちても開ける。** 検証が赤でも、**まず開けてから**報告する

## 4. 閉じ方・開け方

```
kobo.set_merge_queue({ projectTag: "banto", enabled: false, reason: "…（帳簿と一覧に残る）" })
kobo.set_merge_queue({ projectTag: "banto", enabled: true,  reason: "…" })
```

- **プロジェクト単位**。他のプロジェクトのマージは止まらない
- **設定は保存され、Kobo を再起動しても残る**——**再起動すれば開く、ではない**。閉じたら自分で開けること
- いまの状態は `kobo.projects` で読める
- 止まるのは：rebase・マージ前ゲート・マージ・**コンフリクト解消タスクの自動起票**・paused からの自動再開

## 5. 何のために握ったか（この日の記録）

`task-0197`（ゲート中に main が進んでも着地する）を工場の外で着地させるため。
**その直しが要ることの証明を、直しを運ぶ過程が自分でやってしまった**：

- 最終的に `3338ee7d` で着地
