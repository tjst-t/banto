## 目的

Kobo（独立プロセス、`packages/banto-daemon`）を Banto に配線し、**「番頭に頼んでタスクを積むと、Kobo が職人を使って自動でさばき、判断だけが会話に返ってくる」**状態を作る。

**Kobo のコンセプトは変えない**（ADR-0013 決定56）。状態機械・依存ゲート・監査の差配・直列マージ・マージ前ゲートはそのまま残す。足りないのは入口（番頭から積む）・出口（POへ判断を出す）・面（見る画面）と、独自台帳の後始末である。

## 段取り（ADR-0013）

本 epic は4段で進める。**掃除を先にする**——レビューの経路（2段目・3段目）が当たる場所は `_autoProvisionOnReview`＝env コードの真ん中であり、掃除より先に配線すると同じ場所を二度書くことになる。

| 段 | 中身 | 受け入れ |
|---|---|---|
| **1. 掃除** | モジュールがあるものは Kobo 独自を使わない（決定60・61）。task-0058〜0061 | `tests/e2e/pipeline-merge.e2e.spec.ts` が通る |
| **2. 入口と出口** | Kobo をモジュール登録＋`kobo.*`／`origin` と起点参照／番頭への知らせ／`review.policy` 3値（決定57・58） | 会話から積み、会話にレビュー待ちが返り、承認するとマージされる |
| **3. 触れる環境** | `in-review` で Environment Pool が環境を立て、公開URLを判断待ちに添える（決定59） | UI 変更のタスクで、POが札からブラウザ面を開いて触れる |
| **4. 面** | ボード（状態機械のビューア）とレビュー面（DIFF＋承認＋環境リンク） | キャンバスから開ける |

**2段目以降のタスクは、1段目の完了時に起票する**（D10：一度に全部計画しない）。

**1段目・2段目とも完了した**（2026-08-06）。

- 1段目（掃除）: task-0058・0059・0060・0061
- 2段目（入口と出口）: task-0048（読む側）・**task-0064**（入口）・**task-0065**（出口）
  ＋ PO 裁定から生まれた task-0062（訂正経路・決定64）・task-0063（費用の上限・決定67）

**これで「会話から積み、会話にレビュー待ちが返り、承認するとマージされる」が成立する**
（2段目の受け入れ）。残るのは3段目（触れる環境・決定59）と4段目（ボードとレビュー面）。
