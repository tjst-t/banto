## 目的

ADR-0010 決定36 より。**番頭が複数のリポジトリを相手にできるようにする。**

いま番頭は1つのルート（`BANTO_WORKSPACE` か cwd）しか見えない。一方 Kobo は複数プロジェクトを統治している（`spec-multi-project` §1）。PO の要件は「**1つの番頭スレッドで何でも話せること**」——リポジトリごとに会話場所が分かれるのは受け入れられない。

そのために2つを作る：

- **場所（Place）の共通契約**（`banto-core`）。「いま許されている作業場所の集合」を返すだけの極小の契約
- **repo-manager モジュール**。`ghq` / `gwq` が知る Git リポジトリとワークツリーを、状態を持たずに提供する実装

## ユースケース

- 番頭が「loamium の web-search-provider を見せて」と言われて読める（いまは banto の中しか読めない）
- 番頭が別リポジトリにワークツリーを切り、そこで職人を働かせられる
- Git 管理していない作業領域やホスト全体も、**明示的に登録すれば**扱える
- 番頭が登録されていない場所を指しても**弾かれる**（いま `worker.delegate` は無検査で、任意のディレクトリを職人に書き換えさせられる）

## スコープ外

- **Git の変更操作**（`repo.commit` / `push` / `branch.*` / `remote.*` / `tag.*`）。決定24（Git 閲覧系は閲覧専用）を覆す話で、別途の裁定が要る
- **番頭に「焦点」のようなスレッド状態を持たせること**（決定36f で却下済み）
- Kobo をサービス利用へ切り替える段（決定36h の2段目）
