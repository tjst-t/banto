## 背景
task-0268 の実装（main のコミット 91a15e9a / d2736906）で、監査ロールに当てるモデルを「道具呼び出し実証済み」の白リスト（daemon.ts の toolCallProvenModelNames()）で制限し、未実証のモデルが当たっていたら実証済みの標準モデル（PROVEN_AUDIT_FALLBACK_MODEL）へ読み替えて起こすようになった。現状の白リストは ["opus","sonnet","haiku","opencode-go/deepseek-v4-flash"]、読み替え先は "opencode-go/deepseek-v4-flash"。

PO 裁定（2026-08-17・取次 in-d2830460 承認済み）：「opencode の deepseek と Kimi 系は OK に使用」——監査ロールの実効モデルは opencode-go/kimi-k2.7-code に変更済み。opencode-go/deepseek-v4-flash は task-0268 の監査で2回 pass した実証済みモデルなので白リストに残す。kimi が白リストに無いと、daemon の読み替えが kimi を deepseek-v4-flash へ上書きしてしまう（実測：task-0268 の監査が deepseek-v4-flash で spawn されている）ため、kimi 系を白リストに追加して読み替えが起きないようにする。

このタスクは task-0271（旧契約：deepseek を外す）を PO 裁定により置き換えたもの（kobo.supersede）。旧実装 04af5af0（task/task-0271 ブランチ）は deepseek を外したほかは概ね正しいので、必要なら参考にできる。

## やること
1. packages/banto-daemon/src/daemon.ts の toolCallProvenModelNames() が返す配列を次の内容にする
   - "opencode-go/deepseek-v4-flash" は**残す**（実証済み）
   - Kimi 系を加える: "opencode-go/kimi-k2.5" / "opencode-go/kimi-k2.6" / "opencode-go/kimi-k2.7-code" / "opencode-go/kimi-k3"（監査で実証済みの kimi-k2.7-code を含む。同じ opencode-go プロバイダの kimi ファミリー）
   - 既存の "opus" / "sonnet" / "haiku" はそのまま残す（Claude Code 系）
2. 同じ daemon.ts の PROVEN_AUDIT_FALLBACK_MODEL 定数を "opencode-go/kimi-k2.7-code" へ変更し、コメントも読み替え先に合わせて更新する
3. tests/acceptance/kobo-worker-integration.spec.ts の [kobo-roles] 群で、実証済みモデルの具体例として名指しするモデルを、白リストに載っているモデル（"opencode-go/deepseek-v4-flash" か kimi 系のいずれか）で整合させる（モデルカタログ（selectableModelNames）に登録があって白リストにも載っているモデルを使うこと）。テストの意図（白リストに載っているモデルは通る／載っていないモデルは保存時に弾かれる／読み替えが働く／一覧が空なら黙って通す）は変えない
4. 動作確認:
   - npm run test:one tests/acceptance/kobo-worker-integration.spec.ts が全て pass
   - npm run typecheck が通る
   - 可能なら npm test 一式も通す（merge-queue-serial.spec.ts の既知フレーク・claude-quota.spec.ts の認証非依存化は main 側で対処済みのはず）
5. スコープ外（banto-web など）は触らない。変更はこのタスクのスコープ内パスのみ
