## 前提（段取り1は着地済み）

prop-0003（採用案C）の段取り2本目。**段取り1は `c518afb7` で main に入っている**ので、次の3つは**既に在る**。まずこれを読むこと。

- `packages/banto-host/src/backlog.ts` — `BacklogEntry` / `BacklogStatus`(open|tasked|dropped|done) / `BacklogFileInput` / `BacklogPatch` / `BacklogQuery`(status/kind/projectTag) / `BacklogStore` / `BacklogAdoptInput` / `BacklogCapabilities`
- `packages/banto-host/src/backlog-store-file.ts` — `FileBacklogStore`（`{ logFile, markdownDir? }` を受ける。jsonl 追記＋起動時読み直し、md 書き出し）
- `tests/acceptance/backlog-store.spec.ts` — その受け入れ試験

**この仕事では Store の中身を作り直さない。** 既に在るものを**番頭の手に届く口**にするだけ。

## なぜ要るか

いま banto の起票は `work/inbox/**` の md だけで、**それを読むコードはゼロ**。誰も読まないので壊れても誰も困らず、status は10種に分裂し、id は衝突し、決着済みの31%はどの task になったか辿れない。段取り1で「壊れない置き場」は作った。**しかし置き場に道具が無ければ、番頭は今までどおり md を手で書く**——だから道具を配るところまでが1組。

## やること

### 1. `packages/banto-host/src/backlog-tools.ts` を新設する

**`packages/banto-host/src/inbox-tools.ts` に倣うこと**（`createInboxTools(inbox, options)` が Tool 定義の配列を返し、`bin.ts` がそれを展開している）。同じ形で `createBacklogTools(store, options)` を書く。

道具は3本。**説明文は日本語で、`inbox-tools.ts` と同じ調子（何をする口か・例・引数の埋め方）で書くこと。**

- **`backlog.file`** — 起票を1件立てる。入力は `BacklogFileInput` に沿う（`kind` / `title` / `body?` / `bodyPath?` / `status?` / `origin?` / `projectTag?` / `refs?` / `tasks?` / `clientKey?`）。
  **`id` を受ける項目を作らないこと**（型にも、道具のスキーマにも）。採番は Store の専権で、`FileBacklogStore` は実行時にも `id` が紛れ込めば例外にする。**この道具のスキーマでも同じく断ること**（黙って捨てない・I2）
- **`backlog.list`** — 一覧。絞り込みは `BacklogQuery` の3つ（`status` / `kind` / `projectTag`）だけ。**滞留日数のような導出できる値では絞らない**（呼び手が `createdAt` から出す・D3）。**読みはローカル索引から即答する**——ネットワークを待つ処理をここに書かない
- **`backlog.update`** — `id` と `BacklogPatch`。状態は4値の範囲でだけ動かせる。`id` / `clientKey` / `createdAt` は変えられない（Store が既に断る。道具でも断ること）

戻り値は**器に載せられる形**にすること（他の道具と同じく、行の配列を1つ持つ形が読みやすい）。

### 2. `bin.ts` へ配線する

- `FileBacklogStore` を1つ作る。**真実の置き場は `path.join(dataDir(), "backlog.jsonl")`**（取次が `path.join(dataDir(), "inbox.jsonl")` を使っているのと同じ隣）
- `markdownDir` は **banto リポジトリの `work/backlog`** を渡す（記録として git で読める道を残すため）。**リポジトリの場所がホストの設定から解決できないときは `markdownDir` を省略して md を書かないこと**——決め打ちの絶対パスを埋め込まない
- `createInboxTools(...)` を展開している所（`bin.ts` の 1143 行目あたり）に倣って `...createBacklogTools(store)` を足す
- `packages/banto-host/src/index.ts` から `createBacklogTools` を export する（`createInboxTools` がそうなっている）

### 3. **モデルに届く一覧にも載せる（ここが罠）**

**`bin.ts` に足しただけでは、道具はモデルに届きません。** 実際にモデルへ提示される一覧は
`packages/banto-host/src/presented-tools.ts` 側で選ばれていて（`"inbox.post"` がそこに名前で載っている：210行目付近）、**`bin.ts` の配列は逆引き用の写し**です。**両方に載せること。**

これは実際に踏まれた罠なので、**受け入れ条件 a5 で機械が見ます**——「presented-tools の選択を通したときに `backlog.file` / `backlog.list` / `backlog.update` の3つが出てくる」ことを試験で確かめること。既存の `tests/acceptance/banto-presented-tools.spec.ts` に書き方の前例があります。
