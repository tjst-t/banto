## 背景
task-0268 の実装（main のコミット 91a15e9a / d2736906）で、監査ロールに当てるモデルを「道具呼び出し実証済み」の白リスト（daemon.ts の toolCallProvenModelNames()）で制限し、未実証のモデルが当たっていたら実証済みの標準モデル（PROVEN_AUDIT_FALLBACK_MODEL）へ読み替えて起こすようになった。現状の白リストは ["opus","sonnet","haiku","opencode-go/deepseek-v4-flash"]、読み替え先は "opencode-go/deepseek-v4-flash"。

PO 指示（2026-08-17）：「監査モデルは opencode-go/deepseek-v4-flash 外して、Kimi系を入れておきましょう」。
監査ロールの実効モデルは PO により opencode-go/kimi-k2.7-code に変更済み。しかし kimi は白リストに無いため、daemon の読み替えが kimi を deepseek-v4-flash へ上書きしてしまう（実測：task-0268 の監査が deepseek-v4-flash で spawn されている）。これを解消する。

## やること
1. packages/banto-daemon/src/daemon.ts の toolCallProvenModelNames() が返す配列を次の内容にする
   - "opencode-go/deepseek-v4-flash" を外す
   - Kimi 系を加える: "opencode-go/kimi-k2.5" / "opencode-go/kimi-k2.6" / "opencode-go/kimi-k2.7-code" / "opencode-go/kimi-k3"（監査で実証済みの kimi-k2.7-code を含む。同じ opencode-go プロバイダの kimi ファミリー）
   - 既存の "opus" / "sonnet" / "haiku" はそのまま残す（Claude Code 系）
2. 同じ daemon.ts の PROVEN_AUDIT_FALLBACK_MODEL 定数を "opencode-go/kimi-k2.7-code" へ変更し、コメントも新しい読み替え先に合わせて更新する
3. tests/acceptance/kobo-worker-integration.spec.ts の [kobo-roles] 群で、実証済みモデルの具体例として "opencode-go/deepseek-v4-flash" を名指ししている箇所があれば "opencode-go/kimi-k2.7-code" に読み替える。テストの意図（白リストに載っているモデルは通る／載っていないモデルは保存時に弾かれる／読み替えが働く／一覧が空なら黙って通す）は変えない
4. 動作確認:
   - npm run test:one tests/acceptance/kobo-worker-integration.spec.ts が全て pass
   - npm run typecheck が通る
   - 可能なら npm test 一式も通す（merge-queue-serial.spec.ts の既知フレーク・claude-quota.spec.ts の認証非依存化は main 側で対処済みのはず）
5. スコープ外（banto-web など）は触らない。変更はこのタスクのスコープ内パスのみ
