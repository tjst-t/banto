## 背景

2026-08-16、inc-0075（幹の記録が33時間ぶん失われた事故）の調査の中で、**章畳みが12時間以上0本**という状態を切り分けるのに手間取った。

原因は**設計の穴**である。`chapters.ts` は**章畳みに失敗したときだけ `console.error` を出す**（現物の `:175` と `:283`）。
成功のログも、**畳まなかったときのログも無い**。したがって外から見たとき、

- **試行して失敗した**のか
- **そもそも試行していない**（`shouldClose()` が false で早期 return した）のか

**区別が付かない。** 今回はこれを切り分けるために、`git log` でコミット時刻を割り出し、systemd の再起動時刻と突き合わせ、
SDK のセッションファイルから実際の文脈長を数える、という遠回りが必要だった。

**失敗したときだけログが出る設計は、静かに止まる事故を隠す。** 今日はそれで33時間を失っている。

## 分かっていること（この仕事の前提）

- `shouldClose()`（現物の `:208`）は `tokens >= window * thresholdRatio`（既定 **0.6**）
- 文脈長の計測を直したコミット `44616415`「fix(host): 文脈長はハーネスに訊く」（2026-08-15 11:31 UTC・反映は 12:59 の再起動から）以降、**全スレッドで章が1本も畳めていない**
- そのときの thread-61 の文脈は実測**約 296,000〜298,000 / 窓 1,000,000 ＝ 約 0.30**。**閾値 0.6 の半分**
- **これは壊れているのではない。** 以前は計測が最大9.7倍に膨れていて畳みすぎていた（1割しか使っていない時点で畳んでいた）。
  正確になった結果、正しく「まだ畳む時期ではない」と判断している

## やること

### 1. 「畳まなかったこと」を外から読めるようにする

`shouldClose()` の判定を、**畳まなかったときも含めて**外から読めるようにする。少なくとも次が分かること：

- **判定したか**（そもそも判定まで来ているか）
- **いまの文脈長 / 窓 / 閾値**
- **畳むと判断したか**

**毎ターン出してログを埋めないこと。** 間引く・値が動いたときだけ出す・一定間隔で出すなど、**やり方は実装者の判断でよい**。
ただし「畳めていない状態が続いていること」が、**あとから journal を読んで分かる**こと。

### 2. 長く畳めていないことに気づけるようにする

**「誰かが見に行かないと分からない」形にしないこと。** 気づき方（取次へ知らせる／警告ログ／別の手）は実装者の判断でよいが、
**なぜその形にしたかをコードのコメントに書くこと**。

判断の材料：今回は**12時間以上0本**が誰にも気づかれなかった。一方で、**畳まないこと自体は異常ではない**（文脈が伸びていなければ畳む必要は無い）。
**「畳めていない」ではなく「畳むべきなのに畳めていない」を見分けられる形が望ましい**が、そこまで作り込めないなら、まずは前者でもよい。
**過検知でうるさくするより、静かに止まることを防ぐのが目的。**

### 3. 試験で固定する

畳むとき・畳まないときの**両方**で、判定の結果が外から取れることを固定する。
`tests/acceptance/chapters.spec.ts` が既にあり、`ChapterKeeper` に偽の `summarize` を渡して機構だけを検証する形になっているので、
**それを流用する**（既存の試験は消さない・書き換えない。足すだけ）。

## 閾値（0.6）の見直しについて — **この仕事ではやらない**

幹の裁定で**保留**になっている。理由：

- **PO は「早すぎる畳み」で実害を受けた側**である（過大評価による不要な畳み）。正確な計測になったいま、
  **遅めに倒れているのは望ましい方向**で、急いで下げる理由が無い
- ただし**「畳めないまま伸び続ける」も別の事故を呼ぶ**ので、**この仕事（観測点）が入って実データが見えるようになってから、数字を見て決める**

**だから、この仕事の結論に「閾値を見直すなら、どの数字を見ればよいか」を書き残すこと。**
具体的には、コードのコメントに「この値をこう見れば判断できる」と書くこと。
後で数字を見て決める人が、また同じ調査をやり直さずに済むように。

## やらないこと（スコープ外。触ったらマージ前ゲートで落ちる）

- **章畳みの挙動そのものの変更**——変えるのは「外から見えるか」だけ

- `threads.ts` / `thread-store.ts` / `bin.ts` の変更（**同じ夜に別のタスクが触っている**）
