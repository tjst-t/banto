## 直す対象（2026-08-16・SHA `fc673a71` を固定し、変更なしで5回測った実測）

`tests/trunk-branch.spec.ts` は **11件が恒常的に赤い**（run-5 のみ10件）。原因は2つ。

### A. `.u-open` の strict mode violation — 9件（5/5 で決定的）

`.u-open` のロケータが**要素2つに当たる**。当たっているのは
`file.browser を開く` と `file.viewer を開く` のボタンで、**どちらも出て当然のもの**。
＝ **画面の退行ではなく、試験の絞り方が緩い。**

**直す形は同じファイルの中に既にある**——`:809` と `:822` は
`page.locator(".room--trunk .u-open", { hasText: "契約マッピングを読む" })` と絞ってあり、
**この2件だけは strict violation を起こしていない**。同じ形にすればよい。

対象（すべて `.u-open` の無修飾ロケータ）: `:509` / `:534` / `:540` / `:579` / `:591` / `:608` /
`:618` / `:692` / `:730` / `:767`。**`:534` は `.room--trunk` 修飾も無い**ので特に緩い。

**画面（`packages/banto-web/**`）は1行も触らないこと。** スコープにも入れていない。

### B. 打鍵の速さを固定しきい値で見ている — 2件（`:815` / `:827`）

`expect(perChar).toBeLessThan(100)`。実測はこうだった：

| 回 | :815（幹） | :827（枝） |
|---|---|---|
| run-1 | 326.4ms ✖ | 261.4ms ✖ |
| run-2 | 142.0ms ✖ | 242.0ms ✖ |
| run-3 | 190.8ms ✖ | 151.8ms ✖ |
| run-4 | 227.0ms ✖ | 116.0ms ✖ |
| run-5 | 100ms 未満 ✔ | 129.6ms ✖ |

**同じコミット・変更なしで、片方は4/5で落ちて1回だけ通った。** 理由は5回とも同一で、違うのは数値だけ。
このホストは**工場・職人・検証コンテナが同居**しているので、この試験は
**その瞬間に他の誰が何をしていたか**を測っているだけになっている。

**直し方（本筋）**：絶対時間をやめ、**同じ回の中で基準を取って比で見る**。
たとえば「面を開いていないときの打鍵」と「開いているときの打鍵」を同じ回で測り、
**比が一定倍を超えないこと**を見る。負荷は両方に等しく乗るので相殺される。
測りたかったのは「面を開くと遅くなる」ことであって、絶対値ではないはず。

**しきい値を 100 → 400 に緩めるだけの直しは採らない。** それは退行を検出できなくするだけ
（`inc-0078` に明記してある）。
