## 残っている本題：**置き場（cache）が空のまま「用意済み」の印が付く**

`1a93c875` を入れると `docker/Dockerfile.test` の中身が変わるので、置き場の鍵（`meta/environments.yaml` の `cache.key: [package-lock.json, docker/Dockerfile.test, docker/test.yaml]`）が変わり、**新しい空の置き場**が作られます。ここで壊れます。

### 前担当が実測した事実（これが出発点。疑うより先に再現すること）

- その結果、検証コマンドは a1 が「vite: not found」、a3 が「Cannot find package 'tsx'」で落ちた（＝root の node_modules が空だったときの症状）。

### 前提の訂正（重要・番頭の以前の指示は誤りでした）
以前「`banto-web` の vite など per-package の node_modules 小部屋が足りない」と指示しましたが、**これは誤りです。撤回済み。**
- いまの `package-lock.json` が per-package に作る node_modules は **`banto-host` と `banto-worker-pool` の2つだけ**。`vite` は root（`node_modules/vite`）に hoist されます。
- したがって `docker/test.yaml` の3部屋（root・pkg-banto-host・pkg-banto-worker-pool）は**既に全部を覆っています**。`tests/acceptance/env-cache-covers-nested-node-modules.spec.ts` が pass するのがその証拠。
- **小部屋を足さないでください。** そこは問題ではありません。

> `setup` が成功したときだけ `<cachePath>/.banto-primed` に印を書く（途中で死んだ半端な置き場を「入っている」と誤判定しないため）

### 進め方（**推測で直さない。まず再現して原因を1つに絞る**）
