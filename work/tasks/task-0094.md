## 背景

PO 裁定（2026-08-11・第0波 0-3）: Kobo の HTTP 面に PO 専用エンドポイントを追加する。

task-0090（職人ツール結果退避）と task-0091（閉じた枝の開き直し）が review-ready だが、
レビュー先が「po」になっており、PO が承認する経路がない。

現在の Kobo レビュー経路:
- review-ready → in-review（review_opened）→ approved（approved_by:po）→ merging
- ただし「po」による承認は番頭が `kobo.approve` を呼ぶことで実現している
- PO 自身がブラウザから承認する口がない

## やること

1. `packages/banto-daemon/src/http-server.ts` または `packages/banto-daemon/src/kobo-module.ts` に
   PO 専用エンドポイントを追加
2. エンドポイント設計:
   - `POST /api/kobo/projects/:projectTag/tasks/:taskId/approve`
   - 認証: PO 専用トークンまたは既存の認証方式
   - ボディ: `note?: string`（承認コメント）
   - レスポンス: `{ success: true, state: "approved" }`
3. エンドポイントは Kobo の review-ready タスクに対してのみ有効
4. 実装後、Web GUI（packages/banto-web）から呼び出せるようにする——ただし Web の変更はスコープ外とし、
   API 面だけを先に実装。Web 側は別 task 化してもよい
