## 背景（前提を全部ここに書く。あなたは記憶を持たない）

2026-08-16、`banto-env-*` の docker ネットワークが **27本**溜まってアドレスプールが枯渇し、
**工場のマージ前ゲートが検証環境を立てられずに全部落ちた**。

```
docker compose up failed: Error response from daemon:
  all predefined address pools have been fully subnetted
```

**それなのに、孤児検出は「0件」と答えた。** `env.list` の `orphans` は空、
`env.teardown_orphan` に名指しで頼んでも

```
孤児 "env-5bdd2526dc" は見つかりません（照合し直した結果）。いまの孤児: (なし)
```

と断られ、**機構の正しい口からは1件も畳めなかった**。人が docker を手で叩いて数える羽目になった。
実測は `work/inbox/incident/inc-0083-orphan-detection-does-not-see-docker.md` に全部載っている。**先に読むこと。**

## 原因（特定済み。ここから始めてよい）

`packages/banto-environment-pool/src/docker-driver.ts` の `handleList`（1515行目付近）が、

> 記録（STATE_FILE）と実在（`docker compose ls`）の**積**を返す

という作りになっている。`readOwned()` に無い名前は落とされる。

一方 `pool.ts` の `reconcile()`（665行目付近）は、**ドライバの `list` が返したものだけ**を台帳と突き合わせて孤児と呼ぶ。

**したがって「記録に載らずに立ったもの」は、原理的に永久に孤児にならない。**
今回残っていた23件は、**受け入れ試験が自前で compose を起こしたもの**で、最初から記録の管轄外だった。
**いちばん危ない取り残しほど見つからない**、という構造になっている。

## いまの作りが安全側に倒れている理由（**壊さないこと**）

`handleList` のコメントにある通り、以前は `docker compose ls` の全件から
**名前が `-docker` で終わるもの**を自分のものと見なしていた。これは所有の**推測**で、
**無関係な `myapp-docker` を孤児として挙げた実測がある**。その反省で記録ベースに直された。

**その反省を捨てないこと。** 今回の直しは「推測に戻す」ではなく、
**推測の根拠を、当てにならない綴りから、banto 自身が付けた印へ変える**こと。

## やること

### 1. 走査の向きを反転させる

`docker compose ls` の全件を起点にし、**次のどちらかに当てはまるものを「banto のもの」と見なす**：

- プロジェクト名が **`banto-env-` で始まる**（banto が付けている接頭辞。他人のプロジェクトはこれを名乗らない）
- STATE_FILE に記録がある（従来通り）

そのうえで、**台帳（live な環境）に無いもの**を孤児として挙げる。

**`banto-env-` で始まらないものは絶対に孤児にしない。** 実際に、この機械の上には
`hiragana-vite`（PO が見ているアプリ）や `docker_default`（別リポジトリのテスト）が同居している。
これらを孤児として挙げたら、その時点で失敗である。

### 2. 名前の規約から外れたものも拾う

今回 `banto-env-dynport-a` / `banto-env-dynport-b` という、**env id を持たない**プロジェクトが残っていた
（受け入れ試験がプロジェクト名を直書きしていた）。接頭辞 `banto-env-` は満たすので、
**env id の形（`env-` + 16進）を必須にしないこと**。満たさないものも孤児として挙げる。

### 3. 見分けの材料を必ず添える

**孤児だからといって全部消してよいわけではない。** 挙げた各件に次を添える：

- **公開ポートの有無**（`docker ps` の Ports。空でない＝**誰かが画面を見ている可能性がある**）
- **作成時刻／稼働時間**（古いほど残骸の疑いが濃い）
- **由来の working_dir**（compose のラベル `com.docker.compose.project.working_dir`。どのワークツリーから立ったか）

今回、人がこの3点で **(a) 台帳にある / (b) 公開ポートを持つ＝要確認 / (c) それ以外＝残骸** に切り分けて、
**PO が見ているアプリを巻き込まずに**片付けられた。**機械が同じ材料を出せるようにする**のがこの仕事。

**一括で畳む口は作らないこと**（既存の判断を維持する。畳むのは名指しで1件ずつのまま）。

### 4. `env.teardown_orphan` の断り方を直す

いまは孤児一覧の中にしか名前が無いと「いまの孤児: (なし)」で行き止まりになる。
**実体を照合し直したうえで**、docker に在るなら「台帳にも孤児一覧にも無いが、実体は在る」と、
**何が起きているかが分かる形で**答える。

### 5. 枯渇する前に警報を出す

今回の敗因は「止まって初めて気づいた」こと。
`banto-env-*` のネットワーク本数を数え、**しきい値（既定20）を超えたら警告**を出す
（`env.list` の表示にも本数を載せる）。docker の既定プールは
`172.16.0.0/12`(size 16) と `192.168.0.0/16`(size 20) で、実測では **29本で枯渇した**。

## テストの書き方（**docker を叩かないこと**）

検証環境の中から docker には届かない（既知）。**判定のロジックを純関数に切り出して単体で検査する**こと。

`tests/acceptance/env-orphan-scan-from-docker.spec.ts` を新規作成し、
`docker compose ls` / `docker ps` の出力を**文字列の固定値として与えて**、
分類の結果（孤児かどうか・添えられた材料）を検査する。実際の docker には依存させない。

`npm test` は `env-docker-` で始まる spec を除外しているので、**この名前（`env-orphan-` 始まり）のままにすること**
——既定のテスト実行に含める意図でこの名前にしてある。
