## 背景（前提。あなたは記憶を持たないので、ここに書いてあることが全部）

banto ホスト（systemd unit `banto.service`、`packages/banto-host/src/bin.ts`）のプロセスが OOM killer に繰り返し殺されている（2026-08-15 だけで4回以上、同日12回再起動）。OOM 自体の原因は別途調査中で、このタスクでは扱わない。**このタスクは「落ちても記録が壊れない」ようにする側**である。

実際に被害が出ている。8/16 00:48:50、OOM 直後の読み戻しで
`[banto] thread-61 の記録に読めない行があります（その行は飛ばします）`
が1回出た。**壊れた行は黙って捨てられ、その直後の書き戻し（全文置換）で永久に消えた。**

### 確認済みの事実（番頭が現物のコードで確かめた。行番号は 2026-08-16 時点）

- `packages/banto-host/src/thread-store.ts:181` `replace()` が
  `fs.writeFileSync(this.transcriptPath(threadId), body.length > 0 ? \`${body}\n\` : "", "utf-8")`
  で**会話の記録を全文置換**している。tmp+rename も fsync も無い。
- 同 `:221` `writeIndex()` が `threads/index.json` を同じく全文置換している。索引が壊れると `readIndex()`（:203 付近）が throw して**ホストが起動しない**。
- `packages/banto-host/src/thread-store.ts:167` に `append()`（追記）が実装され、コメントに「1発話ごとに全文を書き直すと…途中で落ちたときに壊れる範囲も広がる」と書いてあるが、**呼び出し元がゼロ**。実際の保存経路は `replace()` だけ（`packages/banto-host/src/threads.ts:991` 付近）。
- `packages/banto-host/src/threads.ts:645` `SAVE_DELAY_MS = 400`。発話のたび 400ms ごとに O_TRUNC で開き直している。実物のサイズは幹 thread-61 が 2.91 MB、最大の thread-59 が 6.07 MB。**書いている最中に殺されると数MBが飛ぶ窓が、常時 400ms 間隔で開いている。**
- リポジトリ全体で `fsync` の呼び出しが1つも無い。

## やること

**`replace()` と `writeIndex()` の書き込みを原子的にする。それだけ。**

1. 原子的書き込みのヘルパを1つ作る。置き場は `packages/banto-core/src/atomic-write.ts` を推す（`packages/banto-host` から使う。層の規則は `tests/acceptance/banto-core-layering.spec.ts` を先に読んで、それに反しない置き場を選ぶこと。反するなら banto-host 側に置いてよいが、**理由を実装のコメントに1行残すこと**）。
2. 中身は **同じディレクトリに tmp ファイルを書く → fd に fsync → close → rename → 親ディレクトリを fsync**。`node:fs` だけで書く（**依存を足さないこと**）。tmp 名は衝突しない形にし、**失敗したら tmp を後片付けする**。
3. `thread-store.ts:181` と `:221` の `fs.writeFileSync(...)` をこのヘルパの呼び出しに差し替える。**それ以外の振る舞いは変えないこと**（記録の中身・形式・呼び出し順・`append()` を使うかどうかの設計変更には手を出さない。`append()` を活かす話は別件として意図的に外してある）。
4. 例外は握り潰さない（I2）。書けなかったら例外を投げる。**元ファイルが1バイトも変わっていないこと**が要点。

## やらないこと（スコープ外。触ったらマージ前ゲートで落ちる）

- 壊れた行の退避（`transcript()` の catch の中身）——**後続タスクで別に扱う**
- `append()` を使う形への設計変更、`SAVE_DELAY_MS` の変更
- `/var/lib/banto` 以下の実データへの書き込み・移動・削除。**いま PO の記録の復旧作業が走っている。実データに触らないこと**（テストは必ず一時ディレクトリを使う）
- 他の `writeFileSync`（settings-store / place-grants / artifacts など）の一括置き換え

## 完了の確かめ方

新しい受け入れテストを `tests/acceptance/thread-store-atomic-write.spec.ts` に置く。既存の `tests/acceptance/` の流儀（テストランナー・一時ディレクトリの作り方・後片付け）を先に読んで合わせること。
