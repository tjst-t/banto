Worker Pool の並行制御を「想定消費リソース」ベースに変える設計（work/reports/2026-08-17-worker-resource-based-concurrency.md・accepted）のタスク C。

pool.ts の reserveSlot() / isFull() を canStart() に拡張し、リソース判定を追加する。

- delegate() → reserveSlot() → isFull() の経路に、runtime を渡す
- ConcurrencySlot / starting Map に runtime を追加
- 現在実行中・起動中のスロットの想定消費を合計し、対象ランタイムの想定消費を加えた場合に空きリソースを超えるか判定
- BANTO_WORKER_AUDIT_RESERVED を「監査用予約リソース量（MiB）」に再解釈（既定は2席分＝約2400 MiB を検討）。executor の判定から予約分を差し引き、auditor は予約分を使える
- BANTO_WORKER_RESOURCE_BASED=0 でリソース判定を無効化

設計書の「3. 起動可否の判定ロジック」「5. 既存の枠との整合・後方互換」を参照。タスク A（0247）と B（0248）が前提。
