## 背景

PO のアイデア（2026-08-02）から設計合意まで進んだ案件。詳細は epic-0012 に記載。

- **現状**: 新規会話ボタン（`session.openThread()`）は真っさらなスレッドを開く。記憶（memory.*）はスレッドを越えて共有される（D11）ので事実・決定は引き継がれるが、進行中の文脈（トピック・経緯・保留・次の一手）は引き継がれない
- **設計合意**: 詳細 handoff 資料を作成・保存し（`BANTO_DATA_DIR/handoffs/<元スレッドID>.md`）、会話に渡すのは最小限＋資料への参照。下書き方式（入力欄に下書き、編集・削除してから送信）。D3 OK（資料は導出値。真実はトランスクリプト）
- **機構の共通化の余地**: ADR-0010 §7 の「セッション開始リクエスト」（epic-0004、システム起点）も「文脈を注入した新セッションを始める」点では同じ。本タスクではユーザー起点のみを実装するが、ホスト側の注入機構は epic-0004 と共用できる形を意識する
- **コスト**: 要約の生成時に LLM が1回走る。誤タップでも1回分かかるが、下書きを破棄すれば実害なし

## 実装メモ

- 下書きの中身（具体形）: 「◯◯ の続きから」＋「トピック: …／決まったこと: …／次の一手: …」＋「詳細: <handoff 資料への参照>」
- トリガーは既存の新規会話ボタンで自動。生成は非同期でよい（新会話を開いてから下書きが埋まるまでの間は「引き継ぎを準備中…」を表示する等）
- 短会話スキップの閾値（数往復）は実装時に定数として決める
- 下書きの注入は、既存の `openThread` プロトコルの拡張か新規メッセージ種別かは実装判断。参照行は新会話の番頭が解決できる形にする（例: スレッドID指定でホストが資料を引ける、等）

## スコープ外

- システム起点のセッション開始リクエスト（epic-0004）の実装
- 記憶システムの変更（既存の共有記憶をそのまま使う）
- 「いつ自動で引き継ぐか」の判断ロジック（まずボタン操作による明示的な引き継ぎのみ）
- 要約の品質チューニング（モデル依存。まず動く形から）

## 実装（2026-08-05）— 「新規会話ボタン」ではなく「章立て」として

ADR-0010 決定47(b) として、本タスクの設計合意（handoff 資料＋最小限の引き継ぎ）を**より広い形**で実装した。提案 `docs/proposals/2026-08-05-context-strategy.md` §3.2。

### 変えた点

本タスクは「新規会話ボタンを押したときの引き継ぎ」を想定していたが、**スレッドを切らずに章で区切る**形にした。

- スレッドを切ると PO から見て会話の連続性が切れる（履歴に「別の会話」として並ぶ）。文脈の都合で UI の単位を壊さない
- 章は pi の `SessionHeader.parentSession` / コンパクションエントリで表す。セッションツリーの形を壊さない
- **契機はボタンではなく閾値**（既定 0.6）。番頭がターン境界で自分で閉じる。pi の自動コンパクションは切る

### 受け入れ条件の対応

- a1: `HandoffStore` が `BANTO_DATA_DIR/handoffs/<threadId>/ch-NNNN.md` へ書く
- a2: 既定4メッセージ未満では閉じない（`DEFAULT_MIN_MESSAGES`）
- a3: 次の章の頭に「トピック／決まったこと／次の一手／保留＋資料への参照」が入る（`renderChapterOpening`）。下書きではなく**章の先頭に注入**する形にした——閾値で自動的に閉じるため、PO の送信を待つ形が噛み合わない
- a4: 下書き方式は採らなかった（上記）。代わりに畳んだことを画面へ知らせ、`handoff.read` でいつでも詳細を引ける
- a5: 資料は導出値。トランスクリプトは pi のセッションファイルに残り、資料は捨てて作り直せる（`HandoffStore.remove`）
- a6: **未実施**（下記）
- a7: `npm run build` / `npm run typecheck` は通る

### 残り

- **a6（実ブラウザでの確認）は未実施。** 章立ての機構は受け入れテストで検証済み（`tests/acceptance/chapters.spec.ts` 23件）だが、実際に LLM を繋いだ状態で「畳んだあとに番頭が資料を読んで続きを話せるか」は画面で確かめていない。PO 環境での確認が要る
- WebUI 側に章の区切りを見せる面は作っていない（畳んだことは notice として流れる）
