## 何が起きたか（実測。推測ではありません）

2026-08-16、task-0165 の職人（sessionId `f43ce1bf-2bd0-4648-9cfb-26df39937ff2`）のターンに、
**依頼元が送っていない「答え」が混ざりました。**詳細は `work/inbox/incident/inc-0081-worker-fabricated-an-answer-from-its-requester.md`。

- `worker.events` 全9件のうち、依頼元から届いた答え（`worker_answered`）は **1件だけ**——07:54:58Z の
  「判断：1（あなたは降りてください）」。
- 一方、**07:54:24Z の `worker_turn_ended` の `text` 末尾**に
  `user[依頼元より] 3で。相手は止めた（プロセスは落ちている）。続きを引き取ってくれ。…` が入っていた。**本物の答えより34秒早い。**
- 裏取り済みの結論：**モデルが依頼元の返事を捏造した。** セッション記録では、捏造は
  `role: "assistant"` ／ `content` が配列（`[{type:"text"}]`）の中にあり、職人自身の報告文と**地続きの1つのテキスト**。
  機構が実際に注入するもの（`session-log.ts:64-66` `transcript.user`）は **`role: "user"` ／ `content` が生の文字列**で、
  形が別物。`依頼元より` という語を作るコードは `packages/` 配下に **0件**。
  `pool.ts:1685` の `steer()` は必ず `worker_answered` を積むので、**帳簿に残らない注入経路は無い**。

## 直す方針（**主**）：答えを `ask` の tool result として返す

**捏造そのものはモデル側の挙動で止められません。**塞げるのは「**モデルが書ける場所に答えがある**」という構造の方です。

穴は3つあり、いずれも同じ1枚で塞がります。

1. `ask` の tool result が即返る（`worker-tools.ts:483-511` / `claude-agent/host.ts:250-269`）ので、
   **答えを待たずに続きを書ける**。「答えが来た体で書く」が成立する。
2. 本物の答えが**印の無い生テキスト**として入る（`claude-agent/host.ts:106-107` の `{role:"user", content: text}`）ので、
   文面には真贋を分ける手がかりが一つも無い。
3. `worker_turn_ended` は `waiting:true` を知っているのに、**誰にも知らせない**。

直す形：**`ask({blocking:true})` の tool result を、答えが届くまで返さない。**届いたらその本文を tool result として返す。
`worker.steer` 経由で来た文は、待っている質問があればその答えとして tool result に載せる
（経路はいまと同じ `pool.steer`。`worker_answered` もそのまま積む）。

- **モデルは tool result を書けない**（書けるのは assistant テキストと tool call だけ）。
  「答えは tool result からしか来ない」という不変条件が立てば、**捏造は構造的に不可能**になる。
- **答えが来るまでターンが終われない**（未解決の tool call がある限り SDK のターンは進まない）。
- **待ちが機構の状態になる**——`worker.list` の「質問待ち」が推測ではなく実体になる。

付随して決めること:

- **待ちの上限**（既定 30分程度。**職人の袋の寿命より短くすること**）。超えたら
  `「答えは届きませんでした」`と明示した tool result を返す（I2: 届いたつもりで消えない・黙って進まない）。
- **`blocking:false` の質問はいまどおり即返す**（知らせるだけなので待つ意味が無い）。
- **待っている間の `worker.steer` は答えとして扱う。**答えではない割り込み（方針変更）を区別したいなら
  user メッセージとしても流してよいが、**「答え」の意味は tool result 側だけが持つ**という線は崩さないこと。
- **安全網**：`worker_turn_ended` が `waiting:true` のまま終わったら起動元へ知らせる（番頭側の受け口は `packages/banto-host/src/worker-notice.ts`）。
  上の直しが入れば起きないはずの事象なので、**起きたら機構の壊れの合図**になる。

## 補：印（トークン）

**印は真贋の決め手にはなりません**——印は文脈に載るので、本物を1回見たモデルは同じ枠を複製できます。
したがって印は**主ではなく補**（記録と見分けの補助）として入れること。既存の受け入れ条件 a1〜a6 は残してあるので、
tool result 側（a7〜a11）を先に成立させたうえで、印の側も満たすこと。

1. 職人ごとに、起動時に**そのセッションだけの印**（推測できない値）を発行し、指示書に含める。
2. `worker.steer` と質問への回答で届く本文には、機構が必ずその印を付ける。
3. **照合に失敗しても本物の答えは届くこと**（握り潰さず、記録して続行）。
4. 職人の出力に印の無い自称指示（`依頼元より` 等）が現れたら、**帳簿に残す**（止めるところまでは求めない）。
5. 印の値そのものが帳簿や画面に平文で出続けないこと。
