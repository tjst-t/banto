## 背景

task-0309（着地予定）で `ArtifactStore.read()` に「同じ栞の同じ範囲を2度目に読んだら全文を返さず短く断る」規則が入った（`packages/banto-host/src/artifacts.ts` の `private readonly readRanges = new Set<string>()` と `duplicateReadSlice()`）。断り文はこう言う：

> （同じ範囲は既にこの会話で読み戻し済み。前の artifact.read の結果がそのまま会話に残っている。別の範囲が要るなら offset・limit・grep を変えて読むこと）

**この「前の結果がそのまま会話に残っている」が、章を畳んだ後は事実でなくなる。** 章を畳むと文脈は引き継ぎ資料に置き換わり、前の `artifact.read` の戻り値は番頭の文脈から消える。ところが `readRanges` は `ArtifactStore` の生存期間（＝会話の生存期間）ずっと残るので、番頭が「もう一度あの栞のあの範囲を読みたい」と正しく判断しても、**中身の代わりに嘘の断りが返る**。番頭は offset を1ずらすなどの小細工で迂回するしかなく、これは道具の振る舞いとして不健全（I2：断りは正しい事実に基づいていること）。

いまは章が畳まれていないので害が出ていないが、**task-0308（文脈の窓が引けないときでも章を畳めるようにする。本番218本中184本が一度も畳んでいなかった）が着地すると、章を畳むことが常態になる**——そこで顕在化する。

## やること

1. `packages/banto-host/src/artifacts.ts`：`ArtifactStore` に読み戻し履歴を忘れる公開メソッドを足す(例 `forgetReadHistory()`)。`readRanges.clear()` するだけでよい。**なぜ忘れるのか**（章を畳むと前の読み戻しは文脈から消えるので、断りの前提が崩れる）を JSDoc に残すこと。
2. `packages/banto-host/src/chapters.ts`：章を畳んだ（`closeChapter()` が引き継ぎ資料を作って文脈を差し替えた）ときに、その口を呼べるようにする。`ChapterKeeperOptions` に任意の callback（例 `onChapterClosed?: () => void`）を足す形が既存の作りに合う。**畳めなかったとき（`closeChapter()` が undefined を返したとき）は呼ばないこと。**
3. `packages/banto-host/src/bin.ts`：`ChapterKeeper` を組み立てている箇所（1933行目あたり）で、その会話の `ArtifactStore` と繋ぐ。
