## 何を書くか

`docs/spec/chat-ui.md` に、いま実際に動いている次の3つの挙動を書き足してください。**実装を読んで、書いてあることと実物が一致することを確かめてから書くこと**（推測で書かない）。読む先は `packages/banto-host/src/` の `bin.ts` / `chapters.ts` / `chapter-summarizer.ts` / `sdk-sessions.ts` / `threads.ts` と、`tests/acceptance/model-settings-live.spec.ts`（a1 / a2 / a3 の3ブロックが期待挙動をそのまま固定しています）。

### a1. 章の要約に使うモデルは、章を**畳む直前**に引き直す
- 会話の器を組んだときの値を最後まで使うのではなく、要約を書く1回ごとに設定から解決し直す。
- したがって、**走っている会話でも、設定を変えれば次の1回から新しいモデルで要約される**。
- 解決できなかったときは黙って既定へ落ちるのではなく、理由を添えて断る（同じ文言の連投は抑える）。

### a2. 思考レベルは会話のセッションが覚え、**組み直しても消えない**
- 思考レベルは、中身のハーネスではなく**セッションの皮（`PooledSdkHarness`）**が保持する。
- そのため、セッションを畳んで組み直しても指定が残る。以前は皮を素通りしていて一度も届いていなかった。

### a3. バックエンドを跨ぐときは、**いまの章のぶんだけ**を書き起こして渡す
- pi ↔ Claude Code の**両方向**で、切り替え先に会話の種を渡す。
- 種はハーネスの持ち物ではなく**会話の記録**から作る。範囲は**最後の章の区切りより後ろだけ**。
- 載せるのは PO・番頭・知らせの発言だけで、**思考とツールの入出力は落とす**。
- 上限は 60,000 文字で、超えたら**古い側から切る**。
- ここは利用体験に効く挙動変更です。「切り替えても話の続きができる」一方で「切り替えると思考とツールの記録は引き継がれない」ことが、読んだ人に分かるように書くこと。
