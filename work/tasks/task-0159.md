## やること

### 1. まず、決定番号を全部拾い直す

`docs/adr/**/*.md` の見出しから決定番号を拾う。**書式は2つある**:

- `### N. タイトル（…）` — adr-0010〜adr-0013（古い層）
- `### 決定N: タイトル` / `### 決定N：タイトル` — adr-0014 以降。`#### 決定99a:` のような**枝番**、`### 決定105〜108:` のような**範囲**、`### 決定113・118:` のような**並記**、`### 決定84 の実装（…）` のような**後置注記つき**がある

**片方の書式を落とすと、この仕事は黙って失敗する**（前回それで落ちた）。拾った総数と、その内訳（ファイルごとの番号一覧）を報告に書くこと。

### 2. 引用の見出しを「名乗り」と数えない規則を決める

他所で決まった決定を**引用しているだけ**の見出しがある。既知は2つ:

- `docs/adr/adr-0014-contract-amendment.md:19` の `### 決定64（もとの裁定）` — 決定64 の実体は `docs/adr/adr-0013-kobo-uses-modules.md:155` の `### 64. 積んだ後の訂正は…`
- `docs/adr/adr-0019-inventory-and-presentation.md:328` の `### 決定84 の実装（task-0100・2026-08-13）` — 決定84 の実体は別 ADR

**採る方式**: 試験ファイルの中に**明示の除外一覧**を持つ。一覧の1件は「ファイルパス＋見出しの全文」の対にする（行番号では持たない——行はすぐずれる）。

**その一覧が腐らないように、一覧に載っているのに実在しない見出しがあったら試験を落とすこと。** 除外は黙って増やせる抜け道なので、腐りを機械が見つける形にしておく。

見出しに印を付ける方式（例: `### 決定64（もとの裁定・再掲）` と書いて再掲を除く）でもよいが、その場合も**印の定義を試験の中に1箇所で書き、印を付けた見出しの一覧を実行時に出す**こと。どちらを採ったかと理由を報告に書くこと。

### 5. packages/** はコメントだけ

`packages/**` をスコープに入れたのは、**コメント（doc コメントを含む）の中の決定番号を直すため**だけ。実装（式・型・関数・振る舞い）は1文字も変えないこと。作業のあと `git diff main...HEAD -- packages/` を自分で読み、コメント行以外の変更が無いことを確かめて報告に書くこと。

### 6. 再発を機械で落とす

`tests/acceptance/decision-number-uniqueness.spec.ts` を置く。`tests/acceptance/record-id-uniqueness.spec.ts` を先に読み、走査ヘルパの形・警告の出し方・「落とすもの／落とさないもの」を冒頭コメントに書く作法をそちらに揃えること。

- **落とす**: ADR をまたいだ決定番号の重複（同一 ADR 内の再掲は畳んでよい）。メッセージに「決定NNN: ファイルA / ファイルB」を出す
- **落とす**: 走査の空振り（拾えた番号が**120件未満**なら落とす。前回はしきい値50で書式ひとつ丸ごと欠けても通ってしまった）
- **落とす**: 除外一覧に載っているのに実在しない見出し（§2）
- **落とさないが一覧に出す**: 欠番、番号を読み取れなかった `### ` 見出し。**取りこぼして緑になるのがいちばん悪い**ので、読み取れなかった見出しは必ず名前を出すこと
- 次に採るべき番号（いま使われている最大 +1）を出す

### 7. わざと落ちることを確かめる

振り直した番号を一時的に元へ戻して試験を走らせ、**赤くなり、両方のファイル名が出る**ことを確認してから戻すこと。両方の書式（`### N.` と `### 決定N`）で1回ずつ試すこと。確認後に復元したことを `git diff --stat` で確かめる。

### 8. 記録を残す（後から「なぜ番号がずれているのか」を辿れるように）

`work/inbox/improvement/imp-NNNN-decision-number-renumbering.md` を書く（**NNNN は空き番号を取ること**。`work/inbox` 配下の既存 id を全部拾って、使われていない番号を選ぶ。`record-id-uniqueness.spec.ts` が重複を落とすので、必ず自分で確かめてから決める。front matter の `id` とファイル名を一致させること）。

書く内容:

1. なぜ番号がずれたのか（採番に検査が無く、複数の ADR が同じ番号を別々に名乗っていた）
2. **旧→新の対応表**（adr-0026 の 113〜123→127〜137、決定47→N、決定69→N、adr-0010 決定39 の二重記載を削除）
