## 背景

2026-08-20 の `system.deploy` がゲート（`npm test`）で拒否した。落ちた2件のうちの1件がこれ。

`tests/acceptance/browser-chromium-launcher.spec.ts` は、**実行中のプロセスの環境変数
`BANTO_BROWSER_ALLOW_NO_SANDBOX` に依存している**。デプロイゲートは banto.service の
環境を継承して走るため、そこで `BANTO_BROWSER_ALLOW_NO_SANDBOX=1` が立っていると
**決定的に落ちる**。清潔な検証コンテナ（env.verify）では緑になるので「間欠」に見えるが、
間欠ではなく環境依存である。

## 原因（実測で確定）

`packages/banto-host/src/browser/chromium-launcher.ts:507-509`:

```ts
const allowNoSandboxEnv =
  options.allowNoSandboxEnv ?? process.env["BANTO_BROWSER_ALLOW_NO_SANDBOX"];
const sandboxDisabled = allowNoSandboxEnv === "1";
```

`??` なので、試験が `allowNoSandboxEnv: undefined` を**明示的に**渡しても素通りして
`process.env` を読みに行く。つまり「環境変数が無い場合」を options 経由で表現できない。

落ちるのは `tests/acceptance/browser-chromium-launcher.spec.ts:664`
「BANTO_BROWSER_ALLOW_NO_SANDBOX が無ければ --no-sandbox は入らず、status も enabled」。

## やること

**試験側で環境を作る**（実装は変えない）。`chromium-launcher.ts` は触らないこと——
本番の既定挙動（環境変数が立っているときだけサンドボックスを外す）は正しく、
変える理由が無い。

`tests/acceptance/browser-chromium-launcher.spec.ts` の該当2件を、
**プロセスの実環境変数がどうであっても同じ結果になる**ように直す:

- 「無ければ」の試験 — 実行前に `delete process.env["BANTO_BROWSER_ALLOW_NO_SANDBOX"]`
  し、終わったら**元の値を復元**する（元が undefined なら delete で戻す）
- 「=1 のとき」の試験 — 実行前に `process.env["BANTO_BROWSER_ALLOW_NO_SANDBOX"] = "1"`
  を明示的に立て、終わったら同様に復元する
- 復元は `try { … } finally { … }`、または `before`/`after` フックで確実に行うこと。
  試験が落ちても環境が汚れたまま残らないようにする
- 他の試験が同じ環境変数を読むなら、それらも同様に明示すること

## やらないこと

- `packages/banto-host/src/browser/chromium-launcher.ts` を変更しない（スコープ外）
- 試験を skip / 削除して回避しない
