## 背景

2026-08-20 の改修（コミット `b6e4fec6`）で、**章の要約は「畳む直前にモデルを引き直す」形**になりました。`createLlmChapterSummarizer({ resolve: () => ... })` に解決の口を渡し、要約1回ごとに `resolve()` を呼ぶ形です。これにより、走っている会話でも設定を変えれば次の1回から効きます。

**記憶の抽出だけが、この直しから取り残されています。** `packages/banto-host/src/bin.ts` の 1898 行目あたりに、作者自身の注記が残っています（原文）:

> 記憶の抽出（`createLlmMemoryExtractor`）は今のところ pi 経由でしか呼べない（このタスクの範囲外・別途 inc として追う論点）。章の要約が claude-agent-sdk を選んでいるときは、記憶の抽出だけ会話のモデルへ戻す——以前からの fallback と同じ形。
> **こちらは会話の器を組むときの1回のまま**。抽出器はモデル実体を掴んで組むので、要約と同じ形（毎回引き直す）にするなら抽出器の側から直す必要がある。

いまの実装は `const memoryModel = (() => { try { return resolveChapterPlan().piModel } catch { ... } })() ?? sessionModel;` で**会話を組むときに1回だけ**解決し、その値を掴んだ `createLlmMemoryExtractor({ model: memoryModel, ... })` を章の境界ごとに呼んでいます。つまり**設定画面でモデルを変えても、走っている会話の記憶の抽出には効きません**——PO が報告した①と同じ形の取り違えが、抽出器の側に残っています。

## やること

**記憶の抽出も、抽出が走る直前にモデルを引き直す形にしてください。** 章の要約（a1）と同じ設計に揃えるのが狙いです。

1. `createLlmMemoryExtractor` が**モデル実体を掴んで組む**のをやめ、**呼ばれるたびに解決する口**（`resolve: () => ...` のような形）を受けられるようにする。既存の「モデルを直接渡す形」は試験のために残してよい（`createLlmChapterSummarizer` がユニオン型で両方を受けているのと同じ作り。そちらを手本にすること）。
2. `bin.ts` の `extractMemories` は、抽出が走る時点で解決するようにする。`memoryModel` を組み立て時に固定しない。
3. **解決できなかったときの振る舞いを変えないこと**：いまは起動を止めず `console.warn` して会話のモデルへ落ちています。この「起動を止めない」性質は保つこと。ただし**黙って握り潰さない**（I2）——断る理由は必ず出す。
4. pi 経由でしか呼べないという制約そのものは**このタスクでは直さなくてよい**（claude-agent-sdk 対応は別の論点）。直すのは「いつ解決するか」だけです。

## 完了の形

新しく `tests/acceptance/memory-extraction-model.spec.ts` を書いて、次を固定してください。**LLM には繋がないこと**——`tests/acceptance/model-settings-live.spec.ts` の a1 が、偽の呼び口を渡して呼ばれた回数と使われた座標だけを見る書き方をしています。それに倣ってください。

- 設定を変えたら、**走っている会話の次の抽出から**新しいモデルで走ること（組み立て時の値を使い続けないこと）。
- 解決できないときに**起動も抽出も黙って止まらない**こと（会話のモデルへ落ち、理由が出ること）。
