## この回でやること

`packages/banto-host/src/browser/chromium-launcher.ts`（新規）に、**本物の chromium を起こす `BrowserLauncher` 実装**を書き、`createBrowserModule()` の**既定の launcher をそれにする**。

### 1. chromium の実行ファイルを探す

**`playwright` を import しないこと。** 理由は2つ:
- 追加依存ゼロという設計の前提（`playwright` は devDependency であり、本番の実行時にあるとは限らない。実際 banto の職人プロセスでは `NODE_ENV=production` により devDependencies が落ちる事故が起きている）
- 要るのはバイナリのパスだけで、playwright の API は要らない

探索は**純関数として切り出し、優先順を試験で固定する**:

1. 環境変数 `BANTO_BROWSER_EXECUTABLE` が指すパス（あればそれを使う。無ければ「そこに無い」と言って失敗する——黙って次へ落ちない・I2）
2. `~/.cache/ms-playwright/chromium-<revision>/chrome-linux/chrome`（`chromium_headless_shell-*` ではなく `chromium-*` を選ぶこと。複数あれば **revision の数値が最大のもの**。文字列比較で並べると `chromium-1200` < `chromium-999` になるので必ず数値で比べる）
3. `PATH` 上の `chromium` / `chromium-browser` / `google-chrome` / `google-chrome-stable`

どれも見つからなければ、**どこを探したかを全部並べて失敗する**（I2：「起きたつもり」を作らない）。

純関数の形は任せるが、**ファイルシステムを引数で受ける（またはディレクトリ一覧と存在判定を注入する）形にして、一時ディレクトリに偽の木を作って試験できるようにすること**。

### 2. 起動引数を組み立てる

これも**純関数**にして試験する。少なくとも次を満たすこと:

- `--remote-debugging-port=0`（**ポートは 0 で任せる**。固定ポートは他所と衝突する）
- `--remote-debugging-address=127.0.0.1`（**外に出さない**）
- `--user-data-dir=<起動ごとの一時ディレクトリ>`（`os.tmpdir()` の下に作り、`close()` で消す）
- `--no-first-run` / `--no-default-browser-check`
- `--window-size=<width>,<height>`（`LaunchRequest` の値。既定は 1280x800）
- **`process.env.DISPLAY` があれば headful（`--headless` を付けない）／無ければ `--headless=new`**（§5-2 の指定どおり。Xvfb をこの実装が起こすことはしない。あるものに乗るだけ）
- 最初に開く URL（`LaunchRequest.url`）は最後の位置引数。無ければ `about:blank`

**上に挙げていない引数を思いつきで足さないこと。** 足すなら、なぜ要るのかをコメントに書く。

### 3. CDP の口を掴む（**ここが要注意**）

`--remote-debugging-port=0` なので実ポートは起動後にしか分からない。**`<user-data-dir>/DevToolsActivePort` を待って読む**（1行目＝ポート番号、2行目＝`/devtools/browser/<id>`)。この解析も**純関数に切り出して試験する**（正常な2行／1行しか書かれていない途中の状態／空ファイル）。

**そのうえで、`LaunchedBrowser.webSocketDebuggerUrl` には *page* ターゲットの WS URL を返すこと。** 理由:

- `session.ts` は繋いだ接続に対して **`sessionId` 無しで `Page.enable` / `Page.startScreencast` を送る**。`/devtools/browser/<id>`（ブラウザ級のエンドポイント）に繋ぐと `Page.*` は通らず、**面が真っ黒のまま何も起きない**。
- したがって `http://127.0.0.1:<port>/json/list` を叩いて `type == "page"` のターゲットの `webSocketDebuggerUrl` を返す。page が1つも無ければ `http://127.0.0.1:<port>/json/new?url=<url>` で作る（`PUT` でないと通らない chromium 版があるので、`GET` が 405 なら `PUT` で叩き直すこと）。
- **`launcher.ts` の doc コメントが `ws://127.0.0.1:<port>/devtools/browser/<id>` を例に挙げているのは K1 時点の見込みで、この回で実際と食い違う。** `LaunchedBrowser.webSocketDebuggerUrl` の説明を「**page ターゲットの CDP の口**（`Page.*` が `sessionId` 無しで通ること）」に直し、なぜそうなのかを1行添えること。契約の形（フィールド名・型）は変えない。

HTTP は Node 標準の `node:http` で叩く（`fetch` でもよい）。**外向きの依存を足さない。**

期限内（既定 30 秒・定数1箇所）に口が掴めなければ、**起こしたプロセスを落としてから失敗する**（I2）。

### 4. 落とす（プロセスを残さない）

- `spawn` は `detached: true` でプロセスグループを作り、`close()` は **プロセスグループごと**落とす（`process.kill(-pid, "SIGTERM")` → 猶予（既定 5 秒）後に生きていれば `SIGKILL`）。chromium はレンダラ等の子プロセスを生やすので、親だけ落とすと**孤児が残って費用と資源を食い続ける**。
- `close()` は**冪等**（既に落ちていても成功する）。一時 user-data-dir も消す。
- ホストが終わるときに残さないよう、`process.on("exit")` 相当での後始末も入れる（同期でできる範囲でよい）。

### 5. アイドル TTL

- **面が0で、最後の操作から一定時間（既定 30 分・定数は1箇所＝D3）経ったら自動で落とす。**
- 時計とタイマーは**注入できる形**にして試験する（実時間を待つ試験を書かないこと）。
- TTL で落ちたことは `console.error` ではなく通常のログで1行残す。

### 6. 既定に据える

`createBrowserModule()` が `launcher` を渡されなかったときの既定を、`createUnimplementedLauncher()` から**この chromium launcher** に替える。`createUnimplementedLauncher` は**消さない**（試験と、意図的に起こさない構成のために残す）。launcher の `name` は `"chromium"`。

`bin.ts` は触らない（既に `createBrowserModule()` を register 済み）。**スコープにも入っていない。**
