## 背景（これが依頼の理由。読み飛ばさないこと）

`packages/banto-web/src/views/WorkerViewer.tsx`（職人の面）は、**いま開いている会話と関係なく、全プロジェクト・全会話の職人を混ぜて並べている**。しかも稼働中は3秒ごとに取り直す（`REFRESH_MS = 3000`）。

そのせいで実害が出た。PO が自分の会話で `env.verify` を回したとき、この面に**別の会話が起こした職人**が並んでいたため、「`env.verify` が職人（LLM）を起こしているのでは」という誤った見立てが生まれ、調査が一往復むだになった。**`env.verify` は LLM を1本も起こさない**（コードと実測の両方で確定済み）。面が「誰の職人か」を言わないことが誤読の原因である。

## 目的

**面を開いている会話から起こした職人だけが、既定で並ぶようにする。**「全部見る」道は残す（消さない）。

## いまの実装（確認済みの事実）

- `packages/banto-web/src/views/WorkerViewer.tsx`
  - `useModuleTool<WorkerList>(endpoint, "worker.list", { includeClosed, query, limit: PAGE_SIZE, offset: page * PAGE_SIZE })`（`PAGE_SIZE = 20`）
  - **絞り込みもページ送りも Worker Pool 側で行う**方針（コメントに明記あり。「履歴が増えても全件を受け取らずに済む」）。この方針は崩さないこと——**受け取ってからクライアントで捨てる実装にすると、ページ送りの件数が合わなくなる**（20件取って18件捨てると1ページ2件になる）。
  - 稼働中の職人が居るときだけ 3 秒ごとに `worker.list` と `worker.attach` を取り直す。
- `packages/banto-worker-pool/src/pool.ts` の一覧は **`origin` を返している**（1093行付近ほか）。`worker.list`（`worker-tools.ts`）が受けるのは今のところ `includeClosed` / `query` / `limit` / `offset` / `projectTag` で、**`origin` で絞る口は無い**（`worker.events` にはある：`worker-tools.ts:366`）。
- `origin` の形は **`banto:<threadId>`**（`packages/banto-host/src/worker-notice.ts` の `threadOrigin()` / `threadIdOfOrigin()`。`BANTO_ORIGIN = "banto"`、区切りは `:`）。番頭が職人を起こすとき、この値は**会話側で束ねられて**渡る。
- 画面側は `packages/banto-web/src/App.tsx` が `activeThreadId`（`view.threadId`）を持っている。面（canvas view）へどう渡っているかは `CanvasViewProps` を読んで確かめること。

## やること

1. **`worker.list` に「この会話で起こした職人だけ」を返す絞り込みを足す**（サーバ側で絞る。`origin` を受ける形が素直だが、名前と形は実装者が決めてよい）。`total` / `closedTotal` も絞り込み後の数になること——**ページ送りが壊れないことがこの依頼の肝**。
2. **幹と枝をひとつながりに扱う。** 番頭は幹（例 `thread-61`）から枝（例 `thread-246`）を生やし、**職人は枝から起こされることが多い**。幹の会話を開いているときに、その幹から生えた枝が起こした職人が消えると、この直しは役に立たないどころか有害になる（動いている職人が画面から消える）。**「いまの会話 ＝ 開いている会話と、その幹配下の枝」**として扱うこと。幹と枝の親子は番頭側が持っているので、**画面から渡せる形**（例：対象 threadId の配列を画面が組み立てて渡す／ホストに「この会話の一族」を答えさせる）を選び、選んだ理由をコード上のコメントに1行残すこと。
3. **既定はこの絞り込みを効かせる。全部見る切り替え（トグル）を残す**——`showClosed` の隣あたりに置き、いまどちらで見ているかが一目で分かる表示にする。切り替えたらページは先頭へ戻す（既存の `useEffect` と同じ扱い）。
4. **絞り込んだ結果が0件のときの文言**を、いまの「職人が居ません」から**「この会話では職人を起こしていません（ほかの会話の職人を見るには『全部』へ）」**に相当するものへ変える。**ここが今回の実害の直接の再発防止**である——面が黙って空になると、また別の誤解を生む。
5. 3秒ポーリングは、**絞り込んだ後に稼働中の職人が居るときだけ**回す（居なければ回さない）。

## やらないこと

- 一覧の並び順・ページ数（`PAGE_SIZE = 20`）・`worker.attach` まわりは変えない。
- 職人の起こし方・`origin` の付け方そのものは変えない（既にある値を使うだけ）。
- 画面の見た目を作り直さない。足すのはトグル1つと文言だけ。
