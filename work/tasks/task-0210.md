## 何が起きているか（PO の実観測・2026-08-16）

**畳んだ枝が、一覧に開いたまま残り続ける。**

いまの振る舞い（`tests/acceptance/closed-thread-delivery.spec.ts` T2 に固定済み）：
**畳んだ枝へ知らせ（職人の報告・Kobo の遷移など）が届くと、その枝が開き直り、その枝のターンが回る**（親の幹は 0 本）。
知らせを捨てないための、正しい仕組みです。**これ自体は残すこと。**

**穴はその先にあります。**

- 開き直した枝に渡るのは**畳んだときまでの記録**であって、「あなたは開き直された」という情報がありません。
- したがって枝は**「私はもう畳んだ枝です」と認識したまま**返事をし、**`thread.merge` を呼びません**。
- **畳む口を叩く者が誰もいない**ので、その枝は**開いたまま一覧に残り続けます**。
- 実例：畳んだ枝「Kobo再開の1本目」が、積んだタスク（task-0152 ほか）の知らせが届くたびに起き直り、
  そのつど開いたままになっている。PO から見ると「畳んだはずのものが消えない」、枝から見ると「私は畳んである」——
  **両方が正しくて噛み合っていない。**

## 直す方針（**枝の自己申告に頼らないこと**）

「枝に気づかせて自分で畳ませる」は、LLM の判断に依存するので落ちます。**機構が畳み直す**形にすること。

1. **知らせで開き直した枝は、そのターンが終わったら機構が自動で畳み直す。**
   **元の結論・investigated / decided / remaining は保つこと**（上書きしない・消さない）。
2. 開き直した枝の文脈に、**機構が「あなたは〈何の知らせ〉で一時的に開き直された。用が済んでいれば何もしなくてよい」**と明示する。
   **結論を書き換えたいときだけ枝が `thread.merge` を呼ぶ**——その場合は枝が書いた新しい結論が勝ち、自動の畳み直しは二重に走らないこと。
3. **一覧（`thread.list`・画面の枝タブ）で、「畳んである（知らせで一時的に起きた）」と読めること。**
   ずっと開いている枝と混ざらないこと。**残作業を抱えて畳んだ枝の「未処理 N件」表示（imp-0036）を壊さないこと。**
