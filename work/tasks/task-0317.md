## 背景

2026-08-20 に「番頭のトークン消費の内訳」を実測した（毎ターンの固定費 23.7% / 履歴の再送 76.3%）。このとき、**プロバイダが返した usage（とくに `cache_read_input_tokens` / `cache_creation_input_tokens`）が、どこにも永続化されていない**ことが分かった。

- ターンの台帳は `<BANTO_DATA_DIR>/turns.jsonl`（既定 `.banto/turns.jsonl`）で、書き手は `packages/banto-host/src/turn-log.ts`（116行目あたりでパスを組んでいる）。読み手は `packages/banto-host/src/turn-report.ts`。
- usage 自体はハーネスの中には来ている: `packages/banto-host/src/claude-agent-harness.ts:756` で `message["usage"]` を取り出し、`lastIterationTokens()`（814行目付近）で **文脈長の推定にだけ**使って捨てている。
- そのため「キャッシュが実際にどれだけ効いているか」「履歴の再送が本当に課金されているか」を、本番の記録から後追いで答えられない。

## やること

**ターン台帳の1行に、そのターンの usage を足す。** それだけでよい。

1. `claude-agent-harness.ts` が取り出している usage から、少なくとも次を拾って上へ渡す（プロバイダによって欠けるものがあるので、**在るものだけ**入れ、無ければキーごと省く）:
   - `input_tokens` / `output_tokens`
   - `cache_creation_input_tokens` / `cache_read_input_tokens`
   - モデル名（分かるなら）
   ここで言う usage は「そのターン中に走った全 API 呼び出しの**累計**」である（`claude-agent-harness.ts:714-716` の注記のとおり）。文脈長の推定に使っている `lastIterationTokens()` の**最後の1件を取る挙動は絶対に変えないこと**（imp-0051 の落とし先で、章を畳む判定がこれに乗っている）。累計は累計として別に持つ。
2. `turn-log.ts` が書く1行に `usage` フィールド（オブジェクト）として載せる。**既存のフィールドの名前・意味は変えない**——`turn-report.ts` や既存の解析が壊れる。
3. usage が取れなかったターンでは `usage` フィールドを省く（`null` や 0 で埋めない。「取れなかった」と「0だった」を混ぜない）。

## やらないこと

- 集計・画面表示・レポートは作らない（要るようになってから別に積む）。
- 章を畳む判定（`chapters.ts`）や文脈計の挙動は一切変えない。
- 職人（worker-pool）側の記録には手を出さない。

## 完了条件

ターンが1本回ったあと、`turns.jsonl` の該当行に、プロバイダが返した usage の値がそのまま載っていること。usage が無いターンではフィールドが無いこと。既存の試験一式が通ること。
