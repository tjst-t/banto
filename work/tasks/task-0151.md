# 章の要約に使うモデルを画面から選べるようにする

## なぜやるか（inc-0068）

章を畳むときの引き継ぎ資料が**空で返って畳めない**事故が起きた（inc-0068）。
実機調査で分かった原因は、要約に使われているモデルが**誰の意図でもないもの**だったこと。

- `BANTO_CHAPTER_MODEL` は未設定。README には「指定が無ければ会話と同じモデル」と書いてある。
- しかし会話のモデル `claude/opus`（backend `claude-agent-sdk`）は **pi の台帳で解決できない**。
  起動ログに `claude/opus を解決できないため、起動時のモデルで開きます` が出て、
  `resolveHostDefault()` のフォールバックへ落ちる。
- 実機で実際に使われていたのは `huihui/deepseek-v4-flash-abliterated`（自宅 vLLM・openai 互換）。
  **openai 互換だけはサーバ既定で思考（`reasoning_content`）が出て、思考と本文が同じ
  `max_tokens` を分け合う**。予算4000のうち思考が2,579字を食い、本文が0字になる。これが空返しの正体。

`bc2b396` で「空なら一度やり直す／既定予算 4000→8000／断りに使ったモデルを載せる」は入れた。
**それは保険であって、根の手当てではない。** 根は「要約に何を使うかを、誰も選べていない」ことだ。

## 何を作るか

### 1. バックエンドをまたいでモデルを指定できるようにする

いまの要約器は pi の `complete` しか呼べない。そのため
**claude-agent-sdk のモデル（haiku / sonnet / opus）は指定しても解決できない**。
これを、指定されたモデルのバックエンドに応じて呼び分けられるようにする。

`chapter-summarizer.ts` の LLM を呼ぶ口（`ChapterCompleter`）は `bc2b396` で
差し替え可能になっている。ここに Agent SDK 経由の実装を足す形が素直だが、作り方は任せる。

**要約は会話とは別の呼び出し**であり、本編のキャッシュに触らないこと（README の但し書き）。

### 2. 既定を claude-agent-sdk の haiku にする

指定が無いときに「会話と同じモデル」へ寄せる現在の既定をやめる。**既定は haiku 固定**。

理由は3つ。①要約は安いモデルで足りる ②会話のモデルは思考を出す等級が選ばれがちで、
今回のように出力予算を食い潰す ③「会話と同じ」は解決に失敗したとき静かに別物へ落ちる。

### 3. 画面から選べるようにする

環境変数だけだと**いま何で要約しているかが誰にも見えない**。これが今回の事故を
長引かせた（番頭は「会話と同じモデルのはず」と誤認していた）。

- 設定の画面に「章の要約に使うモデル」を置き、採用しているモデル（pi・claude-agent-sdk の両方）から選べる。
- 選んだ値は保存し、再起動後も残す。
- **いま実際に使われているものが画面から読めること。** 指定と実際が食い違うなら、それが分かること。

### 4. 解決できなかったときに黙らない（I2）

指定が解決できないなら、静かに既定へ落ちるのではなく、
**警告を出し、断りに「指定された名前・解決の結果・実際に使ったもの」を載せる**。
今回の事故は「静かに落ちた」ことで原因の特定が丸一日遅れた。

## 前提と注意

- `BANTO_CHAPTER_MODEL` は既に運用に出ているので**消さない**。環境変数が最優先、次に画面の設定、
  最後に既定（haiku）。優先順位は README に書くこと。
- README の該当行（`BANTO_CHAPTER_MODEL` の説明）は inc-0068 を踏まえて更新済み。
  今回の変更に合わせて直すこと。**「指定が無ければ会話のモデル」という記述はもう嘘になる。**
- pi には思考を切る seam が無い（`reasoning` 未指定＝ anthropic/google では思考オフ、
  openai 互換はサーバ既定が効く）。**思考を切る方向の実装は入れないこと**——今回の答えは
  「思考を出さないモデルを選べるようにする」であって、プロバイダの挙動をねじ伏せることではない。
- 稼働中の本体ツリー（/home/ubuntu/ghq/github.com/tjst-t/banto）で `npm ci` / `rm -rf node_modules` /
  `git clean` を打たないこと（過去にサービスを落とした事故がある）。

## 残っている論点（このタスクでは直さない）

章を切る閾値は**会話側ハーネス（Agent SDK）の文脈長**で決まるのに、資料を書くのは別モデルで、
pi は `maxTokens` を `contextWindow - 入力 - 4096` に切り詰める。入力が要約器の文脈長に
近づくと予算が1トークンまで落ちて即・空になる。**軽いモデルを既定にすると、この食い違いは
むしろ起きやすくなる**（haiku の窓は opus より狭い）。`bc2b396` の切り詰めやり直しで
実害は塞げているが、別途 inc として追う必要がある。
