## 背景

task-0216（`210000ce` で着地）で、工房（Worker Pool）に同時本数の栓が入った。上限に達すると
`WorkerPool.reserveSlot()`（`packages/banto-worker-pool/src/pool.ts:1203`）が待たせずに投げて断る。

**足りていないのが2つある。**

1. **断る前に席を作っていない。** 工房には既に15分の安全弁（`DEFAULT_IDLE_TIMEOUT_MS` /
   `sweepIdle()`、pool.ts:2038）があり、点検は `idleTimeoutMs / 4`（既定3分45秒）ごとの
   `setInterval` でしか回らない。**`reserveSlot` は `sweepIdle` を呼んでいない**ので、
   「15分以上触られていない職人が席を占めているのに、次の職人が断られる」窓が構造的に開く。
   実際に今日、待機中（idle）の職人が1本 約300MB を掴んだまま残っていた。
2. **断ったことが工房の帳簿に残らない。** `reserveSlot` は例外を投げるだけで、
   工房のイベントログ（`this.log`。`worker.events` の元）には何も書かない。呼び出し側が
   その文言を捨てれば、「なぜ遅いのか」は誰にも読めなくなる。

## やること

**`packages/banto-worker-pool/src/pool.ts` だけを触る**（＋試験1本）。

1. **満杯なら、まずアイドルを畳んでから断る。**
   `delegate()` の入口で満杯（`concurrency().running >= limit`）と分かったら、
   **その場で `sweepIdle()` を1回回し**、畳めた分で席が空いたら通す。空かなければ**従来どおり**
   `BANTO_WORKER_LIMIT` の合印つきで断る（断りの文面は変えない）。
   - 待ち行列は作らないこと（task-0216 の設計どおり・D3）。「畳んでみて、駄目なら即断る」だけ。
   - `reserveSlot` は今は同期。`delegate` は `async` なので、`await` できる形に変えてよい。
     枠を `finally` で必ず返す（`this.starting.delete(token)`）性質は壊さないこと。
   - **安全弁が切ってある（`idleTimeoutMs <= 0`）ときは掃かない**——`sweepIdle` は 0 を返して
     何もしないので、そのまま断りへ落ちればよい。
   - 満杯でないときに `sweepIdle` を呼ばないこと（毎回の `delegate` を重くしない）。
2. **断りを帳簿に残す。**
   断った事実を工房のイベントログに1件残す（既存のイベント型の流儀に合わせる。**新しい状態は
   足さない**）。少なくとも「いつ・どのタスクを・何本／上限何本で断ったか」が後から読めること。
   ログ行（`console.error` 等、`sweepIdle` の失敗と同じ流儀）でもよいが、**黙って断らないこと**が要件。

## やらないこと

- Kobo 側（`packages/banto-daemon`）は触らない——満杯を `failed` にしない件は task-0222 の担当。
- 監査に席を確保する件は task-0223 の担当。
