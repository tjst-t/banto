## 背景

ADR-0010 決定38。番頭は `memory.save` 以外に書き込み手段を持たないが、決定15 は「番頭が `work/epics`・`work/tasks` を起票する」と定めており矛盾していた（P3）。

職人へ委譲する案も検討したが、決定を1つ記録するたびに職人を起こすことになり、記憶を持たない職人（D11）に全文を渡す必要があるため**番頭が書いてから転記させる二度手間**になる。

## 実装メモ

- 判定は task-0038 の砦に**1段足すだけ**：「登録された場所の中か」＋「書いてよい範囲か」
- **フレームワークは `docs/` `work/` を知らない**（決定38f）。パス構成はプロジェクト側の語彙で、設定が与える
- 番頭はコミットできない（決定37）ので、書いたものは未コミットで残り PO の diff レビューを通る。**書けることと残せることが分かれているのが安全装置**

## スコープ外

- **要求と承認の UI**（task-0042）。本タスクでは**許可を設定ファイルで与える**。パネルが無くても
  決定38 の安全性（範囲・自己昇格の禁止・`.git/` 除外）は全部そろう——パネルは手間を減らす改善であって前提ではない
- 番頭が Git の変更操作を持つこと（決定37 で却下済み）
- 許可の「じわじわ広がる」ことの機構的な防止。決定38(e) のとおり見えるようにするのみ
