## 背景（事実）

2026-08-20、task-0279「会話に日時表示と日付区切り線」がコミット `8ee583d8` / `eb25c267` として **05:19 に main へ着地**した。09:10 に4ユニット（banto.service / banto-daemon / banto-worker-pool / banto-environment-pool）を全部起こし直した。**それでも PO の画面に時刻が出なかった。**

調査で分かった事実：

- banto.service の ExecStart は `node --import tsx packages/banto-host/src/bin.ts serve --port 4100`。画面は `packages/banto-host/src/bin.ts:813-816` で **`packages/banto-web/dist` を静的配信**している（`BANTO_WEB_DIST` は未設定なので既定パス）。Vite の dev server は動いていない。
- `packages/banto-web/dist/assets/` の mtime は **Aug 19 10:10**（着地の約19時間前）。
- 稼働中のホストが実際に配っていた JS/CSS を取得して grep したところ、task-0279 が入れた `day-divider` / `msg-time` は **0 件**。つまり配信物に改修が1バイトも入っていなかった。
- 一方、**ホスト側は正しく動いていた**。`/var/lib/banto/threads/*.jsonl` の 09:10 以降の行は PO 発言・番頭発言・知らせ・思考・道具のすべてに `at` が乗っている（欠け0件）。データもコードも正常で、**落ちていたのは配信物の1層だけ**。
- `npm run build:web`（= `npm --prefix packages/banto-web run build`）が dist を作る唯一の口。systemd の再起動はこれを走らせない。

## 何が穴なのか

**画面のビルドが配信の前提なのに、着地とも再起動とも連動していない。** 誰かが手で `npm run build:web` を打つまで、`packages/banto-web/src/**` を変えたタスクは「工場で緑になって着地したのに、画面は何も変わらない」という顔をする。今回たまたま気づけたが、次も気づける保証はない（画面の変更は機械が検知しにくい）。**task-0279 固有の問題ではなく、以後の web 変更すべてが同じ形で沈む。**

いま「起こし直し」の正式な口は `system.deploy`（`packages/banto-host/src/deploy-gate.ts`）で、main に検証一式を回して**通ったときだけ**指定ユニットを再起動する。ここに画面のビルドが入っていない。

## やること

### 1. `system.deploy` に画面のビルドを組み込む（`packages/banto-host/src/deploy-gate.ts`）

- 検証（既定 `npm test`）に**通ったあと・ユニットを起こし直す前**に、`npm run build:web` を実行する。
- **ビルドが失敗したら再起動しない**（検証で落ちたときと同じ扱い＝拒否し、失敗内容を返す）。古い dist を配り続ける方が、半端に再起動するより安全。
- ビルドを走らせたこと・成否・かかった時間を、いまの `deploy-pass` / `deploy-rejected` と同じ記録の系に残す（既存の `record(...)` の作法に合わせる）。返答にも1行出す。
- `force: true` のときの扱いは既存のゲート迂回と揃える（迂回したことが記録に残る形）。
- 対象ユニットに `banto.service` が含まれないとき（例：worker-pool だけ起こし直す）にビルドを飛ばすかどうかは実装者の判断でよいが、**飛ばすなら「なぜ飛ばしたか」が返答に出ること**。黙って飛ばさない。

### 2. SKILL `safe-restart` を直す（`packages/banto-host/skills/safe-restart/SKILL.md`）

いまの手順には「画面は再起動では新しくならない」という事実がどこにも書かれていない。次を足す：

- `packages/banto-web/**` を変えたタスクが着地したら、**再起動だけでは反映されない**。`packages/banto-web/dist` を作り直す必要がある（配信しているのは banto-host だが、中身を作るのは Vite のビルド）。
- 正式な口は `system.deploy`（1 で自動化される）。手で確かめるなら `npm run build:web` のあと `curl -s http://127.0.0.1:4100/` で参照されているアセット名を見て、その js/css に変更が入っているか grep する。
- ビルド後は **PO がページを読み込み直せば切り替わる**（index.html は no-cache + ETag なので、banto.service の再起動は要らない）。

## 注意

- **稼働中の本番は `/home/ubuntu/ghq/github.com/tjst-t/banto` の .ts を直読している。**作業はワークツリーで行い、main のチェックアウトに未コミット差分を残さないこと（ff-only のマージが止まる）。
- `dist/` は .gitignore 済み。ビルド成果物をコミットしないこと。
