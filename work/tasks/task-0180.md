## 背景（前提を全部ここに書く。あなたはこの案件の記憶を持っていない）

banto は Ubuntu VM 上で4つの systemd ユニット（banto.service＝番頭ホスト / banto-worker-pool.service＝職人 / banto-environment-pool.service＝検証環境 / Kobo）として動いている。**PO（この製品の持ち主）は日本時間（JST, UTC+9）で生活している**が、機構が人に見せる時刻がすべて UTC で出ており、9時間ずれた案内が実害を出した（`03:36Z` を「今朝」と案内したが PO の時計では 12:36＝昼）。

先に調査を済ませてある（報告書 `/home/ubuntu/banto-desk/reports/2026-08-16-jst-display-investigation.md`。読める環境なら読んでよいが、この依頼だけで作業できるように以下に全部書く）。分かっていること：

- 稼働機は `/etc/localtime -> /usr/share/zoneinfo/Etc/UTC` で **UTC に明示固定**。4ユニットのいずれにも `TZ` 環境変数は無い。**この設定は変えない**（下の「やってはいけないこと」を参照）。
- 記録側（jsonl・帳簿・journal）は全部 `toISOString()` で UTC。**健全なので触らない。**

## 方針（これは決定事項。動かさない）

- **機械が持つ記録は UTC のまま。** 複数サービス・コンテナ・journal・帳簿を突き合わせるとき、同じ物差しであることが決定的。実際、直近の障害調査はすべての記録が UTC で揃っていたから決着した。**ここを崩すと同じ調査ができなくなる。**
- **人が読む出口だけ JST にする。** 対象は (1) 番頭（LLM）が読む Tool 戻り値の**本文テキスト**、(2) Web の画面。
- **戻り値の `details`（JSON フィールド）は UTC ISO のまま残す。** 本文が JST・details が UTC という二枚看板になるので、**本文には必ず `JST` の字を出す**（番頭が「これはもう変換済みか」を毎回推測せずに済むように）。

## この回でやること

### 1. 共有の変換関数を1つ足す

`packages/banto-core/src/time.ts` を新規に作り、`packages/banto-core/src/index.ts` から export する（4パッケージすべてが `@banto/core` を参照しているので、ここに置けば全部から使える）。

```ts
export function formatJst(iso: string | undefined, opts?: { seconds?: boolean }): string
```

- `Asia/Tokyo` 固定。**`process.env.TZ` やロケール既定に依存してはいけない**——`Intl.DateTimeFormat` に `timeZone: "Asia/Tokyo"` を明示し、`formatToParts` から年月日時分（秒）を取り出して自前で組み立てること（ロケール名に頼って書式を決めると環境の ICU 次第で崩れる）。
- 既定の形：`2026-08-16 12:36 JST`。`{ seconds: true }` のとき `2026-08-16 12:36:41 JST`。
- `undefined` / 空文字 → `""` を返す。日付として読めない文字列 → **入力をそのまま返す**（画面や本文が壊れないように）。**例外は投げない。**
- タイムゾーン名 `"Asia/Tokyo"` はこのファイル内の名前付き定数1つに置くこと（あとで設定値にしたくなったとき、直す場所が1つで済むように）。

### 4. 試験

## やってはいけないこと

- **`/etc/localtime`・`timedatectl`・systemd の unit file・`TZ` 環境変数を変えない。** プロセス全体を JST にする案は、記録側に黙って JST が混入する危険があるため**採らないと決めている**。
- **記録の書き込み形式を変えない**（`event-log.ts` / `threads.ts` / `inbox.ts` / `turn-log.ts` / `project-registry.ts` / 各 jsonl・`index.json`・`projects.json`）。
- **スコープ外のファイルを触らない。** `work/**` や `docs/**` に新しいファイルを作らないこと（未追跡ファイルが着地時のマージを壊す）。
- **サービスの再起動をしない。** 反映は番頭が段取りを持つ。
