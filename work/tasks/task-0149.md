## 背景

PO からの調査依頼を受け、職人（ctx-1m-investigate, session 158de983）が一次情報で特定した。

`/api/model` エンドポイント（`packages/banto-host/src/bin.ts:1010-1021` と `1659-1666`
付近）が返す `contextWindow` は、実際には次の経路で「opus とは無関係な別モデルの値」に
なっている:

1. `packages/banto-core/src/llm-registry.ts` の `resolveHostDefault()` は、
   `roles.steward.backend` が `"pi"`（または未指定）でない場合——つまり
   `claude-agent-sdk` のとき——**pi 側のモデル解決を意図的にスキップし**、
   `models().find(m => m.policy.includes("host") && m.tier === "standard")` で
   拾える pi 側の代打モデルへフォールバックする（コメント曰く「pi のモデルだけが
   ここで解決できる」）。これは `createBantoHostSession` が pi-ai の `Model` 型を
   要求するための**内部的な帳尻合わせ**であり、それ自体は妥当。
   - 実機ではこの代打モデルは `huihui/deepseek-v4-flash-abliterated`
     （`~/.pi/agent/models.json`、providerId 昇順で先頭の standard tier モデル）
   - このモデル定義は `contextWindow` を持たず、`node_modules/@earendil-works/pi-coding-agent/dist/core/provider-composer.js:72`
     の `contextWindow: definition.contextWindow ?? 128000` で 128000 が付く
2. **問題はここから**: `bin.ts:1659-1666` が `/api/model` の応答を組み立てる際、
   `currentModelId`（＝役割名 "opus"）はそのまま出しつつ、`vision` / `contextWindow`
   は**上の代打モデル（huihui）の値をそのまま転用**している。結果として
   `{"id":"opus","vision":false,"contextWindow":128000}` が返る——**名前は opus、
   中身は無関係な別モデルの値**という取り違え。
3. 実測（2026-08-14、claude-agent-sdk 経由の `query()` 直叩き）では、実際の
   `opus`（`claude-opus-5`）の `contextWindow` は `1,000,000`。banto はこれを
   定数で書くべきではない（Anthropic 側の仕様変更・プラン変更・環境変数
   `CLAUDE_CODE_DISABLE_1M_CONTEXT` で変わりうるため）。**1,000,000 をハードコード
   する直し方は避けること。**

なお、章の畳み（chapter compaction）閾値は claude 経路では
`packages/banto-host/src/claude-agent-harness.ts` が SDK の `modelUsage.contextWindow`
実測値を返すため、この 128,000 には依存していない（`chapters.ts:178-180` の
`harness.contextWindow?.() ?? options.contextWindow` でハーネス側が優先される）。
つまりこれは**畳みの頻度には影響しない、表示・情報提供上の欠陥**である
（`/api/model` の応答、および初回ターンの result 到着前の一瞬だけ効く
`bin.ts:1471` の `options.contextWindow` 初期値）。

## やってほしいこと

- `/api/model` が `vision` / `contextWindow` を返す際、**steward の backend が
  `pi` でない（`claude-agent-sdk` 等）ときに、無関係な代打モデルの値を
  その backend の値であるかのように出さない**ようにすること。
  - 実際の値が分からない場合（SDK からまだ実測が届いていない等）は、
    その事実が分かる形にする（例: フィールドを省く、あるいは
    「未計測」を表せる形にする）。**代打モデルの値で埋めない**のが要点。
  - 具体的な直し方（どこでガードするか・フィールドを省くかプレースホルダにするか）は
    実装者の判断に委ねる。ただし **1,000,000 のような具体的な文脈長を
    banto 側に新規のハードコード定数として書き込まないこと**
    （Anthropic 側の変更で腐る。上記背景3を参照）。
- `harness-backends.ts:112-119` のコメントの事実誤認（「文脈長が違う」）を訂正する。
  2026-08-14 の実測では `opus` と `opus[1m]` はどちらも `claude-opus-5` /
  `contextWindow: 1000000` で、モデル名（別名）は異なるが文脈長は同じだった。
