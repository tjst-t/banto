## 何が起きているか（2026-08-17 朝・番頭が env.verify で実測）

**main の型検査が落ちている。** 検証環境（profile test）で `npm run typecheck` を回した結果、**exit=2**：

```
tests/acceptance/trunk-folds-branch.spec.ts(196,26): error TS2339: Property 'text' does not exist on type 'TranscriptEntry'.
  Property 'text' does not exist on type '{ role: "branch"; branchId: string; }'.
tests/acceptance/trunk-folds-branch.spec.ts(214,26): error TS2339: Property 'text' does not exist on type 'TranscriptEntry'.
tests/acceptance/trunk-folds-branch.spec.ts(215,26): error TS2339: Property 'text' does not exist on type 'TranscriptEntry'.
```

この試験は **task-0234「幹から枝を畳める口（thread.fold）を足す」** が入れたもので、**マージ前ゲートは通っている**
（task-0234 の受け入れ条件に `npm run typecheck` が入っていなかったため、機械が一度も見ないまま着地した）。

**影響は大きい。** 夜に積んだ6本は受け入れ条件に「既存の全試験と**型検査**が通る」を持っているので、
**中身が正しくても全員がここで落ちる**。実際、職人の1人はこれを自分の変更のせいだと疑って6時間止まっていた。
**このタスクが通るまで、他のどのタスクも完成できない。**

## 原因（読んで確認すること）

`TranscriptEntry` は**判別可能なユニオン**で、`{ role: "branch"; branchId: string }` の枝には `text` が無い。
試験が `entries[i].text` を直接読んでいるため、ユニオン全体に対して `text` が無いと言われている。

## やること

**試験の側を、型で正しく絞る形に直す。**

- `role` で絞り込んでから `text` を読む（`if (e.role === "user")` / `filter` + 型ガード など、既存の他の spec の流儀に合わせる）。
- **確かめている中身は1つも弱めないこと。** この試験が守っているのは
  「**幹から枝を畳むと、枝の記録に結論の行が残る**」という task-0234 の肝である。

## やらないこと（**ここが肝**）

- **`as any` / `@ts-ignore` / `as unknown as ...` で黙らせない。** それは型検査を殺すのと同じで、次に同じ事故が起きる
- **確かめている条を消して通さない**（落ちている行を消せば緑にはなるが、task-0234 の中身が守られなくなる）
- **`packages/**` は1行も触らない。** 直すのはこの spec ファイル1本だけ（`TranscriptEntry` の型定義を変えるのは別の判断）
- 他の spec の整理・ついでの直し（P1）

## 走らせ方（いまの実態）

- **受け入れ基準に添えた検証コマンドは、Kobo が検証環境（あなたの外）で回します。**
  自分で一式（`npm test` / `npm run typecheck`）を叩かないこと——あなたは 2 GiB の袋の中にいて、一式を回すと袋ごと落ちます。
- **自分で叩いてよいのは軽い確認だけ**：`npm run test:one -- tests/acceptance/trunk-folds-branch.spec.ts`、
  1ファイルだけの型検査（`npx tsc --noEmit` は一式なので不可。`tsconfig.check.json` を使う型検査は Kobo に回させること）、
  `grep` / `git diff`。
- **急ぎの仕事です。** 直したら余計なことをせずに `report_done` を呼んでください。
