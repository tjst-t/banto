## 背景・目的

banto の検証環境（`test` プロファイルの docker コンテナ）では **Playwright のブラウザ（chromium）が使えず**、`npx playwright test tests/chat-ux.spec.ts` を含む受け入れ条件が、タスクの中身とは無関係に必ず落ちる（task-0283 の a1 で実測: `/root/.cache/ms-playwright/chromium_headless_shell-1234` が無いため chat-ux.spec.ts の48本が全部落ちた）。「環境を作り直す」では直らない——作り直しても同じ Dockerfile から同じブラウザ無しのイメージが立つだけだから。

リポジトリ自身の方針が `docker/Dockerfile.test` のコメントに「**足りない道具はホストに apt するのではなく、ここに書く**」とある。つまり正しい直しは検証イメージへ Playwright/Chromium を足すこと。これで今後 UI（playwright）の受け入れ条件を持つタスクもゲートで検証できる。

## 現状

- `docker/Dockerfile.test`: `FROM node:24-alpine` + `apk add git make g++ python3 docker-cli`。**chromium 無し**。
- `meta/environments.yaml` の `test` プロファイル: `setup: "npm ci --include=dev"`、cache は `[package-lock.json, docker/Dockerfile.test, docker/test.yaml]` → `/app/node_modules`。**Playwright ブラウザを入れない**。
- `docker/test.yaml`: `..:/app` を bind mount、node_modules を置き場から mount、`command: ["sleep", "infinity"]`。ドライバは `docker compose run --rm test sh -c <cmd>` で検証コマンドを回す。
- ルート package.json の devDependencies に `@playwright/test` は既にある（`npx playwright` は使える。ブラウザバイナリだけが無い）。

## 変更内容

1. `docker/Dockerfile.test` に Playwright の chromium と、alpine 上で動かすために必要なシステム依存を足す。
   - 方針: **ブラウザはイメージに焼き込む**（`RUN npx playwright install chromium` 相当）。検証のたびに再ダウンロードしないこと（acceptance の2条）。alpine（musl）で動く形にすること——`npx playwright install --with-deps chromium` が apk で依存を入れてくれるか、手動で apk パッケージを列挙するか、必要な方で。alpine で無理なら Debian 系イメージ（例: `node:24-bookworm-slim`）への土台変更も検討してよいが、その場合は cache 鍵の材料（Dockerfile.test）が変わって置き場は作り直されることを前提に、既存 acceptance への影響（Node 版・git 等の要件）を壊さないこと。
2. `meta/environments.yaml` の `test` プロファイル（必要なら setup）と `docker/test.yaml`（必要なら volumes）を、ブラウザがイメージ由来で使える形に合わせる。**検証コマンド（`npx playwright test`）が素のまま通るようにする**のがゴール。
3. `tests/chat-ux.spec.ts` の中身は変えない（既存の UI テストをそのまま通すのが目的）。

## 完了条件

- 検証環境（test プロファイル）の中で `npm run build:web && npx playwright test tests/chat-ux.spec.ts` が通る。
- ブラウザが毎回ダウンロードされない（イメージ or 置き場に永続化）。
- 既存の `npm test`（acceptance）と `npm run typecheck` が壊れない。

## 注意

- スコープ外（packages/banto-web の実装・tests/chat-ux.spec.ts の中身・Kobo/番頭核）は触らない。
- イメージのビルド時間は ttl（45分）内に収めること。重すぎるなら Debian 系への土台変更など現実的な解を選ぶ。
- このタスクの検証は、変更後の Dockerfile で立てる検証環境で回る（cache 鍵に Dockerfile.test が入っているので作り直される）。
