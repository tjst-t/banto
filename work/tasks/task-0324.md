## 背景

task-0307（コミット e11e2252「notice の全文注入をやめ、大きいものは栞へ退避する」）が追加した `tests/acceptance/notice-artifact-offload.spec.ts` が、**型検査を通らないまま main に入っている**。

番頭が いまの main に対して検証環境で `npm run typecheck` を回して確認済み（exit 2）。テスト自体は 2933件中 fail 0 で全部通っており、**落ちているのは typecheck だけ**。

`npm test` は typecheck を含むので、この状態が続くかぎり **banto の全タスクがマージ前ゲートで落ち続ける**。最優先で main を緑に戻す。

## 何が起きているか

`packages/banto-host/src/protocol.ts:580` の `TranscriptEntry` は判別 union で、変種のひとつ `{ role: "branch"; branchId: string; at?: string }` は **`text` を持たない**。spec はこれを絞らずに `.text` を読んでいる。

落ちている箇所（`tsc --project tsconfig.check.json` の出力そのまま）:

## やること

`tests/acceptance/notice-artifact-offload.spec.ts` **だけ**を直し、型で正しく絞る。

- `.text` を読む前に `role` で絞る、あるいは `"text" in entry` の型ガードを通す。既存の他の spec（`tests/acceptance/banto-threads.spec.ts` など）が同じ union をどう扱っているかを読んで、そこに合わせるのが望ましい。
- 190行目の `ServerEvent` も同様に、`threadId` を持つ変種へ絞ってから読む。
- **この spec が確かめている振る舞い（知らせの栞への退避）は変えないこと。** 型の絞り方だけを直す。テストの assert を弱めたり、ケースを削って通すのは禁止。

## やらないこと

- **`as any` / `@ts-ignore` / `@ts-expect-error` / 型アサーションでの握り潰しは禁止。** union をきちんと絞ること。
- `packages/banto-host/src/protocol.ts` を含め、**プロダクトコードは一切触らない**（スコープはこの spec 1本だけ）。型定義の側が悪いのではなく、spec の読み方が union に追いついていない。
- 他の spec、work/ 配下の起票ファイル、その他どのファイルも作らない・触らない。**incident の起票は番頭がやる**——職人が work/inbox/ にファイルを足すとスコープ違反でマージ前ゲートが落ちる。
