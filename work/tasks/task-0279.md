## 目的（PO 指示 2026-08-18）

職人や PO の発言に、Slack のように日時を入れる。日にちをまたいだら、Slack のように横線を入れて日にちが変わったことを分かるようにする。

## 前提（既存の取り決め・制約）

- **記録は UTC ISO、表示は出口で JST**（task-0180 で確立した方針）。記録側（thread-store 等）は `toISOString()` しか使わず、JST 変換は必ず表示の出口で行う。プロセスに TZ を立てる案は採らない。
- 既存の JST 表示（task-0180 系）と衝突しないこと。`views/ui.tsx` の `formatTime`（728行、`toLocaleString("ja-JP", { hour12: false, dateStyle: "short", timeStyle: "short" })`・ブラウザ任せ）は**触らない**。新しく JST 固定のフォーマッタを足すこと。
- **検証環境の器にブラウザが無い**ため、UI の機械検査（Playwright・`tests/` 直下の chat-ux.spec.ts 等）は回らない（imp-0068 の既知問題）。acceptance の機械検査はホスト側テスト・ビルド・型検査で守る。見た目は PO レビュー（review.policy は po）で確認する。
- banto-web の反映は `npm run build:web` だけで済む（web-assets.ts が dist を配る・再起動不要）。

## 実装内容

### 1. ホスト側：transcript の各エントリに時刻を付与

- `packages/banto-host/src/protocol.ts` の `TranscriptEntry`（578行〜）の各メンバに `at?: string`（ISO 8601 UTC、`new Date().toISOString()`）を追加する。既に `at` を持つ `branch_result` / `branch_note` / `chapter` はそのまま（上書きしない）。
- 保存の入口（`thread-store.ts` の `append`、232行付近）で、`at` を持たないエントリに現在時刻を付与する。記録済み・配信済みのどこで呼ばれても一貫して付くこと。
- `at` はオプショナルにする（既存の保存済み JSONL には at が無いため。UI は at が無ければ時刻を出さないだけで壊れないこと）。
- 即時表示のため、配信（`server.ts` の `po_message` broadcast 等）にも `at` が載るようにすること（記録と配信で同じ時刻を使う）。

### 2. web 側：発言に時刻、日付が変わったら横線

- `views/ui.tsx` に JST 固定のフォーマッタを追加（既存 `formatTime` は触らない）：
  - 時刻のみ：`14:05`（HH:mm、JST）
  - 日付：`8/18(火)`（JST）
  ※ タイムゾーンは `Asia/Tokyo` を名前付き定数1箇所に。
- `messages.tsx` の `ChatRow` で、**発言系**（`po` / `banto` / `notice` / `error`）の行に時刻（HH:mm）を表示する。`reasoning` / `tool` は発言ではないので時刻を出さない。`at` が無い行（過去の記録・ストリーミング途中）は時刻を出さない。
- **日付区切り線**（Slack 風）：横線＋日付（`8/18(火)`）の 1 行。共通コンポーネント（例: `DayDivider`）を messages.tsx（または views/ui.tsx）に置く。
  - entries を並べて描く所（**Room.tsx のチャット欄**と **ThreadHistory.tsx の履歴表示**）で、直前の行と日付が変わったら divider を挟む。最初の行の前にも出す。
  - 「今日 / 昨日」のような相対ラベルは今回は付けない（素朴に日付だけ）。
  - divider も `at` が無い行は区切り判定の対象にしない（前任の at と比較し、at が無い行は何も挟まない）。

## 完了条件

- 会話履歴（Room.tsx のチャット欄・ThreadHistory.tsx の履歴）で、発言（po / banto / notice / error）に JST 時刻（HH:mm）が付く。
- 日付が変わったところ（および最初の行の前）に、横線＋日付（8/18(火)）の区切り線が出る。
- 過去の記録（at が無い行）では時刻も区切り線も出ず、表示が壊れない。
- 既存の `formatTime`（ブラウザ任せ）の表示は変わらない。
