## 依頼

取次（inbox）の札の「この件の会話へ」を押しても、**その件の会話へ飛ばない**。直す。

## 原因（番頭がコードを読んで特定済み。ここから始めてよい）

二段構えで、**どちらも「移れ」と言っていない**。

1. **画面側** `packages/banto-web/src/App.tsx:302` `openInboxItem`
   - `session.openInbox(itemId)`（＝ホストへ `inbox_open` を投げる）を呼んだあと、`item.opens?.settings` があるときだけ `navigate({face:"settings"})` する。
   - **それ以外は `backToChat()` するだけ**。`backToChat` は `prev.threadId` をそのまま持ち越すので、**いま見ている会話のまま面を閉じる**＝「違う会話が開く」の正体。
   - すぐ上の `App.tsx:270` に `openThread(threadId, {focus})` があり、これが会話を移る正しい口（`session.switchThread` を呼ぶ）。**`openInboxItem` はこれを呼んでいない。**
   - `openInboxItem` の docstring「**会話と面はホストが動かす**。画面が受け持つのは『どの面を出すか』だけ」は**事実に反する**（下記2）。この嘘も直す。
2. **ホスト側** `packages/banto-host/src/server.ts:1938` `handleInbox`
   - `inbox_open` では `item.opens.threadId` の会話の**キャンバスを開くだけ**で `return`（`server.ts:1969`）。
   - **「この会話へ移れ」をクライアントへ送る型がプロトコルに無い**（`protocol.ts`）。ホストは画面の会話を動かせない。

**したがって直しは画面側で完結させる。ホストのプロトコルに型を足さないこと**（スコープ外）。

## やること

`App.tsx` の `openInboxItem` を、押した札が指す会話へ実際に移るようにする。

- `item.opens?.threadId` があるなら `openThread(item.opens.threadId)` を使う（`backToChat` を内包しているので二重に呼ばない）。
- `opens.settings` があるときの今の挙動（設定の面へ移り `section` を渡す）は**変えない**。会話と設定の両方を指す札（試験の `GRANT_ITEM`）は、**会話へ移ったうえで**設定の面を出す——片方だけ効かせない。
- **指す会話が既に畳まれている**とき（開いている幹・枝に無く `session.closedThreads` に在る）は**開き直さない**。`App.tsx:288` の `readThread(threadId)` と同じ＝履歴の面で読む形にする（PO 裁定「確認しに行っただけで開き直るのは事故」）。
- **指す会話がどこにも無い**ときは今のまま（`backToChat()`）でよい。
- 会話の横の `PendingDecisions`（`Inbox.tsx` 下部・`variant="chat"`）は**変えない**。その会話宛の札に導線を出さないのは既に正しい。

- 「知らせをまとめて閉じる」ボタンは**別のタスク**（同じ枝でもう1本積んである）。ここでは触らない。

## 検証について（**ここを読み違えないこと**）

**ブラウザ試験（Playwright）は、マージ前ゲートの器では1件も走らない。** 番頭が 2026-08-16 に実測した：`test` プロファイル（`docker/test.yaml`／`node:24-alpine`）で `npx playwright test` を回すと **152件すべて失敗**し、理由は `browserType.launch: Executable doesn't exist at /root/.cache/ms-playwright/...`。イメージ（`docker/Dockerfile.test`）にブラウザが入っておらず、そもそも alpine（musl）では chromium が動かない。

だから：

- **受け入れ条件の `verify` に `npm run test:ui` を書かないこと**（書くと、中身と無関係にゲートが落ちる）。
- **Playwright 試験は自分のワークツリー（ホスト側）で回す**：`npx playwright test tests/inbox-decisions.spec.ts --reporter=line`。**結果を報告に貼る**（何件通った／落ちた、落ちたものは自分の変更由来か）。
- ブラウザ試験は **inc-0071 で恒常的に9件赤い**。丸ごと回すなら「元から赤い分」と「自分の分」を**分けて**報告すること。
