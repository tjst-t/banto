## 背景（番頭が稼働中の main で確かめた事実）

task-0293（`packages/banto-environment-pool`、コミット 1f49613d）で、照合の結果は3つに分かれるようになった:

- 生きている台帳エントリに一致 → 何も言わない
- **畳み済みエントリに一致 → 孤児ではなく「畳み損ね」。新しい出来事種別 `env_teardown_incomplete` を積む**（event-log.ts:44 / pool.ts:288,508-521,804）
- 台帳のどこにも無い → これまでどおり `env_orphans_found`

ところが番頭側の描画（`packages/banto-host/src/env-notice.ts`）は `env_teardown_incomplete` を知らない。`renderEnvNotice` は if 連鎖で、最後は `return undefined`（env-notice.ts:174 付近）。つまり **`env_teardown_incomplete` は会話に一行も出ない**。

これは task-0293 の前より悪い状態になり得る。以前は「畳み損ねの実体」も（誤った文面ではあるが）`env_orphans_found` として鳴っていた。いまは **Banto 自身のリソースが外に残り続けていても、誰にも届かず無言で消える**。畳み損ねは費用が出続ける事象なので、黙ってはいけない。

## やること

`renderEnvNotice`（packages/banto-host/src/env-notice.ts）に `env_teardown_incomplete` の分岐を足す。文面の条件:

- **「Banto 以外が作ったものかもしれない」という言い方をしないこと。** 台帳に載っている＝持ち主は分かっている。「Banto が作り、畳んだ印も付いているのに、実体がまだ残っている」と書く。
- 残っている実体の名前とドライバを並べる（`env_orphans_found` の分岐と同じ体裁でよい）。分かるなら envId・taskId も添える。積まれるデータの形は `packages/banto-environment-pool/src/pool.ts` の該当ブロック（`type: "env_teardown_incomplete"` を積んでいる箇所）を読んで、実際のキーに合わせること。**憶測で書かない。**
- 求める判断は「`env.teardown` を試し、それでも消えないなら手で片付ける」方向にする。**`env.teardown_orphan` を案内しないこと**——これは孤児の一覧（orphanList）だけを対象にしており、畳み損ねはそこに載らないので、案内しても効かない。
- 費用が出続ける事象であることを一言添える（`env_teardown_failed` の文面が参考になる）。

## やらないこと

- `packages/banto-environment-pool` 側は触らない（task-0293 で入ったばかりで、そちらは正しい）。
- 機構が自動で畳む口は作らない（2026-08-08 の PO 裁定は据え置き）。
- if 連鎖を switch へ書き換えるといった、この件と関係のない整形はしない。
