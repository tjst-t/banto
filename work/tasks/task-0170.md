## 背景

task-0155 で SKILL `safe-restart` に「どのサービスを起こし直すのか」の対応表が入った。
いまそこに載っているのは**3ユニット**：

| 直したファイル | unit | 起こし直し方 |
|---|---|---|
| `packages/banto-host/**` | `banto.service` | `system.restart` |
| `packages/banto-worker-pool/**` | `banto-worker-pool.service` | `kill -9` |
| `packages/banto-environment-pool/**` | `banto-environment-pool.service` | `kill -9` |

**`banto-daemon.service`（＝Kobo。工場の帳簿・マージキュー・`kobo.*` の実体）が抜けている。**
`deploy/banto-daemon.service` は現に存在し（`ExecStart=… packages/banto-daemon/src/index.ts`・
`Restart=on-failure` / `KillMode=mixed`）、他の3つと同じく `--import tsx` で main の
チェックアウトを直に読む。

**現に踏んでいる。** 直前の task-0157 で `packages/banto-daemon/src/kobo-tools.ts` の
`kobo.approve` の説明文を直したが、**Kobo を起こし直すまでその説明文は反映されない**。
表に無いので、次に同じ場面へ来た人は「main に入ったのに変わらない」で止まる
——これは inc-0073（環境まわりを直したのに `env.verify` が古いままだった）と同じ形である。

## やること

### 1. `packages/banto-host/skills/safe-restart/SKILL.md`
- 対応表に **`packages/banto-daemon/**` → `banto-daemon.service`（Kobo：工場の帳簿・
  マージキュー・`kobo.*` の実体）→ `kill -9`** の行を足す
- 本文とフロントマターの `description` にある「**3つの常駐サービス**」「3つのユニット」を
  **4つ**に直す（数が本文と表で食い違わないこと）
- `kill -9` の手順は既存の節をそのまま使えるので**重複して書かない**——unit 名を差し替える
  だけでよい、と読める形にする（`banto-daemon.service` も `Restart=on-failure` /
  `RestartSec=5` である）
- **`kobo.*` の説明文や札の文面を直しても、Kobo を起こし直すまでは番頭に届かない**ことを
  1行添える（task-0157 が実例）

### 2. `tests/acceptance/restart-blast-radius.spec.ts`
既存の it は消さず、**SKILL に4つの unit 名と4つの package 名が揃っていること**を見るよう
広げる（いまは3つずつを要求している）。`deploy/*.service` を見ている既存の検査
（`BindsTo` / `PartOf` が空・`banto.service` に縛られていない）に
`deploy/banto-daemon.service` を足すかどうかは**任意**——足すなら、そのユニットも
`BindsTo` / `PartOf` を持たないことを実際に確かめてからにすること。
