## 背景（実測）

PO が 2026-08-20 04:11 に会話のモデルを Claude へ切り替えた（journal: `[banto] backend(thread-61): claude-agent-sdk / opus[1m]`、`backend(thread-59): claude-agent-sdk / opus[1m]`）。設定ファイルは全て Claude になっている（`/var/lib/banto/model-roles.json` の steward/worker.* は claude、`/var/lib/banto/settings.json` の chapterModel は claude-agent-sdk|claude|haiku、`/var/lib/banto/data/kobo-settings.json` の roleAssignments は opus/sonnet）。

にもかかわらず、幹 thread-61 は**切替後のターンでも毎回** `402: Insufficient credits`（OpenRouter）で失敗として記録され、会話に error 行が積まれ続けている（turns.jsonl: 04:12/04:15/04:26/04:33/04:35/04:45/04:51/04:53 すべて ok:false）。

**しかしこれは新しい OpenRouter 呼び出しではない。** 根拠3つ:

1. `packages/banto-host/src/bin.ts:1958` — `getLastError: () => session.agent.state.errorMessage`。**常に pi セッションの状態を読む**。ハーネスを claude-agent-sdk へ切り替えても、`piHarness` と `claudeHarness` は別オブジェクト（bin.ts:1718-1738）で、`session.agent` は pi のまま。pi はもう走らないので、最後に残った errorMessage が**永久に消えない**。
2. `packages/banto-host/src/server.ts:1106-1108` — ターン終了時に `thread.getLastError()` を引き、値があればそのターンを失敗として記録し、`role: "error"` の行を会話へ積む。**返答本文が出た直後に error 行が付く**（thread-61.jsonl で実測：banto の本文行 → error 行の並びが5回連続）。
3. 所要時間が合わない。本物の課金エラーは1秒以内に落ちる（thread-217 の opencode 401 は 802ms / 1063ms）。thread-61 の「失敗」ターンは 27〜70秒＝Claude が実際に応答を書き切っている時間。
4. 別の幹でも同じ形が出ている。thread-59（帳場・同時刻に Claude へ切替）は毎ターン `Request was aborted` で失敗記録——**その会話の pi 側に最後に残っていたエラーがそのまま貼り付いている**。

## 直すこと

ターンの成否は「**いまそのターンを回したハーネス**」の状態から取る。少なくとも次のどちらか（実装者の判断で選ぶ）:

- ターン開始時に直前のエラー状態をクリアしてから回す（そのターンで起きたことだけが残る）
- あるいは `getLastError` を能動ハーネス側へ委譲し、pi の状態を読まない

**pi 単独の会話ではこれまで通りエラーが出ること**（握り潰しにしない・I2）。エラーを消すのではなく、**別のターンの結果を使い回さない**のが直しの中身。
