Worker Pool 並行制御のリソースベース化（設計書 work/reports/2026-08-17-worker-resource-based-concurrency.md）の一環として、各ランタイムの想定消費リソースを定義し、環境変数で上書きできるようにする。

## 背景
リソースベース判定には、各ランタイム（Pi / Claude）が起動時にどれだけのメモリを想定で消費するかの値が必要。既定値は PO 確定済み。

## 目的
- `RuntimeRegistration` に `assumedResources: { memoryMiB: number; cpuFraction?: number }` を追加する
- `bin.ts` で以下の環境変数を解決し、`WorkerPoolOptions` 経由で pool に渡す:
  - `BANTO_WORKER_PI_MEMORY_MB`（既定 300）
  - `BANTO_WORKER_CLAUDE_MEMORY_MB`（既定 1200）
  - （第2段用）`BANTO_WORKER_PI_CPU_FRACTION`, `BANTO_WORKER_CLAUDE_CPU_FRACTION`
- `WorkerPoolOptions` にリソース設定を追加する

## 完了条件
- `backends.ts` の `RuntimeRegistration` に `assumedResources` があり、既定値が設定されている
- `bin.ts` が新しい環境変数を解決し、pool コンストラクタへ渡している
- 環境変数で想定値を変えたとき、pool の設定に反映される

## 制約
- pool.ts の起動判定ロジック自体はこのタスクでは変更しない（タスク C で行う）
- CPU 関連は第2段なので、型と環境変数の枠だけ準備し、判定には使わない

## 監査人への申し送り
- 判定は必ず `audit_report` ツールで出してください。テキストや箇条書きだけでの報告は、機構が判定を受け取れず failed になります。
- `npm test` / `npm run typecheck` / `npm ci` といった一式は、マージ前ゲートが検証環境で回します。監査人は自分で起動しないでください（2 GiB メモリ上限で落ち、audit_report も出せなくなります）。
- 監査人が行ってよいのは、軽い読み合わせ（`git diff`、`grep`、1ファイルだけの `npm run test:one`）のみです。
