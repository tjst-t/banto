## 背景（あなたは記憶を持たないので全部ここに書きます）

`system.deploy` は main のチェックアウトに対して `npm test` を回し、**通ったときだけ** `banto.service` を起こし直す仕組みです。実装は `packages/banto-host/src/deploy-verify.ts`。

2026-08-20 08:15:34 に実際にデプロイが拒否されたとき、番頭に返ってきた「落ちた箇所」がノイズ行ばかりで、**どの spec が落ちたのか分からず**、生ログも残っていないため事後の切り分けも不能でした。

その直しのうち一部は **task-0299 が既に着地させています**（コミット 32be3dd2、main へ 2026-08-20T08:57:58Z マージ済み）。入ったのは:
- `execFile` に `maxBuffer: 64MiB` を明示（別の本命バグ）
- `FAILURE_MARKERS` から素の `Error:` を除去
- 失敗時に生ログを `os.tmpdir()` へ書き、パスを報告に載せる

**このタスクは、その後に残っている穴だけを塞ぐものです。原因は下に実測で書き切ってあるので、調べ直す必要はありません。**

## 残っている穴（2026-08-20 に現物と機械検証で確認済み）

いまの main の `extractFailures` / `persistRawLog` はこうなっています:

```ts
const FAILURE_MARKERS = /(fail [0-9]+|# fail|not ok|✗|FAILED|AssertionError|npm ERR!|failing tests?)/i;

function extractFailures(output: string, exitCode: number): string {
  const lines = output.split("\n");
  const hit = lines.filter((line) => FAILURE_MARKERS.test(line.trim()));
  const shown = hit.slice(0, 30);
  if (shown.length > 0) return `落ちた箇所:\n${shown.join("\n")}`;
  return `終了コード ${exitCode} で失敗（fail 行は拾えなかった）`;
}

function persistRawLog(output: string): string {
  const file = path.join(os.tmpdir(), `banto-deploy-verify-${Date.now()}.log`);
  fs.writeFileSync(file, output, "utf8");
  return file;
}
```

### (1) ノイズと合格行がまだ誤検知される【検証環境で実測】

上の正規表現に実際の行を通した結果（`node -e` を検証環境で実行）:

```
HIT  | noise-A: [banto-daemon] 検証環境の写しを取り直せませんでした: Failed to reach module "environment-pool" at http://127.0.0.1:1/...
miss | noise-B: [banto] module "environment-pool" への接続に失敗（...）: Error: connect ECONNREFUSED 127.0.0.1:1
miss | noise-C:   reason: verify_env_unavailable
HIT  | pass-line: ✔ [AC-S654396-3-1] returns FAILED status when not_found (12ms)
HIT  | pass-line: ok 3 - handles failing tests gracefully
HIT  | real:      not ok 2 - some spec
```

- **noise-A がまだヒットします**。`FAILED` に `i` フラグが付いているため `Failed to reach module` の "Failed" に一致します。これは 08:15:34 の実障害で報告を埋めた2種類のノイズのうちの片方そのものです。
- **合格行がヒットします**。`✔ ... returns FAILED status` は "FAILED"、`ok 3 - handles failing tests gracefully` は "failing tests" に一致します。
- noise-B（ECONNREFUSED）は task-0299 が素の `Error:` を外したことで解決済みです。

### (2) キャップで消えたことが分からない

`filter` → `slice(0, 30)` の順序自体は正しいのですが、(1) のノイズと合格行が filter を通ってしまうため、**先頭30件がそれらで埋まると本物の失敗が報告から消えます**。しかも**消したことが報告に出ません**。

### (3) 生ログが揮発する置き場にある

`os.tmpdir()` は再起動や tmpfiles の掃除で消えます。デプロイ拒否の事後切り分けは数時間〜数日後になることがあるので、**永続ディレクトリに置く必要があります**。保存先を差し替える口も無いため、テストが実ディレクトリを汚さずに検証できません。

### (4) 生ログの保存失敗が判定を壊す【重要】

`persistRawLog` の `fs.writeFileSync` は **try/catch に包まれていません**。`runDeployVerify` の `catch` ブロックの中で呼ばれているため、**書き込みが失敗すると例外がそのまま `runDeployVerify` の外へ抜けます**。ディスクが一杯・権限が無いというだけで、「検証が落ちた」という判定を返す代わりに例外が飛びます。ログが書けないことでデプロイ判定が壊れてはいけません。

## やること

`packages/banto-host/src/deploy-verify.ts` を次のように直します。

### (1) 合格行と既知ノイズを明示的に除外する
- **合格行**: 行頭（trim 後）が `✔` / `✓` で始まる行、および TAP の `ok ` で始まる行は、何が書いてあっても失敗行とみなさない。`not ok` は当然これに当たらないこと（`ok ` の前方一致で `not ok` を巻き込まないよう注意）。
- **既知ノイズ**: `Failed to reach module` を含む行、`ECONNREFUSED 127.0.0.1:1` を含む行、`への接続に失敗` を含む行、`verify_env_unavailable` を含む行。
- **除外は名前を付けた関数に切り出すこと**（`isKnownNoise` / `isPassLine` 等）。将来ノイズが増えたときに足す場所が一目で分かるようにするためです。
- `i` フラグの扱いは任せますが、`FAILED` が `Failed to reach` に当たるような誤検知を減らす方向で判断してください（必要なマーカーだけ大小両方を明示的に書く手もあります）。

### (2) キャップの当て方
- 上限（30件）は**除外を済ませたあと**に掛ける。
- 上限で打ち切ったときは、報告に「他に N 件」と件数を出す(消えたことが分かるように)。

### (3) 生ログの置き場を永続化し、差し替え可能にする
- 置き場所は `process.env.BANTO_DATA_DIR ?? "/var/lib/banto"` の下の `deploy-verify/`。ファイル名は `deploy-verify-<ISO8601 の : を - に置換>.log`。ディレクトリは `mkdir -p` 相当で作る。
- 保存先は `runDeployVerify` の**第3引数の任意オプション**（例 `{ rawLogDir?: string }`）で差し替えられるようにする。既定値は関数の中で決め、**`bin.ts` / `deploy-gate.ts` 側の呼び出しは無改修で動くこと**（どちらもこのタスクのスコープ外・変更禁止）。

### (4) 保存失敗を握らない・落とさない
- 保存に失敗しても**検証結果は返す**。例外を外へ抜けさせない。
- ただし黙って捨てるのではなく、報告に「生ログの保存に失敗: <理由>」と1行足す(I2 に言う「握り潰し」にしない)。

## やらないこと
