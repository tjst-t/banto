## 背景：なぜ今まで気づかなかったのか

`tests/chat-ux.spec.ts` は Playwright の実ブラウザを要するのに、**マージ前ゲートの検証コンテナに chromium が入っていませんでした**。そのため48本は一度も実行されず、赤が育っても誰にも見えていませんでした。task-0286 で chromium を器に焼き込んだ結果、初めて全48本が走り、**43本 pass / 5本 fail** が明らかになりました。

**この5本は task-0286 が壊したものではありません。**main に元から在った赤です。

5本のうち4本が**モデル選択まわり**（`.model-select-item` 等が0件・見つからない・タイムアウト）です。

## 原因の見当（**鵜呑みにせず実測で確かめること**）

直近の main に、モデル選択の隣へ「思考レベル選択」を足す変更が入っています：

- `b12a96bf` feat(chat): モデル選択横に思考レベル選択を追加。set_model/model_state に thinking を通す
- `4395f15f` feat(settings): 思考レベルの選択肢をモデル（バックエンド）に応じて出し分け、チャットの思考レベル選択をモデル選択とデザイン整合

この改修で **DOM の構造やクラス名（`.model-select-item` など）が変わり、テスト側の locator が当たらなくなった**可能性が高い。5番（送信ボタンの姿）も同じコンポーザ周りの改修の巻き添えの疑いがあります。

## やること

1. **まず失敗を再現する。** ローカルで `npm run build:web && npx playwright test tests/chat-ux.spec.ts` を走らせ、5本が同じ理由で落ちることを自分の目で確認する（ゲートの器には task-0286 で chromium が入っています）。
2. **1本ずつ、「アプリが壊れているのか」「テストが古いのか」を判定する。** ここが本題です。
   - **アプリの挙動が仕様どおりでないなら、アプリ（`packages/banto-web/src/**`）を直す。**
   - **テストが改修に追従できていないだけなら、テストを直す。**
   - **P3（黙って合わせない）を守ること。** 落ちているテストを通すためだけに assert を緩める・消す・skip するのは禁止です。テストが守っていた性質は、直したあとも同じ強さで守られていること。
   - どちらか判断が付かない1本があれば、**その1本だけを明確な日本語で報告して待ちを解いてよい**（残りは進めてよい）。
3. **5本すべてを緑にする。** 除外・skip・`test.fixme` は使わないこと（a1 は除外なしの全48本で判定します）。
4. `npm test && npm run typecheck` も緑のまま保つこと。
