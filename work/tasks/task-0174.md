## 依頼（PO 原文）

> 確認すればいいだけのお知らせまとめてクローズするボタンを「これより下はお知らせ」って書いてるところの**同じ高さの右側**においてください。

## いまの作り（前提。職人は記憶を持たないのでここに書き切る）

取次の面は `packages/banto-web/src/Inbox.tsx` の `InboxFace`。中身を3段に分けている（ADR-0022 決定110）。

```ts
const decisions = items.filter((i) => !i.resolvedAt && !i.notice); // 判断（上・数える）
const notices   = items.filter((i) => !i.resolvedAt &&  i.notice); // 知らせ（中・数えない）
const done      = items.filter((i) =>  i.resolvedAt);              // 答えが出たもの（下）
```

段の頭には区切りが出る：

```tsx
<div className="ib-sep">これより下は、知らせ（読めば片付きます）</div>
<div className="ib-sep">これより下は、答えが出たもの</div>
```

**この1本目の区切り行と同じ高さ・右側**にボタンを置く、というのが依頼。

札は `Letter`。答えるのは `onAnswer(itemId, actionId)`（`InboxFaceProps`）で、押すとホストへ `inbox_answer` が飛ぶ。

**知らせ（`notice: true`・決定109）は判断ではない**：
- 判断待ちの数（`inboxPending`／レールの朱の数字）に入らない
- 選択肢は「了解」1つだけ、という約束で積まれている（例：`packages/banto-host/src/threads.ts:704` の再起動報告は `actions: [{ id: "ack", label: "了解" }]`）
- 答えても**番頭のターンは回らない**（`packages/banto-host/src/server.ts:2029` の `if (answered.notice) return;`）。だから**まとめて閉じても番頭を無駄に起こさない**

## やること

1. **区切り行を、左に文言・右にボタンの1行にする**（同じ高さ）。ボタンの文言は件数を出す（例「お知らせ 12件をまとめて閉じる」）。件数の出し方・語尾は実装者の判断でよいが、**何件消えるのかが押す前に分かる**こと。
2. 押したら、**その時点で閉じられる知らせを全部**答える＝各札について `onAnswer(item.id, <その札の唯一の選択肢の id>)` を呼ぶ。
   - **ホストは触らない。プロトコルに型を足さない**（`inbox_answer` を件数ぶん投げるだけでよい。知らせは番頭のターンを起こさないので、押し込んでも会話は荒れない）。
3. **閉じる対象の線引き**（ここが一番大事・PO 指示）
   - 対象は **`!resolvedAt && notice === true` の札だけ**。**判断を求めている札（`notice` でないもの）は絶対に巻き込まない。**
   - `notice` は既に機構のデータに在る区別（`InboxItemView.notice`・決定109/110）なので、**新しい印を足さずこれで切る**。
   - **選択肢が2つ以上ある知らせは巻き込まない**（安全側に倒す）。まとめて閉じるとき「どれを選んだことにするか」を機械が決めてよいのは、選択肢が1つしかないときだけ。**巻き込まないものは件数にも数えない**——数字と結果が食い違わないこと。
   - 結果として閉じられるものが0件なら、**ボタンを出さない**（押せるのに何も起きない、を作らない）。
4. 見た目は既存の意匠に合わせる（`btn btn--ghost` 系・`ib-sep` の行組み）。`styles.css` に足すのは区切り行を左右に組むための最小限。

## やらないこと（スコープ）

- ホスト（`packages/banto-host/**`）は触らない。
- 「答えが出たもの」の区切りには**ボタンを付けない**（依頼は知らせの段だけ）。
- 判断の段の絞り込み・並び・件数の意味は変えない。
- `App.tsx` は触らない（**同じ枝の `task-0173` が触っている**。この仕事は `task-0173` の着地後に始まる `depends` を付けてある）。
