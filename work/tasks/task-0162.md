## 背景（前提。あなたは記憶を持たないので、ここに書いてあることが全部）

banto ホスト（`banto.service`）が OOM killer に繰り返し殺されている（2026-08-15 だけで4回以上）。**プロセスが書き込みの途中で殺されるので、追記ログの最終行が千切れる**ことが実際に起きる。

`packages/banto-host/src/turn-log.ts:143-147` 付近の読み込みが、行の JSON パースに失敗したとき `catch {}` で**何も出さずに飛ばしている**。壊れたことに誰も気づけない。banto の作法 I2（例外を握り潰さない）に反している。

同種の箇所として `packages/banto-host/src/thread-store.ts` の `transcript()` があるが、**そちらは別タスクで扱うのでこのタスクでは触らないこと**（スコープにも入れていない）。

## やること

1. `turn-log.ts` の読みで、パースできない行を**無言で飛ばさない**。何行目が読めなかったかが分かる形で警告を出す（既存のログの出し方＝`console.error("[banto] …")` の流儀に合わせる）。**読めた行は今まで通り全件返す**（1行のために全部を失わない）。
2. **末尾に改行が無い＝プロセスが書き込みの途中で殺された「千切れた最終行」を検出**し、それが起きた旨を警告に出す。千切れ行を除いた残りは正常に返すこと。
3. 例外は握り潰さない。ただし**読みが失敗しただけでホストが起動しなくなる形にはしないこと**（警告を出して続ける）。

## やらないこと（スコープ外）

- `thread-store.ts` の `transcript()`（別タスク）
- 書き込み側を原子的にする話（別タスク）
- ログの形式そのものの変更・退避ファイルの実装

## 完了の確かめ方

受け入れテストを `tests/acceptance/` に置く。既存の流儀（テストランナー・一時ディレクトリ・後片付け）を先に読んで合わせること。**`/var/lib/banto` の実データには絶対に触らないこと**（いま PO の記録の復旧作業が走っている）。
