## 背景（前提を全部ここに書く。あなたは記憶を持たない）

2026-08-16、banto の開発機で docker のアドレスプールが枯渇し、**工場のマージ前ゲートが検証環境を立てられずに全部落ちた**。

```
docker compose up failed: Error response from daemon:
  all predefined address pools have been fully subnetted
```

`banto-env-*` のネットワークが **27本**、コンテナが **31件（全部 Up）**残っていた。
一方 banto の台帳（`env.list`）が知っていたのは **4件だけ**。

残りを1件ずつ調べた結果（inc-0083 に実測が全部載っている。**先に読むこと**）：

- **20件**が `tests/fixtures/docker` 由来の**受け入れ試験の取り残し**
  （`busybox:latest` で `httpd` が `ok` の1行を返すだけ／マウント無し／ポート 4200 を 32873〜32897 に公開）
- **3件**が `/tmp/banto-rebuild-*` 由来の**リビルド試験の取り残し**
- しかも **task-0175 のワークツリーは既に消えている**のに、そこから立った6件は動き続けていた

**つまり、テストが自前で compose を起こし、後片付けに失敗している。**
消して回っても、テストを回せばまた増える。**ここが本体。**

**なお 2026-08-16 の夕方にも、番頭が名指しで残骸を消す掃除を再度している**（1日に2回同じ掃除をした）。**手で消して回るのを止めるのがこのタスクの目的である。**

## やること

1. **inc-0083 を読む**（`work/inbox/incident/inc-0083-orphan-detection-does-not-see-docker.md`）。実測の表がそのまま載っている。
2. 名指しの4本の spec を読み、**compose プロジェクトを立てている箇所を全部洗い出す**（`env.provision` 経由も、直接 `docker compose up` を叩いているものも）。
3. **どこで落ちても畳まれる形に直す**。要点：
   - 後片付けを `try { ... } finally { teardown() }`、または `afterEach` / `afterAll` / `t.after()` に置く。
   - **テストの最後の行に `teardown()` を書くのは不可**——アサーションが落ちた瞬間に到達しなくなる。今回の残骸はこの形だったと見られる。
   - **畳む処理自体が失敗しても、残りの畳む処理を続ける**（1件目の teardown が投げて2件目以降が実行されない、を防ぐ）。
   - 立てたプロジェクト名を配列に控え、まとめて畳むヘルパを `tests/helpers/compose-cleanup.ts` に置いてよい（新規作成可・scope に入っている）。
4. **番人テストを1本足す**: `tests/acceptance/env-tests-teardown-their-compose.spec.ts`
   - 名指しの4本の **spec ファイルの中身を文字列として読み**、「compose を立てる呼び出しがあるのに、対になる後片付け（finally / afterEach / afterAll / t.after）が無い」ものを**落とす**。
   - **docker は使わないこと**（検証環境の中から docker には届かない。静的な検査で完結させる）。
   - この番人は `env-docker-` で始まらない名前なので `npm test` に含まれる＝**次に誰かが後片付けを外したら気づける**。
   - **形骸化させないこと**: 後片付けを1つ外した状態で番人が実際に落ちることを自分で確かめ、報告に書く。

## やらないこと

- **既に残っているコンテナ・ネットワークを消さない**（別途、番頭が名指しで片付け済み。**`docker system prune` の類は絶対に打たないこと**）。
- `package.json` の `npm test` の除外リストは**この仕事では触らない**（scope 外）。
- 孤児検出そのものの直しは**別タスク**。ここでは触らない。
