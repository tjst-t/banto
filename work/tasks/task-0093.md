## 背景

PO 裁定（2026-08-11・第0波 0-2）: 検証プロファイルを「実行環境用」と「検証用（dev）」に分ける案Bを採用。

現在の `meta/environments.yaml` では `test` と `dev` の2プロファイルが定義されているが、
`docker/dev.yaml` には task-0089 修正前の暫定回避策（command 前置の `npm ci`）が残っている。
本体で provision の順序が修正された（task-0089）ため、この回避策は不要になった。

また task-0075 で「Kobo の検証は検証環境の中でだけ回す」方式になっており、
検証基盤の変更は Kobo に積まない制約がある（職人警告）。
このため、プロファイルの整理は Kobo の外で直接行う。

## スコープ拡張（PO 裁定 2026-08-11・案A）

監査で a4 の typecheck が基底コミット a1b835d 由来の既存バグで落ちることが判明
（tests/acceptance/kobo-worker-integration.spec.ts が Array.prototype.findLast（ES2023）を使用、
tsconfig の target が ES2022 のまま → TS2550）。PO 裁定により本タスクのスコープへ
`tsconfig.json` / `tsconfig.check.json` を追加し、typecheck を直す（推奨: target を ES2023 へ、
または lib に es2023 を追加。Node 22 は ES2023 対応）。
