## これは task-0229 の積み直しです

task-0229 と中身は同じで、**スコープに `packages/banto-host/src/thread-tools.ts` と `packages/banto-host/src/presented-tools.ts` を足してある**のが違いです（PO 裁定・取次 in-01a01087）。task-0229 の職人が正しく指摘したとおり、帳簿（threads.ts）に関数を足すだけでは**番頭が呼べる口が生えません**——道具は `thread-tools.ts` の `createThreadTools` で定義し、`presented-tools.ts` の `PRESENTED_TOOL_NAMES` に名前を載せて初めて番頭に見えます（載っていないものは「在庫に残るが番頭には見えない」＝決定83）。task-0229 のワークツリーの書きかけは**引き継げません**。ここで書き直してください。

## 何が困っているか（PO の実観測・2026-08-16）

**幹（番頭）には、枝を畳む口がありません。**

- `thread.merge` は**「いまのこの枝」**を畳む口で、**幹からは呼べません**（幹は畳めない）。
- したがって幹にできるのは **`thread.steer` で「畳んでください」と頼むこと**だけ。**枝は知らせが来ないと動かない**ので、頼んでも動くとは限らず、幹は待つしかありません。
- **今日、開いたままの枝が10本以上たまり、PO の画面のレールが枝の丸で埋まりました。** 中身はほとんど「仕事は終わって結論も書いてあるのに、知らせで開き直されたまま畳み直されていないもの」です（開き直しの畳み直しは task-0228 が直しますが、それでも「幹の判断で終わらせたい枝」は残ります——もう追わないと決めた調査、前提が変わって無意味になった枝など）。

## やること

**幹から枝を畳む口を1本足す**（名前は `thread.fold` を推す。既存の `thread.settle` と同じ形に揃えること）。

- **帳簿**：`threads.ts` に畳む処理を足す。
- **口**：`thread-tools.ts` の `createThreadTools` に道具として定義する。**`presented-tools.ts` の `PRESENTED_TOOL_NAMES` にも名前を足す**（載せないと番頭からは見えない）。並びは thread 系の道具の近くへ。
- **幹（親）からだけ呼べること。** **他人の幹の枝は畳めない**こと（`thread.settle` と同じ制約に揃える）。
- **結論を必ず書かせること**——引数に結論（1行）を必須にする。畳んだ理由が空の枝を作らない。**枝が自分で書いた結論がある場合は、それを消さないこと**（幹の結論は「幹が畳んだ」ものとして分かる形で残す）。
- **枝が走行中（ターンが回っている最中）のときは畳まない**（断る）。理由：途中で切ると、その枝が起こした職人や書きかけの記録の所在が消えます。**「走行中なので畳めない」と分かる断り方**にすること。
- **残作業（`remaining`）を持っている枝を畳むときは、幹も所在を書けること**（`thread.settle` と同じ考え方）。書かずに畳めてしまうと、所在の無い残作業が生まれます。
- **畳んだことが枝の記録に残る**こと（誰が畳んだのか＝幹が畳んだ、と読めること）。
- 口の説明文（道具の description）は、他の thread 系の道具と同じ調子で日本語で書くこと。`bin.ts` のプロンプトにも一行足して、幹が「頼む」以外に「畳める」ことが読めるようにする。

## 気をつけること

- **幹を畳めてしまわないこと**（幹は畳めない、は維持）。
- **`/var/lib/banto` 以下の実データに触らないこと。** 試験は必ず一時ディレクトリで。
