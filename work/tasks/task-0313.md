## 背景（あなたは記憶を持たないので全部ここに書きます）

`system.deploy` は main に対して `npm test` を回し、**通ったときだけ** `banto.service` を起こし直します。実装は `packages/banto-host/src/deploy-verify.ts` の `runDeployVerify` / `extractFailures`。

2026-08-20 に実際にデプロイが拒否されたとき、返ってきた「落ちた箇所」34行が**ほぼ全部ノイズ**で、どの spec が落ちたのか分かりませんでした。その直しは2本入っています:

ノイズ3行と `✔` 合格行3行は**正しく落ちました**（task-0311 の成果）。残った問題は2つです。

### (1) `▶` の見出し行が除外されていない

`isPassLine` が見ているのは `✔` / `✓` / `ok ` だけですが、**node:test は describe / suite の見出しを `▶` で出します**。上の4行目がそれで、本文の「failed」が `FAILURE_MARKERS` の `FAILED`（`i` フラグ付き）に一致してしまいます。合格した suite の見出しなので失敗ではありません。

実生ログでは、現行の正規表現がヒットする**先頭30件の9行目**がまさにこの行でした。

### (2) `✖`（U+2716）が失敗の目印に入っていない

`FAILURE_MARKERS` に入っているのは `✗`（U+2717）で、**node:test が実際に使う `✖`（U+2716）とは別の文字**です。そのため上の報告に、**落ちたテストの名前が1行も出ていません**。

実生ログでは、本物の失敗はこう出ていました:

```
13534	✖ BANTO_BROWSER_ALLOW_NO_SANDBOX が無ければ --no-sandbox は入らず、status も enabled (118.203175ms)
13535	  AssertionError [ERR_ASSERTION]: 既定なのに --no-sandbox が入っている

13550	  AssertionError [ERR_ASSERTION]: Expected values to be strictly equal:
```

`AssertionError` の行だけでは**どのテストが落ちたのか分かりません**。このタスク群の目的は「次に落ちたとき現物を掴めるようにする」ことなので、テスト名が出ないままでは目的を達しません。

## やること

`packages/banto-host/src/deploy-verify.ts` を次のように直します。**小さい変更です。**

1. **`▶` を除外に足す。** `isPassLine` に足すのが素直ですが、意味が「合格行」ではなく「見出し行」なので、`isSuiteHeading`（`▶` で始まる）として別の名前付き関数に切り出すか、`isPassLine` を `isNotAFailureLine` のような名前へ改めるか、**どちらでも構いません**。判断は任せます。ただし**なぜ除外するのかがコードから読めるようにすること**。
2. **`FAILURE_MARKERS` に `✖`（U+2716）を足す。** 既存の `✗`（U+2717）は消さないこと（他のランナーが使う可能性があるため）。`✖` を含む合格行は存在しないので、除外規則とは衝突しません。
