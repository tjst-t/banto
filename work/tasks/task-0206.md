## なぜこれを積むか（**計測して分かったこと**。推測ではない）

`task-0193`（ゲートの重なり判定を「証明可能に交わらないなら塞がない」へ）が main に着地し、
**Kobo も起こし直した**（`MainPID 1843281 → 167207` / `NRestarts 4→5`）。そのうえで測った：

| | 直し前 | 直し後（再起動20分後） |
|---|---|---|
| queued | 24本 | **24本**（顔ぶれもほぼ同じ） |
| task-0177 の待ち | 10本 | 7本（**減った3本は queued から出ていっただけ**） |

**待ちはほとんど解けなかった。**

**残っている待ちの中身が答えだった。** `task-0194` は
`meta/environments.yaml` / `docker/browser.yaml` / `tests/acceptance/browser-profile.spec.ts` の
**名指し3本しか触らない**のに、**6本に塞がれている**。確認できた範囲で**その全部が
`tests/acceptance/**` を持っている**（task-0168 / 0172 / 0177 は契約を読んで確認）。

一方、**task-0169 と task-0170 は task-0194 を塞いでいない**——**どちらも名指しだけの契約**だから。

**＝判定は正しく動いている。塞いでいるのは契約の書き方である。**

## なぜ「積む瞬間」なのか

**そこが唯一の機会だから。** `imp-0071` に記録があるとおり、**着手後はスコープを狭められない**
——既に触った差分がスコープ外になり、マージ前ゲートで落ちる。
だから「あとで狭める」は選べない。**書く瞬間に断るしかない。**

そして**書き手の注意力に頼っても効かない**ことは、今日の記録 id 衝突（**10組**）で分かっている。
**機械で断る。**

## 何をするか

契約検査（`validateContractInput` と watcher の取り込み検査の**両方**）に、スコープの広さの検査を足す。

1. **先頭ワイルドカードまでの前置詞が浅い glob を断る。**
   判定は `task-0193` が入れた `globPrefix`（`*` の直前まで文字単位で切る）を**そのまま使ってよい**
   ——**同じ物差しで測るのが正しい**（ゲートが「重なる」と判定する基準と、積むときに断る基準がずれると読めなくなる）。
   断る例：`**` / `packages/**` / `tests/**` / `tests/acceptance/**` / `docs/**`
2. **名指しと十分に深い glob は通す。**
   通す例：`packages/banto-host/src/threads.ts` / `tests/acceptance/foo.spec.ts` /
   `tests/acceptance/backlog-*.spec.ts`
   **新しく作るファイルも名指しできる**（実際、いま通っている契約の多くはそうしている）
3. **逃げ道を1つだけ用意する。** `scope.rationale` に理由を書けば広い glob も通る。
   **ただし理由は帳簿に刻む**——**黙って広く書けるのをやめる**のが目的であって、
   広いスコープを禁じるのが目的ではない（コンフリクト解消や大規模な移設では要る）。
4. **既に取り込んだ契約は再評価しない。** 遡って落とすと、いま並んでいる24本が全部止まる。

## 断り文の書き方（**ここが効く**）

「スコープが広すぎます」だけでは書き手は直せない。**どのパターンが悪く、どう書けばよいか**を出すこと：

```
scope.paths[1] "tests/acceptance/**" は広すぎます。
  触るファイルを名指ししてください（新しく作るファイルも名指しできます）。
  例: "tests/acceptance/contract-scope-breadth.spec.ts"
  どうしても広く取る必要があるなら scope.rationale に理由を書いてください（帳簿に残ります）。
```
