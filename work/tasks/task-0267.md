## 背景

banto のマージ前ゲート（verify）が claude-quota.spec.ts で必ず落ちる既存欠陥。task-0266 の監査は通ったのに `merge_gate_failed: verify_failed:a1(exit=1)` で落ちたのはこのテストのせいで、task-0266 の実装とは無関係。

## 何が落ちるか

tests/acceptance/claude-quota.spec.ts の「[決定98a] 枠が尽きかけた Claude バックエンド」ブロックの3テスト（特に148行目 `assert.equal(withAuth.unavailable(), undefined)`）が、quota を渡さない createClaudeBackend に対して `unavailable()` を呼ぶ。unavailable() は quota 判定より先に `claudeAgentAvailability()`（packages/banto-worker-pool/src/claude-agent/availability.ts:28）を**実環境**で実行し、認証（/root/.claude/.credentials.json か ANTHROPIC_API_KEY）が無いと「認証が見つかりません（…）」を返して assert が失敗する。

検証コンテナ（docker compose run）は HOME=/root で認証が無く、ANTHROPIC_API_KEY も未転送（docker compose run は process.env を転送しない）ため、この3テストは必ず落ちる。ファイル冒頭の「fetch と readCredentials を差し替える」という自己完結の宣言と実態が食い違っている。

## 直し方（どちらでもよい）

1. （推奨）このブロックのテストを自己完結化する：createClaudeBackend に認証/可用性チェックを注入できるようにする、または当該テスト中 process.env.ANTHROPIC_API_KEY（or 認証）を立てて claudeAgentAvailability が通るようにする。モック済み readCredentials が quota モニターだけでなく availability にも効く形に整合させる。
2. availability の注入が必要で関数シグネチャを変える場合、packages/banto-host/src/harness-backends.ts も変更してよい。

## 満たすべきこと

- claude 認証が無い clean な検証コンテナで `npm test`（tests/acceptance/claude-quota.spec.ts を含む）が通る
- 「計測できなければ「尽きた」と混同しない（I2）」の性質は保たれる（認証不要・モックの範囲で判定する）
- 既存の他テストを壊さない
