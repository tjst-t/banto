## 目的
PO が取次で「緩めてよい」と答えたのに、その答えが kobo.amend へ届く口が無い問題（imp-0086）を直す。決定113 の既存の橋（po-decision）に `decision: "amend"` を1つ足す。新しい橋は架けない（守りを1つも外さずに済むため）。

## 前提（調査済み・行番号つき・2026-08-16 時点の main）
- daemon の中身は既に PO を通せる形になっている。到達する外の口が1本も無いだけ。
  - `amendTask` の署名は `by: "banto" | "po"` を受ける — `packages/banto-daemon/src/daemon.ts:1582`
  - 断りの判定は `loosens && options.by !== "po"` — `daemon.ts:1628-1636`（文言は :1632）
    - `loosens` が立つのは2つ：スコープを広げた（daemon.ts:1443→:1446）／レビュー段を緩めた（:1470-1475、厳しさは :1549-1558）
  - しかし `amendTask` の呼び出し元は1箇所だけで、`by: "banto"` を直書きしている — `packages/banto-daemon/src/kobo-tools.ts:1069-1074`（特に :1073）
  - daemon の HTTP ルートは2本しかない — `packages/banto-daemon/src/http-server.ts:413`（`po-decision`）と :491（`/tools/*`）
    - `po-decision` は `decision` が `approve` / `send_back` 以外なら 400 で弾く — http-server.ts:476-480
  - `packages/banto-host/src/kobo-po-decision.ts:18-20` に「kobo.amend のように by:"banto" を直書きしている道具も、decision を1つ足せば同じ橋に乗せられる」と設計意図が既に書いてある。

## 設計判断（PO による決定済み・案A）
**「PO が承認する『改訂の中身』を誰がどう書くか」は案A：番頭（ホスト）が札に改訂内容（新しい scope / acceptance の全項目）を全部書いて、PO は「はい／いいえ」を押すだけ。** 面は新設しない（kobo.review 相当の面は作らない）。これは決定113 の形（PO は番頭が出した具体案に是非を答える）と同じ。inbox.post の引数は改訂の全項目を載せる分だけ一段重くなるが、それでよい。

## 外してはいけないもの（ここを外したら改悪）
決定113 の橋は「PO が実際に押したという事実に紐づいて初めて by: "po" が立つ」構造。この4つを1つも外さないこと：
1. 番頭は `effect` を書けない — `inbox.post` は `effect` を受け取らない（inbox-tools.ts:79-93）。呼ぶ先を決めるのはホスト側の結線（bin.ts:1192-1196）
2. 画面にも `effect` を配らない — `toView` が必ず落とす（inbox.ts:135-145）。画面は「押された」を投げ返すだけ（useBantoSession.ts:801）
3. 番頭は effect 付きの札を畳めない — `inbox.resolve` が拒否（inbox-tools.ts:232-238）。effect が走るのは画面から押された経路だけ（server.ts:1990-2007）
4. 記録で担保する — `via`（inbox:<itemId>#<actionId>）は daemon で必須（http-server.ts:427-439）。帳簿に by: "po" と via が残る

**やってはいけない直し（非推奨）**：`scopePatternCovered`（daemon.ts:1531 付近）を緩めて「1パス追加は番頭が通せる」にする案は10行で済むが、PO が答えていなくても番頭が通せるようになり、決定57 の線を消すのと同じで改悪。やらない。
