## 2. 直す方針（実装が見つからなかったときのため）

**穴**：畳んだ枝へ知らせが届くと開き直るが、枝は「私はもう畳んだ枝です」と認識したままなので `thread.merge` を呼ばず、**開いたまま一覧に残る**。

**前の職人が調べ上げた事実（写し）**：
- **開き直しているのは `server.ts` の `reopenClosedTarget()`（1108行〜）**。
- **呼び出し元は `server.ts` の `deliverToThread()`（1029行〜）**——`reopenClosedTarget → record(知らせ) → turn_start → await promptEvenWhileBusy → turn_end` という**ターン1本の全体**を持っており、**ターンの終わりを知っているのはここだけ**。
- 枝の LLM に渡るのは `thread.harness.prompt(text)` の `text` だけで、`thread.record` した印は文脈に入らない。**「あなたは開き直された」を伝える口も `server.ts` 側。**
- **`threads.ts` だけで閉じると**、`thread.notices` の Promise 鎖に継ぎ足す形になり、**配達の実装が変わった瞬間に黙って効かなくなる**（**採らないこと**）。

**PO が承認した形**：**判断とデータは `threads.ts` / `thread-store.ts`、`server.ts` へは繋ぎだけ**（十数行）。**D5（判断を Surface に置かない）を保つこと。**

1. 知らせで開き直した枝は、**そのターンが終わったら機構が自動で畳み直す**（**元の結論・investigated / decided / remaining は保つ**）。
2. 開き直した枝の文脈に、**機構が「あなたは〈何の知らせ〉で一時的に開き直された。用が済んでいれば何もしなくてよい」**と明示する。
3. **枝が自分で `thread.merge` を呼んだ場合は枝の結論が勝ち**、自動の畳み直しは二重に走らない。
4. **一覧で「畳んである（知らせで一時的に起きた）」と読める**こと。**「未処理 N件」表示（imp-0036）を壊さない**こと。
