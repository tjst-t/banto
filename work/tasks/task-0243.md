## 何が起きたか（実際の事故・2026-08-16 夜）

夜に7本を積んだ枝 thread-167「夜の仕込み」を畳んだあと、そのタスク群の職人が6本続けて質問を出して `paused` になった。**質問の知らせの宛先は「積んだ会話」＝畳んである thread-167** だったので、誰も答えなかった。職人は待ちくたびれて `agent_exited` で消え、`task_stalled`（paused のまま4時間）の知らせも**同じ宛先へ配られた**ので、これも誰にも届かなかった。翌朝 PO が気づくまで6本が5〜6時間半止まった。

task-0228 で「知らせで開き直った枝を機構が畳み直す」ようにはなったが、**開き直しても、その枝には答える者がいない**——穴はそこ。

## いまの実装（読んでから直すこと）

`packages/banto-host/src/server.ts` の `routeNotice()`（900行目あたり）。

- T3 の決まりは「**幹へ配られようとした知らせだけ、用件の枝へ回す**」。幹が宛先なら `subjectBranch()` で用件の枝を引き当て（無ければ立て）、そこへ配る＝**その枝のターンが起きて、誰かが読む**。
- ところが `if (target.kind !== "trunk") return asIs;` の1行で、**宛先が枝ならそのまま配る**。ここに「その枝が畳んであるか」の判定が無い。**畳んだ枝は、開いている枝と同じ扱いになっている。**

## やること

`routeNotice()` に「**宛先が畳んである枝なら、親の幹へ配られようとしているものとして扱う**」を足す。

1. 宛先の枝が畳んである（`closedAt` が入っている）ときは、`parentId` から親の幹を引き、**幹が宛先のときと同じ道**（`reopenClosedTarget` → `subjectBranch`）に乗せる。結果、**開いている用件の枝へ配られ、ターンが起きる**。
2. **元の宛先を見失わせない。** 回した知らせの本文に、元はどの枝宛てだったか（枝の題と id）を1行添えること。あとから「あの枝の続きだ」と辿れなくなるのがいちばん困る。
3. **開いている枝が宛先なら、いままでどおり素通し**（用件の枝を重ねない）。
4. **他の幹からの言伝（`source === "thread"`）と、宛先を名指しした `conversation` の一通は、いままでどおり素通し。**
5. I2：親の幹が引けない・用件の枝が立てられないときは、**知らせを捨てず**元の宛先へ配り、`console.error` を残すこと（既存の catch と同じ流儀）。知らせが消えるのは、幹が1本回るより遥かに悪い。

## やらないこと

- **`packages/banto-host/src/threads.ts` は触らない**（`reopenClosedTarget` / `subjectBranch` / 畳み直し（task-0228）の仕掛けはそのまま使う）。
- 知らせの種類で選り分けようとしないこと。**畳んだ枝には、どの種類の知らせについても答える者がいない**ので、種類は見ないでよい。
- ADR-0025「知らせで幹のターンは起こさない」は**変えない**。回した先は用件の**枝**であって幹ではない——幹のターンは起きないままにすること。
