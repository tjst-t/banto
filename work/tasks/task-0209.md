## なぜこれを直すのか（2026-08-16 実測。推測ではない）

**番頭は `kobo.amend` でスコープを狭められない。** 道具の説明は「狭める向きは番頭が通せる／緩める向きだけ PO 判断」と書いてあるが、**実装がそうなっていない。**

`packages/banto-daemon/src/daemon.ts` の `classifyAmendment`（1236行目付近）：

```ts
const curScope = ((current["scope"] as { paths?: string[] } | undefined)?.paths ?? []).slice();
const nextScope = ((next["scope"] as { paths?: string[] } | undefined)?.paths ?? []).slice();
if (JSON.stringify(curScope) !== JSON.stringify(nextScope)) {
  const widened = nextScope.some((p) => !curScope.includes(p));
  ...
  if (widened) loosens = true;
}
```

**判定が「その文字列が元の一覧に在るか」だけ**なので、

```
[..., "tests/acceptance/**"] → [..., "tests/acceptance/banto-worker-delegation.spec.ts"]
```

という**明らかな絞り込み**も「新しい文字列を足した＝広げた」と読まれ、500 で断られる（task-0203 で2回実測。文面は「番頭が通せるのは、検証コマンドの訂正・スコープからパスを取り除く・受け入れ条件を増やす方向だけです」）。

**番頭に残された道は「パスを消す」ことだけだが、試験のパスを消すと職人が試験を書けなくなる**ので実用にならない。**PO 側にも道が無い**——canvas の catalog に amend の面は無く、HTTP の `po-decision` は approve / send-back 専用である。**つまり、いま誰もスコープを狭められない。**

## 何が困っているのか（この不具合が実際に止めたもの）

マージ前ゲートの重なり判定（`gate-evaluator.ts` Condition 2）は、**自分より前に作られた未レビューのタスクと scope が重なると待たせる。**
`tests/acceptance/**` を持つ契約は、**試験を1本でも持つ後続を全部塞ぐ。**

2026-08-16 時点で `task-0207`（受け入れ試験が compose を畳む）は**スコープが名指し6本なのに8本に塞がれており**、塞いでいる側は全部 `tests/acceptance/**` を持っていた（task-0165 / 0167 / 0168 / 0171 / 0172 / 0177 / 0202 / 0203）。
**狭める訂正が通れば直列は解けるが、それが撃てない。**

## やること

`classifyAmendment` の `widened` の判定を、**文字列の在/不在から「覆われているか」へ変える。**

- 新しいパスのそれぞれについて、**元の `scope.paths` のいずれかのパターンに覆われているか**を見る
- **1つでも覆われていないパスがあれば `widened = true`**（従来どおり PO 判断。**迷ったら塞ぐ側に倒す**という既存の方針は変えない）
- 全部が覆われていれば `widened = false`——**番頭が通せる**

判定は `packages/banto-daemon/src/gate-evaluator.ts` に既にある **`fileMatchesGlob(filePath, pattern)` をそのまま使ってよい**（`export` されている。読むだけでよく、`gate-evaluator.ts` は**触らないこと**）。

- **新しいパスが名指し（ワイルドカードなし）なら、そのまま `fileMatchesGlob` に渡せる**——これがいちばん多い形である
- **新しいパスがまだワイルドカードを含む場合**（例: `tests/acceptance/**` → `tests/acceptance/chapter*.spec.ts`）は、`fileMatchesGlob` に glob を渡すことになる。**そこで機械的に決められないなら、覆われていないものとして扱ってよい**（＝ PO 判断へ倒す）。**安全側に倒すこと。どう扱うと決めたのかをコードのコメントに書くこと。**

**断り文に、どのパスが覆われていないのかを出すこと。** いまの文面は「緩める方向なので PO の判断が要ります」とスコープ全体を並べるだけで、**何が問題なのかが読めない。**
