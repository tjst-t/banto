## このタスクの位置（先に読むこと）

**`packages/banto-host/src/thread-store.ts` の `replace()` を触るタスクは3本あり、これは3番目である。**

| 順 | id | 何をした／するか |
|---|---|---|
| 1 | task-0161 | 書き込みを**原子的**にする（tmp + fsync + rename）。土台 |
| 2 | task-0164 | **縮む書き戻しを拒む**（メモリに載せた行数より少ない entries での上書きを拒否し、拒んだ内容を `<threadId>.jsonl.rejected-<ISO8601>` へ退避する） |
| 3 | **これ** | **壊れた行を捨てずに退避し、取次で人に届ける** |

**先行2本は着地済みである**（現物の `thread-store.ts:303` 付近に「拒んだ内容を退避する」処理が入っている）。
**その直しを1行も壊さないこと。** 特に task-0164 の「縮む書き戻しの拒否」と、このタスクの「上書き前に元ファイルを退避する」は
**どちらも `replace()` の中で働く**。**現物のコードを読んでから、両方が生きる形に組むこと**（先行の判定を消して自分の処理に置き換えない）。

## 背景（前提。あなたは記憶を持たないので、ここに書いてあることが全部）

banto ホスト（`banto.service`）が OOM killer に繰り返し殺されている（2026-08-15 だけで4回以上、同日12回再起動）。**書き込みの途中で殺されると会話の記録に半端な行が残る。**

8/16 00:48:50、OOM 直後の読み戻しで
`[banto] thread-61 の記録に読めない行があります（その行は飛ばします）`
が1回出た。その1行は `console.error` に出ただけで**中身はどこにも残らず**、直後の書き戻し（全文置換）で**永久に消えた**。しかも誰も気づかなかった（画面には出ない）。

`transcript()` の catch は例外も行の中身も束縛していない：

```ts
try {
  entries.push(JSON.parse(trimmed) as TranscriptEntry);
} catch {
  // I2 の例外ではない: 1行壊れても残りは読める。1行のために会話全部を失わない
  console.error(`[banto] ${threadId} の記録に読めない行があります（その行は飛ばします）`);
}
```

**読み飛ばす判断そのものは正しい**（1行のために会話全部を失わない）。問題は「捨てている」ことと「気づけない」ことの2つ。

**なお、同じ穴の `turn-log.ts` 側（千切れた最終行の検出）は既に着地している**（`turn-log.ts:193` 付近）。
**書き方の流儀はそちらを読んで合わせるとよい**（ただし `turn-log.ts` は**スコープ外**。触らないこと）。

## やること

1. **壊れた行を退避する。** `transcript()` が読めない行に当たったら、その行の**生テキストをバイト単位でそのまま**
   `<記録ファイルと同じディレクトリ>/<threadId>.corrupt-<ISO8601>.jsonl` へ書き出す（1回の読みで複数行壊れていたら同じファイルへまとめる）。
   退避は追記でよいが、**退避に失敗しても読み自体は続けること**（退避が新しい落とし穴にならないように）。
2. **上書きの前に、現行ファイルも丸ごと退避する。** 壊れた行が見つかったスレッドについては、`replace()` が上書きする前に
   **そのときのファイル全体**を退避側へ残す（同じ命名規則でよい）。これが無いと「壊れた行以外の、読めたが古い内容」も消える。
   **壊れが見つかっていないスレッドでは余計な退避をしないこと**（毎回コピーすると 2〜6MB の記録が積み上がる）。
3. **人に届ける。** 退避が起きたことを **取次（inbox）に1件積む**。`console.error` だけでは誰も気づかないことが 8/16 の実例で分かっている。
   **起動あたり1件だけ**にすること（スレッドごと・行ごとに積むと札で溢れる）。札には「どのスレッドか・何行壊れていたか・退避ファイルのパス」を書く。
   取次への積み方は `packages/banto-host/src` 内の既存の呼び出し箇所を読んで、その流儀に合わせること
   （**ただし触ってよいのは `thread-store.ts` だけ**。他のファイルは読むだけ。既存の関数で積めない形になっていたら、
   `thread-store.ts` 側から渡せる差し込み口（コンストラクタ引数・コールバック）を作って、**呼び出し元の変更は要らない既定値**にすること）。

## やらないこと（スコープ外。触ったらマージ前ゲートで落ちる）

- 書き込みを原子的にする話（**task-0161 で済んでいる**）と、縮む書き戻しの拒否（**task-0164 で済んでいる**）。**どちらも壊さないこと**
- `append()` を使う形への設計変更、`SAVE_DELAY_MS` の変更
- `turn-log.ts`（**着地済み**）、`threads.ts`（**同じ夜に別のタスクが触っている**）
- 退避したものから自動で復元する仕組み（人が判断する。ここでは作らない）
- **`/var/lib/banto` 以下の実データへの書き込み・移動・削除。テストは必ず一時ディレクトリを使うこと**（実データを触ると PO の記録が壊れる）
