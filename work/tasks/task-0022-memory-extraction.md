## 背景

ADR-0010 決定10 (b)(c) と決定28 より。現状の記憶は「覚えて」と言われたものを保存するだけで、`docs/vision.md` の「番頭は覚えている。POが同じ経緯を二度説明しなくてよい」には届いていない。Hermes Agent の設計を踏襲し、会話から記憶すべきことを背後のLLMで抽出する。

決定28 で定めた制約が実装の骨格になる：
- **抽出は独立した呼び出し**なので本セッションのプロンプトキャッシュを壊さない。壊れるのは注入を途中でやる場合——記憶はシステムプロンプト（キャッシュされる先頭）に入るため。よって**注入は次セッション開始時のみ**
- **契機は会話の区切り**（新しい会話・圧縮境界）。毎ターンは不採用（コストが会話長に比例する）
- **抽出対象はPOの発言と番頭の結論に限る**。ツール出力からは抽出しない（記憶は長生きするため汚染が効き続ける）
- **自動で有効。ただし origin を残しPOが消せる**（削除の面は task-0023）
