Worker Pool 並行制御のリソースベース化（設計書 work/reports/2026-08-17-worker-resource-based-concurrency.md）の第2段として、各ランタイムの実際のメモリ消費ピークを収集し、想定消費値を校正する仕組みを導入する。

## 背景
タスク A〜E では、想定消費の既定値を Pi 300 MiB / Claude 1200 MiB に仮置きしている。これらは実測に基づく校正が必要。cgroup の `memory.peak` を収集することで、runtime 別の実測ピークを導出できる。

## 目的
- `packages/banto-worker-pool/src/worker-cgroup.ts` で `memory.peak` を読めるようにする（既存の cgroup 読みを拡張）
- `packages/banto-worker-pool/src/pool.ts` で職人終了時に `memory.peak` を収集し、runtime 別の実測ピークを集計する
- 集計結果をログまたは `worker.list` / 専用コマンドで確認できるようにする
- 手動または定期的な自動更新の枠を準備する（自動更新はPO判断を伴うため、まずは可視化）

## 完了条件
- 各 runtime の実測ピークがログまたは画面で確認できる
- 実測ピークの集計が継続的に行われる
- 型検査とテストが通る

## 制約
- 想定値の自動更新はこのタスクでは行わない。まず可視化を実現する
- CPU 関連の実測はこのタスクでは対象外
- タスク C のリソースベース判定が前提
