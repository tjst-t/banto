## 背景

これは task-0149 の後続。task-0149（「/api/model が代打モデルの文脈長 128000 を返す」）は
コミット `e4dbb90` で手当て済みで、**誤った 128000 は出なくなった**。しかしその直し方は
「標準そのものを pi の登録で解けないときは contextWindow の欄ごと落とす」というもので、
**正しい値が出るようにはなっていない**。

実測（2026-08-14、稼働中の banto）:

```
$ curl -s http://localhost:4100/api/model
{"id":"opus","vision":false}
```

`contextWindow` の欄が無い。番頭は `claude-agent-sdk` の `opus` で動いていて、
本当の文脈長は 1,000,000 である。

### なぜ欄が落ちるのか（調査済み・実装を読めば確かめられる）

`packages/banto-host/src/harness-backends.ts` の `hostModelInfo()` は、
backend が `"pi"` **以外**のときは `resolveExact` を呼ばずに `exact = undefined` とする。
その結果 `isHostDefault` が必ず false になり、`{ id, vision: false }` だけを返す。
`claude-agent-sdk` のモデルは pi の LLM 登録に載らないので、**このバックエンドで動いている
限り構造的に必ず欄が落ちる**。バグではなく、task-0149 の直しの設計どおりの挙動である。

### なぜ直すのか（実害）

- `packages/banto-web/src/Room.tsx` の `ContextMeter` は `if (!contextWindow) return null`
  で、**欄が無いと文脈使用量の目盛りごと消える**（Room.tsx:101、921行目で
  `model?.contextWindow` を渡している）。目盛りのすぐ隣に「章を畳む」ボタンがあり、
  人が畳むかどうかを決める材料が、いま画面から消えている。
- 一方、**自動の章畳み判定には実害が無い**。`chapters.ts:178` は
  `harness.contextWindow?.() ?? options.contextWindow` で、ハーネスの実測値が勝つ。
  つまり機械側は既に正しい値で動いている——**正しい値は既に手元にあるのに、画面へ出す
  経路にだけ載っていない**、というのが今の状態。

### 値の出どころ（ハードコードしないで済む）

`packages/banto-host/src/claude-agent-harness.ts:438` の `contextWindow()` が、SDK の
`result` メッセージに載る `modelUsage.contextWindow` を実測して保持している
（同ファイル 570行目付近）。**これが唯一の正しい出どころ**であり、
`chapters.ts` が既に使っている。1,000,000 を定数で書くのは禁止
（Anthropic 側の仕様変更・プラン変更・`CLAUDE_CODE_DISABLE_1M_CONTEXT` で変わるため。
書いた瞬間に嘘になる）。

## やってほしいこと

1. `hostModelInfo()`（または `/api/model`・`model_state` を組み立てる経路）が、
   backend が `claude-agent-sdk` のときに、**ハーネスの実測値**を contextWindow として
   載せられるようにする。代打モデル（pi 側の standard tier フォールバック）の値を
   転用してはならないという task-0149 で入れた不変条件は**維持すること**。
2. 実測値が届く前は欄を落としたままにする（a2）。「まだ分からない」と
   「値が無い」を数で埋めない。
3. 実測値が初めて届いたときに `model_state` を配信し直す（a3）。
   `packages/banto-web/src/useBantoSession.ts:412` のコメントにあるとおり、
   いまの `model_state` は**接続直後とモデル切替のときにしか流れない**ので、
   ここを塞がないと「1往復したら目盛りが出る」にならない。
   どこで拾って誰が配信するか（ハーネスからの通知の口を足すのか、
   `server.ts` 側で見にいくのか）は実装者の判断に委ねる。
4. UI（`packages/banto-web/**`）は触らない。値さえ届けば `ContextMeter` は既に描ける。
