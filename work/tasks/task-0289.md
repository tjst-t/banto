## 背景（実測）

**2026-08-19、工場が17時間止まった。** 原因は工場ではなく、知らせの受け手だった枝 thread-227 が OpenRouter のクレジット切れ（402 Insufficient credits）でターンを回せなくなっていたこと。`task_stalled` の知らせは3本とも正しく届いていたが、そのたびに応答が 402 で落ち、誰も `kobo.reopen` を打てなかった。

**同じことが 2026-08-20 04:30 と 04:44 に、いま現在も起きている。** 畳んだ枝 thread-217（pi/opencode-go/deepseek-v4-flash）へ task-0279 の「レビュー待ちです」の知らせが届き、開き直し → `401: {"type":"CreditsError","message":"Insufficient balance..."}` で 800ms〜1秒で落ちる → 「捌いたので畳み直しました」で閉じる、を繰り返している。**task-0279 はレビュー待ちのまま誰にも届いていない。**

### いちばんの問題：どこにも痕跡が残らない

`journalctl -u banto.service -u banto-daemon.service -u banto-worker-pool.service` を `Insufficient credits` / `openrouter.ai` で引いても**3日ぶんで0件**（実測）。エラーが残るのは会話の jsonl と turns.jsonl だけで、
- 機械（journal）を見ても分からない
- 会話を開かないと分からない。しかもその会話は**畳んだ枝**なので、誰も開かない
- 外からは「番頭が考え込んでいる」のと区別が付かない

## 直すこと

### 1. 呼べなかったことを journal に出す

ターンが「**モデルを呼べない**」系のエラーで落ちたとき、`console.error` に一行出す。載せるもの：会話 id・ターンの出どころ（source）・その会話のモデル座標・理由の一行。

「呼べない系」の判定は**純粋な関数**として独立させる（判定を server.ts のあちこちに散らさない）。拾う形は少なくとも次：
- HTTP 401 / 402 / 403 で始まる本文
- `Insufficient credits` / `Insufficient balance` / `CreditsError`（OpenRouter・opencode の実物。本文は上に貼ってある）
- 認証切れ（`Unauthorized` / `invalid api key` 系）

判定に迷うものは**呼べない系として扱わない**（誤検知で幹を起こす方が害が大きい）。

### 2. 知らせが捌けなかったなら、幹へ上げる

そのターンの出どころが**自分以外**（`kobo` / `worker` / `nudge` / `thread`）だったとき、つまり**誰かがこの会話に何かを頼んでいた**ときは、落ちたことを**親の幹**へ札として立て、幹のターンを起こす（枝なら親の幹、幹なら帳場）。

札に載せるもの：どの会話が・どの知らせを・なぜ捌けなかったか（モデル座標と理由の一行）。**知らせの本文の頭200字も載せる**——幹はその枝の中を見ていないので、「何が届いていたか」が分からないと手が打てない。

これがあれば、昨日の17時間は「1時間後に幹が気づく」で済んだ。

### 3. 連打しない

同じ会話・同じ理由の札は**10分に1回まで**（知らせは繰り返し再配達されるので、そのたびに幹を起こすと幹が埋まる）。cooldown の持ち方は `watchdog.ts` の nudge 連打防止と揃えてよい。
