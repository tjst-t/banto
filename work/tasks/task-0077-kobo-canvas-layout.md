## 背景

**PO報告 2026-08-07**：「キャンバスの工場のUIもレビューのUIも壊れていて使い物にならないので、
UIを徹底的に見直してください。」スクリーンショット2枚つき。

**原因は3つとも寸法の話**で、型検査もユニットテストも一切気づけない類だった。

## 何が壊れていたか

### 1. ボードが狭い方に入っていた（いちばん効いた）

`SplitView` は「一覧（狭い）＋詳細（広い）」の形。**ボードは横に流すカンバン**なのに
一覧側（`is-lg` ＝ 340px）へ入れていたので、230px の列が**1列半しか見えない**。
隣には空の「タスクを選ぶ」が残り全部を占めていた。

実物で再現した：13件・7列あるのに、見えていたのは2列と半分。

**直し**：`WorkView`（新）——主が残り全部を取り、詳細は**選んだときだけ**右に 380px で出る。
狭いときは詳細が被さる。**空の詳細ペインを描かない**のが要点。

### 2. 札の題が横に切れていた

`S4a8d2f-1-1: Tauri ... 格の完成確` のように、どこまでが題なのか分からない形で切れる。
`overflow-wrap: anywhere` ＋ 3行で省略記号に。

### 3. レビューが空でも2枚に割れていた

「判断待ちはありません」と「判断するものを選ぶ」が並び、**面の全部が空白**。
判断待ちが0のときは1枚に畳んだ。

## ついでに直したもの（見て初めて分かったもの）

- **空の列を畳む**。工場のボードはたいてい**まばら**で、空の列に等分の幅を与えると
  見たいものが押し出される。畳むと、PO が実機で見た形（失敗2件＋終わった1件）は
  **横スクロールなしで7列すべて収まる**
- **列に地を敷く**。敷かないと札が宙に浮いて、どこまでが1つの列か読めない
- **経緯の行が重なっていた**。`grid-template-columns` の種類が 10em 固定で、
  `state_transitioned` がはみ出して詳細と重なる。`minmax(0, max-content)` へ
- **レビューは先頭を自動で開く**。決めるために来る面で、着いた先が「選んでください」の
  空白では一往復無駄になる。選んだものが列から消えたら（通した・取次へ上げた）また先頭へ

## 見張り方（a6）

**寸法は目でしか分からないので、寸法で見張る**（`tests/kobo-canvas.spec.ts`）：

- ボードの幅がキャンバスの98%以上か（＝狭い方に入っていないか）
- 収まっている列が4つ以上か／まばらなら7つ全部か
- 札の題の `scrollWidth - clientWidth` が0か（＝切れていないか）
- 経緯の行で、種類の右端が詳細の左端を越えていないか
- レビューが空のとき `.cv-empty` がちょうど1つか
- 判断待ちがあるとき「判断するものを選ぶ」が出ていないか

**直す前の形に戻すと3件落ちる**ことを確かめた。

`tests/koboHost.ts`（新）＝ ビルド済みのUIを配り `kobo.*` にだけ答える偽ホスト。
**常駐している番頭ホストには繋がない**（`layoutHost.ts` と同じ理由）。

`npm run test:ui` を足した——UI の試験に名前が無く、走らせ忘れる形だった。
