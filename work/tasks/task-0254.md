Worker Pool 並行制御のリソースベース化（設計書 work/reports/2026-08-17-worker-resource-based-concurrency.md）の一環として、`packages/banto-worker-pool/src/pool.ts` の起動可否判定を本数枠からリソースベースに拡張する。

## 背景
タスク A（host-resources.ts）とタスク B（RuntimeRegistration 拡張）が完了すると、ホストの空きリソースと各ランタイムの想定消費が取得できるようになる。これらを使って、Pi 軽量職人を多数起動しつつ Claude 重い職人を空きリソースに応じて抑える判定を実装する。

## 目的
- `delegate()` から `reserveSlot()` へ `runtime` を渡す
- `ConcurrencySlot` / `starting` Map に `runtime` フィールドを追加する
- `reserveSlot()` / `isFull()` を拡張し、以下の判定順で起動可否を決める:
  1. 本数上限チェック（`BANTO_WORKER_MAX_CONCURRENT`、絶対安全弁）
  2. 役による予約チェック（executor は `executorLimit` で頭打ち）
  3. リソースチェック（`BANTO_WORKER_RESOURCE_BASED=0` で無効化可能）
- `concurrency()` に想定消費合計を追加する
- `BANTO_WORKER_AUDIT_RESERVED` を「監査用予約リソース量（MiB）」に再解釈し、auditor は executor 用判定から差し引かれた予約リソース内で起動できるようにする

## 完了条件
- リソース充足時に Pi 軽量職人を多数起動できる
- Claude 重い職人は空きリソースに応じて抑えられる
- 実装枠満杯時でも監査職人が `BANTO_WORKER_AUDIT_RESERVED` の予約リソース内で起動できる
- `BANTO_WORKER_RESOURCE_BASED=0` で旧来の本数のみ判定に戻せる

## 制約
- 本数上限は廃止せず、安全弁として残す
- CPU 判定は第2段なので、このタスクではメモリのみを対象とする
- 断りメッセージの拡張はタスク D で行う

## 監査人への申し送り
- 判定は必ず `audit_report` ツールで出してください。テキストや箇条書きだけでの報告は、機構が判定を受け取れず failed になります。
- `npm test` / `npm run typecheck` / `npm ci` といった一式は、マージ前ゲートが検証環境で回します。監査人は自分で起動しないでください（2 GiB メモリ上限で落ち、audit_report も出せなくなります）。
- 監査人が行ってよいのは、軽い読み合わせ（`git diff`、`grep`、1ファイルだけの `npm run test:one`）のみです。
