## 背景（PO 指摘 2026-08-17）
取次（inbox）に「どの選択肢をクリックしてもエラー」になる古い質問が残っている。task-0273（2c0e51c3）が導入した `resolveStaleInboxForTask`（閉じたタスクの取次を自動解決）は**「今後タスクが閉じたとき」のイベントでしか発火しない**。task-0270（abandon）・task-0271（supersede）などはこの仕組の導入前に閉じたため、紐づく取次（PO レビュー依頼・amend 依頼）が誰にも解決されずに残っている。PO UI で「通す／差し戻す」を押しても、タスクが review-ready でないためエラーになる。

## やること
1. 既存の実装を読む（packages/banto-host/src/kobo-po-decision.ts の resolveStaleInboxForTask・kobo-notice.ts の onTaskClosed 配線・inbox-tools.ts の resolve/resolveStale）
2. **起動時または定期スイープ**で、closed / superseded / settled タスクに紐づく未解決の取次を自動解決する処理を足す。開始点は `resolveStaleInboxForTask` の再利用を第一候補とする（全タスク × 取次を掃く口をどこに置くかは実装を読んで決める。startKoboNotices の起動時・または daemon の起動時 reconcile）。
3. **守り**:
   - 生きているタスク（queued/gating/implementing/auditing/review-ready/merging/approved）の取次は絶対に巻き込まない
   - 解決は黙って消さない——取次の履歴に理由（superseded 等の marker）を残す（resolveStale の仕様どおり）
   - 既存の守り（via 必須・inbox.resolve での畳み拒否・決定57/113）を壊さない
4. テスト:
   - 新設 tests/acceptance/kobo-stale-inbox-sweep.spec.ts: 導入前に残った古い取次が起動時スイープで解決される／生きているタスクの取次は残る／履歴に理由が残る
   - 既存の kobo-po-amend-from-inbox.spec.ts が通ること（守りを壊していない証拠）
5. npm run typecheck が通ること

## 完了条件
- 既存の stale 取次（task-0270 / task-0271 等に紐づくもの）が起動時スイープで自動解決され、PO UI に出なくなる
- 生きている判断待ちはそのまま残る
- 解決理由が記録に残る
