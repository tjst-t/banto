## 何が起きたか（実測。**機構の言い分は誤りだった**）

task-0164 が落ちた。帳簿の文言はこれ：

```
audit_reported_without_verdict: 監査人が判定の口（audit_report）を使わずに報告しました。
**このランタイムには監査の口が載っていません。** 監査人の言い分:「テストの完走を待っています」
```

**「このランタイムには監査の口が載っていません」は、確かめていない推測である。**
`daemon.ts:2740` に**文字列として決め打ちされている**だけで、口の有無はどこでも観測していない。

### 実際に起きていたこと（監査人の出力を最後まで読んだ）

1. 監査人は `npm test` を**背景（`run_in_background`）で起こした**
2. 出力ファイルを読んだ（**まだ空**）
3. `until [ -s ...output ]; do sleep 10; done` という**待ちを、また背景で**起こした
4. **「テストの完走を待っています。」と書いて、ターンを終えた**

ターンが終わったので、工房はそれを**「終わった」報告（done:true）として工場へ渡した**。
判定が無いので daemon が `audit_reported_without_verdict` で即 failed にした。

### 「ランタイムに口が無い」ではない証拠

- task-0164 の監査人は **`claude-agent-sdk/opus`**（`worker.list` で確認）
- `claude-agent/host.ts` は `audit_report` を**この経路に載せている**
  （`createKoboChannel()` が `BANTO_DAEMON_URL` / `BANTO_PROJECT` / `BANTO_TASK_ID` から作れたときだけ）
- **同じ今日・同じランタイムで、task-0161 の監査は判定を返して通り、いま merging まで進んでいる**

＝ **口は載っている。載っていないのは「待っている最中にターンが終わった」ことへの手当て。**

## なぜ急ぐか

**検証が長いほどこの穴に落ちる。** `npm test` は全量2420件で約400秒かかるので、
監査人は自然と背景実行を選び、**待つと言ってターンを終える**。
つまり **重い検証を持つタスクほど、監査で判定が返らない。**
（今日この幹で見つかっている「重い・遅い・大きいものが罰される」勾配の、もう1つの形である。）

## 既存の番人があるのに効いていない

`inc-0030`（監査人の事故を握り潰す件）を受けて、**判定を出さずに落ちたときは
`AUDIT_ATTEMPT_LIMIT`（2回）まで起こし直す**手当てが入っている（`tests/acceptance/audit-crash-retry.spec.ts`）。
**ところが今回は「落ちた」のではなく「報告した」ので、その手当てを通らずに即 failed へ行く。**

## この直しの位置づけ（**外さないこと**）

**これは `task-0186`（検証を職人の袋の外で回し、結果だけ職人へ返す）が入るまでの安全網である。**
0186 が入れば監査人は長い検証を自分で抱えなくなるので、この穴を踏む頻度は下がる。
**だが、この直しは 0186 が入っても外さない。**——判定を返さずにターンが終わる事故は、
検証の長さ以外の理由（文脈切れ・落ちる・待ちの入れ違い）でも起きうるからで、
**「判定が無いまま終わった」を安全に扱う手当ては、恒久的に要る。**
実装を 0186 の有無に依存させないこと（条件分岐で無効化できる作りにしない）。

## 何をするか

### 1. 判定なしの報告を、即 failed にしない（`packages/banto-daemon/src/daemon.ts:2726` 付近）

- **1回だけ起こし直す。** 数え方は既存の監査の起こし直しと**共通**にし、**合計で無限に回らない**ようにする
  （`inc-0063` の周回にしない）
- 起こし直すときの指示に、**次を必ず入れる**：
  「**検証は前面で回すこと。背景に流して『待っています』でターンを終えないこと**——
  ターンを終えると工場は『終わった』と受け取る。長い検証は待ち時間ごと前面で受けること。
  判定は必ず `audit_report` で返すこと」
- 2回目も判定が無ければ failed。**理由には両方の試行の言い分を残す**

### 2. 原因を断定する文言をやめる（同 `:2740`）

いまの文言は**確かめていないことを事実として書いている**（I2 違反）。観測どおりに直す：

- 事実：**「監査人が判定（audit_report）を出さないままターンを終えた」**
- 言い分（監査人の summary）はそのまま添える
- **ランタイムの口の有無を断定しない。** 触れるなら「口が載っていない可能性もある」と可能性として書く

### 3. 監査人の手順にも書く（`skills/audit-checklist.md`）

「**長い検証を背景に流して待たない**。待つと言ってターンを終えると、工場は終わったものとして扱う」を1行。

## やらないこと

- 判定が無いのを「pass」と読み替える（**絶対にしない**。それがこの枝の主題そのもの）
- 自由文から通す／通さないを決める（決定57：一次受けは判定表であって作文ではない）
- 無限に起こし直す（周回になる）
- 監査人の落ち方を握り潰して黙る（I2）

## 試験の書き方

`tests/acceptance/audit-no-verdict-retry.spec.ts` を新設する。**直す前の実装で落ちることを先に確かめ、
その出力を報告に貼ること。**

1. 監査人が `done:true` かつ判定なしで報告 → **failed にならず、起こし直しが1回起きる**（帳簿で確認）
2. 起こし直した監査人が `audit_report(pass)` を返す → 通る
3. 2回目も判定なし → failed になり、**理由に両方の言い分が入っている**
4. 失敗の文言に「このランタイムには監査の口が載っていません」という**断定が含まれない**
5. 起こし直しの指示に「前面で回す／背景に流してターンを終えない」が含まれる
