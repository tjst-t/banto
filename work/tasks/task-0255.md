Worker Pool 並行制御のリソースベース化（設計書 work/reports/2026-08-17-worker-resource-based-concurrency.md）の一環として、リソース不足による拒否を利用者に分かりやすく伝え、管理画面での内訳も充実させる。

## 背景
タスク C でリソースベース判定が入ると、拒否理由に「本数上限」「役による予約」「リソース不足」が混在する。現状の `WORKER_LIMIT_CODE` と `declineHeadline` ではリソース不足が判別できない。また、`worker.list` には本数しか表示されておらず、空きリソースや想定消費が見えない。

## 目的
- `packages/banto-worker-pool/src/pool.ts` の拒否時のメッセージを拡張し、リソース不足も理由として表現する
- `packages/banto-worker-pool/src/worker-tools.ts` の `worker.list` 表示に、以下を追加する:
  - 現在の空きメモリ（MiB）
  - 実行中・起動中のスロットの想定消費合計
  - 各スロットの想定消費（必要に応じて）
- 既存の acceptance テスト `worker-pool-audit-reservation.spec.ts`（a1〜a6）が枠表現を契約として固定しているため、文言変更に対応してテストを修正する

## 完了条件
- リソース不足で断られたとき、理由が分かるメッセージになる
- `worker.list` に空きリソースと想定消費合計が表示される
- 既存の acceptance テスト a1〜a6 がリソースベース下でも通る

## 制約
- pool.ts の判定ロジック自体はタスク C で変更済み。このタスクではメッセージと表示の拡張のみ行う
- 文言変更はテスト修正を伴う
