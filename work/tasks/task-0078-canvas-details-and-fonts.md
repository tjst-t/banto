## 一番効いていたもの：書体が描画をブロックしていた（a5）

**実測した**。実機の初回読み込みは 1.80MB / 41本で、**最大は 885KB の Google Fonts の CSS**。
日本語の書体3つ（Zen Kaku Gothic New・Shippori Mincho・M PLUS 1 Code）の @font-face は
unicode-range の分割が多く、それだけで 885KB になる。

`index.html` のコメントには「**繋がらなくても壊れない**——読み込めなければトークンの
後段（Hiragino 等）へ落ちるだけ」と書いてあった。**それは失敗したときの話**で、
素の `rel="stylesheet"` は**描画をブロックする**——遅いときは画面が出るまで丸ごと待つ。

`preload` → 届いてから `stylesheet` に変える形にした。意匠は変わらない（届けば入れ替わる）。

**測った結果**（Google Fonts が3秒遅い状況を作って、ボードが出るまで）：

| | 時間 |
|---|---|
| 直す前 | **3582 ms** |
| 直した後 | **629 ms** |

## 終わったタスクは増え続けるのか（PO の問い）

**増え続ける。** 調べた結果：

| | 実装 |
|---|---|
| ローテーション（セグメント分割）・スナップショット | **あり** |
| ロールアップ・アーカイブ・**保持期間による削除**（spec-daemon-core §2.3 の3・4） | **無い** |

スナップショットは導出済みの状態を丸ごと持ち越すので、**終わったタスクは消えない**。
そして `kobo.list` は `MAX_ROWS = 100` で**黙って切っていた**——task-0068 で直したのと
同じ形。100件を超えた時点で、古い「終わった」が動いているタスクを押し出す。

**今回は「黙って切る」だけ直した**（a6：`total` と `truncated` を返し、札に `12 / 340 件`
と出す）。**保持期間そのものは spec にあるのに未実装**で、設計の判断が要るので触っていない。
