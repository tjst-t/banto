## 背景

基底コミット a1b835d（test: acceptance テストを Kobo モジュール化に合わせて更新・追加）が
`tests/acceptance/kobo-worker-integration.spec.ts` で `Array.prototype.findLast`（ES2023）を
6箇所使うようになったのに、`tsconfig.json` / `tsconfig.check.json` の `target` が ES2022 のまま。
このため `npm run typecheck`（tsc --project tsconfig.check.json）が TS2550（findLast は ES2023）
と連鎖の TS7006 で exit 2・12件のエラーで落ちる。

この既存バグが banto プロジェクトのタスク（task-0093・task-0094）の a4 を塞いでいる。
PO 裁定（2026-08-11・案C）により、typecheck 修正を独立タスクとして直し、
main に入ってから該当タスクを rework で通す方針になった。

## やること

- `tsconfig.json` / `tsconfig.check.json` の `target` を ES2022 → ES2023 に上げる
  （または `lib` に ES2023 を足す）。**検証済み**: tsconfig.check.json の target を ES2023
  にする1行で、typecheck が 0 エラーで通ることを実測済み（2026-08-11・task-0094 職人）。
- Node 22 は ES2023 に対応しており、出力される構文は ES2022 と変わらない（差は lib のみ）。
- `tests/acceptance/kobo-worker-integration.spec.ts` など .ts ファイルは**触らない**（スコープ外）。
