## 依頼（PO 原文）

> 確認すればいいだけのお知らせまとめてクローズするボタンを「これより下はお知らせ」って書いてるところの**同じ高さの右側**においてください。

## いまの作り（前提。職人は記憶を持たない）

取次の面は `packages/banto-web/src/Inbox.tsx` の `InboxFace`。中身を3段に分けている（ADR-0022 決定110）。

```ts
const decisions = items.filter((i) => !i.resolvedAt && !i.notice); // 判断（上・数える）
const notices   = items.filter((i) => !i.resolvedAt &&  i.notice); // 知らせ（中・数えない）
const done      = items.filter((i) =>  i.resolvedAt);              // 答えが出たもの（下）
```

段の頭に区切りが出る：

```tsx
<div className="ib-sep">これより下は、知らせ（読めば片付きます）</div>
<div className="ib-sep">これより下は、答えが出たもの</div>
```

**この1本目の区切り行と同じ高さ・右側**にボタンを置く、というのが依頼。答えるのは `onAnswer(itemId, actionId)`（`InboxFaceProps`）で、押すとホストへ `inbox_answer` が飛ぶ。

**知らせ（`notice: true`・決定109）は判断ではない**：
- 判断待ちの数（`inboxPending`／レールの朱の数字）に入らない
- 選択肢は「了解」1つ、という約束で積まれている（例 `packages/banto-host/src/threads.ts:704`）
- 答えても**番頭のターンは回らない**（`packages/banto-host/src/server.ts:2029` の `if (answered.notice) return;`）。まとめて閉じても番頭を無駄に起こさない

## やること

1. **区切り行を、左に文言・右にボタンの1行にする**（同じ高さ）。ボタンには**件数**を出す（例「お知らせ 12件をまとめて閉じる」）。語尾や書き方は任せるが、**何件消えるのかが押す前に分かる**こと。
2. 押したら、閉じられる知らせを**全部**答える＝各札について `onAnswer(item.id, <その札の唯一の選択肢の id>)` を呼ぶ。**ホストは触らない。プロトコルに型を足さない。**
3. **線引き（ここが一番大事・PO 指示）**
   - 対象は **`!resolvedAt && notice === true` の札だけ**。**判断を求めている札は絶対に巻き込まない。**
   - `notice` は既に機構のデータに在る区別（`InboxItemView.notice`）なので、**新しい印を足さず、あるもので切る**。
   - **選択肢が2つ以上ある知らせは巻き込まない**（安全側）。機械が「どれを選んだことにするか」を決めてよいのは選択肢が1つのときだけ。**巻き込まないものは件数にも数えない**——数字と結果を食い違わせない。
   - 閉じられるものが0件ならボタンを出さない。
4. 見た目は既存の意匠に合わせる（`btn btn--ghost` 系・`ib-sep` の行組み）。`styles.css` の追加は区切り行を左右に組む最小限。

## やらないこと

- `packages/banto-host/**` は触らない。
- 「答えが出たもの」の区切りにはボタンを付けない（依頼は知らせの段だけ）。
- 判断の段の絞り込み・並び・件数の意味は変えない。
- `App.tsx` は触らない（**同じ枝の `task-0175` が触っている**。このタスクは `depends: task-0175`）。

## 検証について（**ここを読み違えないこと**）

**ブラウザ試験（Playwright）は、マージ前ゲートの器では1件も走らない。** 番頭が 2026-08-16 に実測：`test` プロファイル（`docker/test.yaml`／`node:24-alpine`）で `npx playwright test` を回すと **152件すべて失敗**、理由は `browserType.launch: Executable doesn't exist at /root/.cache/ms-playwright/...`。イメージ（`docker/Dockerfile.test`）にブラウザが無く、alpine（musl）では chromium が動かない。

だから：

- **受け入れ条件の `verify` に `npm run test:ui` を書かないこと。**
- **Playwright 試験は自分のワークツリー（ホスト側）で回す**：`npx playwright test tests/inbox-notices-bulk-close.spec.ts --reporter=line`。**結果を報告に貼る。**
- ブラウザ試験は **inc-0071 で恒常的に9件赤い**。丸ごと回すなら「元から赤い分」と「自分の分」を分けて報告すること。
