# 依頼

## 何が起きたか（2026-08-10・PO 報告を opus 職人が調査）

PO 報告: **閉じた枝を開くと、すぐクローズされる**。チャットはできなくていいので、開いたままにしてほしい。あと閉じた枝もチャット再開できる仕組みがあるといい。

opus 職人による調査で、原因は以下の1箇所と特定された:

### ④ 閉じた枝を開くとすぐ閉じる（UI の効果の副作用）

`packages/banto-web/src/App.tsx:235-239`

```ts
useEffect(() => {
  if (branch?.state !== "closed") return;
  const parent = branch.parentId ? session.threadOf(branch.parentId) : undefined;
  if (parent) openThreadRef.current?.(parent.threadId);
}, [branch, session]);
```

コメント（App.tsx:229-234）のとおり「**見ていた枝が畳まれたら幹へ戻す**」（PO報告 2026-08-10）の実装。しかし判定が「**いま見ている枝が closed か**」だけなので、**「畳まれた瞬間」と「畳んだ枝をこちらから開いた」を区別できず**、PO が閉じた枝を開くと即座に親の幹へ戻す＝「開いたのにすぐ閉じる」ように見える。

閉じた枝への入口は2つあり、どちらもこの効果で跳ね返される:
- 幹に残る枝の札 `BranchCard`（Branch.tsx:59-62。状態は「畳みました」と出る＝押せる想定）
- 還った1行の「中身をひらく」（Branch.tsx:119-124）

`ThreadHistory` には畳んだ枝は並ばない（App.tsx:841 で `.filter((t) => t.kind === "trunk")`）。つまり**現状は閉じた枝を読む手段が実質ない**。

### ⑤ 閉じた枝のチャット再開（機構は既にある・④が潰しているだけ）

- ホスト: `threads.ts:938-948` `reopen()` — state を open に戻し、結論は残す（追記のみ・D3）
- 配線: `server.ts:795-802` `thread_reopen`
- UI: `packages/banto-web/src/Room.tsx:751-770` — 閉じた会話では入力欄の代わりに結論と**「開き直して続ける」**ボタンを出す（`session.reopenThread(threadId)`）

したがって⑤に必要な変更は **④の1箇所（App.tsx:235-239）だけ**。それで「閉じた枝を開いて読む（チャット欄なし・結論表示）」と「開き直して再開」の両方が同時に満たされる。

## 修正方針

効果を「**自分が見ている最中に closed へ遷移した**」に限定する。`App.tsx:735-738` の `onMergeBranch` は既に自分で `openThread(trunk)` しているので、番頭が `thread.merge` を呼んだ場合（＝見ている最中に畳まれた）だけを拾えば足りる。直前の state を ref で持つ、または merge を発行した本人だけ戻す、のどちらかの実装にする。

上記 acceptance をすべて満たすこと。a3 が本修正の本質（「畳まれた瞬間」と「畳んだ枝を開いた」の区別）。
