## 背景

決定18 のセッションビューアとも関連。epic-0002 のスコープ外だった Kobo GUI（アテンションキュー・ボード）をここで扱う。Kobo が Module として配線される（epic-0010・task-0048）のに合わせて、Kobo の GUI をキャンバスのカタログエントリとして登録し、番頭が `canvas.open` で出せるようにする。カタログの形式は epic-0002（task-0012）で入った「Tool 契約を土台に component 参照を拡張したもの」にそのまま乗る。

## 実装（2026-08-07）

- **ボード**（`KoboBoard`）: 状態機械のビューア。列は状態の**集約**で、独自の分類を持たない
  （spec-daemon-core §1：かんばんの Now / Next / Later は状態の集約であって別の状態ではない）。
  **閲覧専用**——承認をここから押せると、経緯を読まずに通すことになる（決定57 の一次受けが
  形骸化する）
- **レビュー面**（`KoboReview`）: 経緯・変更の範囲・受け入れ基準・監査の判定が1画面に揃い、
  **触れる環境があれば開ける**（決定59）。`po` と判定されたものは**通すボタンが出ない**
  ——判定は工場が機械的に行い、画面は結果を描くだけ（D5）
- **状態の反映は取り直し（8秒）にした。** 当初の a2 は WebSocket と書いていたが、
  番頭ホストの WS は**会話の protocol** で、そこにボード用の押し出しを相乗りさせると
  「番頭との会話」と「工場の実況」が1本の口に混ざる。Kobo 自身の WS をホストが橋渡しする
  作りも要る。**見て判断する面が8秒遅れて困ることは無い**ので、機構を増やす前に取り直しで
  置いた（増やすなら、判断待ちが増えたことを会話へ返す既存の経路の方が先）
- **到達先が2つある**（決定25 の注意点）。Kobo は独立プロセスで 127.0.0.1 にしか出ていない
  ので、UI からは直接届かない。モジュールの `endpoint.baseUrl` は**同一オリジンの相対パス**に
  し、ホストが `/api/kobo/tools/*` を受けて Kobo へ中継する
